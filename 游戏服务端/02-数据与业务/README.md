# 数据与业务 · 分类导航

> 游戏服务端「数据与业务」专题：从存储选型、存档表设计、缓存与排行榜，到分布式高可用、安全反作弊、部署运维监控，覆盖游戏服务器"数据层 + 业务层"的完整工程链路。
> 属于 [游戏服务端知识库](../README.md) 的第二大分类，建议先完成 [01-架构与网络](../01-架构与网络/README.md) 的基础篇目，再进入本分类。

## 分类简介

游戏服务器的业务本质是：**处理玩家操作 → 修改游戏状态 → 可靠地保存状态**。本分类围绕这条主线展开：

1. **存什么、存在哪**：数据库选型（MySQL/Redis/MongoDB）、玩家存档表设计、读写分离、分库分表、索引与慢查询优化、存档快照与异步落盘；
2. **怎么读得快**：Redis 缓存体系、缓存穿透/击穿/雪崩治理、缓存与 DB 的一致性、ZSet 排行榜、热点数据处理；
3. **多机怎么协作**：一致性哈希、消息队列、负载均衡、服务发现、CAP/BASE、Raft、容灾多活、分布式锁；
4. **怎么防作弊**：服务器权威、客户端数据校验、协议加密与签名、常见外挂与对策、行为风控、防沉迷与合规；
5. **怎么稳定运行**：Docker/K8s 部署、CI/CD、日志采集（ELK/Loki）、监控告警、配置中心、热更新、压测与容量规划。

本分类的阅读顺序建议：**存储 → 缓存 → 分布式 → 安全 → 运维**，因为缓存依赖存储、分布式依赖前两者的数据模型、安全与运维是贯穿性工程能力。

## 学习顺序建议

1. **入门（建立数据观）**：先读 [01-数据库选型与存储设计](01-数据库选型与存储设计.md) 的选型对比与存档表设计，理解"一行一玩家"与"内存权威 + 异步落盘"两条主线；
2. **进阶（性能与体验）**：再读 [02-缓存与排行榜系统](02-缓存与排行榜系统.md)，掌握缓存三大问题与排行榜实现，这是面试与实战的高频考点；
3. **扩展（架构能力）**：读 [03-分布式与高可用](03-分布式与高可用.md)，理解多机协作与容灾，注意与 01 篇的分库分表、02 篇的分布式锁呼应；
4. **加固（安全合规）**：读 [04-安全与反作弊](04-安全与反作弊.md)，建立"服务器权威、客户端不可信"的安全底线思维；
5. **落地（工程化）**：读 [05-部署运维与监控](05-部署运维与监控.md)，把前面所有知识放进可部署、可观测、可扩容的工程框架里。

> 提示：本分类各篇内部均按「概述 → 核心概念（表格）→ 原理详解 → 代码/配置示例 → 最佳实践 → 常见问题 FAQ → 关联阅读」组织，可直接按需查阅。
