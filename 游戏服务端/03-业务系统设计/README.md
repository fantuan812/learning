# 03-业务系统设计 · 游戏业务系统设计

> 业务系统是游戏服务端承上启下的"业务层"：上层对接客户端玩法与表现，下层依赖 `01-架构与网络`、`02-数据与业务` 提供的基础设施。本分类从最常见的六大业务系统入手，讲解每个系统的数据模型、核心流程、一致性 / 幂等 / 防作弊等工程要点。

## 分类简介

游戏服务端的价值最终体现在业务系统上：玩家看到的是背包里的道具、正在进行的任务、商店里的商品、匹配到的对手、聊天的消息、战斗的结算。这些系统虽然玩法各异，但共性问题高度一致：

- **数据模型**：如何组织静态配置与动态玩家数据（模板/实例、槽位、订单、任务状态机、好友关系）；
- **流程一致性**：如何保证扣款、发货、任务奖励、邮件附件等跨模块操作在并发与失败场景下不重不漏（事务、幂等、流水日志）；
- **同步与表现**：服务端权威数据如何以全量 / 增量方式同步给客户端，客户端表现如何与服务端结算保持一致；
- **防作弊与安全**：数值校验、服务端权威计算、随机种子与回放校验、频率限制、敏感词过滤；
- **性能与容量**：海量玩家、海量物品、高并发聊天与匹配下的架构取舍（分片、缓存、队列、弹性伸缩）。

建议先阅读 `01-架构与网络`（理解消息 / 并发 / 同步基础）与 `02-数据与业务`（理解存储 / 缓存 / 反作弊），再进入本分类；本分类内的篇目按依赖关系从基础到综合排列。

## 学习顺序建议

1. **先读 [01-背包与道具系统](01-背包与道具系统.md)**：背包是最基础、最通用的"玩家资产"系统，事务、锁、幂等、流水重放的套路在这里讲得最细，后续所有系统的资产操作（任务奖励、商城发货、邮件附件）都会复用这套思路。
2. **再读 [02-任务与成就系统](02-任务与成就系统.md)**：学习"事件驱动 + 数据驱动"的通用模式——用配置描述逻辑（任务表/条件/奖励），这个模式在成就、每日任务、活动玩法中反复出现。
3. **然后读 [03-商城与经济系统](03-商城与经济系统.md)**：涉及虚拟货币与真实支付，重点掌握订单状态机、支付回调验签与防重、对账、流水审计——这是严谨性要求最高的业务系统。
4. **接着读 [04-匹配与房间系统](04-匹配与房间系统.md)**：从"单玩家数据"上升到"多人会话编排"，理解匹配队列、超时策略、房间状态机与服务器分配（GameLift/Fleet）。
5. **然后读 [05-聊天与社交系统](05-聊天与社交系统.md)**：理解高吞吐消息路由、过滤限频与关系型数据（好友/邮件/公会），是对消息基础设施的实战应用。
6. **最后读 [06-战斗结算与验证](06-战斗结算与验证.md)**：综合前面全部知识，掌握服务端权威结算、随机种子同步与回放校验，是服务端反作弊能力的集大成者。

> 学习提示：每篇都包含「概述 → 核心概念 → 原理详解 → 代码/表结构示例 → 最佳实践 → 常见问题 FAQ → 关联阅读」七个部分；示例语言不限（SQL / JSON / Go / Python 伪代码等），重点理解设计思想而非具体语法。
