# 工作日志：2026-08-03

## 任务：服务器假人 AI 的 A* 寻路算法优化 + 耗时点测试

### 背景
- 服务器上假人（Bot）数量多，AI 寻路调用频繁，A* 路径搜索成为 CPU 热点。
- 目标：降低单次寻路耗时与整体 CPU 占用，保证服务器主循环（Tick）稳定。

### 1. A* 算法优化（进行中）
优化方向：
- Open List 数据结构：由线性扫描改为二叉堆 / 四叉堆，降低取最小代价节点的开销。
- Closed List：网格地图用标记数组（O(1) 判定），替代线性查找。
- 启发式函数：根据地图类型选用 Manhattan / Octile，保证一致性（consistent）以减少节点重复入队。
- 搜索范围控制：设置最大搜索节点数 / 时间预算，超限走降级方案（直线行走 + 简单避障）。
- 节点复用与对象池：避免寻路过程中频繁分配/释放，降低 GC 压力。
- 路径缓存：起终点相同且目标未变化时直接复用上次结果。
- 多假人调度：寻路按 Tick 预算分批执行，避免单帧集中开销。

- 在 A* 关键阶段插入计时点：Open List 入队/出队、邻居节点扩展、启发式计算、路径重建、整体寻路。
- 采用高精度单调时钟统计每次调用耗时，按 Tick 汇总累计 / 平均 / 最大耗时。

### 3. 耗时点测试（第二阶段：perf 采样）
- 用 perf 挂载服务器进程采样，无需改代码即可拿到真实调用栈分布：
  - `perf record -F 99 -g -p <pid> -- sleep 60`
  - `perf report` 查看热点，导出数据生成火焰图确认调用链。
- 结论：与插桩结果互相印证，确认热点函数（待补充具体数据）。

### 收获 / 结论
- 插桩测试：精确、能统计特定代码段的次数与耗时，但需要改代码、有少量开销，适合定位逻辑层热点。
- perf 采样：零侵入、能看全链路调用栈，适合验证插桩结论并发现底层问题（内存分配、缓存缺失、锁竞争）。
- 两种手段结合：先插桩圈定逻辑热点，再用 perf 验证、查漏。
