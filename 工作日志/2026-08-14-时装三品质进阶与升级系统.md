# 工作日志：2026-08-14

## 任务：新类型时装添加 —— 三品质 × 十级（进阶 + 升级）系统（已完成）

### 背景
- 新增一种新类型时装，设计上分为三个品质（低级 / 中级 / 高级）。
- 服务器实现上：三个品质实际是**三个独立的时装**（各自独立模板与配置），不是同一时装的三个状态位。
- 品质之间有进阶关系：低级 → 中级 → 高级；每个品质内部可以升级，共 10 级。
- 已确认规则：**进阶不要求满级**（任意等级均可进阶）；进阶成功后**单独下发对应的那一件下一品质时装**（非整套），旧品质时装保留（不替换、不回收）。
- 服务器配置要求：
  - **进阶道具按时装单独配置**：低→中、中→高 两个进阶步骤各自单独配置进阶道具（中阶→高阶也是单独配置，不共用）；
  - **升级配置升级道具组**：升级消耗一组（多个）道具，需要整组校验、整组扣减；
  - **配置完备性检查已实现**：启动期校验两个可进阶起点（低级、中级）都配齐对应进阶道具，并校验三个品质都配齐升级道具组；缺失即告警。

### 系统结构
```mermaid
flowchart LR
    A[低级时装<br/>品质1 · 1~10级] -->|进阶 · 消耗进阶道具1| B[中级时装<br/>品质2 · 1~10级]
    B -->|进阶 · 消耗进阶道具2| C[高级时装<br/>品质3 · 1~10级]
```

图：三个品质是三个独立时装；横向箭头为进阶（跨品质），纵向（图内省略）为升级（品质内 1~10 级）。

- 进阶：跨品质操作，不要求当前品质满级；成功后**单独下发对应的那一件**下一品质时装，旧品质时装保留；
- 升级：品质内操作，当前品质内等级 +1，最高 10 级。

### 配置要求（服务器侧）
- 进阶道具：**每个可进阶起点单独配置**（低→中、中→高 各自独立；高级没有下一品质，不配置进阶道具）。进阶时按“当前时装”取自己的进阶道具配置，校验时不能假设两个进阶步骤共用一份配置。
- 升级道具组：一组多个道具，逐个校验数量、整组扣减；道具组配置缺失时要能识别并报明确错误。
- 完备性检查：启动期校验低级/中级时装的进阶道具，以及低级/中级/高级时装的升级道具组；缺失即告警。

### 实现与校验逻辑（本次主要工作量）
代码本身不复杂，工作量集中在进阶与升级的**校验逻辑**上：边界分支多，且每个分支都要返回明确的错误码 / 提示。

#### 1. 进阶校验清单
| 校验点 | 说明 |
| --- | --- |
| 品质顺序 | 只能相邻进阶（低→中、中→高），禁止跳级（低→高） |
| 品质上限 | 最高品质（高级）不可再进阶 |
| 等级条件 | **不要求满级**，任意等级均可进阶（如有等级下限要求按配置补充） |
| 进阶道具 | 按当前时装取进阶道具配置，校验背包数量充足 |
| 目标时装 | 目标品质的时装配置存在、模板合法 |
| 重复 / 幂等 | 防止重复请求、并发下**重复发放新时装**（旧时装保留，重点是发新的幂等） |

#### 2. 升级校验清单
| 校验点 | 说明 |
| --- | --- |
| 等级上限 | 当前品质内已满 10 级不可再升级 |
| 等级连续性 | 只能逐级 +1，不能跳级 |
| 升级道具组 | 道具组内多个道具逐项校验数量，缺一不可 |
| 配置存在性 | 升级道具组未配置时给明确报错，不静默跳过、不空指针 |
| 扣减一致性 | 校验全部通过后再统一扣减；扣减过程失败不留下半扣状态 |
| 操作互斥 | 同一时装同一时刻只允许一种变更（升级 / 进阶不能同时进行） |

### 收获 / 结论
- 主要工作量在“繁琐的校验”：品质边界、等级边界、道具组多道具、并发重复请求，每个边界分支都要返回明确错误；
- 业务本质不复杂：**状态校验 → 道具扣减 → 状态变更（升级）/ 单独下发新时装（进阶）**；
- 三品质 = 三时装的映射带来重复配置与重复校验：进阶道具按时装独立配置，校验必须按当前时装取配置，不能假设三品质共用。

### 已确认规则（本次定案）
- 进阶**不要求满级**，任意等级均可发起进阶；
- 进阶成功后**单独下发对应的那一件下一品质时装**（非整套），旧品质时装保留（不替换、不回收）；
- 因此进阶本质是「扣进阶道具 + 单独下发新时装」的加性操作，重复 / 幂等校验的重点是防止并发下**重复发放新时装**（而非防止旧时装被覆盖）；
- 进阶道具配置：低→中、中→高 各自单独配置，不共用；
- **配置完备性检查已实现**：启动期校验低级/中级时装的进阶道具，以及三个品质时装的升级道具组，缺失即告警；高级时装不要求进阶道具。
