## 学习顺序

1. 先阅读 [01-确定性与基准工程总览](01-确定性与基准工程总览.md) 的元数据、事实边界、架构总览与分篇指引。
2. 复习 [A* 算法与优化](../01-寻路与图论/02-A星算法与优化.md)，明确静态搜索的正确性与启发式基础。
3. 按需精读分篇：[02-动态寻路LPA与DStarLite](02-动态寻路LPA与DStarLite.md)（增量重规划）→ [03-NavMesh工程Recast与Detour](03-NavMesh工程Recast与Detour.md)（烘焙与查询）→ [04-RVO与数值鲁棒](04-RVO与数值鲁棒.md)（局部避障与数值）→ [05-联机确定性与基准工程](05-联机确定性与基准工程.md)（回放与基准门禁）。
4. 用 [碰撞检测](../02-数学与碰撞/04-碰撞检测.md) 补齐几何查询、连续碰撞和退化输入的边界。
5. 用 [AOI 与视野计算](../03-工程与实用技巧/03-AOI与视野计算.md) 连接邻居查询、分区和服务端预算。
6. 最后联读 [AI 评测与回放](../../游戏AI/03-评测与安全/01-AI评测回放.md)、[LLM-NPC 安全](../../游戏AI/03-评测与安全/03-LLM-NPC安全.md) 与 [平台可靠性总览](../../游戏服务端/04-平台与可靠性/00-平台可靠性总览与迁移说明.md)，把路径系统接入回放、限流、审计和故障恢复。

## 来源边界

- 算法原理可以使用论文和教材中的通用结论，但复杂度只在明确的数据结构、图模型和实现条件下陈述。
- Recast/Detour 的烘焙、查询、TileCache 和 Crowd 结论以官方仓库及其源码为证据，不推断任何未公开的 UE 内部实现。
- RVO/ORCA 的适用范围以 RVO2 官方页面和算法假设为边界，不把局部避障承诺扩大为全局路径最优。
- 数值与连续碰撞示例引用 Box2D、Bullet 等官方资料；工程阈值必须通过本地尺度、平台和回放测试重新标定。
- 文章中的 P50/P95/P99、内存和失败率是基准方法，不是跨项目的固定性能承诺。
- 代码示意以 C++17 与 Python 3.12 为知识基线，接口名可按项目封装层调整。

## 推荐产出

- 为每张地图建立固定种子、固定障碍版本和固定目标集。
- 把搜索、几何、局部避障、回放和服务端限流拆成可独立测量的阶段。
- 用状态哈希、输入回放和报告阈值把“看起来能走”升级为可回归的工程证据。
