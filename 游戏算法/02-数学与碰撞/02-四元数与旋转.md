# 02 · 四元数与旋转

> 前置知识：01-向量与矩阵基础（向量点积/叉积、矩阵乘法）。
> 本文讲解游戏引擎中旋转的标准表示——四元数（Quaternion）。

## 概述

旋转是游戏中最常见的操作之一：角色转身、镜头环绕、枪口指向、骨骼摆动、刚体翻滚……
而「用什么数据结构表示旋转」直接决定代码的稳定性与质量。早期游戏与许多教学代码
使用**欧拉角（Euler Angles）**（绕 X/Y/Z 三轴的角度），它直观易读，却有两个致命
缺陷：**万向锁（Gimbal Lock）**导致自由度丢失、姿态出现诡异抖动；三角度插值不平滑，
且不同顺序（YXZ、ZXY…）含义完全不同。

**四元数**是复数在四维空间的推广，用 4 个分量 `(w, x, y, z)` 紧凑地表示旋转：
它没有万向锁、插值平滑（Slerp）、组合旋转只需一次乘法、与矩阵互转有闭合公式，
因此成为 Unity、Unreal、Godot 等引擎旋转数据的**默认存储格式**。

本文先剖析欧拉角与万向锁问题（用飞行模拟器与 FPS 镜头的真实例子说明），再给出
四元数的代数定义与几何意义（旋转轴 + 半角），推导核心公式：旋转公式 `v' = q·v·q⁻¹`、
四元数乘法、共轭与逆、Slerp 插值、与旋转矩阵的互转；最后讲解骨骼动画中的关节
旋转、第三人称相机的平滑旋转等应用，并附 C++/Python 实现与完整 FAQ。

## 核心概念

| 概念 | 定义/公式（简） | 关键要点 |
| --- | --- | --- |
| 欧拉角 | 绕三个坐标轴依次旋转的角度 `(α, β, γ)` | 直观但依赖旋转顺序，有万向锁 |
| 万向锁 | 中间轴旋转 ±90° 时两轴重合、丢失一个自由度 | 表现为姿态突然「卡死」与抖动 |
| 四元数 | `q = w + xi + yj + zk`，四个实数 | 复数的四维推广 |
| 单位四元数 | `|q| = 1`，表示旋转 | 非单位四元数需归一化后再用 |
| 旋转四元数 | `q = (cos(θ/2), sin(θ/2)·轴)` | 旋转 θ 角，注意是**半角** |
| 共轭 | `q* = (w, -x, -y, -z)` | 表示反向旋转（对单位四元数即逆） |
| 逆 | `q⁻¹ = q*/|q|²` | 单位四元数 `q⁻¹ = q*` |
| 四元数乘法 | `q1·q2`（哈密顿积，非交换） | 复合旋转：先 q1 后 q2 |
| Slerp | 球面线性插值，沿测地线 | 恒定角速度、无加速感 |
| Nlerp | 归一化线性插值 | 快但角速度不均，小角度可用 |
| 四元数↔矩阵 | 有闭合公式互转 | 渲染前必须转成矩阵 |

## 原理详解

### 1. 欧拉角与万向锁

欧拉角把任意旋转分解为绕三个固定（或随动）轴的依次旋转，例如 Unity 的 `(x, y, z)`
表示「先绕 Z 轴，再绕 X 轴，最后绕 Y 轴」（顺序因引擎而异）。问题在于：

1. **顺序依赖**：`(90, 0, 0)` 再绕 Y 转 30° 与先绕 Y 转 30° 再 `(90, 0, 0)` 结果不同；
2. **万向锁**：当**中间那次旋转**（如 YXZ 顺序中的 X）达到 ±90° 时，第一次与第三次
   旋转的轴在空间中重合，三个角度退化成「两个自由度」，表现为：无论怎么转，某个方向
   都无法到达；且角度微小变化会导致姿态突变、插值抖动。

**飞行模拟器实例**：飞机先抬头 90°（俯仰），此时再「偏航」实际是在绕机头轴滚动；
玩家继续操作偏航，飞机却像被卡住一样打转——这就是万向锁。**FPS 镜头实例**：第一人称
相机把俯仰限制在 ±89°，正是为了避免俯仰到达 ±90° 触发万向锁。

### 2. 四元数的定义

四元数由哈密顿（Hamilton, 1843）提出，形如：

```text
q = w + x·i + y·j + z·k
```

其中虚部满足：

```text
i² = j² = k² = i·j·k = -1
i·j = k,  j·i = -k     （乘法不交换）
```

把纯虚部记为三维向量 `v = (x, y, z)`，四元数可写作标量-向量对 `q = (w, v)`。

**几何意义**：单位四元数（`w² + x² + y² + z² = 1`）对应**绕单位轴 `n̂` 旋转 `θ` 角**：

```text
q = (cos(θ/2), sin(θ/2)·n̂)
```

**为什么是半角？** 因为四元数旋转通过**双面乘法**实现（见下一节）：`q` 作用两次
等价于旋转 θ。类比复数：单位复数 `e^{iθ}` 通过单面乘法旋转 θ；四元数在 3D 中
必须以「左乘 q、右乘 q⁻¹」的方式夹逼，每次只贡献 θ/2。□

### 3. 旋转公式：v' = q·v·q⁻¹

把三维向量 `v` 写成纯四元数 `(0, v)`，则绕单位轴 `n̂` 旋转 θ 的公式为：

```text
v' = q · v · q⁻¹，   q = (cos(θ/2), sin(θ/2)·n̂)
```

**推导**：把 `v` 分解为平行于轴与垂直于轴的两部分：

```text
v = v_∥ + v_⊥
v_∥ = (v·n̂)·n̂          # 平行分量，旋转不变
v_⊥ = v - v_∥          # 垂直分量，在垂直于轴的平面内旋转
```

垂直分量在平面内旋转 θ 等价于复数平面乘法：`v_⊥' = cosθ·v_⊥ + sinθ·(n̂ × v_⊥)`。
将 `cosθ = cos²(θ/2) - sin²(θ/2)`、`sinθ = 2sin(θ/2)cos(θ/2)` 代入，并利用四元数乘法
的几何性质（纯四元数相乘：`(0,a)(0,b) = (-a·b, a×b)`），整理后恰好得到
`q·v·q⁻¹` 的展开式。□

由此可知四元数旋转**保长保角**（是刚体变换），且**不引入剪切**。

### 4. 四元数乘法（哈密顿积）

设 `q1 = (w1, v1)`、`q2 = (w2, v2)`：

```text
q1·q2 = (w1·w2 - v1·v2,  w1·v2 + w2·v1 + v1 × v2)
```

**推导**：展开 `(w1 + x1i + y1j + z1k)(w2 + x2i + y2j + z2k)`，利用虚部乘法表
（`ij = k` 等）合并同类项，标量部分得到 `w1w2 - (x1x2 + y1y2 + z1z2)`，向量部分
得到 `w1v2 + w2v1 + v1×v2`。□

**复合旋转**：先应用 `q1`、再应用 `q2` 的等价旋转为：

```text
q_total = q2 · q1      （注意顺序：与矩阵相同，右乘先作用）
```

验证：`q2·(q1·v·q1⁻¹)·q2⁻¹ = (q2·q1)·v·(q2·q1)⁻¹`。□

**共轭与逆**：

```text
q* = (w, -v)
q⁻¹ = q* / |q|²
```

单位四元数 `|q| = 1`，故 `q⁻¹ = q*`。几何上共轭即**反向旋转**（绕同轴转 −θ）。

**点积与夹角**：两个单位四元数 `q1·q2`（当作 4D 向量点积）的绝对值越大，表示两个
旋转越接近；`dot < 0` 时两者方向相反（表示同一旋转的双倍覆盖现象，见 FAQ）。

### 5. 旋转插值：Slerp 与 Nlerp

**Slerp（球面线性插值）**：在四维单位球面上沿**测地线（大圆弧）**插值，保证恒定
角速度。公式：

```text
Ω = acos(q1 · q2)                 # 两旋转之间的夹角
q(t) = [ sin((1-t)·Ω)·q1 + sin(t·Ω)·q2 ] / sin(Ω)
```

**推导**：在 2D 平面上类比——单位圆上两点 `p0, p1`，其夹角 Ω，圆上点可写作
`p0` 与 `p1` 的线性组合：`p(t) = [sin((1-t)Ω)·p0 + sin(tΩ)·p1] / sinΩ`（由三角恒等式
`sin((1-t)Ω) = sinΩ·cos(tΩ) - cosΩ·sin(tΩ)` 可验证其位于圆上且与 p0 夹角为 tΩ）。
把这个构造直接推广到四维单位球面即得 Slerp。□

**工程要点**：

- 若 `q1·q2 < 0`，先取 `q2 = -q2`（两个四元数表示同一旋转，但取反后插值路径更短，
  避免绕远路）；
- `Ω` 很小时（如 `sinΩ < 1e-6`），退化为普通 Lerp + 归一化，避免除零；
- 对**多个**四元数插值可用 `nlerp` 近似（如骨骼动画的多个姿态混合），速度更快。

**Nlerp**：普通线性插值后归一化。速度最快但角速度不均匀（中间快两端慢），
小角度旋转（< 30°）时误差可忽略，是 Slerp 的廉价替代。

### 6. 与旋转矩阵互转

设单位四元数 `q = (w, x, y, z)`，对应旋转矩阵（列主序向量乘法 `v' = R·v`）：

```text
R = [ 1-2(y²+z²)   2(xy-wz)    2(xz+wy)  ]
    [ 2(xy+wz)     1-2(x²+z²)  2(yz-wx)  ]
    [ 2(xz-wy)     2(yz+wx)    1-2(x²+y²)]
```

**推导思路**：把基向量 `e1=(1,0,0)` 代入旋转公式 `v' = q·v·q⁻¹`，用纯四元数乘法
展开得到矩阵第一列；同理可得第二、三列。该矩阵是正交矩阵（`RᵀR = I`），且
`det(R) = 1`，符合刚体旋转特征。□

**矩阵 → 四元数**（从迹 `tr = m00+m11+m22` 出发）：

```text
若 tr > 0：  w = 0.5·sqrt(tr + 1)，再由 R 反对称部分解出 x, y, z
若 tr ≤ 0：  取最大对角元所在轴为基准（数值稳定），例如 m00 最大时：
  x = 0.5·sqrt(1 + m00 - m11 - m22)
  w = (m21 - m12) / (4x)
其余分量由 R 元素线性组合求出（实现见代码示例）
```

**为什么要分情况？** 因为 `acos` 类反解在接近 ±1 时数值不稳定；从最大对角元出发
可保证除法分母最大、误差最小。这是工业实现的标准技巧。□

### 7. 骨骼动画与相机应用

**骨骼动画**：每个关节的局部旋转用四元数存储，顶点变换链为：

```text
P_world = M_parent · M_joint · P_bindPose⁻¹ · P_vertex
```

其中 `M_joint` 由局部旋转（四元数转矩阵）与局部平移复合。动画混合时对同一关节的
多个动画姿态做**加权混合**：小角度用 Nlerp 逐对混合（如 `normalize(Σ wi·qi)`），
需要高质量时用「多四元数加权平均」（Shoemake 算法）。四元数避免了三角度混合时
的万向锁抖动。

骨骼动画中四元数的完整流转：

```mermaid
flowchart LR
    A["动画剪辑<br/>每关节一组四元数关键帧"] --> B["动画混合<br/>Nlerp/Slerp 加权平均"]
    B --> C["局部姿态<br/>关节的 q（旋转）+ t（平移）"]
    C --> D["正向动力学 FK<br/>M = M_parent · T(t) · R(q)"]
    D --> E["蒙皮矩阵<br/>M_joint · BindPose⁻¹"]
    E --> F["顶点着色器<br/>批量变换网格顶点"]
```

**第三人称相机**：相机跟随角色时，期望朝向 `targetRot` 与当前朝向 `currentRot`
之间的平滑过渡用：

```text
currentRot = Slerp(currentRot, targetRot, 1 - exp(-k·dt))    # 帧率无关平滑
```

比直接赋值更自然，且**不会**出现欧拉角插值中途「转大圈」的问题（因为 Slerp 走
最短弧）。FPS 相机则把「俯仰」与「偏航」分开累计，再合成四元数，规避万向锁。

## 伪代码与代码示例

### 伪代码：Slerp 与四元数旋转

```text
function Slerp(q1, q2, t):
    dot = q1·q2                        # 4D 点积
    if dot < 0:                        # 最短路径修正
        q2 = -q2; dot = -dot
    if dot > 0.9995:                   # 夹角过小，退化为 Nlerp
        return normalize(q1 + t·(q2 - q1))
    Ω = acos(dot)
    return (sin((1-t)·Ω)·q1 + sin(t·Ω)·q2) / sin(Ω)

function RotateVector(q, v):           # v' = q·v·q⁻¹
    qv = (0, v)
    return (q · qv · q⁻¹).vector
```

### C++ 示例

```cpp
#include <cmath>

struct Quat {
    float w, x, y, z;
    Quat operator*(const Quat& o) const {          // 哈密顿积
        return {
            w*o.w - x*o.x - y*o.y - z*o.z,
            w*o.x + x*o.w + y*o.z - z*o.y,
            w*o.y - x*o.z + y*o.w + z*o.x,
            w*o.z + x*o.y - y*o.x + z*o.w
        };
    }
    Quat conj() const { return {w, -x, -y, -z}; }
    Quat normalized() const {
        float l = std::sqrt(w*w + x*x + y*y + z*z);
        return {w/l, x/l, y/l, z/l};
    }
};

// 轴角 → 四元数（注意半角）
Quat FromAxisAngle(float ax, float ay, float az, float angle) {
    float h = angle * 0.5f;
    float s = std::sin(h);
    return {std::cos(h), ax*s, ay*s, az*s};
}

// Slerp（假设两个都是单位四元数）
Quat Slerp(Quat a, Quat b, float t) {
    float d = a.w*b.w + a.x*b.x + a.y*b.y + a.z*b.z;
    if (d < 0.0f) { b = {-b.w, -b.x, -b.y, -b.z}; d = -d; }
    const float kEps = 1e-6f;
    if (d > 1.0f - kEps) {                       // 几乎相同，用 Nlerp
        Quat r = {a.w + t*(b.w-a.w), a.x + t*(b.x-a.x),
                  a.y + t*(b.y-a.y), a.z + t*(b.z-a.z)};
        return r.normalized();
    }
    float omega = std::acos(d);
    float s0 = std::sin((1-t)*omega) / std::sin(omega);
    float s1 = std::sin(t*omega)   / std::sin(omega);
    return {a.w*s0 + b.w*s1, a.x*s0 + b.x*s1,
            a.y*s0 + b.y*s1, a.z*s0 + b.z*s1};
}

// 四元数 → 旋转矩阵（列主序）
void ToMatrix(const Quat& q, float m[16]) {
    float xx=q.x*q.x, yy=q.y*q.y, zz=q.z*q.z;
    float xy=q.x*q.y, xz=q.x*q.z, yz=q.y*q.z;
    float wx=q.w*q.x, wy=q.w*q.y, wz=q.w*q.z;
    m[0]=1-2*(yy+zz); m[4]=2*(xy-wz);   m[8]=2*(xz+wy);  m[12]=0;
    m[1]=2*(xy+wz);   m[5]=1-2*(xx+zz); m[9]=2*(yz-wx);  m[13]=0;
    m[2]=2*(xz-wy);   m[6]=2*(yz+wx);   m[10]=1-2*(xx+yy); m[14]=0;
    m[3]=0; m[7]=0; m[11]=0; m[15]=1;
}
```

### Python 示例（NumPy）

```python
import numpy as np

def quat_mul(a, b):
    wa, va = a[0], a[1:]
    wb, vb = b[0], b[1:]
    return np.concatenate(([wa*wb - va @ vb],
                           wa*vb + wb*va + np.cross(va, vb)))

def quat_conj(q):
    return np.array([q[0], -q[1], -q[2], -q[3]])

def slerp(q1, q2, t):
    d = float(q1 @ q2)
    if d < 0:
        q2 = -q2; d = -d
    if d > 1 - 1e-6:
        r = q1 + t*(q2 - q1)
        return r / np.linalg.norm(r)
    omega = np.arccos(np.clip(d, -1, 1))
    s0 = np.sin((1-t)*omega) / np.sin(omega)
    s1 = np.sin(t*omega) / np.sin(omega)
    return s0*q1 + s1*q2

def rotate_vector(q, v):
    qv = np.concatenate(([0.0], v))
    qinv = quat_conj(q) / (q @ q)          # 通用逆
    return quat_mul(quat_mul(q, qv), qinv)[1:]

# 验证：绕 Z 轴转 90°，(1,0,0) 应变为 (0,1,0)
q = np.array([np.cos(np.pi/4), 0, 0, np.sin(np.pi/4)])
print(rotate_vector(q, np.array([1., 0, 0])))   # ≈ [0, 1, 0]
```

## 复杂度分析

| 运算 | 浮点开销（约） | 对比矩阵 |
| --- | --- | --- |
| 四元数乘法 | 16 次乘 + 12 次加 | 矩阵乘 48 次乘 + 36 次加（快 3 倍） |
| 旋转向量 `q·v·q⁻¹` | 约 30 次乘加 | 矩阵旋转 9 次乘加（矩阵更快，适合批量） |
| Slerp | 1 次 acos + 2 次 sin + 若干乘加 | 无矩阵等价物（矩阵插值无意义） |
| 四元数→矩阵 | 常数（约 20 次乘加） | 每帧对渲染批处理一次即可 |
| 存储 | 4 个 float（16 字节） | 3×3 矩阵 9 个 float（36 字节） |

结论：**单次旋转向量时矩阵更快，但四元数在存储、组合、插值、稳定性上全面占优**。
工业实践：逻辑层（动画、相机、物理姿态）用四元数，渲染前统一转矩阵并批量变换顶点。

## 最佳实践

1. **存储与交换一律用单位四元数**：任何外部输入（文件、网络、物理引擎）进入系统时
   先归一化；非单位四元数会导致旋转「附带缩放」，渲染出拉伸的物体。
2. **Slerp 前检查点积符号**：`dot < 0` 时对其中一个取反，否则插值会绕远路（看似
   突然翻转 360°）。这是四元数「双倍覆盖」特性带来的最隐蔽 bug。
3. **避免存储欧拉角**：仅在编辑器/调试 UI 中用欧拉角展示；运行期姿态一律四元数。
   需要欧拉角时（如 FPS 俯仰偏航）独立累计角度再合成四元数，且**俯仰限幅 ±89°**。
4. **组合旋转注意顺序**：`q_total = q2·q1` 表示先 q1 后 q2（右乘先作用）。相机
   偏航、俯仰组合时先乘偏航再乘俯仰，可避免世界轴/本地轴混淆。
5. **小角度插值用 Nlerp**：骨骼动画批量混合、误差容忍度高时，Nlerp 快且足够好；
   需要恒定角速度（相机旋转、观感敏感的 UI 旋转）才用 Slerp。
6. **矩阵互转注意数值分支**：矩阵→四元数务必按迹/对角元分情况取最大分母，否则
   接近 180° 旋转时数值误差被放大。
7. **测角差用 `q1·q2⁻¹` 的旋转角**：想得到「从 q1 到 q2 的旋转」用
   `Δq = q2·q1⁻¹`，其旋转角 `θ = 2·acos(Δq.w)` 可用来驱动转向动画。

## 常见问题 FAQ

**Q1：为什么旋转公式用半角？直接四元数乘向量不行吗？**
不行。三维旋转必须保持向量模长与「垂直轴分量」的旋转结构。若只用单侧乘法 `q·v`，
结果不仅旋转还会沿轴拉伸（除非 v 恰在旋转平面内）。双面乘法 `q·v·q⁻¹` 恰好抵消
轴向分量、让垂直分量旋转 2·(θ/2) = θ。这也是四元数能表示**三维**旋转而复数只能
表示二维旋转的原因。

**Q2：万向锁到底是怎么发生的？能举个具体数字吗？**
以 YXZ 顺序（先绕 X 再绕 Y 再绕 Z，Unity 常见）为例：绕 X 转 90° 后，原来的 Z 轴
被转到了 Y 方向，此时「绕 Z 转」与「绕 Y 转」作用于同一根物理轴。设初始姿态为
`(90°, 0, 0)`，后续无论怎么调 Y、Z 角度，只能改变两个自由度方向，第三方向不可达；
而为了让姿态「看起来动了」，Y、Z 会以相反方向快速变化——表现为旋转轴疯狂摆动。

**Q3：四元数能表示所有旋转吗？为什么说它双倍覆盖？**
能。任何三维旋转都能写成单位四元数。但 `q` 与 `-q` 表示**同一个旋转**（因为
`(-q)·v·(-q)⁻¹ = q·v·q⁻¹`），这就是双倍覆盖：四维单位球面上的每个点与其对跖点
对应同一姿态。Slerp 若不处理符号，可能在两个「等价」表示之间绕远路。

**Q4：Slerp 和 Lerp+归一化（Nlerp）差在哪？什么时候用哪个？**
Slerp 沿四维球面测地线走，角速度恒定，但包含 acos/sin，开销约为 Nlerp 的 5~10 倍。
Nlerp 是直线插值后投影回球面，角速度不均匀（中段偏快），但实现简单、可批量。
准则：相机、武器、观感敏感处用 Slerp；骨骼动画逐关节混合、角度差 < 30° 时用 Nlerp。

**Q5：为什么矩阵→四元数要分 `tr > 0` 和 `tr ≤ 0` 两种情况？**
因为 `w = 0.5·sqrt(tr+1)` 在 `tr ≈ -1`（即 180° 旋转附近）时分子趋近 0，后续
用 `w` 做除法的公式会爆炸。标准解法：tr > 0 用 w 作分母；否则取最大对角元（x、y、
z 中最大者）作分母，保证除法稳定。

**Q6：FPS 相机用欧拉角真的会出问题吗？很多教程就这么写的。**
现代引擎内部都是四元数；教程里的「欧拉角」通常是**输入层**的俯仰/偏航累计，
最终合成四元数。若直接把三个角度存下来并互相叠加，俯仰 ±90° 时（例如玩家抬头看
正上方）偏航与滚动混淆，镜头会瞬间翻转——这正是万向锁。所以工程上：输入用角度，
状态用四元数。

**Q7：骨骼动画为什么要用四元数而不是矩阵？**
每个骨骼关节存一个矩阵的话，动画数据量是四元数的 2.25 倍（36 vs 16 字节），且
矩阵插值没有数学意义（线性插值矩阵会引入剪切/缩放）；四元数可以 Slerp/Nlerp 出
物理上正确的旋转路径。此外四元数混合（加权平均后归一化）天然保持单位性。

**Q8：怎么判断两个四元数「几乎相同」？**
计算 `|q1·q2|`（4D 点积绝对值）：接近 1 表示旋转几乎一致（注意取绝对值是因为
`q` 与 `-q` 等价）。在动画过渡检测、网络同步的旋转差值计算中常用此判据。
