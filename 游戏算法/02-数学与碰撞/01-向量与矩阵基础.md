## 概述

游戏世界本质上是一个**数学建模的世界**：角色站在 `(x, y, z)`，枪口朝某个方向，
相机从某个位置看向目标，敌人沿着路径移动——这些全部由**向量（Vector）**描述；
而把一个物体从局部坐标系搬进世界、再从世界搬进相机视野，靠的是**矩阵（Matrix）**
变换。可以说，不懂向量与矩阵，就谈不上理解游戏引擎的任何一层。

本文先介绍向量的基本运算（加减、数乘、模长、归一化），再重点推导**点积**与**叉积**
这两个"游戏开发中使用频率最高的数学工具"：点积用于判断朝向（敌人是否在视野内）、
计算投影与光照；叉积用于计算法线、判断左右、构造正交坐标系。之后引入矩阵，推导
平移、旋转、缩放的变换矩阵，并解释为什么游戏引擎统一使用 4×4 齐次矩阵；最后讲解
**局部空间 → 世界空间 → 观察空间**的变换链，并给出 LookAt 观察矩阵的完整推导。

全篇会穿插游戏实例：FPS 的命中判定（点积判朝向 + 射线方向）、第三人称相机的
跟随（向量加减与归一化）、角色移动（速度向量与帧率无关的位移）、以及 Unity/Unreal
中的 API 对照。

## 核心概念

| 概念 | 数学定义（简） | 游戏中的用途 | 关键要点 |
| --- | --- | --- | --- |
| 向量 | 既有大小又有方向的量，如 `v = (x, y, z)` | 位置、位移、速度、朝向、法线 | 位置向量与方向向量含义不同 |
| 模长 | `|v| = sqrt(x² + y² + z²)` | 距离、速度大小 | 比较距离时用平方避免开方 |
| 归一化 | `v̂ = v / |v|` | 只取方向、单位法线 | 零向量归一化是未定义操作 |
| 点积 | `a·b = x1x2 + y1y2 + z1z2 = |a||b|cosθ` | 朝向判定、投影、光照 | 结果为标量，符号即夹角信息 |
| 叉积 | `a×b`（右手定则确定方向） | 法线、左右判定、构造坐标架 | 仅三维有定义（2D 用标量叉积） |
| 矩阵 | 数的矩形阵列，线性变换的载体 | 旋转、缩放、剪切 | 矩阵乘法不满足交换律 |
| 平移矩阵 | 4×4 齐次矩阵中的第 4 列 | 位置移动 | 必须用齐次坐标（w=1） |
| 复合变换 | `M = T · R · S` | 模型变换、层级变换 | 顺序：先缩放后旋转再平移 |
| 坐标空间 | 局部/世界/观察/裁剪/屏幕 | 渲染管线、相机 | 变换链 `M = View · World · Local` |
| 齐次坐标 | `(x, y, z, w)`，w=1 表示点 | 统一平移与旋转为矩阵乘法 | w=0 表示方向（不受平移影响） |

## 原理详解

### 1. 向量的基本运算

设 `a = (ax, ay, az)`、`b = (bx, by, bz)`、标量 `s`：

```text
加法：a + b = (ax + bx, ay + by, az + bz)      # 首尾相接，几何上平移
减法：a - b = (ax - bx, ay - by, az - bz)      # 从 b 指向 a 的向量（a - b）
数乘：s · a = (s·ax, s·ay, s·az)               # 缩放长度，s<0 时反向
模长：|a| = sqrt(ax² + ay² + az²)              # 勾股定理在 3D 的推广
```

游戏中最常见的用法：

- **位移**：`newPos = pos + velocity * dt`，速度向量乘时间得位移向量。
- **相对方向**：`dir = targetPos - myPos`，得到「从自己指向目标」的方向向量。
- **距离判断**：`distSq = |a - b|²`，与 `(r1 + r2)²` 比较，避免每帧开方。

### 2. 点积（Dot Product）

**定义**（代数形式）：

```text
a · b = ax·bx + ay·by + az·bz
```

**几何形式**：

```text
a · b = |a| · |b| · cos θ     （θ 为两向量夹角，0 ≤ θ ≤ π）
```

**推导**：由余弦定理，三角形三边为 `a`、`b`、`a - b`：

```text
|a - b|² = |a|² + |b|² - 2|a||b|cosθ
```

而左边展开：

```text
|a - b|² = (a - b)·(a - b) = a·a - 2a·b + b·b = |a|² + |b|² - 2a·b
```

两式相等，消去 `|a|² + |b|²` 即得 `a·b = |a||b|cosθ`。□

**游戏应用**：

| 场景 | 做法 |
| --- | --- |
| FPS 命中判定 | `dot(枪口方向, normalize(目标-枪口)) > cos(半锥角)` 判定目标是否在准星锥内 |
| 敌人在前方还是后方 | `dot(角色前向, normalize(敌人-角色)) > 0` 在前方，< 0 在后方 |
| 光照漫反射 | `dot(表面法线, 光源方向)` 作为亮度系数（Lambert 模型） |
| 投影 | `a` 在 `b` 上的投影长度 `proj = a·b̂` |
| 判定是否朝向目标 | 相机看向 `v`，目标方向 `d`，`dot(v, d) > 0` 表示目标在视野前半区 |

### 3. 叉积（Cross Product）

**定义**（三维）：

```text
a × b = (ay·bz - az·by, az·bx - ax·bz, ax·by - ay·bx)
```

**几何性质**：

```text
方向：垂直于 a 与 b 张成的平面，由右手定则确定
长度：|a × b| = |a||b|sinθ  （等于两向量张成的平行四边形面积）
若 a ∥ b，则 a × b = 0
```

**推导思路**：叉积的分量公式可以写成行列式形式：

```text
a × b = det( [ i, j, k ]
             [ ax, ay, az ]
             [ bx, by, bz ] )
```

按第一行展开即得上述分量公式；而其「垂直于平面、长度等于面积」的性质可由
`|a×b|² = |a|²|b|² - (a·b)²`（拉格朗日恒等式）结合 `cos²θ + sin²θ = 1` 推出。

**游戏应用**：

| 场景 | 做法 |
| --- | --- |
| 平面法线 | `n = normalize((B - A) × (C - A))` 得到三角形 ABC 的法线 |
| 判断左右 | 2D 标量叉积 `cross = ax·by - ay·bx`：>0 左转，<0 右转（用于转向判定） |
| 构造坐标架 | 已知前向 `f` 与近似上方向 `up`，`right = normalize(f × up)`，再 `up' = right × f` 得到正交基 |
| 力矩/角速度 | `τ = r × F`，刚体物理中的扭矩 |
| 三角形面积/法线朝向 | 面积 `= 0.5·|a×b|`，可用于背面剔除与碰撞法线 |

> 注意：3D 叉积结果仍是向量；2D 中「叉积」通常指标量 `ax·by - ay·bx`，其绝对值等于
> 两向量张成的平行四边形面积，符号表示旋转方向。

### 4. 归一化与投影

**归一化**：

```text
v̂ = v / |v| = (vx/|v|, vy/|v|, vz/|v|)
```

单位向量只保留方向。使用前务必判断 `|v| ≈ 0`，否则会出现除零（NaN/Inf 会污染
整个后续计算，这是游戏开发中最经典的 bug 之一）。

**投影（Projection）**：

```text
proj_b(a) = (a · b̂) · b̂     # a 在单位向量 b̂ 方向上的投影向量
proj_b(a) = ((a·b)/(b·b)) · b   # 任意非零 b 的通用形式
```

**推导**：投影向量 `p = k·b̂`，要求 `(a - p) ⊥ b̂`，即 `(a - k·b̂)·b̂ = 0`，
展开得 `a·b̂ - k = 0`，故 `k = a·b̂`。□

**游戏应用**：把速度分解为「沿斜坡方向」与「垂直斜坡方向」两个分量，用于斜坡行走
与滑行；把角色到目标点的向量投影到移动平面上，实现「贴地寻路」。

### 5. 矩阵与线性变换

矩阵是线性变换的代数载体。**线性变换**满足：

```text
L(u + v) = L(u) + L(v)，L(s·u) = s·L(u)
```

旋转与缩放都是线性变换，因此可以用 3×3 矩阵表示；平移不满足线性（原点被移动），
所以需要升维到 4×4 **齐次矩阵**。

**2D 旋转矩阵推导**：设点 `P = (x, y)`，极坐标形式 `x = r·cosφ, y = r·sinφ`，
绕原点旋转 `θ` 后：

```text
x' = r·cos(φ + θ) = r(cosφ·cosθ - sinφ·sinθ) = x·cosθ - y·sinθ
y' = r·sin(φ + θ) = r(sinφ·cosθ + cosφ·sinθ) = x·sinθ + y·cosθ
```

写成矩阵：

```text
[x']   [ cosθ  -sinθ ] [x]
[y'] = [ sinθ   cosθ ] [y]
```

**3D 基本旋转矩阵**（右手系，逆时针为正）：

```text
Rx(θ) = [ 1    0      0   ]      Ry(θ) = [ cosθ  0  sinθ ]
        [ 0  cosθ  -sinθ ]              [  0    1   0    ]
        [ 0  sinθ   cosθ ]              [ -sinθ 0  cosθ ]

Rz(θ) = [ cosθ  -sinθ  0 ]
        [ sinθ   cosθ  0 ]
        [  0      0    1 ]
```

**缩放矩阵**：

```text
S(sx, sy, sz) = [ sx 0 0 ]   （各轴可不同，负值会镜像）
                [ 0 sy 0 ]
                [ 0 0 sz ]
```

### 6. 齐次坐标与复合变换

4×4 齐次矩阵把平移也变成矩阵乘法：

```text
[ x' ]   [ m00 m01 m02 tx ] [ x ]     点：w = 1，受平移影响
[ y' ] = [ m10 m11 m12 ty ] [ y ]     方向：w = 0，不受平移影响
[ z' ]   [ m20 m21 m22 tz ] [ z ]
[ w' ]   [  0   0   0   1  ] [ 1 ]
```

这一点很重要：**方向向量（如法线）做变换时 w=0，旋转照常、平移被忽略**；而位置
向量 w=1。这也是为什么「法线变换」在非均匀缩放下必须用逆转置矩阵 `(M⁻¹)ᵀ`
（否则法线不再垂直于表面）。

**复合变换**：先缩放、再旋转、最后平移：

```text
M = T · R · S
v' = M · v = T · (R · (S · v))
```

**推导顺序**：矩阵乘法从右向左作用于向量，所以写变换代码时要从「离向量最近」的
变换开始读。若顺序颠倒为 `S·R·T`，物体将绕旋转后的轴缩放，产生剪切效果——这是
新手最常见的错误。注意**矩阵乘法不满足交换律**：`T·R ≠ R·T`。

**内存布局**：游戏引擎（DirectX、Unity）惯用**列主序**存储，即 `m[col*4+row]`，
第 4 列为平移；OpenGL 数学库（glm）默认列主序，而 C 数组手写时容易搞混，建议
始终用现成库（glm、Eigen、Unity.Mathematics），并显式标注约定。

### 7. 坐标空间变换：局部 → 世界 → 观察

一个模型在美术软件中建模时，顶点坐标是相对于模型自身原点（**局部空间/模型空间**）。
把它放进游戏世界需要**模型矩阵 `M`**（由位置、旋转、缩放复合而成）：

```text
P_world = M · P_local，   M = T · R · S
```

相机看到的世界需要**观察矩阵 `V`**（把世界变换到以相机为原点的观察空间，相机看向
−Z 或 +Z，取决于 API 约定）。`V` 的推导（LookAt）：

```text
已知：相机位置 eye，注视点 target，上方向 up（近似即可）

f = normalize(target - eye)          # 前向
s = normalize(f × up)                # 右向（先叉积再归一化，保证正交）
u = s × f                            # 上向（s、u、f 构成右手正交基）

V = [ sx  sy  sz  -s·eye ]
    [ ux  uy  uz  -u·eye ]
    [ -fx -fy -fz   f·eye ]
    [ 0   0   0    1     ]
```

**推导思路**：观察变换分两步——先把相机平移到原点（平移 `-eye`），再旋转使相机坐标
轴与世界坐标轴对齐。旋转矩阵的每一行是相机基向量（s、u、−f）在世界系中的坐标，
因为旋转矩阵的逆等于其转置，所以「把世界点变换到相机系」就是用相机基向量做点积；
最后补上平移项 `-dot(轴, eye)` 即得上述形式。□

完整变换链（渲染管线视角）：

```mermaid
flowchart LR
    A["局部空间<br/>模型顶点坐标"] -->|"模型矩阵 M"| B["世界空间<br/>物体在世界中的位置"]
    B -->|"观察矩阵 V"| C["观察空间<br/>以相机为原点"]
    C -->|"投影矩阵 P"| D["裁剪空间<br/>视锥剔除"]
    D -->|"视口变换"| E["屏幕空间<br/>像素坐标"]
```

**游戏应用**：

- **相机跟随**：`eye = 角色位置 - 前向 * 距离 + 上向 * 高度`，再用 LookAt 生成观察矩阵。
- **子物体/骨骼**：`P_world = M_parent · M_local · P_local`，层级变换逐级向上复合。
- **朝向判定**：把目标变换到相机空间后检查 `z` 符号与屏幕投影，可做视锥剔除与
  「是否在屏幕内」的判断。

## 伪代码与代码示例

### 伪代码：朝向判定 + 命中锥测试

```text
function IsInFront(forward, from, to):
    dir = normalize(to - from)
    return dot(forward, dir) > 0          # 点积符号判定前后

function IsInCone(forward, from, to, cosHalfAngle):
    dir = normalize(to - from)
    return dot(forward, dir) >= cosHalfAngle   # 命中锥（FPS 判定）
```

### C++ 示例（含 3D 向量与 LookAt）

```cpp
#include <cmath>

struct Vec3 {
    float x, y, z;
    Vec3 operator+(const Vec3& o) const { return {x+o.x, y+o.y, z+o.z}; }
    Vec3 operator-(const Vec3& o) const { return {x-o.x, y-o.y, z-o.z}; }
    Vec3 operator*(float s) const { return {x*s, y*s, z*s}; }
    float dot(const Vec3& o) const { return x*o.x + y*o.y + z*o.z; }
    Vec3 cross(const Vec3& o) const {
        return { y*o.z - z*o.y, z*o.x - x*o.z, x*o.y - y*o.x };
    }
    float lenSq() const { return dot(*this); }
    float len() const { return std::sqrt(lenSq()); }
    Vec3 normalized() const {
        float l = len();
        return (l > 1e-8f) ? (*this) * (1.0f / l) : Vec3{0, 0, 0};
    }
};

// FPS 命中锥判定：forward 为枪口方向，halfAngle 为散射半角
bool IsInHitCone(const Vec3& from, const Vec3& to,
                 const Vec3& forward, float cosHalfAngle) {
    Vec3 dir = (to - from).normalized();
    return dir.dot(forward) >= cosHalfAngle;
}

// 观察矩阵（列主序，OpenGL 风格）——相机看向 -Z
struct Mat4 { float m[16]; };
Mat4 LookAt(const Vec3& eye, const Vec3& target, const Vec3& up) {
    Vec3 f = (target - eye).normalized();
    Vec3 s = f.cross(up).normalized();   // 右
    Vec3 u = s.cross(f);                 // 上
    Mat4 v{};
    v.m[0]=s.x; v.m[4]=s.y; v.m[8] =s.z; v.m[12]=-s.dot(eye);
    v.m[1]=u.x; v.m[5]=u.y; v.m[9] =u.z; v.m[13]=-u.dot(eye);
    v.m[2]=-f.x;v.m[6]=-f.y;v.m[10]=-f.z;v.m[14]= f.dot(eye);
    v.m[15]=1.0f;
    return v;
}
```

### Python 示例（NumPy 验证）

```python
import numpy as np

def is_in_hit_cone(frm: np.ndarray, to: np.ndarray,
                   forward: np.ndarray, cos_half_angle: float) -> bool:
    d = (to - frm)
    norm = np.linalg.norm(d)
    if norm < 1e-8:
        return False
    d = d / norm
    return float(forward @ d) >= cos_half_angle

def look_at(eye, target, up):
    f = (target - eye); f /= np.linalg.norm(f)
    s = np.cross(f, up); s /= np.linalg.norm(s)
    u = np.cross(s, f)
    V = np.eye(4)
    V[0, :3] = s;   V[1, :3] = u;  V[2, :3] = -f
    V[0, 3] = -s @ eye; V[1, 3] = -u @ eye; V[2, 3] = f @ eye
    return V

# 验证：相机在原点看向 (0,0,-1)，上方向 (0,1,0)
print(look_at(np.array([0.,0,0]), np.array([0.,0,-1]), np.array([0.,1,0])))
```

## 复杂度分析

| 运算 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 3D 点积 / 向量加减 | O(1)（常数：3 次乘加） | 与维度 n 相关时写 O(n) |
| 3D 叉积 | O(1) | 6 次乘法 + 3 次减法 |
| 归一化 | O(1) | 1 次开方 + 3 次除法（开方慢，可近似） |
| 向量 × 矩阵 | O(9)（3×3）／O(16)（4×4） | 每个分量是 4 次乘加 |
| 矩阵 × 矩阵 | O(n³)，n=4 时为 64 次乘加 | 实际库会用 SIMD 优化 |
| 复合变换求值 `T·R·S·v` | 逐次乘：3 次向量×矩阵 | **不要**先把矩阵乘起来再乘向量，除非复用到多个顶点 |
| LookAt | O(1) | 3 次归一化 + 2 次叉积 + 点积 |

性能提示：矩阵乘法是 O(n³)，但 4×4 是常数级；真正的性能关键在于**批量顶点变换时
避免重复计算**（预乘 `M = V·W·L` 后再作用到整批顶点），以及**用 SIMD/NEON 一次处理
4 个分量**（齐次坐标的 w 恰好补齐 4 分量对齐）。

## 验证与基准建议

- 输入规模与边界用例：覆盖零向量、近平行/近垂直向量、非均匀缩放、奇异矩阵、齐次坐标 `w=0/1`、局部到世界到观察的往返变换，以及 2D/3D 两种维度。
- 正确性断言：断言 `dot(a,b)` 的对称性、`cross(a,b)` 的正交性、单位向量长度接近 1、`M⁻¹M` 接近单位矩阵，并用已知点验证旋转和 LookAt 的方向；比较时显式记录容差。
- 复杂度与耗时指标：记录向量/矩阵维度、批量元素数量、误差最大值、吞吐量和 P50/P95 耗时；分开比较标量、库实现与 SIMD，不能用一次机器测量推广到所有平台。
- 命令示意（仅示意，不表示仓库已有测试）：`python -m pytest tests/test_math3d.py -q`；C++ 可替换为项目自有单元测试或 benchmark 目标。

## 最佳实践

1. **永远先归一化再点积**：点积的几何解释依赖单位向量；拿非单位向量做夹角判断会
   得到错误结果。归一化前检查模长，避免 NaN。
2. **距离比较用平方**：`distSq < r*r` 比 `dist < r` 少一次开方；开方在 CPU 上是
   相对昂贵的指令，且容易成为性能热点（每帧成千上万次判定时尤其明显）。
3. **变换顺序约定要写进代码规范**：统一「S → R → T」复合顺序与「列主序」存储，
   并给矩阵类写单元测试（用已知点验证：`(1,0,0)` 绕 Z 轴转 90° 应得 `(0,1,0)`）。
4. **法线变换用逆转置**：非均匀缩放（`S=(2,1,1)`）后普通变换会破坏法线垂直性，
   用 `(M⁻¹)ᵀ` 变换法线；若只有刚体变换（旋转+平移）则可直接用 `M` 的旋转部分。
5. **方向向量 w=0，位置向量 w=1**：自定义变换代码时保持这一约定，可避免「方向被
   平移」的经典 bug。
6. **不要每帧重建 LookAt**：相机不动时缓存观察矩阵；角色移动时只更新平移部分。
7. **用库，别手写**：glm / Eigen / Unity.Mathematics / Godot 内置 Vector3 均已
   优化且经过验证；手写仅用于学习或极小依赖场景。

## 常见问题 FAQ

**Q1：点积结果 > 0 就代表「在前方」吗？**
是的，前提是参与运算的两个向量都已归一化：`cosθ > 0` 即夹角小于 90°，目标在
前向的 180° 半平面内。若要限定更小的视野锥，需与 `cos(半角)` 比较。

**Q2：3D 中怎么判断一个点在一个平面的哪一侧？**
取平面法线 `n` 与平面上一点 `P0`，计算 `dot(n, P - P0)`：大于 0 在法线侧，小于 0
在背面，等于 0 在平面上。这是视锥剔除、碰撞分离的基础。

**Q3：为什么平移必须用 4×4 矩阵？3×3 不行吗？**
3×3 矩阵是线性变换，必须把原点映射到原点，无法表示平移。把点升维到齐次坐标
`(x,y,z,1)` 后，平移变成对第 4 列的线性作用，从而可以与其他变换统一为矩阵乘法，
也才能做「一次矩阵乘完成复合变换」。

**Q4：行主序和列主序到底怎么区分？**
两种约定描述的是**同一矩阵在内存中的存放顺序**：列主序按列存（`m[col*4+row]`），
行主序按行存（`m[row*4+col]`）。只要「向量×矩阵」的写法配套一致，数学结果相同；
混用时会出现转置错乱（常见症状：物体沿错误轴旋转、平移跑到对角线）。跨引擎移植
时务必先确认约定。

**Q5：归一化时模长接近 0 会怎样？**
产生除零：浮点结果是 Inf/NaN，NaN 会传染所有后续计算（点积、矩阵、碰撞判定全部
失效），且极难排查。规范做法是设定阈值 `eps`（如 1e-8），小于阈值时返回零向量或
默认方向，并打日志。

**Q6：左手系和右手系会影响公式吗？**
会影响**叉积方向**与**旋转正方向**：右手系中 `x×y = z`，旋转正方向为逆时针；
左手系（如 DirectX、Unity 的某些约定）中 `x×y = -z`。点积不受影响。矩阵公式中
`sinθ` 的符号会随约定翻转，跨引擎时注意。

**Q7：为什么推荐「先缩放、再旋转、最后平移」？**
因为这样最符合直觉：缩放沿物体自身轴、旋转绕物体自身原点、最后把物体放到世界
位置。若先平移再旋转，旋转会绕世界原点进行，物体位置会产生预料之外的偏移。
