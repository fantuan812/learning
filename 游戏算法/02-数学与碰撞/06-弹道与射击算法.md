# 弹道与射击算法（Ballistics & Shooting）

> 知识基线：引擎无关的游戏算法通用原理；弹道/射击算法属于"数学与碰撞"分类的实战应用，覆盖抛物线落点、移动目标提前量、命中检测、散布模型与网络下的射击一致性问题；涉及 UE 的实现以[游戏知识/06-网络同步/README.md](../../游戏知识/06-网络同步/README.md)与[游戏知识/09-物理系统/README.md](../../游戏知识/09-物理系统/README.md)为交叉验证边界。
> 适用范围：射击游戏（FPS/TPS）、炮塔/投掷物（手雷/弓箭）、MOBA 技能弹道、载具炮击、以及服务端命中验证（防作弊）。
> 事实边界：抛物线/提前量/命中检测公式为通用数学事实；具体引擎的射线/物理 API、网络回滚语义以其文档为准；散布与手感参数（重力、弹速、散布曲线）需按项目实测调参。
> 最后更新：2026-08-07。
> 参考来源：[Wikipedia: Projectile motion](https://en.wikipedia.org/wiki/Projectile_motion)、[Wikipedia: Lead (angle)](https://en.wikipedia.org/wiki/Lead_(angle))。

> 射击玩法的高频问题：**手雷抛物线怎么算落点？打移动目标要提前多少？服务器怎么判定这一枪打没打中？** 本文把弹道从"发射到命中"的数学链路一次讲清：直线/抛物线弹道、落点求解、移动目标提前量、命中检测、散布与网络权威判定。

## 三、原理详解

### 3.1 抛物线弹道基础

投射物运动（忽略阻力）：

```text
p(t) = p0 + v0·t + ½·g·t²
```

其中 p0 为发射点，v0 为初速度向量，g 为重力加速度向量。

**初速度分解**：给定发射角 θ 与速率 s：

```text
v0x = s·cos(θ)
v0y = s·sin(θ)        // 2D 示意；3D 需方位角 φ
```

### 3.2 落点求解

#### 3.2.1 水平地面落点

```text
飞行时间 t = 2·s·sin(θ) / g
水平距离 d = s²·sin(2θ) / g
```

#### 3.2.2 任意高度差落点（解二次方程）

目标高度差 h（向下为负）：

```text
½·g·t² - s·sin(θ)·t + h = 0
t = [s·sin(θ) ± sqrt(s²·sin²(θ) - 2·g·h)] / g
```

取正根；判别式 < 0 表示该角度/速率无法到达（弹道不够高）。

#### 3.2.3 "给定落点反求发射角"（AI 瞄准手雷）

已知起点、落点、弹速，求发射角——常用解析法（高低两解）或数值法（二分/迭代）：

```text
// 伪代码：按落点求发射角（节选/示意）
function solve_angle(p0, target, speed, g):
    dx = target.x - p0.x
    dy = target.y - p0.y
    a = g * dx * dx / (2 * speed * speed)
    b = -dx
    c = a + dy
    disc = b * b - 4 * a * c
    if disc < 0: return null          // 不可达
    tan1 = (-b + sqrt(disc)) / (2 * a)   // 高抛
    tan2 = (-b - sqrt(disc)) / (2 * a)   // 低平
    return atan2 解（可再按障碍/手感选高抛或低平）
```

### 3.3 移动目标提前量

#### 3.3.1 直线等速目标

```text
// 伪代码：线性提前量（节选/示意）
function lead_linear(p0, target_pos, target_vel, speed):
    d0 = target_pos - p0
    a = dot(target_vel, target_vel) - speed * speed
    b = 2 * dot(d0, target_vel)
    c = dot(d0, d0)
    t = solve_quadratic_min_positive(a, b, c)   // 最小正根
    return target_pos + target_vel * t          // 瞄准点
```

几何直觉：瞄准点 = 目标当前位置 + 目标速度 × 飞行时间；飞行时间又依赖瞄准点距离——二次方程一次解出。

#### 3.3.2 曲线目标（加速度）

- 目标带加速度：`t` 求解变三次/迭代——用 2~3 次牛顿迭代收敛；
- 目标有转向：用目标速度预测 + 方向修正（按最近 N 帧速度平滑）。

#### 3.3.3 实用技巧

- **提前量上限**：限制最大提前距离，防"预测过头"（目标变速/转向时）；
- **速度平滑**：用目标近几帧平均速度（低通）而非瞬时速度；
- **反馈修正**：投射物带跟踪修正（自导）时可放松提前量精度。

### 3.4 散布模型

```text
// 伪代码：圆形散布（节选/示意）
function apply_spread(dir, spread_angle, rng):
    // 在圆锥内随机偏移瞄准方向
    offset = random_direction_in_cone(dir, spread_angle)
    return normalize(offset)
```

- **分布形态**：均匀圆盘（弹着均匀）或高斯（中心密）；高斯手感更"准"；
- **动态散布**：移动/连射/蹲伏影响散布角（FPS 经典手感曲线）；
- **弹道形态差异**：Hitscan 直接偏方向；投射物偏初速度方向；
- **服务端一致性**：散布随机数必须在服务端权威生成（或客户端上报种子校验）。

### 3.5 命中检测

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| 射线检测 | Hitscan | 发射点沿方向扫一条射线，取最近命中 |
| 扫掠球体 | 粗弹体 | SphereCast：弹体半径容差 |
| 连续碰撞 | 高速弹体 | CCD：按步长子步检测，防"穿墙" |
| 延迟命中 | 网络补偿 | 客户端回滚到开枪时刻判定（见[游戏知识/06-网络同步/03-客户端预测与延迟补偿.md](../../游戏知识/06-网络同步/03-客户端预测与延迟补偿.md)） |

### 3.6 网络下的射击一致性

```mermaid
flowchart LR
    A["客户端: 开枪+本地命中"] --> B["上报(位置/时间/瞄准)"]
    B --> C["服务端: 回滚验证\n权威判定"]
    C --> D["广播命中/伤害"]
    D --> E["客户端: 表现对齐"]
```

*图释：射击的网络权威链路——客户端先行表现，服务端回滚验证后广播结果，防作弊与一致性兼得。*

- **客户端先行**（Hit Registration 优化）：本地立刻出伤害反馈，服务端验证后修正；
- **服务端回滚**：用玩家开枪时刻的快照（延迟补偿）判定命中；
- **验证字段**：位置、朝向、时间戳、散布种子、武器参数——缺一不可防伪造；
- 详细网络一致性见[游戏知识/06-网络同步/03-客户端预测与延迟补偿.md](../../游戏知识/06-网络同步/03-客户端预测与延迟补偿.md)。

### 3.7 武器参数与手感调校

弹道手感由参数组合决定，调校是射击玩法的核心工作：

| 参数 | 影响 | 调校方向 |
| --- | --- | --- |
| 弹速 | 飞行时间/提前量大小 | 越快越"即时"，越慢越有"弹道感" |
| 重力系数 | 抛物线下坠程度 | 0=直线（激光），大=迫击炮 |
| 散布基值/随动 | 精度与射击节奏 | 移动/连射惩罚曲线 |
| 伤害衰减 | 距离收益 | 近战武器短衰减，狙击长距离 |
| 穿透/跳弹 | 命中后行为 | 与掩体玩法配合 |

调校方法：

- **数据驱动**：武器参数全部进配置表，策划自助调参；
- **对照基准**：每把武器与"手感标杆"（如 AK/弓）对比 TTK（击杀耗时）与命中率曲线；
- **自动化验证**：用固定 AI 目标测试弹道参数改动后的命中率分布（见[游戏AI/03-评测与安全/02-自动测试玩家与AI回归基准.md](../../游戏AI/03-评测与安全/02-自动测试玩家与AI回归基准.md)）；
- **手感主观验收**：自动化测"可量化部分"，手感（后座/音效/抖动）保留人工测试。

### 3.8 弹道与场景遮挡

- **低抛 vs 高抛**：低抛受掩体阻挡，高抛可越障（手雷翻墙）——AI 选抛法需查询遮挡（射线采样）；
- **弹道采样**：抛物线路径分段采样做遮挡检测（每段射线），判断"会不会撞墙"；
- **提前量 UI**：客户端预测弹道画落点/轨迹线，服务端仍权威判定（防止轨迹与实际不一致被利用）。

## 四、伪代码/示例：完整射击管线

```text
// 伪代码：射击判定管线（节选/示意）
function fire_weapon(server, shooter, aim, params):
    // 1. 散布
    dir = apply_spread(aim, params.spread(shooter.state), rng)

    if params.hitscan:
        // 2a. 即时命中：射线检测（支持回滚快照）
        hit = server.raycast(shooter.eye_pos, dir, params.range,
                             time = shooter.aim_time)
    else:
        // 2b. 投射物：生成弹体实体（服务端模拟）
        spawn_projectile(shooter.eye_pos, dir * params.speed)

    // 3. 命中处理：伤害 + 衰减 + 反馈
    if hit:
        dmg = params.damage * falloff(hit.distance)
        apply_damage(hit.actor, dmg, shooter)
    return hit
```

## 五、最佳实践

1. **Hitscan 与投射物分开建模**：性能与手感差异大，别混在一个"弹道系统"里。
2. **落点求解用解析式**：二次方程有解析解就别迭代；判别式 <0 需降级（自动减力/改高抛）。
3. **提前量加平滑与上限**：目标变速是常态，预测过头比预测不足更伤手感。
4. **散布服务端权威**：种子/散布结果服务端生成或校验，客户端只做表现。
5. **命中验证回滚**：服务端按开枪时刻快照判定，回滚窗口（如 150~250ms）按网络情况配置。
6. **高速弹体防穿墙**：用 CCD（子步/扫掠），别用大步长射线。
7. **伤害衰减曲线**：近战加成/远距衰减进配置表，调手感不动代码。
8. **AI 用同一套弹道**：AI 的提前量计算复用玩家弹道函数，行为才可信（见[游戏AI/02-移动学习与服务端/01-移动与群组行为.md](../../游戏AI/02-移动学习与服务端/01-移动与群组行为.md)）。
9. **性能**：投射物数量设上限（对象池+生命周期），Hitscan 射线批量查询（每帧预算）。
10. **可回放**：射击输入（时间/位置/瞄准/种子）入回放，命中判定可复现（见[游戏知识/06-网络同步/09-网络回放与DemoNetDriver.md](../../游戏知识/06-网络同步/09-网络回放与DemoNetDriver.md)）。

## 六、常见问题 FAQ

1. **Q：手雷怎么瞄准落点？** A：解析求发射角（高抛/低平两解）或数值二分；UI 上画落点预测线需客户端预测弹道。
2. **Q：提前量算不准（目标老躲开）？** A：目标速度平滑 + 提前量上限 + 投射物跟踪修正（自导）三层递减。
3. **Q：散布用均匀还是高斯？** A：FPS 常用高斯（中心密）手感更稳；散弹枪类用均匀圆盘更像"喷子"。
4. **Q：延迟补偿窗口多大？** A：常见 100~250ms，需按游戏节奏与反作弊权衡；窗口越大越宽容也越易作弊。
5. **Q：客户端命中表现和服务端判定不一致怎么办？** A：客户端先行 + 服务端权威；不一致时回滚表现（或保留本地命中但标"疑似"）。
6. **Q：投射物穿过薄墙？** A：大时间步导致；用 CCD 子步或扫掠检测；或限制最大速度。
7. **Q：AI 的弹道要完全和玩家一致吗？** A：物理一致、参数可调（AI 散布更大/更小）——"物理同规则，参数定难度"。
8. **Q：抛物线受阻力（空气）影响？** A：加阻力后无解析解，用数值积分（见[05-数值积分与运动学模拟.md](05-数值积分与运动学模拟.md)），提前量同步改迭代求解。
9. **Q：服务端弹道模拟开销大？** A：投射物数量受限（池化），命中检测只对"可能命中"的弹体做细判定。
10. **Q：怎么测弹道系统？** A：解析解对照（固定初始条件断言落点/命中）+ 回放断言（同输入同结果），见[游戏AI/03-评测与安全/02-自动测试玩家与AI回归基准.md](../../游戏AI/03-评测与安全/02-自动测试玩家与AI回归基准.md)。
