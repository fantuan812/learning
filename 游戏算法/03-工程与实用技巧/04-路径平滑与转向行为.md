## 1. 概述

一个完整的"移动管线"通常分四层：

```mermaid
flowchart LR
    A["A* / 流场<br/>全局路径（折线）"] --> B["路径简化<br/>RDP / 弦拉直"]
    B --> C["漏斗算法<br/>走廊内最短可视路径"]
    C --> D["转向行为<br/>seek/arrive/避障"]
    D --> E["速度合成<br/>+ 物理/动画"]
```

前三层是**几何**问题（路径本身），最后一层是**行为**问题（单位怎么沿路径动）。RTS 的群组移动还会加一层：**队形/流场**。

## 2. 核心概念

| 术语 | 说明 |
| --- | --- |
| 路径简化 | 减少路径点数且不显著改变形状（RDP、弦拉直） |
| 走廊（Corridor） | 导航网格上路径经过的三角形序列（含出入口 portal） |
| 漏斗算法 | 在走廊内求"起点到终点最短且不穿墙"的折线 |
| Steering | 把期望速度与当前速度的差作为"转向力"，逐帧积分 |
| seek / flee | 直奔目标 / 直离目标 |
| arrive | 靠近目标减速停止 |
| pursue / evade | 预测目标未来位置后 seek / flee |
| obstacle avoidance | 提前绕开前方障碍 |
| Boids | 分离 + 对齐 + 凝聚三规则涌现的群集行为 |
| 队形（Formation） | 把群体约束到锚点周围的槽位布局 |
| RVO | 速度障碍法，双方向避障（RTS 常用） |

## 3. 路径简化

### 3.1 Ramer–Douglas–Peucker（RDP）

RDP 用"点到线段距离 ≤ ε"递归剔除冗余点：取首尾连线，找离它最远的中间点；若距离 > ε，则在该点处分裂递归；否则中间点全部删除。最坏 O(n²)，典型 O(n log n)。

```python
def rdp(points, eps):
    if len(points) < 3:
        return points
    (x1, y1), (x2, y2) = points[0], points[-1]
    dmax, idx = 0.0, 0
    for i in range(1, len(points) - 1):
        d = abs((x2 - x1) * (y1 - points[i][1]) -
                (x1 - points[i][0]) * (y2 - y1)) / ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5
        if d > dmax:
            dmax, idx = d, i
    if dmax > eps:
        left = rdp(points[:idx + 1], eps)
        right = rdp(points[idx:], eps)
        return left[:-1] + right
    return [points[0], points[-1]]
```

### 3.2 弦拉直（String Pulling）

网格寻路后，尝试"两点之间直线可达就删中间点"：维护当前锚点，向后试探下一个点，若与后续点之间无障碍（对导航网格做线段可见性测试），跳过中间点。O(n²) 可见性测试可用网格射线（Bresenham/DDA）加速。

**工程建议**：RDP 减少点数（面数），弦拉直/漏斗保证"最短且不穿墙"（正确性），两者常组合：先 RDP，再弦拉直或直接漏斗。纯视觉平滑（Catmull-Rom 样条、Chaikin 细分）只改表现不改几何，需保证不切角穿墙。

## 4. 漏斗算法（Funnel）

### 4.1 原理

漏斗算法（Simple Stupid Funnel，Mikko Mononen 2010）在**走廊**（连续的凸区域序列，例如导航网格三角形或门洞序列）内求最短可视路径。核心是维护一个"漏斗"：顶点（apex）为当前路径点，两侧边（left/right）为走廊边界，逐段收紧：

```
left ← right ← apex ← start
for 每个 portal (l, r)（按走廊顺序）:
    # 左端点使漏斗左边界右移（更紧）
    if l 位于当前左边界右侧:
        if 左边界越过右边界（漏斗"折断"）:
            把左边界点加入路径; apex ← 左边界点
            重置 left = right = apex; 重试当前 portal
        else:
            left ← l
    # 右端点对称处理
    if r 位于当前右边界左侧:
        if 右边界越过左边界:
            把右边界点加入路径; apex ← 右边界点
            重置; 重试当前 portal
        else:
            right ← r
path ← path + [goal]
```

每次"折断"意味着当前 apex 到更远点被走廊挡住，必须拐弯；拐点即最短路径顶点。方向判断用二维叉积：`cross(a, b) = a.x·b.y − a.y·b.x`，`cross(dir, p) > 0` 表示 p 在有向线 `dir` 左侧（实现时统一符号约定并用单元测试验证）。

### 4.2 Python 实现

```python
def cross(a, b):
    return a[0] * b[1] - a[1] * b[0]

def sub(a, b):
    return (a[0] - b[0], a[1] - b[1])

def funnel(portals):
    """portals: [(left, right), ...] 每个走廊段的左右端点（含起终点）"""
    path = [portals[0][0]]
    apex = portals[0][0]
    left = right = apex
    i = 1
    while i < len(portals):
        l, r = portals[i]
        # 左边界更新
        if cross(sub(l, apex), sub(left, apex)) >= 0:
            if left != apex and cross(sub(left, apex), sub(l, apex)) <= 0:
                path.append(left)
                apex = left
                left = right = apex
                continue          # 重试当前 portal
            left = l
        # 右边界更新
        if cross(sub(r, apex), sub(right, apex)) <= 0:
            if right != apex and cross(sub(right, apex), sub(r, apex)) >= 0:
                path.append(right)
                apex = right
                left = right = apex
                continue
            right = r
        i += 1
    path.append(portals[-1][1])
    return path
```

### 4.3 复杂度与工程注意

- 每个 portal 至多处理常数次，总 O(n)，空间 O(1)（不含输出）；
- 走廊必须由**凸区域**组成（导航网格三角形天然满足）；凹多边形走廊会得到错误结果；
- 与 A* 的结合：A* 输出路径点 → 沿途收集网格三角形边界作为 portal → 漏斗平滑；导航网格方案（Recast/Detour）内置该流程；
- 结果仍可能与障碍"擦边"，移动时留半径余量（膨胀障碍物或在 agent 半径上偏移）。

## 5. 转向行为（Steering Behaviors）

### 5.1 基本行为

转向行为的统一框架（Reynolds 1999）：每个行为输出一个**期望速度**，转向力 = 期望速度 − 当前速度，逐帧积分并钳制：

```
steer = clamp(desired − velocity, maxForce)
velocity = clamp(velocity + steer, maxSpeed)
position += velocity · dt
```

| 行为 | 期望速度 | 说明 |
| --- | --- | --- |
| seek | normalize(target − pos)·maxSpeed | 直奔目标 |
| flee | normalize(pos − target)·maxSpeed | 逃离目标 |
| arrive | 距离 < slowRadius 时按比例降速 | 平滑停下，队形落位核心 |
| pursue | 对 `target + vel·t` 做 seek（t = 距离/速度） | 追移动目标，含预测 |
| evade | 对预测位置做 flee | 躲追击 |
| wander | 目标点绕单位前方圆随机游走 | 闲逛巡逻 |
| obstacle avoidance | 检测前方圆锥内最近障碍，输出侧向力 | 绕障 |
| separation | 对邻域内单位输出排斥力 | 防重叠（见 Boids） |

```python
import math

class Vec2:
    def __init__(self, x=0.0, y=0.0): self.x, self.y = x, y
    def __add__(self, o): return Vec2(self.x + o.x, self.y + o.y)
    def __sub__(self, o): return Vec2(self.x - o.x, self.y - o.y)
    def __mul__(self, k): return Vec2(self.x * k, self.y * k)
    def length(self): return math.hypot(self.x, self.y)
    def norm(self):
        l = self.length()
        return Vec2() if l < 1e-9 else self * (1.0 / l)

class Boid:
    def __init__(self, pos, vel, max_speed=3.0, max_force=5.0):
        self.pos, self.vel = pos, vel
        self.max_speed, self.max_force = max_speed, max_force

    def apply(self, acc, dt):
        # 转向力 = 期望速度 − 当前速度，钳制后积分
        acc = acc.norm() * min(acc.length(), self.max_force)
        self.vel = self.vel + acc * dt
        if self.vel.length() > self.max_speed:
            self.vel = self.vel.norm() * self.max_speed
        self.pos = self.pos + self.vel * dt

    def seek(self, target):
        return (target - self.pos).norm() * self.max_speed - self.vel

    def arrive(self, target, slow_radius=1.5):
        to = target - self.pos
        d = to.length()
        if d < 1e-6:
            return Vec2()
        speed = self.max_speed * min(1.0, d / slow_radius)
        return to.norm() * speed - self.vel

    def pursue(self, target):
        t = (target.pos - self.pos).length() / self.max_speed
        return self.seek(target.pos + target.vel * t)
```

### 5.2 组合与参数

多个行为加权求和：`steer = w₁·seek + w₂·separation + w₃·avoid`。要点：

- **权重与钳制**：每个行为先各自钳制再求和，总力再钳制，防止个别行为主导抖动；
- **优先级分层**：避障 > 队形 > 目标（紧急行为优先，其他降权），比纯加权更稳；
- **预测时间钳制**：pursue 的 t 上限（如 1s），防止预测过远；
- **速度方向插值**：转向力产生的角速度限制（maxTurnRate），配合动画。

### 5.3 避障（Obstacle Avoidance）

在单位前方 `lookahead = speed·k` 的圆锥内检测最近障碍（圆形包围体或网格采样），若有则输出"远离障碍 + 沿障碍切线"的力：

```
if 障碍在圆锥内:
    侧向力 = 障碍中心到单位的方向 · 权重（与距离成反比）
    减速力 = 与前方障碍距离成反比
```

网格寻路后的局部避障建议用 **RVO/ORCA**（速度障碍法，双向避让，两个单位各自承担一半避让），避免"商量式抖动"（你让我我让你）。在采用其模型假设、参数和实现的项目中，RVO/ORCA 可作为成熟参考；具体引擎适配、稳定性和性能仍需按目标场景实测。

## 6. Boids 群集

### 6.1 三规则（Craig Reynolds, 1986）

| 规则 | 计算 | 效果 |
| --- | --- | --- |
| 分离（Separation） | 对邻域内每单位：`(pos − neighbor.pos)/dist²` 求和 | 避免拥挤重叠 |
| 对齐（Alignment） | 邻域内平均速度 − 自身速度 | 朝向一致 |
| 凝聚（Cohesion） | 邻域质心 − 自身位置（向质心 seek） | 聚成群体 |

```
邻居 = 距离 < neighborRadius 且（可选）在视野锥内的单位
acceleration = w_sep·separation + w_ali·alignment + w_coh·cohesion
```

```python
def boids_update(flock, dt, radius=2.0, w_sep=1.5, w_ali=1.0, w_coh=1.0):
    for b in flock:
        sep = align = coh = Vec2()
        count = 0
        for o in flock:
            if o is b:
                continue
            d = (o.pos - b.pos).length()
            if d < radius and d > 1e-6:
                sep = sep + (b.pos - o.pos) * (1.0 / d)   # 距离平方反比
                align = align + o.vel
                coh = coh + o.pos
                count += 1
        if count:
            align = align * (1.0 / count) - b.vel
            coh = (coh * (1.0 / count) - b.pos).norm() * b.max_speed - b.vel
        acc = sep * w_sep + align * w_ali + coh * w_coh
        b.apply(acc, dt)
```

### 6.2 工程要点

- **邻域查询**：朴素 O(n²)，几百个单位够用；上千单位用空间哈希/网格加速（每帧重建网格 O(n)，查询 O(k)）；
- **视线过滤**：只对"看得见"的邻居作用（前方 270° 或做射线），避免隔墙聚团；
- **参数敏感**：w_sep 过大 → 队伍松散振荡；w_coh 过大 → 群体挤压抖动；速度与转向钳制要匹配 dt；
- **表现层**：鸟/鱼群常用"速度对齐 + 少许分离"，配合朝向插值（转向力 → 角速度 → 旋转）效果更好；
- **与寻路结合**：Boids 只解决局部，全局目的地由 leader 走 A*，或整体用流场（见 01 篇）。

## 7. 队形保持（Formation）

### 7.1 槽位模型

队形 = 锚点（领队/阵心）+ 一组**槽位偏移**。每帧把锚点变换应用到每个槽位得到世界坐标，各单位用 `arrive(slot)` 落位，同时叠加 separation 防重叠：

```python
def formation_update(anchor_pos, anchor_yaw, slots, units, dt):
    # 槽位世界坐标 = 锚点 + 旋转(偏移)
    for unit, off in zip(units, slots):
        rot = rotate(off, anchor_yaw)
        slot_world = anchor_pos + rot
        steer = unit.arrive(slot_world, slow_radius=1.0)
        steer = steer + separation(unit, units) * 1.2   # 槽位 + 防挤
        unit.apply(steer, dt)
```

| 队形类型 | 做法 | 特点 |
| --- | --- | --- |
| 刚性队形 | 槽位严格跟随锚点 | 整齐，但被地形撕裂后难恢复 |
| 弹性队形 | 槽位 + 逐单位避障/寻路 | 自然，但队形易变形 |
| 领队制 | 只有 leader 走全局寻路，其余 follow | 经典 RTS（星际争霸） |
| 流场队形 | 全员沿流场 + 槽位扰动 | 大规模（全战） |

### 7.2 与寻路/避障的结合

经典 RTS 流程：

1. 玩家框选 → 计算队形槽位（矩形/扇形/楔形按目标点朝向）；
2. **整体寻路**：以锚点为整体走 A*/流场（或 leader 寻路）；
3. 各单位 `arrive(slot) + separation + obstacle avoidance` 局部移动；
4. 被障碍阻断的单位**动态重排槽位**（跳过不可达槽位、队形缺口补位）；
5. 到达后按槽位收敛（arrive 的 slowRadius 逐步缩小，避免震荡）。

**要点**：

- 全员各自 A* 会互相踩踏（路径重复 + 碰撞死锁），所以用"共享路径/流场 + 局部避障"；
- 槽位分配用"就近匹配"（匈牙利算法或贪心），避免单位穿越整个队形换位；
- 队形旋转用锚点朝向平滑插值，槽位随旋转更新；
- 帧率鲁棒：所有转向积分用 dt 归一，避免 30/60 FPS 表现不一致。

## 8. 复杂度分析

| 算法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| RDP 简化 | O(n²) 最坏 / O(n log n) 典型 | O(n) | ε 越大点越少 |
| 弦拉直 | O(n²)（可见性测试） | O(1) | 网格射线加速 |
| 漏斗算法 | O(n) | O(1) | 线性最优 |
| Steering 单行为 | O(1) | O(1) | 每单位每帧 |
| 避障（朴素） | O(障碍数) | O(1) | 可用网格裁剪 |
| Boids 朴素 | O(n²) | O(n) | ≤ 几百单位 |
| Boids + 空间哈希 | O(n·k) | O(n) | k = 邻居数 |
| RVO/ORCA | O(n·k) 每单位 | O(n) | 双向避让 |
| 队形槽位分配 | O(n²) 贪心 / O(n³) 匈牙利 | O(n) | n = 队伍规模 |

## 9. 最佳实践

1. **分层移动管线**：全局寻路（A*/流场）→ 路径简化（RDP）→ 漏斗平滑 → 转向行为 → 局部避障（RVO），每层独立可测。
2. **转向力钳制**：所有行为输出先钳制再求和，总力再钳制；加 maxTurnRate 防"甩头"。
3. **参数配置化**：maxSpeed/maxForce/权重/半径进单位配置表；提供调试可视化（画期望速度、转向力、邻居圈）。
4. **避免每帧全量邻居查询**：空间哈希 + 每帧重建，或利用 AOI 兴趣集（见 03 篇）。
5. **群体不各自 A***：共享路径/流场 + 槽位 + RVO，千人大军才跑得动。
6. **确定性测试**：固定 dt 与种子的回放测试，验证寻路→平滑→移动的确定性。
7. **表现同步**：移动频率低时客户端插值；转向与动画（根运动、朝向）解耦，避免"滑步"。

## 10. 常见问题 FAQ

**Q1：漏斗之后路径还是穿墙？**
走廊必须是凸区域序列（导航网格三角形）；另外 agent 有半径，路径需按半径膨胀后的几何计算，或对路径做"半径偏移"后处理。

**Q2：Boids 群体振荡/堆积怎么调？**
先降 w_coh 或增大 separation 半径；检查速度钳制是否每帧生效；dt 不稳定时用固定步长积分；邻居视野加视线过滤。

**Q3：RTS 千人大军各自寻路太卡？**
不要各自 A*：用流场（一次 BFS 全图，所有单位共享）或 leader 寻路 + 队形槽位；单位间碰撞交给 RVO 局部处理。

**Q4：队形过窄路口被撕裂，恢复不了？**
动态重排：路口后按"目标槽位就近分配"重新匹配；或队形收缩成纵队（星际争霸式"编队过窄道"）。

**Q5：pursue 预测不准，追不上或冲过头？**
限制预测时间 `t = min(距离/速度, 1s)`；到达目标点改用 arrive；追逐者速度低于目标时预测无意义，直接 seek。

**Q6：转向和寻路结果打架（来回摆）？**
优先级分层：避障最高、队形次之、目标最低；给转向力加低通滤波（惯性）；路径重算节流（每 0.5s 一次）。
