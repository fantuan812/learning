# 存档版本迁移与兼容性测试
> 知识成熟度：L2（本轮审计修订时补标）。

## 文档定位

- 定位：游戏测试与质量库的存档数据可靠性专题。
- 目标：验证本地 SaveGame 与服务端持久化在版本演进、失败恢复和跨版本运行时仍可预测。
- 适用对象：客户端、服务端、数据平台、QA、发布工程和客服恢复团队。
- 最后更新：2026-08-07。
- 稳定结论：存档格式是长期接口，不能把一次性反序列化脚本当作迁移方案。
- 事实边界：本文不规定具体引擎、数据库、云厂商或序列化库。
- 事实边界：平台云存档的容量、冲突和保留期限必须以目标平台当前文档为准。
- 事实边界：涉及玩家申诉的数据恢复必须遵守产品隐私政策和当地法规。
- 核心取舍：宁可拒绝不安全的旧数据，也不应静默覆盖玩家进度。
- 核心取舍：迁移应可观测、可重放、可回滚，不能只在发布日人工盯日志。
- 核心取舍：小而明确的 schema 变化优于一次跨多个大版本的隐式重写。

## 阅读和使用方式

- 先看“事实边界”，再根据产品架构选择本地、云端或混合矩阵。
- 先建立版本目录，再编写迁移测试；不要从异常样本反推唯一版本。
- 将每个测试用例绑定输入快照、迁移脚本版本、输出快照和校验结果。
- 将门禁结果接入发布流水线，禁止只在测试人员电脑上运行。
- 将玩家可见提示与内部诊断码分离，避免在界面暴露内部路径或凭据。
- 若产品没有服务端存档，仍应执行本地损坏、备份和跨客户端测试。
- 若产品只有服务端存档，仍应执行离线、断网和旧客户端读取测试。

## 术语与数据对象

- SaveGame：玩家可恢复的游戏状态集合，可包含进度、配置和可选缓存。
- 本地存档：保存在设备文件系统、沙盒或平台本地容器中的副本。
- 服务端持久化：由后端数据库、对象存储或平台云存档托管的权威副本。
- 快照：测试时不可变的输入或输出文件，带有哈希和采集时间。
- 逻辑版本：游戏规则或数据语义版本，例如 season=3。
- schema 版本：字段结构和类型版本，例如 schema=7。
- 迁移版本：将一个 schema 转换为另一个 schema 的脚本版本。
- 数据世代：同一玩家在冲突解决后形成的单调递增修订号。
- 校验和：用于发现意外改写或截断的完整性摘要。
- 兼容窗口：仍被当前客户端或服务端支持的版本范围。
- 旧客户端：低于当前发布版本、但可能仍连接服务的客户端。
- 新客户端：已包含新 schema 或迁移逻辑的客户端。
- 有效载荷：经过解析、验证、授权和业务规则检查的数据。
- 不可恢复数据：经多份副本和人工核验仍无法安全还原的数据。

## 数据分层与权威性

- 将不可重建的玩家进度与可重建缓存分开保存。
- 将用户设置与服务器授予的货币、道具分开保存。
- 将统计、排行榜和成就等派生数据标记为可重算。
- 对每一层声明权威来源、更新方向和冲突策略。
- 本地副本只能作为候选恢复源，不能凭文件时间戳直接覆盖服务端。
- 服务端权威数据不能因客户端提交空对象而被清空。
- 客户端提交应包含玩家身份、数据世代和客户端构建号。
- 服务端写入应包含服务器时间和审计事件编号。
- 迁移只处理明确的 schema 区域，不应顺带改写业务数值。
- 缓存字段即使迁移失败，也不应阻塞核心进度恢复。
- 每个字段记录来源：玩家输入、服务器计算、平台同步或派生。
- 对来源不明字段采用保守默认值并生成诊断事件。

## 最小数据合同

- 顶层必须包含 schemaVersion。
- 顶层必须包含 dataGeneration 或等价的并发控制值。
- 顶层必须包含 createdAt、updatedAt 和时区明确的格式。
- 顶层必须包含产品或游戏标识，防止跨产品误导入。
- 顶层必须包含校验和或可替代的完整性证明。
- 顶层必须包含迁移历史摘要，但不得无限增长。
- 每个可变资源应定义取值范围和单位。
- 时间字段必须声明使用 UTC、单调时钟或服务器时间。
- 枚举字段应对未知值有明确拒绝或降级策略。
- 数组字段应声明最大长度，避免异常存档造成资源耗尽。
- 字符串字段应声明最大字节数，而不仅是字符数。
- 二进制字段应声明编码、压缩和加密状态。
- 引用外部资源时应使用稳定 ID，不保存易变路径。
- 删除字段时先停写，再观察兼容窗口，最后移除读取逻辑。
- 新增字段默认值必须是业务安全值，而不是语言默认值。
- 关键经济字段须由服务端重新计算或签名校验。
- 迁移后的输出不得比输入增加未声明的玩家资产。

## schema 版本策略

- 版本号采用单调整数或明确的语义版本，不混用日期字符串。
- 一个版本只表达一组可审查的结构变化。
- 记录字段新增、删除、重命名、类型变化和语义变化。
- 类型变化必须有正向迁移、失败分支和回滚策略。
- 语义变化即使字段类型不变，也必须提升版本。
- 旧版本读取能力写入支持矩阵，不依赖口头约定。
- 将 schema 定义、样例和迁移脚本放在同一发布工件中。
- 迁移脚本保持幂等：重复执行不会二次增加资产。
- 迁移脚本保持确定性：相同输入和配置得到相同输出。
- 迁移脚本禁止读取网络实时状态来决定核心字段。
- 迁移脚本失败时保留原始快照，不原地覆盖唯一副本。
- 新版本发布前冻结字段命名和默认值，并完成审查。
- 对跨大版本迁移设置最大跳跃值。
- 超过最大跳跃值时使用链式迁移或人工恢复流程。
- 删除旧迁移脚本前确认兼容窗口已结束并有归档副本。

## 本地 SaveGame 流程

- 写入采用临时文件、刷新、原子替换的顺序。
- 写入前生成上一份只读备份，保留数量由产品策略决定。
- 写入期间崩溃不得留下“新文件名但内容不完整”的状态。
- 读取先检查文件存在、大小上限、编码和魔数。
- 读取再校验校验和、版本、字段类型和业务不变量。
- 解析失败时从最近可验证备份恢复，不自动拼接未知片段。
- 恢复成功后保留损坏文件供诊断，并限制其权限。
- 多个存档槽位必须隔离路径和加密上下文。
- 临时存档不能被正式列表误识别为可加载档。
- 退出游戏时的自动保存应可取消或延迟，避免并发覆盖。
- 在主线程外写入时使用单一写入队列，禁止多协程竞态。
- 写入失败必须向上层返回明确错误码和重试建议。
- 设备空间不足时保留旧存档，不用零字节文件替换。
- 迁移生成的新文件需重新计算校验和并记录迁移链。
- 用户手动删除前显示范围和不可恢复性。

## 服务端持久化流程

- 服务端先鉴权和授权，再解析存档载荷。
- 服务端以玩家 ID、产品 ID 和数据世代做唯一键约束。
- 使用乐观并发控制拒绝过期客户端覆盖新数据。
- 服务器计算的资产写入应覆盖或校验客户端同名字段。
- 数据库事务应同时写入主记录、版本和审计事件。
- 对象存储写入完成后再更新数据库指针。
- 指针更新失败时旧对象仍应可读取。
- 读路径将迁移分为预览、执行和提交阶段。
- 大批量在线迁移采用限速、分批和熔断。
- 离线迁移输出新的对象键，不覆盖原对象。
- 权限最小化：迁移服务不应拥有删库或读无关玩家数据的权限。
- 管理后台显示数据世代、schema 和迁移状态，不显示完整敏感载荷。
- 服务端返回可供客户端理解的恢复码，不返回内部堆栈。
- 数据保留策略必须包括原始快照、迁移后快照和删除时间。

## 冲突与合并

- 冲突检测至少比较数据世代、更新时间和服务器修订号。
- 不能用客户端时钟作为唯一的新旧判断依据。
- 可合并字段应定义字段级策略，不使用全对象深合并默认值。
- 货币、库存、任务奖励等不可重复发放字段优先服务器裁决。
- 进度标志的合并必须声明是并集、最大值还是版本锁定。
- 设置类字段可采用最后写入，但要保留冲突诊断。
- 无法安全合并时提供只读预览和人工恢复入口。
- 冲突提示不得要求玩家猜测哪个副本“看起来更新”。
- 合并结果重新经过完整性校验和业务不变量检查。
- 任何合并都生成新数据世代，旧副本保持可审计。

## 迁移与回档设计

- 先在离线副本执行迁移，再对输出做统计比对。
- 预迁移阶段只读输入，不修改原始文件或对象。
- 执行阶段写入临时目标并记录每一步计数。
- 提交阶段用原子指针切换或事务提交。
- 每一步记录输入哈希、输出哈希、脚本版本和操作者。
- 回档依据是稳定快照 ID，不依据“最近文件”猜测。
- 回档前锁定玩家写入，避免新旧数据交叉覆盖。
- 回档后增加数据世代或回档世代，防止旧客户端再次写回。
- 回档不应撤销已核实的支付或合规记录。
- 迁移只改变结构，不隐式补偿玩家资产。
- 需要补偿时由独立、可审查的运营流程处理。
- 对大表迁移提供暂停、继续和安全中止能力。
- 熔断阈值包括失败率、校验失败率、耗时和资源占用。
- 迁移完成后保留抽样输入输出用于发布验收。
- 发布说明明确哪些版本可以继续写入。

## 损坏分类

- 截断：文件长度小于最小结构或末尾校验失败。
- 编码损坏：字节序列无法按声明编码解码。
- 结构损坏：JSON、二进制容器或数据库页无法解析。
- schema 损坏：版本缺失、未知版本或字段类型不符。
- 业务损坏：解析成功但违反资源、任务或时间不变量。
- 加密损坏：密钥不可用、认证标签不匹配或上下文错误。
- 并发损坏：多个写入者造成世代倒退或半提交。
- 逻辑损坏：迁移成功但资产数量或进度异常。
- 外部损坏：平台同步返回旧副本、冲突副本或空对象。
- 人为损坏：误删、误导入或客服手工改写未留审计。
- 每类损坏绑定唯一诊断码和恢复等级。
- 诊断码不应包含完整路径、令牌、密钥或个人数据。

## 损坏恢复策略

- 一级恢复：从同一设备最近可验证备份恢复。
- 二级恢复：从平台云存档候选副本恢复并保留本地副本。
- 三级恢复：从服务端历史快照恢复到新的数据世代。
- 四级恢复：由授权人工依据审计记录重建最小可玩状态。
- 恢复前验证玩家身份和数据归属。
- 恢复后重新运行迁移、完整性和业务不变量检查。
- 任何恢复都写入恢复原因、来源快照和结果哈希。
- 恢复失败不得清空现有候选副本。
- 玩家取消恢复时保持原始和候选副本可选。
- UI 提示区分“正在尝试恢复”和“无法自动恢复”。
- 不能承诺恢复已不存在、未备份或违反保留期限的数据。
- 客服工具提供脱敏差异摘要，不提供任意 SQL 或文件上传。

## 跨版本兼容矩阵

| 写入端 | 读取端 | 预期 | 门禁重点 |
|---|---|---|---|
| 旧客户端 | 旧客户端 | 基线可读写 | 回归快照一致 |
| 旧客户端 | 新客户端 | 新端迁移后可读 | 正向迁移 |
| 新客户端 | 新客户端 | 新 schema 稳定 | 幂等与性能 |
| 新客户端 | 旧客户端 | 只在声明窗口内可读 | 反向兼容 |
| 离线旧档 | 新客户端 | 可提示迁移 | 过期版本策略 |
| 损坏旧档 | 新客户端 | 可恢复或安全拒绝 | 诊断码 |
| 云端旧档 | 新客户端 | 冲突可解释 | 世代控制 |
| 新档 | 旧服务端 | 必须拒绝写入 | 服务端门禁 |
| 旧档 | 新服务端 | 链式迁移 | 迁移限速 |
| 混合设备 | 云端 | 不丢进度 | 冲突合并 |
| 升级中断 | 同版本 | 可重试 | 原子提交 |
| 回档后 | 新客户端 | 可继续写入 | 新世代 |

## 迁移测试矩阵

| 类别 | 输入 | 操作 | 观测 | 通过标准 |
|---|---|---|---|---|
| 单字段新增 | v1 正常档 | 升到 v2 | 默认值和日志 | 只新增声明字段 |
| 字段重命名 | v2 样本 | 升到 v3 | 新旧字段 | 旧值恰好迁移一次 |
| 类型收窄 | 合法边界值 | 升级 | 转换结果 | 越界被拒绝并留档 |
| 枚举新增 | 未知枚举 | 读取 | 降级或拒绝 | 无静默资产变化 |
| 数组扩容 | 最大长度样本 | 升级 | 内存和耗时 | 资源上限不超标 |
| 大整数 | 最大合法值 | 升级 | 精度 | 无浮点舍入 |
| 时间跨区 | UTC 和夏令时 | 升级 | 时间线 | 事件顺序不倒退 |
| 空值 | 缺失可选字段 | 升级 | 默认值 | 与合同一致 |
| 重复迁移 | 已迁移输出 | 再执行 | 哈希 | 输出不变 |
| 中途崩溃 | 迁移第 n 步 | 重启 | 原始和临时档 | 可继续或安全重跑 |
| 断网 | 云端提交中 | 断开 | 世代 | 不覆盖新数据 |
| 并发写入 | 两客户端 | 同时提交 | 冲突 | 明确胜者 |
| 校验失败 | 篡改字节 | 读取 | 诊断 | 不加载未知状态 |
| 截断 | 去掉尾部 | 读取 | 备份列表 | 自动回退或提示 |
| 错误密钥 | 不同密钥 | 读取 | 安全日志 | 不泄露明文 |
| 旧服务端 | 新客户端 | 提交 | HTTP/协议码 | 被门禁拦截 |
| 回档 | 历史快照 | 切换 | 数据世代 | 新写入不回穿 |
| 多语言 | 中文/RTL | 迁移 | 字符编码 | 文本不丢失 |
| 多平台 | 主机/PC/移动 | 同步 | 字段差异 | 平台差异可解释 |
| 大规模 | 百万级抽样 | 批量 | QPS、失败率 | 在预算内完成 |

## 边界值与故障注入

- 生成零字节、单字节、最大允许大小和超限大小样本。
- 生成缺失顶层字段、重复键、额外键和未知类型样本。
- 生成校验和正确但业务不变量错误的样本。
- 在文件刷新前、替换前、云端提交前注入进程终止。
- 在数据库事务提交前后注入连接断开。
- 在对象上传完成但指针未切换时模拟重试。
- 模拟密钥轮换期间旧密钥只读、新密钥写入。
- 模拟平台返回两个合法但不同世代的副本。
- 模拟客户端时钟倒退、快进和时区错误。
- 模拟磁盘只读、空间耗尽和权限变更。
- 模拟迁移脚本依赖缺失、超时和内存不足。
- 故障注入必须使用隔离测试账号和非生产数据。

## 证据要求

- 保存输入快照哈希和来源说明。
- 保存客户端构建号、服务端版本和 schema 版本。
- 保存迁移脚本提交号或不可变工件摘要。
- 保存关键字段迁移前后差异摘要。
- 保存校验、业务不变量和性能结果。
- 保存失败诊断码、时间线和重试次数。
- 保存回滚前后数据世代及对象指针。
- 保存抽样人工复核记录和复核人。
- 证据中对玩家 ID、设备 ID、令牌和自由文本脱敏。
- 证据可在隔离环境重放，但不应可直接写入生产。

## 失败信号

- 迁移后资源总量非预期变化。
- 输出 schema 版本与工件声明不一致。
- 同一输入重复迁移得到不同哈希。
- 旧客户端意外写入已停止支持的版本。
- 云端冲突被静默覆盖。
- 损坏文件被当作空新档加载。
- 回档后旧写入仍能覆盖回档结果。
- 迁移失败后原始唯一副本消失。
- 失败率、耗时或内存超过门禁阈值。
- 日志暴露完整载荷或敏感凭据。
- 玩家界面显示内部堆栈、路径或对象键。
- 自动恢复循环反复改写同一副本。

## 通过标准

- 所有声明支持的写入端和读取端组合通过矩阵。
- 迁移脚本具备幂等、确定性和可审计输出。
- 任何失败都保留原始或最近可验证副本。
- 业务不变量和关键资产总量保持产品定义的范围。
- 冲突、过期写入和未知版本均有明确可见结果。
- 本地原子写入和服务端事务在故障注入下成立。
- 大批量迁移在容量、延迟和错误率预算内完成。
- 诊断证据经脱敏后可由独立人员复核。
- 发布门禁记录测试工件、批准人和适用兼容窗口。
- 回滚演练在目标时间内恢复可玩状态。

## 回滚与排障

- 先暂停有问题版本的写入，不先删除异常数据。
- 记录受影响的 schema、脚本、构建和数据世代。
- 以快照哈希定位可验证输入和最后成功输出。
- 将异常对象复制到隔离区，避免排障再次触发迁移。
- 回切服务端指针前确认新写入已排队或安全拒绝。
- 回切后要求客户端重新拉取并清理过期本地缓存。
- 若本地档损坏，提示玩家选择备份，不要求反复重启碰运气。
- 若云端冲突，保留双方副本并转人工恢复。
- 若密钥问题，先恢复密钥访问，再判断是否需要迁移。
- 若迁移超时，按批次继续，不扩大并发掩盖瓶颈。
- 排障完成后补充根因、影响范围和预防测试。
- 回滚工单必须关联审计事件和验证证据。

## 常见误区与最佳实践

- 误区：schema 版本不变就代表业务兼容；实践：语义变化也升版本。
- 误区：把空档当作损坏档；实践：区分首次创建、删除和解析失败。
- 误区：只测“最新档能打开”；实践：覆盖所有支持窗口和中断点。
- 误区：用当前时间修复过期事件；实践：使用服务器时间和审计顺序。
- 误区：迁移失败直接清理文件；实践：原始副本只读保留。
- 误区：把客服手改当作临时操作；实践：使用受限工具和双人复核。
- 误区：只统计迁移成功数；实践：同时统计资产差异和恢复成功率。
- 误区：凭文件名选择云副本；实践：使用数据世代和完整性证明。
- 误区：为兼容旧端永久保留所有字段；实践：公布窗口并有删除计划。
- 误区：让客户端决定货币余额；实践：服务端重算或验证签名。
- 最佳实践：每个迁移版本配套正例、负例、幂等和回滚样本。
- 最佳实践：用合成数据覆盖边界，用脱敏真实快照覆盖组合。
- 最佳实践：把迁移演练纳入灾备和发布日历。
- 最佳实践：为客服提供诊断摘要而不是数据库权限。
