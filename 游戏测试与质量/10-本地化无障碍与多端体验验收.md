# 10 · 本地化无障碍与多端体验验收
> 知识成熟度：L2（本轮审计修订时补标）。

## 文档定位

- 定位：游戏测试与质量库的语言、可访问性和设备体验验收专题。
- 目标：验证不同语言、输入方式、感知能力和设备条件下，核心流程可理解、可操作、可恢复。
- 适用对象：客户端、UI、叙事、本地化、QA、发行、客服和平台合作团队。
- 最后更新：2026-08-07。
- 核心取舍：先保证信息和操作可达，再追求视觉装饰与像素级一致。
- 核心取舍：自动化检查发现结构问题，人工体验确认语义、节奏和负担。
- 核心取舍：WCAG 是网页可访问性基线，游戏内体验还需结合平台和玩法验证。
- 事实边界：地区法律、分级、平台输入 API 和字体授权以目标市场当前要求为准。
- 事实边界：本文不承诺所有残障玩家均可在所有玩法中达到相同结果。
- 事实边界：辅助功能设置应尊重玩家选择，不能未经同意收集健康或能力信息。

## 验收范围与排除项

- 范围包括启动、登录、设置、教程、战斗、菜单、社交、商店、错误恢复和退出。
- 范围包括本地化文本、字体、格式化、音频字幕和图片内文字。
- 范围包括键鼠、手柄、触摸、陀螺仪和平台辅助设备的输入路径。
- 范围包括窗口化、分辨率、HDR、低带宽、低帧率和小屏设备。
- 范围包括色觉、听觉、视觉、运动、认知和语言负担的可调设置。
- 排除纯营销页面的合规结论，但可复用其文本和键盘检查方法。
- 排除医学诊断，不根据测试结果给玩家贴能力标签。
- 排除目标平台未开放的系统级辅助接口，记录为平台边界。
- 排除翻译质量的专业审校责任，但验收其在产品上下文中的呈现。
- 所有排除项必须写明影响、替代路径和再次评估时间。

## 基线与事实边界

- 每个语言包记录语言、地区、脚本、复数规则和最后审校日期。
- 每个字体记录授权、覆盖字符集、回退链、字重和渲染限制。
- 每个平台记录输入 API、焦点模型、屏幕安全区和系统缩放行为。
- 每个辅助设置记录作用范围、默认值、可逆性和存档方式。
- 每个严重度绑定用户影响和发布门禁，不用“看起来不舒服”代替证据。
- 文字可读性不等于 WCAG 对比度通过；两者均要测。
- WCAG 成功标准不能自动推导出实时战斗、空间音频或沉浸玩法结论。
- RTL 镜像不等于所有图标、数字、地图和按键提示都应镜像。
- 自动翻译不等于本地化完成；角色语气、术语和文化禁忌需要人工审校。
- 平台系统设置可能覆盖游戏设置，需记录最终生效值。

## 伪本地化策略

- 伪本地化在开发早期运行，不等到翻译锁定才发现截断。
- 扩展拉丁字符长度以模拟德语、俄语等长文本。
- 插入重音符号和组合字符以发现错误的字素处理。
- 插入双向控制字符的安全测试样本，但不把控制符写入正式文案。
- 用占位符标记未翻译、拼接、格式化和上下文缺失。
- 对数字、日期、货币和百分比使用不同地区格式样本。
- 对复数、性别和占位符分别覆盖单数、复数、零和未知值。
- 伪本地化不改变逻辑 ID，便于回溯原始字符串。
- 截断检查覆盖按钮、提示、通知、成就、错误和动态文本。
- 溢出检查覆盖最小窗口、系统缩放和大字体模式。
- 伪本地化报告记录屏幕、字符串 ID、最大宽度和截图。
- 通过后将最小失败样本加入自动化快照。

## 文本与格式化

- 文本从资源表读取，不在代码中散落硬编码可见字符串。
- 占位符名称稳定，禁止按语言顺序猜测参数。
- 缺少占位符、额外占位符和类型不匹配都应在构建期失败。
- 动态数字按照地区规则格式化，不拼接千位分隔符。
- 时间显示声明相对时间、绝对时间和时区来源。
- 货币显示币种符号、位置、小数位和舍入规则。
- 复数规则由语言资源决定，不用英文单复数逻辑泛化。
- 断行遵循词边界、字素边界和产品术语规则。
- 禁止依赖固定像素宽度承载任意长度文本。
- 文案变更保留上下文、截图和角色信息供译者使用。
- 错误信息说明用户下一步，不只显示内部编号。
- 文本中的玩家名、队名和自由输入必须进行长度与字符安全处理。

## 字体与脚本

- 选择覆盖目标语言的主字体和可审查的回退字体。
- 检查汉字、假名、谚文、阿拉伯文、希伯来文、泰文和西里尔文。
- 检查组合字符、变音符号、emoji、符号和数学字符。
- 检查粗体、斜体、描边、阴影和小字号下的笔画损失。
- 检查字体加载失败时的可读回退，而不是方框或空白。
- 检查字体许可证、嵌入限制和平台包体影响。
- 检查数字宽度、等宽需求和表格对齐。
- 检查阿拉伯文连接形态、RTL 标点和数字混排。
- 检查东亚字体 fallback 造成的基线、字重和行高跳变。
- 检查大字体模式下按钮高度和滚动区域。
- 字体问题记录字符码点、字体链和渲染后截图。
- 发布前对每个语言包做缺字扫描并复核高风险文本。

## RTL 与双向文本

- 先定义界面容器的方向，再决定图标和装饰是否镜像。
- 不镜像品牌标识、媒体控制符号、数字和通用方向标记。
- 镜像导航箭头、进度方向和空间布局时提供产品依据。
- 混排阿拉伯文、拉丁文、数字和玩家名时检查阅读顺序。
- 动态字符串不通过手工插入不可见控制符解决全部问题。
- 使用 Unicode 双向算法测试样本并记录安全处理。
- 列表、表格、聊天和日志中分别测试方向隔离。
- RTL 下焦点移动顺序应与视觉和阅读顺序一致。
- RTL 下手柄提示和快捷键位置不能被错误翻转。
- 地图、瞄准、时间线和战斗方向需由玩法团队确认语义。
- 对不支持 RTL 的平台显示明确语言限制和替代路径。

## 输入法与文本输入

- 测试中文、日文、韩文输入法的组合态、候选态和提交态。
- 测试键盘布局、死键、组合键、全角半角和大小写。
- 测试移动端软键盘遮挡、旋转和安全区。
- 测试手柄、触摸和键盘切换时焦点不丢失。
- 文本框在输入法组合期间不提前验证或截断。
- 粘贴、删除、选中、撤销和重做行为可用且不泄漏隐私。
- 名称、聊天和代码输入分别定义允许字符、长度和过滤规则。
- 输入错误提示不在组合态插入破坏性文本。
- 网络断开时输入草稿按产品策略保留或明确丢弃。
- 语音输入、屏幕键盘和系统辅助输入按平台能力测试。
- 输入法测试记录设备、语言、输入法版本和焦点变化。
- 禁止将过滤器当作翻译或安全策略的唯一实现。

## 字幕与音频信息

- 字幕覆盖对白、关键音效、环境声、说话者和方向提示。
- 字幕与语音同步，快速连续对白不重叠或不可读。
- 允许调节字号、背景、位置、颜色和显示时长。
- 说话者在多人场景可区分，但不只依赖颜色。
- 重要非语言信息提供文本、图标、振动或视觉替代。
- 字幕在安全区内显示，不被 HUD、刘海或系统栏遮挡。
- 音频动态范围和混音设置不能使关键信息完全不可听。
- 单声道、左右声道错接和耳机断连需有可感知回退。
- 音频描述、提示音和振动不应相互覆盖。
- 过场跳过后，关键剧情信息有可再次查看入口。
- 字幕测试使用正常、快速、低速和语言切换场景。
- 发行前审查字幕术语、标点、断行和敏感内容。

## 颜色、对比度与视觉提示

- 关键状态不只通过颜色传达，至少有形状、文本、图标或声音之一。
- 颜色组合覆盖红绿色觉差异、蓝黄色觉差异和低饱和显示。
- 检查文本、图标、焦点、禁用态和背景的对比度。
- 检查 HDR、SDR、夜间模式和不同亮度下的可辨识度。
- 检查屏幕滤色、系统高对比度和反色设置的交互。
- 命中、伤害、队友、敌人和可交互对象有非颜色区分。
- 闪烁、快速变化和高亮特效设置可关闭或降低。
- 关键 HUD 在低分辨率和小屏上仍可读。
- 照片敏感或动态模糊设置不阻塞操作。
- 色彩说明在教程、图例和图标中保持一致。
- 视觉缺陷记录原始色值、背景、显示模式和替代信号。

## 焦点、导航与操作

- 所有核心 UI 控件有可见焦点，并能被键盘或手柄到达。
- 焦点顺序与信息层级一致，不在弹窗后跳到背景。
- 打开、关闭、返回和取消操作有一致的按键和提示。
- 首次进入页面时焦点落在安全且可理解的位置。
- 动态列表更新不把焦点静默移到别处。
- 弹窗打开时背景不可误操作，关闭后焦点恢复原控件。
- 读屏或辅助输出能获得控件名称、状态、值和操作结果。
- 不可操作控件说明原因或以一致方式禁用。
- 需要精确时序的玩法提供可选简化、保持或辅助模式。
- 连续按键、长按和双击均有可调时间窗口。
- 操作失败后焦点和上下文保持，便于重试。
- 录入设置变更可预览、撤销和恢复默认。

## 控制器与替代输入

- 默认键位在各平台与产品说明一致。
- 支持重映射、按键保持、切换式操作和左右摇杆交换。
- 重映射冲突有提示，不强制覆盖用户已有设置。
- 多控制器连接、断开和重新连接不丢失玩家编号。
- 触摸目标足够大且间距合理，不把精度压力转嫁给用户。
- 鼠标灵敏度、指针加速度和死区可调且有即时预览。
- 方向盘、适配器或辅助开关输入按平台可用性记录。
- 震动、触觉和陀螺仪可分别关闭并不阻塞核心反馈。
- 输入提示随当前设备切换，避免展示错误按键。
- 本地多人为每位玩家保留独立设置和焦点。
- 控制器测试包含低电量、睡眠唤醒和系统弹窗抢焦点。

## 认知负担与可理解性

- 教程一次只介绍必要概念，并允许暂停、重播和跳过。
- 目标、奖励、失败条件和下一步在界面中可回看。
- 长任务提供阶段进度和明确完成标志。
- 重要设置使用普通语言，避免只写内部术语。
- 复杂经济、技能和状态效果提供可选详细说明。
- 时间限制、音效和视觉压力可通过辅助设置降低。
- 失败后说明可控因素和重试路径，不只显示“失败”。
- 多步骤操作提供确认、撤销和恢复中断状态。
- 同一概念的名称、图标和颜色在全流程一致。
- 在信息密集界面允许隐藏非关键层并保存偏好。
- 不用羞辱、诱导或模糊措辞迫使玩家继续操作。
- 认知负担检查邀请真实玩家或可访问性顾问参与。

## WCAG 适用边界

- 将 WCAG 2.2 的可感知、可操作、可理解和健壮原则映射到游戏 UI。
- 对网页登录、账户、商店和帮助页面可直接执行 WCAG 成功标准。
- 对实时战斗、空间导航和平台特有输入，记录映射方法和差异。
- 对比度、焦点、键盘可操作性和非文本内容仍应优先纳入。
- 不把通过自动扫描当作完整体验通过。
- 不把 WCAG A/AA 标签当作地区法律合规证明。
- 平台无障碍 API 的限制写入风险登记，不伪造符合性。
- 为不可满足的成功标准提供替代内容、设置或客服路径。
- 每条适用标准记录版本、测试环境、证据和责任人。
- 发现冲突时优先保护安全、信息理解和可操作性。

## 可核对示例

- 示例 A：德语伪本地化使按钮扩大 40%，按钮改为自适应并保持焦点顺序。
- 示例 B：阿拉伯文菜单镜像导航箭头，但品牌标识和数字未错误镜像。
- 示例 C：中文输入法处于组合态时，名称框不提交半成品文本。
- 示例 D：静音模式下，敌人方向和重要警告通过字幕与视觉标记呈现。
- 示例 E：红绿色觉模拟下，队友和敌人仍可由图标和形状区分。
- 示例 F：大字体与 200% 系统缩放下，任务详情可滚动且不遮挡确认按钮。
- 示例 G：手柄断开再连接后，玩家设置、焦点和按键提示保持一致。
- 示例 H：关闭震动、闪烁和镜头抖动后，核心目标和结果仍可理解。
- 示例 I：RTL 混排玩家名与数字时，文本方向和复制结果可核对。
- 示例 J：跳过过场后，关键目标在日志和教程入口仍可回看。

## 证据要求

- 保存语言、地区、版本、字体包和平台构建信息。
- 保存伪本地化配置、字符串 ID、截图或录屏。
- 保存设备型号、系统版本、显示缩放和辅助设置。
- 保存输入设备、重映射表、焦点路径和操作结果。
- 保存字幕、音频轨、音量设置和同步偏差。
- 保存对比度、色觉模拟和闪烁检查结果。
- 保存 WCAG 映射、适用边界和替代路径。
- 保存翻译审校、术语表版本和已知例外。
- 证据避免真实玩家姓名、聊天和健康信息。
- 失败样本最小化，确保可由发布团队重放。

## 失败信号

- 任一支持语言在核心流程出现不可读、不可操作或错误语义。
- 缺字、字体回退或组合字符导致关键状态丢失。
- RTL 下阅读顺序、焦点顺序或按键提示矛盾。
- 输入法组合态被截断、误提交或覆盖。
- 重要音频信息在静音或听觉辅助设置下没有替代。
- 关键状态只用颜色表示，色觉模拟下无法区分。
- 大字号、高对比或系统缩放使确认、返回或错误处理不可达。
- 弹窗打开后焦点落在背景，造成误操作或读屏混乱。
- 重映射后提示未更新，或无法恢复默认键位。
- 关闭闪烁、震动和镜头抖动后无法完成核心目标。
- WCAG 结论没有版本、环境或适用边界。
- 设备矩阵只覆盖开发机，未覆盖最低支持配置。

## 通过标准

- 支持语言的核心流程无截断、缺字、错误格式和阻塞性语义问题。
- 伪本地化、长文本、RTL、组合字符和地区格式检查通过。
- 核心操作可由声明支持的输入设备完成并可恢复焦点。
- 字幕和视觉替代覆盖产品定义的关键音频信息。
- 关键状态不依赖单一颜色，焦点和对比度达到项目门槛。
- 辅助设置可关闭、可保存、可撤销且不引入新的阻塞。
- WCAG 适用项目有证据，游戏特有边界有书面解释和替代路径。
- 最低设备和主流设备在性能、布局和系统覆盖下均可玩。
- 严重问题在发布前关闭，例外有责任人、补偿和复审日期。
- 发布签字包含本地化、可访问性、QA、发行和平台负责人。

## 核心流程的可达性状态

~~~mermaid
stateDiagram-v2
    [*] --> Discover: 进入页面
    Discover --> Operable: 文本/焦点/输入可理解
    Discover --> Blocked: 缺字、焦点丢失或不可读
    Operable --> Recoverable: 错误有提示且可重试/撤销
    Operable --> Blocked: 关键操作不可达
    Recoverable --> Complete: 目标完成并保留设置
    Recoverable --> Blocked: 断线/切换后无法恢复
    Blocked --> FixAndRetest: 修复或记录边界
    FixAndRetest --> Discover
    Complete --> [*]
~~~

## 回滚与排障

- 先确认问题是资源、字体、布局、输入、平台覆盖还是翻译语义。
- 固定语言包、字体包、客户端构建和设备设置，避免环境漂移。
- 用字符串 ID、截图坐标和操作步骤定位最小样本。
- 语言包回滚时保留旧包的安全签名和版本映射。
- 字体回滚时确认授权、包体和字符覆盖未回到更坏状态。
- UI 布局回滚后重新跑大字体、RTL和安全区矩阵。
- 输入回滚后重置焦点和按键提示缓存。
- 字幕回滚后检查音频轨、时间码和翻译版本一致。
- 无障碍设置不因更新丢失；若必须重置，明确告知并提供恢复。
- 发布期间出现严重可达性问题，暂停扩大灰度并保留反馈样本。
- 排障报告区分平台限制与产品缺陷，不将责任推给玩家设置。
- 复盘将用户反馈转为自动化或人工验收用例。

## 常见误区与最佳实践

- 误区：英文正常就代表所有语言正常；实践：伪本地化和真实长文本并测。
- 误区：自动对比度扫描等于可访问；实践：加入焦点、输入和人工体验。
- 误区：RTL 只需整体镜像；实践：逐项判断方向、品牌和数字语义。
- 误区：字幕只抄对白；实践：包含说话者、关键音效和方向提示。
- 误区：重映射只改设置页；实践：同步教程、HUD、帮助和提示。
- 误区：大字体由玩家自己承担；实践：核心流程布局自适应并可回退。
- 误区：辅助模式必然降低玩法公平；实践：分级设计并说明竞技边界。
- 误区：WCAG AA 是所有游戏的法律结论；实践：写清标准版本和适用范围。
- 最佳实践：把字符串 ID、截图、术语和设备条件作为缺陷最小证据。
- 最佳实践：优先修复阻塞操作、误导信息和不可恢复错误。
- 最佳实践：邀请本地化审校者和可访问性顾问参与候选版本。
- 最佳实践：把系统辅助设置与游戏设置的最终生效值纳入日志。
- 最佳实践：在发布后持续分析匿名反馈，避免只看一次验收。
