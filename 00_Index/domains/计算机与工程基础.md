## 1. 领域定位与三层推导体系

“计算机与工程基础”是整个技术知识库的底层底座，回答所有上层系统“为什么这样设计”与“性能瓶颈在哪里”的核心机理：

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                           上层业务与引擎工程                             │
│  UE5 客户端 (GAS/渲染/UObject/GC) │ 游戏服务端 (MainLoop/AOI/分布式/DS平台) │
└────────────────────────────────────▲────────────────────────────────────┘
                                     │ 约束与抽象
┌────────────────────────────────────┴────────────────────────────────────┐
│                           核心系统与机制设计                             │
│  并发模型/内存序 │ 反应器/网络协议 │ 存储引擎/事务 │ 编译器优化/SIMD     │
└────────────────────────────────────▲────────────────────────────────────┘
                                     │ 硬件与内核原理
┌────────────────────────────────────┴────────────────────────────────────┐
│                           硬件与操作系统底座                             │
│  CPU Cache/MESI │ 虚拟内存/PageFault │ 系统调用/中断 │ ISA汇编与ABI规则  │
└─────────────────────────────────────────────────────────────────────────┘
```

本域为以下业务场景提供第一性原理支撑：
- 解释为什么 Cache Miss 会导致游戏帧率剧烈波动（08 体系结构 ↔ 02 对象模型 ↔ 05 数据结构）；
- 解释为什么多线程原子计数可能比加锁还慢（04 并发 ↔ 08 体系结构的 False Sharing 证据）；
- 解释为什么移动语义让 `TArray` 扩容性能提升数倍（01 C++核心值语义 ↔ UE 容器实现）；
- 解释为什么 Epoll ET 模式下必须循环读到 `EAGAIN` 且小心背压（07 Linux系统编程 ↔ 服务端网关）；
- 解释为什么虚拟内存 Page Fault 会引起服务端微卡顿（06 操作系统 ↔ 服务端内存治理）。

## 3. 五大工程角色导向学习路径

根据研发方向的不同，推荐按照以下依赖拓扑分阶段阅读与验证：

### 路径 A：C++ / 游戏引擎客户端底层研发
```text
01-C++核心 (生命周期/RAII/值语义)
  └─→ 02-C++对象模型与内存 (对象布局/虚函数表/分配器)
        └─→ 08-计算机体系结构 (存储层次/SIMD向量化/流水线)
              └─→ 10-编译链接与ABI (符号解析/动态库加载/导出宏)
                    └─→ 11-工程调试与性能分析 (ASan/调试器/崩溃分析)
```
- **核心目标**：透彻理解 UE5 `UObject`、`TArray`、`TaskGraph`、`FMallocBinned` 源码级行为，掌控内存占用与每帧微秒级开销。

### 路径 B：高性能游戏服务端研发
```text
04-C++并发与内存模型 (锁/Atomic/无锁队列/线程池)
  └─→ 06-操作系统 (虚拟内存/PageFault/系统调用开销)
        └─→ 07-Linux系统编程 (Epoll/Reactor/io_uring/perf采样)
              └─→ 09-计算机网络 (TCP/QUIC/拥塞控制/NAT穿透)
                    └─→ 12-数据库与分布式 (存储引擎/事务/一致性共识/缓存MQ)
```
- **核心目标**：掌握单服高吞吐、低延迟网关通信、毫秒级定时器调度、无锁跨线程投递与分布式世界服状态一致性。

### 路径 C：游戏算法与 AI 核心研发
```text
13-数学与算法基础 (离散图论/线性代数/概率统计)
  └─→ 05-数据结构与复杂度 (时间空间复杂度/紧凑容器局部性)
        └─→ 08-计算机体系结构 (CPU Cache/分支预测优化)
```
- **核心目标**：支撑 A* 寻路优化、空间索引（网格/四叉树/BVH）、Mass/ECS 批量实体更新、连续物理碰撞与确定性模拟。

### 路径 D：可靠性工程、安全与 Devops 质量保障
```text
15-软件工程与构建 (构建图/版本管理/静态分析/Fuzz/CI-CD)
  └─→ 14-安全与密码基础 (认证授权/数据防篡改/反作弊防护)
        └─→ 16-容器云与可观测性 (容器隔离/Metrics追踪/SLO/故障演练)
```
- **核心目标**：保障工程持续交付可靠性、Dedicated Server 自动化集群编排扩缩容、业务防刷防挂与生产故障快速自愈。

## 4. 底座基础 ↔ 业务/引擎层映射网格

| 底座知识专题 | 业务工程映射系统 / 关键类与组件 | 核心机理与工程收益 |
| :--- | :--- | :--- |
| **01-值语义与移动** | UE5 `TArray::Emplace` / `MoveTemp` | 容器扩容时不触发逐元素深拷贝，利用右值转移避免内存频繁重分配与碎片化 |
| **02-对象布局与内存分配** | UE5 `FMallocBinned2` / `UObject` 内存对齐 | 按固定 Bin 分配避免外碎片，对象按 16/64 字节对齐适配 CPU 缓存行并减少跨行访问 |
| **04-内存序与无锁** | 服务端 `ServerMainLoop` / `TickScheduler` 计数器 | 使用 `std::memory_order_relaxed` 累加监控指标，避免全局总线锁带来的吞吐瓶颈 |
| **04-False Sharing 规避** | 实体分区多线程 Tick / 工作窃取队列 | 数据结构使用 `alignas(64)` 填充隔离独立核心的写入变量，避免多核 RFO 缓存行乒乓 |
| **06-虚拟内存与 Page Fault** | 游戏大地图资源流送 / 预分配内存池 | 启动期对关键堆进行预触摸（Pre-fault），规避运行期高频 Major/Minor 缺页中断引发的帧卡顿 |
| **07-Epoll 与 Reactor** | 游戏网关服务器网络层（TCP/UDP 网关） | 采用 Edge-Triggered 非阻塞反应器模型，以极小线程数承载数万在线连接的高并发分发 |
| **08-CPU Cache 与局部性** | 游戏服务端 AOI 网格 / UE5 Mass 实体架构 | 采用 Structure of Arrays (SoA) 代替 AoS，显著提高连续循环遍历时的 L1 数据缓存命中率 |
| **09-QUIC 协议原理** | 弱网环境下移动端游戏信令通道 | 利用单条 UDP 连接多路复用彻底解决 TCP 队头阻塞，并在基站切换时支持连接无缝迁移 |
| **10-编译链接与 ABI** | UE5 `MODULE_API` / 插件动态热重载 | 严格遵循 DLL 导出规约与虚函数表顺序，保证动态链接边界一致性并防范 ODR 违规崩溃 |
| **12-分布式共识与事务** | 跨服玩家数据迁移 / 拍卖行分布式交易 | 采用两阶段提交 (2PC) 或 Saga 配合 Raft 状态机，保障极端宕机情况下玩家资产最终一致 |
