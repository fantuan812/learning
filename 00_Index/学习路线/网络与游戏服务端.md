# 网络与游戏服务端：学习路线

本页提供前置知识、阅读选择、练习与验收建议，知识成熟度：L0；主题细节由链接主文负责。练习均待执行，本文不提供新的 UE、运行时、生产或基准验证，也不表示所有正文事实已经全面核实。

## 网络协议基础：从传输机制到连接拓扑

前置是[编程与计算机基础路线](编程与计算机基础.md)中的非阻塞 I/O、所有权、线程与有界队列。按 [网络分层协议与工程实践](../../知识/01-编程与计算机基础/网络协议基础/01-网络分层协议与工程实践.md) → [QUIC 与 HTTP 演进](../../知识/01-编程与计算机基础/网络协议基础/02-QUIC与HTTP演进.md) → [IPv6、NAT、服务发现与负载均衡](../../知识/01-编程与计算机基础/网络协议基础/03-IPv6NAT服务发现与负载均衡.md)学习，顺序是先解释一条连接如何传数据，再解释弱网与迁移，最后解释请求如何到达正确实例。

TCP 阶段要能区分可靠有序字节流、应用消息边界、滑动窗口流控与拥塞控制。用拆包／粘包、慢读端、丢包和往返时延变化观察队列与重传，并区分 CUBIC／BBR 等策略的目标与实际可用配置。把 Nagle、延迟确认、小包频率与延迟一起测量，再决定 TCP_NODELAY；不能把固定几十毫秒延迟或“任何高频小包都必须开启”当作普遍结论。

QUIC 阶段对照 HTTP/1.1、HTTP/2 与 HTTP/3 的流和阻塞边界，再比较 KCP／ENet 等游戏 UDP 方案的可靠性、拥塞控制、加密与维护成本。QUIC 可减少不同流之间因单流丢包产生的传输层队头阻塞，但共享拥塞、连接级资源及流内有序交付仍有约束；连接迁移是否成功依赖端点和网络路径。练习记录 Wi-Fi／蜂窝切换或等效路径变化的恢复行为，检查 0-RTT 的重放风险及业务可重试性，而不是只看建连时间。

包体预算必须按路径 MTU、IP／UDP／加密与协议头计算并实测；“1400 字节以下”只能作为某些路径的起始预算，不能保证所有网络不分片。将分片／丢包与应用重传分开记录，并注明 PMTU 发现或探测策略。验收包括完整消息、超长包拒绝、断线／半关闭和应用队列上限，避免把 TCP 流控当成应用内存自然有界的证明。

拓扑阶段画出 IPv4／IPv6 双栈、NAT、STUN／TURN／ICE、服务发现和四／七层负载均衡的路径；打洞失败时定义中继与超时回退。比较按会话／房间绑定、哈希路由和负载分配的故障转移，一致性哈希减少部分迁移但不能替代会话权威与状态交接协议。产物是一张包含重连、地址变化和后端失效的拓扑图，加上失败注入记录；LVS／DPDK 等实现只在负载与运维成本支持时继续评估。

## 持久化前置：事务、共识、缓存与消息

按 [存储引擎与事务](../../知识/07-网络与游戏服务端/持久化与分布式一致性/01-存储引擎与事务.md) → [分布式系统基础](../../知识/07-网络与游戏服务端/持久化与分布式一致性/02-分布式系统基础.md) → [缓存与消息队列](../../知识/07-网络与游戏服务端/持久化与分布式一致性/03-缓存与消息队列.md)阅读；前置是 [文件系统与存储栈](../../知识/01-编程与计算机基础/操作系统与系统I-O/03-文件系统与存储栈.md)中的 Page Cache、刷盘与故障边界。

先比较 B+Tree／LSM-Tree 在读写放大、范围查询、写入合并和压实中的取舍，再理解 WAL、恢复、ACID、隔离级别与 MVCC。用并发修改同一角色余额的案例区分丢失更新、写偏差和重复请求；MVCC 并不表示所有读都无锁，事务提交是否持久取决于实现与刷盘配置。验收提交前／提交后崩溃的允许结果，解释行锁、乐观版本检查和约束各自保护什么。

再引入网络分区、延迟和节点失效，学习 CAP／PACELC、物理／逻辑时钟、Raft／Paxos 的共识职责以及 2PC／Saga／TCC 的业务选择。不要把“用了共识”视为跨服务事务已经正确：拍卖、道具或代币转移还须写出守恒、不重复执行、补偿与人工恢复的条件；2PC 可能阻塞，Saga 补偿并非一般意义的数据库回滚，TCC 需要可靠的 Try／Confirm／Cancel 合同。

缓存阶段对比 Cache-Aside、Write-Through 和 Write-Back 的可见性、失效与丢失窗口；热点、穿透、击穿和雪崩分别设计限流、合并回源或过期策略。角色脏标记＋定时刷盘、停服刷盘或 Redis 缓存都不能单独保证宕机不丢档。消息阶段把 at-least-once 的重复、乱序与重试纳入幂等键、去重表／唯一约束和消费事务；所谓 exactly-once 必须说明作用范围，不外推到所有外部副作用。

综合练习模拟角色存盘、重复发奖与跨 Zone 交接：在消息投递前后、数据库提交前后、所有权转移前后逐点故障注入。Redis 锁与版本 CAS 的示例还需考虑租约过期、进程暂停、持久化与 fencing／权威代次；验收任何时刻仅一个有效写者，重试不重复发奖，允许的数据丢失窗口有明确记录。接 [分布式系统基础](../../知识/07-网络与游戏服务端/持久化与分布式一致性/02-分布式系统基础.md)的协议条件，继续游戏业务的一致性与恢复路线。

## 从权威状态到运行和发布

先读网络/并发和数据前置，再按“架构与通信 → 世界 Tick → 玩法状态机 → 数据持久化 → 平台可靠性 → 压测与发布”建立全局联系；DS 编排可在世界运行基础后并行推进。把接入网关、业务服务、世界实例、战局进程、数据库/缓存和消息通道画成权威与数据流图，说明每一步由谁持有状态、确认操作和恢复失败。

主原则是业务合同与证据：AOI、异步落盘、幂等键或背压都不会独自保证固定容量、绝对零丢失或端到端 exactly-once。区分可重放输入、已提交资产、可丢展示广播与需要补偿的副作用，设定故障模型后验证。

练习覆盖拆帧、半包/粘包、心跳、重连、队列所有权和慢消费者背压；明确借用缓冲的生存期与跨线程移交。protobuf 需分开 wire、presence、JSON 与业务兼容，[协议主文](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E6%9C%8D%E5%8A%A1%E6%9E%B6%E6%9E%84%E4%B8%8E%E6%B6%88%E6%81%AF%E9%80%9A%E4%BF%A1/02-%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1%E4%B8%8E%E5%8D%8F%E8%AE%AE%E8%AE%BE%E8%AE%A1.md)链接的 Python 新旧 schema 实验有其 runtime 边界，不能外推为 C++ runtime 已验证。

品类用于提出问题：MOBA/格斗/竞速比较输入同步、数值确定性和传输延迟；MMO/射击比较 Zone、AOI、状态复制与预测；中台/跨服重点查消息、RPC、重试和并发。SLG 再进入大地图计算、定时事件、经济/活动、资产事务与对账；回合制/卡牌/弱联机比较无状态服务和异步结算是否适用，并验证防刷、防篡改和录像复算。不能由游戏名称推断实际架构，也不能把定点数当作独立的确定性证明。

新人可先读架构、协议与并发的线程模型，再回头补同步和消息；框架品牌只作比较对象，选型需考虑团队、预算和已有系统。

## 预测、历史查询与兴趣管理选择

接 [客户端预测与延迟补偿](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E5%90%8C%E6%AD%A5%E9%A2%84%E6%B5%8B%E4%B8%8E%E5%9B%9E%E6%94%BE/03-%E5%AE%A2%E6%88%B7%E7%AB%AF%E9%A2%84%E6%B5%8B%E4%B8%8E%E5%BB%B6%E8%BF%9F%E8%A1%A5%E5%81%BF.md) 时先写出输入序号、ACK、未确认输入、权威时间、表现时间与历史查询时刻。移动平滑负责可见过渡，不能替代正确的输入重放。射击补偿必须说明时间有效范围、历史形状、遮挡策略及公平性取舍。

基础正确后再按实际复制架构选择 [ReplicationGraph](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E7%8A%B6%E6%80%81%E5%A4%8D%E5%88%B6%E4%B8%8E%E5%85%B4%E8%B6%A3%E7%AE%A1%E7%90%86/05-ReplicationGraph%E5%85%B4%E8%B6%A3%E7%AE%A1%E7%90%86.md) 与 [Iris](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E7%8A%B6%E6%80%81%E5%A4%8D%E5%88%B6%E4%B8%8E%E5%85%B4%E8%B6%A3%E7%AE%A1%E7%90%86/07-Iris%E5%A4%8D%E5%88%B6%E4%BD%BF%E7%94%A8%E4%B8%8E%E8%BF%81%E7%A7%BB.md)，核对功能覆盖、迁移条件和测试成本；原阅读先后关系不代表两者可以随意叠加或必须先部署前者。网络调试与回放分别读 [网络调试](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E7%8A%B6%E6%80%81%E5%A4%8D%E5%88%B6%E4%B8%8E%E5%85%B4%E8%B6%A3%E7%AE%A1%E7%90%86/08-%E7%BD%91%E7%BB%9C%E8%B0%83%E8%AF%95%E4%B8%8E%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90.md) 和 [DemoNetDriver](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E5%90%8C%E6%AD%A5%E9%A2%84%E6%B5%8B%E4%B8%8E%E5%9B%9E%E6%94%BE/09-%E7%BD%91%E7%BB%9C%E5%9B%9E%E6%94%BE%E4%B8%8EDemoNetDriver.md)。平台会话接 [在线子系统/会话](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E4%BC%9A%E8%AF%9D%E8%BA%AB%E4%BB%BD%E4%B8%8E%E5%9C%A8%E7%BA%BF%E6%9C%8D%E5%8A%A1/06-%E5%9C%A8%E7%BA%BF%E5%AD%90%E7%B3%BB%E7%BB%9F%E4%B8%8E%E4%BC%9A%E8%AF%9D%E5%8C%B9%E9%85%8D.md)，区分发现、加入、身份验证、对象就绪和重连。

## 弱网与时间域的练习验收

建立最小双端场景，分别安排延迟、抖动、丢包、乱序、迟加入与断线重连；保存配置和实际 RTT，不只写模拟器参数。记录输入确认位置、待重放数量、修正量、可见延迟、历史请求被接纳/拒绝的原因。验收要能回答“哪一个输入被确认、查询的是哪一刻、为何拒绝回退”，并展示非法时间、超窗请求与过期对象不会改变权威结果。

兴趣管理练习固定场景与移动路径，对比候选集、相关对象数、更新频率、总包量与 CPU 时间；把来源的固定半径、2Hz 与 25KB/s 改成项目可测的自变量和预算，不能先认定某组参数保证结果。独立 C++11 历史查询断言只能覆盖该模型，不能替代 UE 复制、真实碰撞和多人测试。
