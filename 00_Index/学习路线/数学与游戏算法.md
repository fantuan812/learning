# 数学与游戏算法学习路线

> 知识成熟度：L0（学习路线，不代表链接正文已全部实测；本页练习待执行）。

## 起点与共同前置

先把问题写成输入、约束、输出与失败条件，再选算法。路线连接离散图、连续几何、概率采样和可复现模拟；完整概念正文见[数学与游戏算法知识入口](../../知识/02-数学与游戏算法/README.md)。引擎 API、AI 决策、服务端调度和玩法业务分别由相邻领域承接，不能以一个算法示例代替整个系统的实现或验证。

共同前置按 [数学与算法基础总览](../../知识/02-数学与游戏算法/数学与数值计算/数学与算法基础总览.md) → [概率、线性代数与数值计算](../../知识/02-数学与游戏算法/数学与数值计算/02-概率线性代数与数值计算.md) → [数据结构复杂度与容器选型](../../知识/02-数学与游戏算法/数据结构与编码/01-数据结构复杂度与容器选型.md)阅读。先用集合、关系、命题与归纳法解释状态机、图的连通性和依赖拓扑，再区分离散／连续分布、独立抽样与带历史状态的保底机制；随后把渐进复杂度、内存峰值、缓存局部性和实际输入规模放在一起判断。

练习分别构造一个依赖 DAG、一个带权地图和一个可复现抽样序列，注明非法输入与边界。容器对照同时测小／大规模、顺序／随机访问和增删比例；平铺数组有局部性优势的可能，节点容器、树与哈希仍按需求选。不能把小规模线性扫描优于树泛化为所有 N，也不能预设 TMap 是开放寻址平铺哈希。若瓶颈在布局、分配或并发，补读[编程与计算机基础路线](编程与计算机基础.md)的所有权和体系结构。定时器另比较时间轮与最小堆的精度、插入／取消、稀疏到期与突发到期成本；实体管理则比较连续 Archetype 表与 Sparse Set 的遍历、稀疏 ID 和结构变更。UE 中 TArray、TSparseArray 与 TSet 的布局以实际实现为准，不把某类容器全面禁用当作通用规则。

## 图搜索与导航流水线

先读 [图论基础与搜索算法](../../知识/02-数学与游戏算法/路径搜索与导航/01-图论基础与搜索算法.md)，用同一张地图表示邻接矩阵、邻接表、连续紧凑邻接和隐式网格，比较遍历、修改与存储成本。DFS 适合遍历、连通性和回溯，不能直接充当无权最短路。BFS 用 FIFO 队列解决战棋等成本步数、洪水填充和无权连通域；Dijkstra 对非负权图做松弛，可处理沼泽／道路等地形代价、单源多目标距离和塔防距离场。负权超出这里的 Dijkstra 契约；有权图直接用 BFS 会把“边数少”误认为“代价小”。

在此基础上读 [A* 算法与优化](../../知识/02-数学与游戏算法/路径搜索与导航/02-A星算法与优化.md)，明确 g 是已走代价、h 是估价、f=g+h；用 Dijkstra 作为小图正确性对照。按移动规则选择曼哈顿、对角或欧氏启发，证明是否高估，并检查一致性、关闭节点的重开规则、重复入堆后的过期项跳过与同优先级顺序。二叉堆、索引堆和 Flat Array 是开放列表候选，要同时比较维护成本与节点规模，不能从名称推断最快。

选型时依次问：地图表示是否满足假设，目标是否共享，拓扑是否变化，是否允许次优路径。

- 点对点、目标分散：先做可解释的 A* 基线。规则网格且移动／代价约束满足时再试 JPS／JPS+，验证跳点与强制邻居；不能直接搬到任意 NavMesh，也不承诺固定提速倍数
- 超大世界长距离：讨论 HPA* 的分块、出入口和跨层路径；把路径次优程度、预计算空间与动态边界维护成本写进验收
- 许多单位共享少数目标：读 [流场与群体寻路](../../知识/02-数学与游戏算法/路径搜索与导航/03-流场与群体寻路.md)，从目标反向构建距离标量场，再生成方向场与插值采样。距离场的构建成本由图、权值和队列决定；单位取样较便宜不代表整体系统没有拥塞或 CPU 瓶颈。目标分散、场失效、局部密度变化和不可达区域都需要更新策略
- 局部开门、落石或探索地图：读 [动态寻路 LPA* 与 D* Lite](../../知识/02-数学与游戏算法/路径搜索与导航/02-动态寻路LPA与DStarLite.md)，保存 g／rhs 不一致状态并重用搜索结果；实际改变范围小才有复用价值，大面积重建或目标频繁变化时比较重新 A*／分层搜索／流场的成本，设置回退
- 连续三维几何：读 [NavMesh 工程 Recast 与 Detour](../../知识/02-数学与游戏算法/路径搜索与导航/03-NavMesh工程Recast与Detour.md)，区分离线三角网格 → 体素／过滤 → 区域／轮廓 → 多边形邻接，与在线多边形通道 → 漏斗 → 运动执行。TileCache 更新、查询过滤和 Crowd 的职责各自验证，通道存在不能证明局部移动始终可行

练习交付三张相同起终点的测试图：等成本网格、有权绕行、不可达目标。再加入动态门和共享目标单位，记录总路径代价、扩展节点、重算范围、内存、失效／取消行为和耗时分布。验收先以小图最短路 oracle 检查正确性，再在开阔、迷宫、狭门及不同障碍密度下评价优化。[A* 实验](../../evidence/algorithms/astar/README.md)与 [A* 契约实验](../../evidence/algorithms/astar-contract/README.md)是复现入口；是否包含某种堆、缓存计数或已测平台，以实验文件为准，不由旧导航的概述代为证明。

## 空间索引、AOI 与压缩选型

先读 [空间分区与索引](../../知识/02-数学与游戏算法/空间查询与碰撞/04-空间分区与索引.md)，再读 [AOI 与视野计算](../../知识/02-数学与游戏算法/空间查询与碰撞/03-AOI与视野计算.md)。索引解决候选检索，AOI 还需要可见性、进入／离开／移动事件和广播合同；候选命中不是最终可见。选择前记录物体尺寸、空间密度、移动速度、瞬移率以及范围／射线／近邻查询比例。

- 均匀网格适合尺度相近、密度较均匀的动态实体；单元定位可常数时间，但查询还要扫描覆盖格与候选。格子太大导致候选多，太小增加跨格和多格覆盖开销；拥挤热点可退化，空旷大世界的密集格表可能浪费内存
- 空间哈希适合稀疏、广阔或不便预分配边界的网格；节省空格存储，代价是哈希、冲突和桶访问。期望查找时间依赖实现与负载，哈希碰撞不能当成空间相同
- 四叉树／八叉树适合非均匀空间与层次范围查询，可用于地形层级和视锥裁剪；深度、节点重叠、边界物体归属及动态跨区更新都会影响成本。平铺存储和指针存储是实现选择，不能把所有树都描述成相同布局
- BVH 按包围体组织候选，适合宽相碰撞与射线查询；比较 SAH 等构建启发式、构建质量、refit 与重建。剧烈运动／变形造成重叠增加时，refit 后仍可能查询退化；查询并非无条件 O(log N)
- KD-Tree 适合低维相对静态点集的最近邻检索；动态更新、维数升高和不平衡会削弱剪枝，不把它当成动态大物体的通用首选
- Sweep & Prune／十字链表利用轴序时间相干性，适合移动平缓的区间重叠与可变视野；瞬移、大量插入删除和高重叠可使维护变贵。排序数组或链表的成本不同，需要按实际实现测量

灯塔／Beacon 可用于明确区块或房间的广播汇聚，但覆盖边界和广播粒度可能牺牲精度。九宫格、灯塔和十字链表都应与视野锥、遮挡、战争迷雾的业务规则分层；玩家聚集时需要关注实际可见对数和带宽，即使候选查找很快也可能广播过载。

接着读 [位运算与性能优化技巧](../../知识/02-数学与游戏算法/数据结构与编码/05-位运算与性能优化技巧.md)和 [数据压缩与序列化](../../知识/02-数学与游戏算法/数据结构与编码/06-数据压缩与序列化.md)：用 Bitset 表达可见集合并计算差集；了解位掩码、布隆过滤器的假阳性、Morton 编码的空间局部性，再按测量决定 SoA／SIMD。同步编码按值域、分布、精度和包长选择 Varint／Zigzag、定点量化、位打包、差分和 Huffman／LZ4；小包压缩必须计入头部与 CPU 成本，解码必须拒绝截断、超长和越界值。

练习让同一实体轨迹依次经过均匀分布、热点聚集、稀疏大地图和集中瞬移，使用暴力查询核对可见集合及 Enter／Leave 事件。交付每种结构的更新／查询耗时、候选数、峰值内存、事件数与编码后带宽；测试重复事件、量化误差和解码失败。参考 [AOI 实验入口](../../evidence/algorithms/aoi/README.md)，再与 [寻路时间预算](../../知识/07-网络与游戏服务端/运行调度与过载保护/11-AI与寻路时间预算.md)及[网络与游戏服务端路线](网络与游戏服务端.md)接合；这里不承诺特定实体规模或吞吐。

## 几何、碰撞与运动学

按 [向量与矩阵](../../知识/02-数学与游戏算法/数学与数值计算/01-向量与矩阵基础.md) → [四元数与旋转](../../知识/02-数学与游戏算法/数学与数值计算/02-四元数与旋转.md) → [插值与曲线](../../知识/02-数学与游戏算法/数学与数值计算/03-插值与曲线.md)阅读。先用点积做夹角／投影、叉积做法线／左右判断，明确左／右手系、矩阵布局与局部 → 世界 → 观察 → 裁剪变换；然后实现单位四元数复合、共轭／逆与最短弧 Slerp，处理 q 与 −q 等价、归一化和接近共线的退化。四元数提供不依赖欧拉角参数化的旋转表示，但控制流程转回欧拉角时仍可能遇到相应表示问题。

练习用 Lerp／Ease、Bezier 与 Catmull-Rom 生成同一路径，比较是否经过控制点、连续性、过冲和按弧长运动的速度变化；网络插值／外推另有时间戳与纠偏合同。验收坐标往返、旋转复合和插值端点，保留零向量、平行方向与大坐标精度案例；LWC／原点重定位等引擎处理从数值误差需求出发选择。

再进入 [碰撞检测](../../知识/02-数学与游戏算法/空间查询与碰撞/04-碰撞检测.md)：宽相索引先缩小候选，窄相按形状选择 Sphere／AABB／Capsule、OBB 的 SAT，或凸体 GJK；相交后需要穿透方向和深度时再讨论 EPA。OBB 的 SAT 要覆盖面法线与边叉积候选轴并处理近零轴；GJK／EPA 要规定迭代上限、退化单形、接触容差和失败结果，不能把未收敛当作确定不相交。

最后读 [弹道与射击算法](../../知识/02-数学与游戏算法/空间查询与碰撞/06-弹道与射击算法.md)，在明确“恒重力、无阻力”等假设下解落点／仰角；目标匀速时求提前量并处理无解、近零系数和可行时间。散布先说明圆盘、立体角或高斯等分布合同；高速物体用 Raycast／Sphere Sweep／CCD 检查跨帧穿越，区分视觉轨迹和服务端命中裁定。练习产物是一组可见的轨迹与接触反例，覆盖薄墙、擦边、重叠初始状态、移动目标和大步长，验收以几何／解析对照而非“画面看起来正常”为准。

## 数值积分的比较练习

读 [数值积分与运动学模拟](../../知识/02-数学与游戏算法/数学与数值计算/05-数值积分与运动学模拟.md)时，把受力模型、时间步长、精度阶数和碰撞／约束处理分别列出，不按“某引擎默认使用”决定选择。

- 显式 Euler 使用旧速度更新位置、旧状态求加速度更新速度；适合作为最小对照。对无阻尼简谐振子，其离散能量会增长，但不能据此宣称它对所有微分方程都无条件不稳定
- 半隐式 Euler 先更新速度再更新位置，单步成本低；在合适 Hamiltonian 模型下保辛，其长期能量行为仍受步长和模型限制。简谐振子的常见稳定条件是步长乘角频率小于 2；这不等于每步精确守恒，也不覆盖任意阻尼、约束或碰撞实现
- Position Verlet 通过前后位置隐含速度，适合讨论绳索／布料的位置表示；冲量和变步长需要额外处理。PBD／XPBD 的约束投影与柔度求解不等同于积分器本身
- Velocity Verlet 保留显式速度，使用当前与下一位置的加速度，适合平滑保守力的二阶比较；缓存旧加速度后通常每步增加一次新受力评估，初始化和速度相关力另论。它可改善某些长期能量误差表现，不保证精确能量守恒或任意步长稳定
- RK4 对平滑导数问题提供四阶局部推进，每步通常四次导数评估；要比较同误差下的总成本。接触不连续时需事件定位／子步等额外机制，不能直接按光滑问题的阶数承诺碰撞精度

必须保留的练习是：在同一个无阻尼简谐振子、相同初值和总时长下，对显式 Euler 与半隐式 Euler 绘制位置、相位和能量曲线；扫多个步长，并记录超出稳定范围的失败。随后加入 Position Verlet、Velocity Verlet 和 RK4，比较误差、能量漂移／振荡、每步受力次数和总耗时。另做绳索约束与高速碰撞案例，以显示积分与接触求解的不同问题。产物包括参数文件、曲线、原始数据和解释；这些是待完成练习，不是本页已取得的实验结果。

## 局部运动、群聚与避障

全局规划决定去哪条通道，局部方法决定当前怎么走，执行器还必须遵守速度／加速度与碰撞约束。读 [路径平滑与转向行为](../../知识/02-数学与游戏算法/路径搜索与导航/04-路径平滑与转向行为.md)，把 Funnel／String Pulling、Seek／Arrive／Pursue／Wander 与 [RVO 与数值鲁棒](../../知识/02-数学与游戏算法/路径搜索与导航/04-RVO与数值鲁棒.md)接成流水线，并用 [流场](../../知识/02-数学与游戏算法/路径搜索与导航/03-流场与群体寻路.md)区分完整可达距离场与只取局部引斥力的势场。

Steering 易做局部反应和运动表现，优先级／力混合可能在狭窄处震荡；Boids 的分离、对齐、凝聚适合鸟群鱼群，但需要近邻查询，也不自动满足静态障碍、队形槽位或战术走位。人工势场 APF 通过目标引力与障碍斥力给方向，U 型障碍、对称布局和局部极小值可能使其停滞。RVO／ORCA 通过相对速度障碍及半平面约束选择速度，需要考察互惠假设、感知半径、时间窗、可行速度和数值容差；不能保证任意场景无碰撞、无震荡或无死锁，也不能代替全局寻路走出死胡同。

练习固定同一组单位与目标，分别运行 Steering、Boids、APF 和 ORCA；场景至少有 U 型障碍、对向狭门、十字交汇、静止障碍和初始重叠。交付到达率、停滞时长、最小间距、碰撞／约束违反数与尾延迟；为不可行或长时间无进展定义等待、退让、重规划和降级结果。接入 [UE NavMesh 寻路](../../知识/06-游戏AI/导航移动与群体协同/03-NavMesh寻路.md)或 [Mass 群集](../../知识/06-游戏AI/导航移动与群体协同/04-Mass实体框架与群集模拟.md)后，重新验证引擎的半径、坐标与执行约束。

## 随机采样与程序化生成

先读 [随机数与洗牌算法](../../知识/02-数学与游戏算法/随机采样与程序化生成/01-随机数与洗牌算法.md)，从种子、流和 PRNG 状态理解重现；Fisher–Yates 的无偏性依赖正确的区间均匀抽样，不能用随意取模替代。权重较少或查询不密集时先比较前缀和＋二分；权重相对静态且查询密集时评估 Alias 的预处理与 O(1) 查询；频繁改权时评估 Fenwick／线段树的更新与查询成本。保底或 PRD 是有状态分布，应检查长期频率、连续失败长度和状态迁移，不等同于独立同分布抽样。游戏逻辑 PRNG 的可复现性也不是密码学不可预测性。

接着读 [概率分布与采样工程](../../知识/02-数学与游戏算法/随机采样与程序化生成/07-概率分布与采样工程.md)，先写 Bernoulli／Poisson／Normal 的参数、支持集与单位，再选择 Reservoir 流式抽样、Poisson-disk 最小间距采样、蒙特卡洛或重要性采样。泊松圆盘强调空间间距，不能将点间排斥误称为独立均匀抽样；估计量偏差、方差与置信区间要按采样假设说明。

之后读 [程序化生成](../../知识/02-数学与游戏算法/随机采样与程序化生成/02-程序化生成.md)，连接 Perlin／Simplex 噪声、Voronoi 群系、回溯／Prim／Kruskal 迷宫和 WFC 约束传播。必须产出一张多倍频／多 octave 叠加高度图，保存种子、频率、振幅与归一化参数；再产出一组 WFC 瓦片关卡，保存邻接规则、边界规则、矛盾检测与回溯／重启策略。WFC 得到局部相容瓦片不自动保证全局道路连通或玩法可达，需另验。

验收包含固定种子的重现、洗牌小规模频率检查、权重／零权／非法权输入、流式样本规模、点间最小距离和生成地图连通性；统计结果用样本量与误差界说明，不能凭一次直方图宣布随机数公平。引擎落地可接 [PCG 程序化内容生成](../../知识/03-引擎架构与资源系统/程序化内容生成/04-PCG程序化内容生成.md)，保持算法参数与引擎图执行结果分别记录。

## 确定性与可复现实验

读 [确定性与基准工程总览](../../知识/02-数学与游戏算法/确定性与基准/01-确定性与基准工程总览.md)，把全局拓扑、局部运动和在线回放分层，再读 [联机确定性与基准工程](../../知识/02-数学与游戏算法/确定性与基准/05-联机确定性与基准工程.md)。固定步长、定点数或关闭 fast-math 都只是设计条件的一部分；还须统一舍入／溢出／三角函数策略、遍历和任务提交顺序、同优先级裁决、PRNG 流、输入时间与序列化格式。浮点方案也要在明确平台和工具链范围内验证，不能由数值类型单独宣布跨平台一致。

状态哈希应针对规范化、确定顺序的逻辑字段，排除填充字节、指针和无关表现数据；差异时先找首个不一致帧，再细分字段和输入。练习录制一次带动态障碍、随机事件和取消请求的输入序列，在声明支持的构建／平台上回放，交付逐帧哈希、首差报告与最小复现。[AI 评测回放](../../知识/06-游戏AI/评测安全与运行预算/01-AI评测回放.md)承接决策层，[AI 与寻路时间预算](../../知识/07-网络与游戏服务端/运行调度与过载保护/11-AI与寻路时间预算.md)承接任务过载与迟到结果，不能把算法成功率代替服务端截止时间达标。

性能报告固定输入集合、版本、机器、编译参数、预热、采样与重复次数；同时观察 P50／P95／P99、峰值内存、正确性与失败率。A*、AOI 等已有实验入口提供复现材料，本页没有运行基准或验证其历史性能数字。需要 CI 门禁时转到[工程实践与质量路线](工程实践与质量.md)，为允许误差和退化阈值说明依据。

## 五条工程角色路径

### Gameplay 与战斗表现

向量／矩阵 → 四元数 → 插值／曲线 → 碰撞 → 弹道与提前量 → 平滑与转向。前置是坐标系与数值误差；交付一个可回放的技能位移／镜头轨迹／射击小场景。验收端点、旋转短弧、命中边界和高速穿越，再将玩法裁定交给 [Gameplay 与交互系统](../../知识/05-Gameplay与交互系统/README.md)，将具体物理解算交给 [Chaos 物理概览](../../知识/04-图形动画与物理仿真/物理求解与动力学/01-Chaos物理引擎概览.md)。

### 大规模 MMO 与 RTS 服务端算法

图论／Dijkstra → 共享目标流场 → 空间索引 → AOI 事件 → 位集合与序列化。前置是有界任务与缓存局部性；交付同一批实体的热点、稀疏与瞬移轨迹对照，验证候选查询、进入／离开事件和带宽，报告更新时间与尾延迟。应用阶段沿[网络与游戏服务端路线](网络与游戏服务端.md)加入广播预算与退让，不预设“万人同屏”的承载保证。

### 物理、载具与运动学

向量与数值前置 → 积分器对照 → SAT／GJK／EPA → CCD → 局部避障的数值鲁棒性，再接 [Chaos 物理](../../知识/04-图形动画与物理仿真/物理求解与动力学/01-Chaos物理引擎概览.md)和 [Chaos 车辆](../../知识/04-图形动画与物理仿真/物理求解与动力学/06-Chaos车辆系统.md)。交付同一振子的能量对比和一个悬挂／弹道案例，检验步长敏感性、接触退化与超速穿透；局部避障与刚体接触求解分别验收。

### 联机帧同步与确定性引擎

三层架构与事实边界 → 数值／PRNG／顺序合同 → 动态 LPA*／D* Lite → NavMesh 与通道 → 状态哈希与输入回放。先有可测基线，再把局部避障和并发调度纳入同一回放；交付跨声明平台的首差定位工具和性能报告。A* 增量复用、固定步长或定点数任何一个单项通过都不能替代系统确定性验收。

### PCG 与抽卡数值算法

PRNG 与洗牌 → 加权抽样／保底状态 → 分布与 Reservoir／Poisson-disk → 噪声／Voronoi／迷宫／WFC → 引擎 PCG。交付可复现高度图、WFC 瓦片关卡、参数与规则文件，以及抽样统计与地图连通性检查。验收同时覆盖种子重现、分布目标、最小间距和规则矛盾处理，保留失败样本作为下一轮参数修改的依据。

## 阅读与完成标准

每条角色路线都应能回答四件事：为什么前置知识必要，为什么当前输入适合该方法，什么条件会使它失效，怎样用独立对照验收。这里的练习和测量均是待执行要求；正文成熟度、历史实验记录与这份路线的验证状态相互独立。
