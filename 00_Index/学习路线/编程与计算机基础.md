# 编程与计算机基础学习路线

> 知识成熟度：L0（学习路线，不代表链接正文已全部实测；本页练习待执行）。

## 起点与学习边界

这条路线用于从 C++ 代码的局部行为推到系统机制，再回到帧时间、任务停止、网络背压等工程问题。先能编译一个小型 C++ 程序、读懂指针与引用、使用调试器观察调用栈；缺少这些条件时，先用最小程序完成构造、移动和析构观察，再进入并发与性能分析。

阅读顺序由依赖决定，不由文件编号决定：所有权与值语义是对象模型、泛型和并发的共同前置；操作系统解释执行与 I/O 边界；体系结构解释访存与计算成本；ABI 将源代码的承诺落实到模块边界。每一阶段先提出可被推翻的机制假设，再设计对照实验，最后把结论限定在实际输入、工具链和平台内。

正文的分类和完整内容从[编程与计算机基础知识入口](../../知识/01-编程与计算机基础/README.md)进入。数据结构与数学的详细选型由[数学与游戏算法路线](数学与游戏算法.md)承接；网络协议、数据库与分布式一致性由[网络与游戏服务端路线](网络与游戏服务端.md)承接；调试、构建、测试、安全和容器运维由[工程实践与质量路线](工程实践与质量.md)承接。本页保留连接这些方向所需的前置和角色链，不复制相邻领域正文。

## 所有权、值语义与异步停止

先读 [对象生命周期与 RAII](../../知识/01-编程与计算机基础/C%2B%2B语言与对象模型/01-C%2B%2B对象生命周期与RAII.md)，建立自动、静态、线程、动态存储期和构造／逆序析构模型，区分资源释放与业务提交。用文件句柄、锁和连接资源各实现一个最小守卫；在成功、提前返回和异常路径上计数释放次数。验收要求是每项资源释放责任唯一、失败路径仍维持约定不变量，并能分别说明基本、强和不抛异常保证的适用范围。

随后读 [Copy、Move 与值语义](../../知识/01-编程与计算机基础/C%2B%2B语言与对象模型/02-Copy-Move与值语义.md)，沿 Rule of Zero/Five、复制／移动构造、RVO/NRVO 和 moved-from 状态顺序理解容器行为。对同一对象分别测试复制、显式移动和容器扩容，记录构造计数、分配次数与容量变化；参考 [移动语义实验入口](../../evidence/labs/cpp-move/README.md)。std::move 表达可移动的值类别，是否执行移动取决于候选操作；移动后可用状态按类型契约判断。std::vector 的重分配策略受移动异常保证等条件影响；UE 的 TArray 重定位还须核对元素 trait 和引擎版本，不能把标准容器规则直接当作 UE 实现证明。

异步工作要再分清三个寿命：任务拥有者、共享数据和业务会话。共享指针可以延长对象存活，不能自动同步对象字段，也不能保证迟到结果仍属于当前会话。把 RAII 与 [线程同步与锁](../../知识/01-编程与计算机基础/并发与同步/02-线程同步与锁.md)、[AI 与寻路时间预算](../../知识/07-网络与游戏服务端/运行调度与过载保护/11-AI与寻路时间预算.md)连读：先发停止请求，再等待完成屏障／join，最后释放依赖资源；结果提交前检查会话或请求代次。练习在任务排队、执行和提交三个时点取消任务，验收要求是无释放后访问、无持锁等待环、旧结果不覆盖新会话。示例断言或 Sanitizer 通过不等于真实线程池、数据库和 UE 生命周期已经验证。

## 对象布局、容器与泛型选择

读 [对象布局、虚函数与内存分配](../../知识/01-编程与计算机基础/C%2B%2B语言与对象模型/01-对象布局、虚函数与内存分配.md)，再读 [STL 容器与 Allocator](../../知识/01-编程与计算机基础/C%2B%2B语言与对象模型/02-STL容器与Allocator.md)。用编译器布局输出观察字段填充、alignof、单／多／虚继承与 this 调整；把对象大小、虚派发、分配次数和缓存访问分开记录。布局是具体 ABI 下的观察，不能仅凭语言语法推定每个编译器都相同。

容器选择先写需求：遍历比例、查找规模、增删位置、迭代器稳定性、内存峰值和所有权。把 vector、deque、list 置于同一负载，参照 [数据结构复杂度与容器选型](../../知识/02-数学与游戏算法/数据结构与编码/01-数据结构复杂度与容器选型.md)解释比较次数与随机访存成本的区别。连续存储有利于局部性，但不保证每次命中缓存；节点结构在稳定引用或特定增删模式下仍可能合适。哈希表必须按实际实现区分拉链、开放寻址和其他布局，不能预设 TMap 就是平铺开放寻址表。

从默认分配器到 Pool／Slab／Arena 的练习，应比较申请来源、对齐、复用、释放时机和峰值。帧分配器只有在预留容量、对齐和回收策略满足负载时，才可能减少热路径系统堆分配；扩容、内部对象分配与并发同步仍须计数。替换 jemalloc／mimalloc、使用 FMallocBinned 或拆为 Mass／ECS 连续组件，都应先有瓶颈证据，不能把“零分配”“无碎片”当作容器名称的性质。

之后读 [Concepts、Ranges 与泛型设计](../../知识/01-编程与计算机基础/C%2B%2B语言与对象模型/01-Concepts、Ranges与泛型设计.md)，把一个模板接口改为 requires 约束，并保留错误输入的编译诊断；给惰性 view 加入源对象失效测试，明确借用与所有权。再读 [异常、类型系统与标准库实现](../../知识/01-编程与计算机基础/C%2B%2B语言与对象模型/02-异常、类型系统与标准库实现.md)，对比异常、错误码、optional、expected、variant 表达缺失、失败及多种结果的能力；结合 Itanium 异常表与 SEH 的实现背景理解正常路径、展开路径及二进制代价。组件能力与序列化接口可做编译期契约练习，UE 的 TEnableIf 等实现应按所用版本对照。optional／expected 本身不保证整个路径无锁、无分配、noexcept 或全部驻留栈上；承载类型、回调和库实现都参与决定。验收时逐条检查错误是否丢失、view 是否悬垂、异常策略是否符合实际构建配置，再用分配计数和生成代码检验性能假设。

## 从锁到任务调度与进程通信

按 [线程同步与锁](../../知识/01-编程与计算机基础/并发与同步/02-线程同步与锁.md) → [Atomic 与 C++ 内存模型](../../知识/01-编程与计算机基础/并发与同步/02-Atomic与C%2B%2B内存模型.md) → [LockFree 与 False Sharing](../../知识/01-编程与计算机基础/并发与同步/03-LockFree与FalseSharing.md) → [线程池、任务调度与协程调度](../../知识/01-编程与计算机基础/并发与同步/04-线程池、任务调度与协程调度.md) → [进程间通信与跨进程同步](../../知识/01-编程与计算机基础/并发与同步/05-进程间通信与跨进程同步.md)推进。前两步先证明正确性，后面才比较吞吐与调度方式。

- 锁阶段：写出共享状态的不变量、锁持有范围和全局锁序；条件变量等待使用谓词处理虚假唤醒。用全线程栈与等待图解释死锁，不能因使用 lock_guard 就认为不会死锁
- 内存序阶段：画出一次消息发布的 happens-before 链，说明 release/acquire 通过哪个原子对象建立同步；独立统计计数可讨论 relaxed，数据发布不能只因更快就换成 relaxed
- 无锁阶段：先区分数据竞争、ABA、对象回收和进展保证，再比较 SPSC／MPSC 适用的生产消费关系。无锁不自动意味着延迟更低；CAS 重试、热点原子和回收方案都可能主导成本
- 缓存阶段：比较相邻与隔离计数器，用 [原子内存序实验](../../evidence/labs/atomic-memory-order/README.md)与 [False Sharing 实验](../../evidence/labs/false-sharing/README.md)作为复现入口。记录硬件缓存行、线程放置、重复次数和分布；alignas(64) 是待核对的具体设置，不能代替平台事实
- 调度阶段：实现有界任务队列、停止协议、依赖 DAG 和任务预算，再讨论工作窃取及协程挂起。协程不消除任务所有权、线程亲和性和阻塞调用的成本；与 UE TaskGraph／Tasks 对照时要回到对应实现
- 跨进程阶段：按消息大小、复制成本、故障隔离和恢复要求，在管道、Unix Domain Socket 与共享内存中选型。共享内存还需明确跨进程同步、对象格式与对端崩溃后的恢复，不因共享地址可见就认为协议完整

综合练习把网络 I/O、逻辑分片和异步存盘之间的消息流做成小型模型。验收至少覆盖队列满、生产者退出、取消、重复完成和消费者崩溃；交付队列容量与等待边界说明，再报告吞吐和尾延迟。[Tick 调度实验](../../evidence/server/tick-scheduler/README.md)可承接时间轮精度与负载实验，不能由它推断生产世界服容量。

## 操作系统、内存与系统 I/O

先读 [进程线程、虚拟内存与系统调用](../../知识/01-编程与计算机基础/操作系统与系统I-O/01-进程线程虚拟内存与系统调用.md)，弄清线程调度、抢占、用户态／内核态边界与亲和性，再读 [虚拟内存、PageFault 与 mmap](../../知识/01-编程与计算机基础/操作系统与系统I-O/02-虚拟内存、PageFault与mmap.md)。练习分别观察保留地址、首次触摸和重复触摸的时间与缺页计数，区分 minor／major fault、TLB 与工作集；预触摸、预读、大页和绑核是有成本的候选措施，不能保证消除运行期缺页或调度抖动。

继续读 [文件系统与存储栈](../../知识/01-编程与计算机基础/操作系统与系统I-O/03-文件系统与存储栈.md)，追踪写入用户缓冲、Page Cache、脏页回写和持久化介质的链路。比较批量缓冲写、fsync／fdatasync 与直接 I/O，写清吞吐、尾延迟和故障后允许丢失的数据边界。mmap 不是任何 I/O 的自动零拷贝保证；UE Pak／IoStore 的具体路径需回到平台与引擎版本核对。

再读 [权限、安全与隔离](../../知识/01-编程与计算机基础/操作系统与系统I-O/04-权限安全与隔离.md)，把 DAC／MAC、Capabilities、Namespaces、cgroups、seccomp 分别对应到访问权限、资源视图、资源限额和系统调用边界。练习的产物是 DS 进程的资源与故障边界图；内存配额、CPU throttling 和 OOM 后果在[工程实践与质量路线](工程实践与质量.md)中继续验证。

具备系统调用与网络协议基础后，进入 [Socket、Epoll 与 Reactor](../../知识/01-编程与计算机基础/操作系统与系统I-O/01-Socket-Epoll与Reactor.md)。先用非阻塞 LT 模型建立可观察的读写状态机，再做 ET：正确处理 EAGAIN、EINTR、partial write、半关闭、连接清理和 EPOLLOUT 注册；慢消费者时同时约束应用队列与写缓冲。连接就绪是可尝试读写的通知，不代表完整消息已经到达。用 [Epoll Reactor 契约实验](../../evidence/labs/epoll-reactor/README.md)检查边界，另测容量；测试项数量不能代替生产容量报告。

最后读 [io_uring 与异步 I/O](../../知识/01-编程与计算机基础/操作系统与系统I-O/03-io_uring与异步I-O.md)，比较 SQ／CQ、批处理、完成通知和可能的轮询模式。保持相同消息、存储工作集和正确性合同，再评估 epoll 与 io_uring 的 CPU、队列深度及 P95／P99；内核支持、缓冲寿命和完成错误路径属于前置条件。插桩与 perf 的方法转到[工程实践与质量路线](工程实践与质量.md)，网络拥塞和协议选择转到[网络与游戏服务端路线](网络与游戏服务端.md)。

## 体系结构、编译器与 ABI

按 [处理器存储层次与性能工程](../../知识/01-编程与计算机基础/硬件体系结构与性能/01-处理器存储层次与性能工程.md) → [ISA、汇编与调用约定](../../知识/01-编程与计算机基础/编译链接与ABI/03-ISA汇编与调用约定.md) → [编译器优化与 GPU 异构](../../知识/01-编程与计算机基础/硬件体系结构与性能/04-编译器优化与GPU异构.md) → [虚拟化与硬件辅助隔离](../../知识/01-编程与计算机基础/硬件体系结构与性能/05-虚拟化与硬件辅助隔离.md)阅读。先解释缓存层级、预取、MESI 与 NUMA，再用反汇编定位参数传递、寄存器、栈帧与内联，之后讨论 AVX／NEON、自动向量化和 GPU SIMT 分歧，最后才把虚拟机 VM-exit、扩展页表和 IOMMU 加到模型中。缓存延迟、SIMD 宽度与 NUMA 代价都依赖硬件和负载，旧表中的固定数值只适合作为测量问题，不能沿用为本机结论。

练习以同一实体更新为基线比较 AoS／SoA、连续／指针访问和标量／向量实现；先核对结果与溢出、对齐、别名约束，再观察编译器向量化报告、缓存缺失和带宽。GPU 版本另计传输与调度成本。验收应能解释瓶颈在访存、分支、同步还是计算；“更紧凑”或“有 SIMD”本身不是通过条件。

再读 [编译链接与 ABI 全流程](../../知识/01-编程与计算机基础/编译链接与ABI/01-编译链接与ABI全流程.md)，从预处理、编译、汇编、静态链接到动态加载追踪同一符号。做三个小故障：声明与定义不匹配的未定义符号、跨编译单元宏不一致的 ODR 问题、动态库导出或对象布局变更的 ABI 问题。结合 ELF／PE、符号修饰、GOT／PLT／PIC 和调用约定解释差异；UE 中对照 Build.cs 依赖与 MODULE_API。热重载和 Live Coding 的能力按具体引擎版本检查，不能假定任意布局变更都安全。

模块边界采用 C ABI 或版本化接口可以缩小兼容面，但仍须约定结构布局、分配／释放方、异常、编译器与运行库；抽象虚基类不自动跨编译器稳定。验收提交最小复现、符号或布局证据、修复前后调用结果，并把依赖图与增量构建的后续问题交给[工程实践与质量路线](工程实践与质量.md)。

## 四条工程角色路径

### C++ 与游戏引擎客户端底层

所有权／值语义 → 对象布局与分配器 → 存储层次与 SIMD → 编译链接与 ABI → 调试与性能闭环。前面的共同主线完成后，接 [UObject 与反射](../../知识/03-引擎架构与资源系统/对象模型与生命周期/01-UObject与反射系统.md)、[UObject 与 GC 源码](../../知识/03-引擎架构与资源系统/对象模型与生命周期/02-UObject与垃圾回收源码.md)，分别核对 GC 与原生 RAII 的寿命边界、TArray 元素重定位和 FMallocBinned 分配策略，再观察 TaskGraph 的任务依赖。产物是一个对象创建、扩容、异步使用和销毁的最小案例，能用布局／分配／调用栈证据解释一次卡顿或错误；具体引擎运行仍由对应平台验证。

### 高性能游戏服务端

锁／Atomic／队列 → 进程、虚拟内存与系统调用 → Reactor／io_uring → TCP／QUIC／拓扑 → 事务、共识、缓存与消息。先按本页完成所有权和停止协议，再沿[网络与游戏服务端路线](网络与游戏服务端.md)完成协议、持久化和世界服业务链。综合产物是有界网关队列、Tick 调度和异步存盘模型；验收队列增长受控、慢消费者有退让、停止能完成，并报告负载及尾延迟，吞吐上限由真实压测确定。

### 游戏算法与 AI 核心

离散数学／线性代数／概率 → 数据结构与复杂度 → CPU Cache 与分支成本，再到[数学与游戏算法路线](数学与游戏算法.md)的 A*、空间索引、数值积分与确定性。将同一批实体更新放入 [Mass 实体框架](../../知识/06-游戏AI/导航移动与群体协同/04-Mass实体框架与群集模拟.md)对照时，区分通用数据布局收益和引擎调度开销。产物至少包括正确性 oracle、地图或实体分布、节点扩展／候选对数、时间分布；用规模变化判断算法与布局谁在主导。

### 可靠性、安全与 DevOps

模块化、版本与构建 → 测试／静态分析／Fuzz → 威胁建模、认证授权 → 容器隔离、可观测性、SLO 与演练。到[工程实践与质量路线](工程实践与质量.md)逐项实践；在基础侧补足权限隔离、文件持久化和跨进程故障机制。产物是一个可复现故障包与回归门禁，另有服务资源、对局退出和恢复验收记录；工具已接入或配置存在不能代替故障演练结果。

## 练习证据与完成标准
