# Gameplay 与交互系统学习路线

> 本页提供角色路径、选择问题和练习建议，不复制 Canonical 正文；知识成熟度：L0，UE 与多人练习均待执行。

## 角色路线与共同前置

保留原角色 A（客户端与 Gameplay 开发）：[引擎架构与资源系统](引擎架构与资源系统.md)的 UObject、Actor、Gameplay 框架与 Subsystem → 输入、标签、能力和移动 → 动画与 UI → [UE 源码阅读](UE源码阅读.md#lyra-按装配到业务闭环阅读)中的 Experience、Pawn 初始化、技能武器与界面。先能解释谁拥有状态、谁能够发起操作、谁负责最终裁决，再选择一条业务链练习。

基础阅读是 [对象生命周期与 RAII](../../%E7%9F%A5%E8%AF%86/01-%E7%BC%96%E7%A8%8B%E4%B8%8E%E8%AE%A1%E7%AE%97%E6%9C%BA%E5%9F%BA%E7%A1%80/C%2B%2B%E8%AF%AD%E8%A8%80%E4%B8%8E%E5%AF%B9%E8%B1%A1%E6%A8%A1%E5%9E%8B/01-C%2B%2B%E5%AF%B9%E8%B1%A1%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E4%B8%8ERAII.md)、[UObject](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E5%AF%B9%E8%B1%A1%E6%A8%A1%E5%9E%8B%E4%B8%8E%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F/01-UObject%E4%B8%8E%E5%8F%8D%E5%B0%84%E7%B3%BB%E7%BB%9F.md)、[Actor/Component](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E5%AF%B9%E8%B1%A1%E6%A8%A1%E5%9E%8B%E4%B8%8E%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F/02-Actor%E4%B8%8EComponent%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F.md)、[Gameplay 框架](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E6%A8%A1%E5%9D%97%E5%8C%96%E6%A1%86%E6%9E%B6%E4%B8%8E%E5%AF%B9%E8%B1%A1%E9%80%9A%E4%BF%A1/03-Gameplay%E6%A1%86%E6%9E%B6%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%A8%A1%E5%BC%8F.md) 与 [委托事件](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E6%A8%A1%E5%9D%97%E5%8C%96%E6%A1%86%E6%9E%B6%E4%B8%8E%E5%AF%B9%E8%B1%A1%E9%80%9A%E4%BF%A1/04-%E5%A7%94%E6%89%98%E4%BA%8B%E4%BB%B6%E4%B8%8E%E5%AF%B9%E8%B1%A1%E9%80%9A%E4%BF%A1.md)。对象仍然活着不代表某次异步操作仍有提交资格；在跨世界、换 Pawn 和退出 UI 时尤其要说明解绑和结果失效条件。

## 输入、移动、设备与相机

按 [Enhanced Input](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E7%A7%BB%E5%8A%A8%E4%B8%8E%E4%BA%A4%E4%BA%92/02-EnhancedInput%E5%A2%9E%E5%BC%BA%E8%BE%93%E5%85%A5.md) → [CharacterMovement](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E7%A7%BB%E5%8A%A8%E4%B8%8E%E4%BA%A4%E4%BA%92/06-%E8%A7%92%E8%89%B2%E7%A7%BB%E5%8A%A8%E7%B3%BB%E7%BB%9FUCharacterMovement.md) 阅读。先为 InputAction、MappingContext、Modifiers、Triggers 标注配置与执行责任，再连接输入采样、移动模式和状态输出。设备分支接 [设备抽象](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E7%A7%BB%E5%8A%A8%E4%B8%8E%E4%BA%A4%E4%BA%92/10-%E8%BE%93%E5%85%A5%E8%AE%BE%E5%A4%87%E6%8A%BD%E8%B1%A1%E4%B8%8E%E6%89%8B%E6%9F%84%E8%A7%A6%E6%8E%A7.md)；相机与投射物分支接 [相机与视口](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E7%A7%BB%E5%8A%A8%E4%B8%8E%E4%BA%A4%E4%BA%92/07-%E7%9B%B8%E6%9C%BA%E7%B3%BB%E7%BB%9F%E4%B8%8E%E8%A7%86%E5%8F%A3.md)、[辅助移动组件](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E7%A7%BB%E5%8A%A8%E4%B8%8E%E4%BA%A4%E4%BA%92/11-%E5%B8%B8%E7%94%A8%E7%A7%BB%E5%8A%A8%E4%B8%8E%E8%BE%85%E5%8A%A9%E7%BB%84%E4%BB%B6.md)。

选择标准：需要角色地面/空中模式及已有网络移动语义时，先确认 CMC 能否满足；只需投射物或预设路径运动时，先核对辅助组件职责。镜头运动和角色权威位移分别验收。网络重放与修正的前置是 [预测与延迟补偿](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E5%90%8C%E6%AD%A5%E9%A2%84%E6%B5%8B%E4%B8%8E%E5%9B%9E%E6%94%BE/03-%E5%AE%A2%E6%88%B7%E7%AB%AF%E9%A2%84%E6%B5%8B%E4%B8%8E%E5%BB%B6%E8%BF%9F%E8%A1%A5%E5%81%BF.md) 中的时间域与输入确认合同，不能靠增大误差阈值掩盖模拟差异。

练习：同一角色在键鼠、手柄和触控输入之间切换，再依次打开菜单、失去焦点、换 Pawn、恢复游玩。验收日志需要能还原输入由谁消费、MappingContext 何时改变、焦点回到哪里、移动是否仍被错误触发；同时记录相机切换、设备热插拔和取消动作。设备响应时间和弱网手感均需实际测量，不能继承“毫秒级无缝”描述。

## 能力、任务与动作战斗

先读 [GameplayTag 与数据资产](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%8E%A9%E6%B3%95%E6%9E%B6%E6%9E%84%E4%B8%8E%E4%BB%BB%E5%8A%A1%E5%8D%8F%E4%BD%9C/03-GameplayTag%E4%B8%8E%E6%95%B0%E6%8D%AE%E8%B5%84%E4%BA%A7.md)，为标签层级、资产身份和加载条件建词汇；然后读 [GAS](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/01-GameplayAbilitySystem%E8%83%BD%E5%8A%9B%E7%B3%BB%E7%BB%9F.md)，区分能力启动、效果、属性和表现；再读 [GameplayTasks](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%8E%A9%E6%B3%95%E6%9E%B6%E6%9E%84%E4%B8%8E%E4%BB%BB%E5%8A%A1%E5%8D%8F%E4%BD%9C/09-GameplayTask%E4%BB%BB%E5%8A%A1%E6%A1%86%E6%9E%B6.md)，检查取消、确认、超时与重入。该顺序保留了原依赖图中“标识/资产先于能力”的信息，也让后续 [ModularGameplay](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%8E%A9%E6%B3%95%E6%9E%B6%E6%9E%84%E4%B8%8E%E4%BB%BB%E5%8A%A1%E5%8D%8F%E4%BD%9C/08-ModularGameplay%E6%A8%A1%E5%9D%97%E5%8C%96%E7%8E%A9%E6%B3%95.md) 的组件装配有清晰状态边界。[蓝图与 C++ 协作](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%8E%A9%E6%B3%95%E6%9E%B6%E6%9E%84%E4%B8%8E%E4%BB%BB%E5%8A%A1%E5%8D%8F%E4%BD%9C/05-%E8%93%9D%E5%9B%BE%E4%B8%8EC%2B%2B%E5%8D%8F%E4%BD%9C.md) 用于决定可配置行为与稳定接口，热点是否下沉要由测量决定。

动作表现沿 [骨骼基础](../../%E7%9F%A5%E8%AF%86/04-%E5%9B%BE%E5%BD%A2%E5%8A%A8%E7%94%BB%E4%B8%8E%E7%89%A9%E7%90%86%E4%BB%BF%E7%9C%9F/%E5%8A%A8%E7%94%BB%E6%B1%82%E5%80%BC%E4%B8%8E%E8%A7%92%E8%89%B2%E8%A1%A8%E7%8E%B0/07-%E5%8A%A8%E7%94%BB%E8%B5%84%E4%BA%A7%E4%B8%8E%E9%AA%A8%E9%AA%BC%E5%9F%BA%E7%A1%80.md) → [状态机](../../%E7%9F%A5%E8%AF%86/04-%E5%9B%BE%E5%BD%A2%E5%8A%A8%E7%94%BB%E4%B8%8E%E7%89%A9%E7%90%86%E4%BB%BF%E7%9C%9F/%E5%8A%A8%E7%94%BB%E6%B1%82%E5%80%BC%E4%B8%8E%E8%A7%92%E8%89%B2%E8%A1%A8%E7%8E%B0/01-%E5%8A%A8%E7%94%BB%E8%93%9D%E5%9B%BE%E4%B8%8E%E7%8A%B6%E6%80%81%E6%9C%BA.md) → [蒙太奇](../../%E7%9F%A5%E8%AF%86/04-%E5%9B%BE%E5%BD%A2%E5%8A%A8%E7%94%BB%E4%B8%8E%E7%89%A9%E7%90%86%E4%BB%BF%E7%9C%9F/%E5%8A%A8%E7%94%BB%E6%B1%82%E5%80%BC%E4%B8%8E%E8%A7%92%E8%89%B2%E8%A1%A8%E7%8E%B0/02-%E5%8A%A8%E7%94%BB%E8%92%99%E5%A4%AA%E5%A5%87%E4%B8%8E%E6%B7%B7%E5%90%88%E7%A9%BA%E9%97%B4.md) → [动作战斗](../../%E7%9F%A5%E8%AF%86/04-%E5%9B%BE%E5%BD%A2%E5%8A%A8%E7%94%BB%E4%B8%8E%E7%89%A9%E7%90%86%E4%BB%BF%E7%9C%9F/%E5%8A%A8%E7%94%BB%E6%B1%82%E5%80%BC%E4%B8%8E%E8%A7%92%E8%89%B2%E8%A1%A8%E7%8E%B0/08-%E5%8A%A8%E4%BD%9C%E6%88%98%E6%96%97%E7%B3%BB%E7%BB%9F%E4%B8%8E%E6%89%93%E5%87%BB%E6%89%8B%E6%84%9F.md) 衔接。输入缓冲、取消窗口、Montage 通知、碰撞采样、受击反馈和 Root Motion 必须共享明确的事件与时间合同；视听表现触发不等于伤害已被权威确认。

练习：做一条“输入→技能申请→费用检查→前摇→命中请求→结算→反馈”的最小状态图，加入中途取消、死亡、重复请求、迟到结果和资源加载失败。验收要求每个终态都能清理任务与回调，费用与技能结果能够对账，取消后到达的结果不会再次结算。规则与数值深入 [技能与战斗框架](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/08-%E6%8A%80%E8%83%BD%E4%B8%8E%E6%88%98%E6%96%97%E6%A1%86%E6%9E%B6.md)、[技能释放完整链路](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/03-%E6%8A%80%E8%83%BD%E9%87%8A%E6%94%BE%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)；数值主责仍在 [伤害与属性结算](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/11-%E4%BC%A4%E5%AE%B3%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)，不把 GAS 配置等同服务端事务保证。

## 背包、装备与存档

标签和资产身份准备好后，按 [SaveGame 与序列化](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%83%8C%E5%8C%85%E8%A3%85%E5%A4%87%E4%B8%8E%E5%AD%98%E6%A1%A3/12-SaveGame%E5%AD%98%E6%A1%A3%E7%B3%BB%E7%BB%9F%E4%B8%8E%E5%BA%8F%E5%88%97%E5%8C%96.md) → [背包与装备](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%83%8C%E5%8C%85%E8%A3%85%E5%A4%87%E4%B8%8E%E5%AD%98%E6%A1%A3/13-%E8%83%8C%E5%8C%85%E4%B8%8E%E8%A3%85%E5%A4%87%E7%B3%BB%E7%BB%9F.md) 阅读。需要先分别回答：什么会被序列化、哪个时间点的版本被持久化、哪些状态只能由服务器裁决。实体身份、schema 迁移、属性过滤、异步快照与写入顺序是学习重点，不能只以“文件能重新打开”认定完成。

练习建立三个小用例：旧版本存档迁移；两次异步保存以相反顺序完成；装备替换时 UI 更新与属性变化。验收要给出实体 ID 与资产 ID 的区别、读写版本和失败恢复策略；旧快照不得覆盖新状态，无法识别的数据有明确处理，服务器拥有的数据不由本地存档决定。多人或持久化交易按 [背包道具完整链路](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%83%8C%E5%8C%85%E8%A3%85%E5%A4%87%E4%B8%8E%E5%AD%98%E6%A1%A3/05-%E8%83%8C%E5%8C%85%E9%81%93%E5%85%B7%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md) 继续，导航不另抄服务器事务原理。

## UI 数据、焦点与可观测性

按 [UMG 控件](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%95%8C%E9%9D%A2%E8%AE%BE%E7%BD%AE%E4%B8%8E%E6%97%A0%E9%9A%9C%E7%A2%8D/01-UMG%E6%A1%86%E6%9E%B6%E4%B8%8E%E6%8E%A7%E4%BB%B6%E7%B3%BB%E7%BB%9F.md) → [UI 数据与 MVVM](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%95%8C%E9%9D%A2%E8%AE%BE%E7%BD%AE%E4%B8%8E%E6%97%A0%E9%9A%9C%E7%A2%8D/02-UI%E6%95%B0%E6%8D%AE%E7%BB%91%E5%AE%9A%E4%B8%8EMVVM.md) 阅读布局、属性通知与列表项寿命；并行学习 [CommonUI 输入与焦点](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%95%8C%E9%9D%A2%E8%AE%BE%E7%BD%AE%E4%B8%8E%E6%97%A0%E9%9A%9C%E7%A2%8D/07-CommonUI%E8%BE%93%E5%85%A5%E8%B7%AF%E7%94%B1%E4%B8%8E%E7%84%A6%E7%82%B9%E7%AE%A1%E7%90%86.md)，然后在 [UI 状态闭环](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%95%8C%E9%9D%A2%E8%AE%BE%E7%BD%AE%E4%B8%8E%E6%97%A0%E9%9A%9C%E7%A2%8D/06-UI%E7%8A%B6%E6%80%81%E4%B8%8E%E5%8F%AF%E8%A7%82%E6%B5%8B%E6%80%A7%E9%97%AD%E7%8E%AF.md) 中汇合。只在现有控件无法表达所需绘制或交互时进入 [Slate 扩展](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E7%95%8C%E9%9D%A2%E8%AE%BE%E7%BD%AE%E4%B8%8E%E6%97%A0%E9%9A%9C%E7%A2%8D/08-Slate%E8%87%AA%E5%AE%9A%E4%B9%89%E6%8E%A7%E4%BB%B6%E4%B8%8E%E6%A0%B7%E5%BC%8F%E7%B3%BB%E7%BB%9F.md)。

选择标准是更新频率、状态拥有者、控件复用方式与观测成本。事件通知、列表虚拟化、Invalidation 与 Retainer 都要确认适用边界，不能先断言所有 Tick/绑定都必须替换，或任一缓存一定减少开销。

练习：做一个背包列表和两层弹窗，在列表滚动/复用、数据刷新、手柄返回、触控关闭、设备切换时记录状态迁移。验收应证明列表项不会显示旧对象数据，关闭后焦点归还到有效控件，订阅无重复或遗漏；同时用 [Profiling](../../%E7%9F%A5%E8%AF%86/08-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5%E4%B8%8E%E8%B4%A8%E9%87%8F/%E8%B0%83%E8%AF%95%E4%B8%8E%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90/03-%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90%E5%B7%A5%E5%85%B7%E4%B8%8EProfiling.md) 与 [渲染/加载性能](../../%E7%9F%A5%E8%AF%86/08-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5%E4%B8%8E%E8%B4%A8%E9%87%8F/%E8%B0%83%E8%AF%95%E4%B8%8E%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90/04-%E6%B8%B2%E6%9F%93%E4%B8%8E%E5%8A%A0%E8%BD%BD%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96.md) 对比刷新、布局、绘制与资源驻留。通过 [GameplayDebugger](../../%E7%9F%A5%E8%AF%86/08-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5%E4%B8%8E%E8%B4%A8%E9%87%8F/%E8%B0%83%E8%AF%95%E4%B8%8E%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90/05-GameplayDebugger%E4%B8%8E%E8%BF%90%E8%A1%8C%E6%97%B6%E8%B0%83%E8%AF%95.md) 关联运行状态；性能热点的判定需要 Trace，不能沿用来源中的固定控件数量或毫秒阈值。

## 完成标准与证据边界

以一条业务链交付状态图、拥有者/裁决者、正常与失败时序、最小输入、预期及实际结果。覆盖取消、重复、过期、对象失效和版本迁移，而不只演示成功路径。用 [全栈运行闭环](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E8%BF%90%E8%A1%8C%E6%9E%B6%E6%9E%84%E4%B8%8E%E4%BB%BB%E5%8A%A1%E8%B0%83%E5%BA%A6/00-%E5%85%A8%E6%A0%88%E8%BF%90%E8%A1%8C%E9%97%AD%E7%8E%AF.md) 检查客户端表现、网络传递、服务端裁决与运营/发布条件是否混为一谈。

本路线没有新增 UE 运行或 benchmark 结论。已有独立逻辑实验只能证明它所建模的规则；平台输入、真实资产、渲染、多人网络和生产持久化仍需各自证据。旧导航的成熟度统计与效果保证不复制到本页。
