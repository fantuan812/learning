# 端到端案例：学习路线

本页提供前置知识、阅读选择、练习与验收建议，知识成熟度：L0；主题细节由链接主文负责。练习均待执行，本文不提供新的 UE、运行时、生产或基准验证，也不表示所有正文事实已经全面核实。

## 读案例时追踪同一份状态

案例连接客户端输入、网络、权威逻辑、存储、测试与性能；已知概念回主文，不再复制一份 GAS、RPC 或 Buff 原理。读每一步都记录模块/文件、消息或调用、状态身份/版本、所有权、提交点、失败/回滚和可验证入口；图必须能由文字说明其条件。

推荐按问题选择：[进入游戏](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E4%BC%9A%E8%AF%9D%E8%BA%AB%E4%BB%BD%E4%B8%8E%E5%9C%A8%E7%BA%BF%E6%9C%8D%E5%8A%A1/01-%E8%A7%92%E8%89%B2%E8%BF%9B%E5%85%A5%E6%B8%B8%E6%88%8F%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)追身份、票据消费、幂等、DS分配、旅行、二次鉴权、Spawn、JIP快照与追赶；[角色移动](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E5%90%8C%E6%AD%A5%E9%A2%84%E6%B5%8B%E4%B8%8E%E5%9B%9E%E6%94%BE/02-%E8%A7%92%E8%89%B2%E7%A7%BB%E5%8A%A8%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)追输入、SavedMoves、ServerMove、时间戳、防加速、扫掠、确认、回滚重放与表现平滑；[技能释放](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/03-%E6%8A%80%E8%83%BD%E9%87%8A%E6%94%BE%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)追预测、校验、状态机、Buff、伤害、同步和回放。

继续选 [Buff](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/04-Buff%E7%B3%BB%E7%BB%9F%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)的叠加/驱散/冲突、持续时间与恢复；[背包/道具](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E8%83%8C%E5%8C%85%E8%A3%85%E5%A4%87%E4%B8%8E%E5%AD%98%E6%A1%A3/05-%E8%83%8C%E5%8C%85%E9%81%93%E5%85%B7%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)的幂等、槽位dry-run、原子提交、outbox、revision增量复制与对账；[伤害/属性](../../%E7%9F%A5%E8%AF%86/05-Gameplay%E4%B8%8E%E4%BA%A4%E4%BA%92%E7%B3%BB%E7%BB%9F/%E6%8A%80%E8%83%BD%E6%88%98%E6%96%97%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97/11-%E4%BC%A4%E5%AE%B3%E4%B8%8E%E5%B1%9E%E6%80%A7%E7%BB%93%E7%AE%97%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)的属性快照、Override/Add/Mul、暴击/增伤/护甲/抗性/受伤加成、上限、护盾、生命/过量和死亡归属。

世界与工程问题可选 [假人AI](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/07-%E5%81%87%E4%BA%BAAI%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)和 [性能定位](../../%E7%9F%A5%E8%AF%86/08-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5%E4%B8%8E%E8%B4%A8%E9%87%8F/%E8%B0%83%E8%AF%95%E4%B8%8E%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90/10-%E6%80%A7%E8%83%BD%E9%97%AE%E9%A2%98%E5%AE%9A%E4%BD%8D%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)。原索引曾记载不同L3/L4/L5与计划状态，其中部分表格互相滞后；本路线不沿用计数或自动升级成熟度，实际状态看主文、身份图和原始证据。

## 按系统类型选择阅读模板

- Gameplay事务：输入/触发 → 本地状态 → 预测（适用时）→ 请求/RPC → 服务端校验 → 领域执行 → 状态变更 → 持久化（适用时）→ 复制 → 表现 → 重连/恢复 → 单测 → 集成 → 负载/基准 → 失败/回滚；技能再细查目标筛选、Buff冲突和伤害管线
- 世界运行时：World Tick → 实体选择 → 优先级/预算 → 模拟 → 空间查询 → 状态变更 → Interest计算 → 网络批量 → 指标 → 过载检测 → 降级 → 回放 → 正确性测试 → 负载测试 → 容量结论
- 平台/运维：Build → Artifact → Deploy → Start → Register → Allocate → Ready → Runtime → Health → Metrics → Drain → Crash/Failure → Recovery/Rollback → Load/Capacity → Postmortem
- 性能定位：症状 → 复现 → 基线 → 插桩 → 采样 → 假设 → 补丁 → 基准/回归 → 部署/灰度 → 观察/对比 → 回滚条件 → 结论/复盘

这些是原有场景的阅读框架，不意味着所有系统都必须采用同一种运行顺序或同一个SDK。将不适用步骤写明原因，保留数据/责任的连续性；匹配、AOI与DS等尚无对应完整案例时，组合已有主文与证据，不能把规划标题写成已完成案例。

## 证据、失败与完成标准

至少覆盖单元、网络异常、重连、机器人负载与性能，记录P50/P95/P99、CPU、内存、带宽和场景输入。先查对应 [Gameplay实验](../../evidence/tests/gameplay-core/README.md)、[伤害结算实验](../../evidence/tests/damage-core/README.md)、[性能实验](../../evidence/labs/profiling/README.md)及[完整实验目录](../../evidence/README.md)的实际源码和原始结果；索引中的83条断言、微秒/纳秒数和事件数不能证明当前版本已重新执行。

每个案例最终回答五个问题：谁拥有权威状态；数据从哪里来到哪里去；失败如何处理；如何证明逻辑正确；如何证明性能够用。用“假设→实验→数据→结论→失败方案→最终方案”留证，引用[工作日志](../../工作日志/README.md)保留日期与项目上下文。局部模型、源码阅读、真实引擎与生产运行是不同证据，不以案例摘要代替原记录。

质量收口见[工程实践与质量](工程实践与质量.md)，基础合同分别回[Gameplay](Gameplay与交互系统.md)、[网络与游戏服务端](网络与游戏服务端.md)、[游戏AI](游戏AI.md)与[数学算法](数学与游戏算法.md)；写作和成熟度仍按[现行规范](../../references/写作规范.md)，没有运行结果就不声称验证通过。
