# 游戏AI：学习路线

本页提供前置知识、阅读选择、练习与验收建议，知识成熟度：L0；主题细节由链接主文负责。练习均待执行，本文不提供新的 UE、运行时、生产或基准验证，也不表示所有正文事实已经全面核实。

## 从感知到执行与证据

按“环境刺激 → 记忆/黑板 → 决策 → 运动/动作 → 权威调度 → 评测与反馈”划分责任。视觉、听觉与遮挡只是输入，黑板需要类型、有效期和遗忘规则；决策频率也不必等于渲染帧率。先读 [AI 架构、感知与黑板](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/01-AI%E6%80%BB%E4%BD%93%E6%9E%B6%E6%9E%84%E4%B8%8E%E6%84%9F%E7%9F%A5.md)，再进入下面的模型与运动路线。

先补 [数学与游戏算法](数学与游戏算法.md)中的图搜索、随机分布和采样；引擎对象与线程约束接[引擎路线](引擎架构与资源系统.md)。AI 决定意图，算法解释寻路和数值条件，服务端负责世界权威与预算，UE 专题负责实现组件，不能用同一份 AI 正文替代它们。

## 决策模型的递进与选择

先从感知分别进入 [FSM/HSM](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/02-%E7%8A%B6%E6%80%81%E6%9C%BA%E4%B8%8E%E5%B1%82%E6%AC%A1%E7%8A%B6%E6%80%81%E6%9C%BA.md)与 [行为树](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/03-%E8%A1%8C%E4%B8%BA%E6%A0%91%E9%80%9A%E7%94%A8%E5%8E%9F%E7%90%86.md)；理解状态转换、Composite/Decorator/Task、黑板写入与 Abort 后，再读 [Utility、GOAP 与 HTN](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/04-Utility%E4%B8%8EGOAP.md)。感知基础后可并行学习 [模糊逻辑](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/06-%E6%A8%A1%E7%B3%8A%E9%80%BB%E8%BE%91%E4%B8%8E%E8%BF%9E%E7%BB%AD%E5%86%B3%E7%AD%96.md)；规划之后选择 [Minimax、Alpha-Beta 与 MCTS](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/05-%E5%8D%9A%E5%BC%88%E6%90%9C%E7%B4%A2%E4%B8%8E%E5%AF%B9%E6%88%98AI.md)，BT/Utility 之后进入 [人格、对话与社交](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AD%A6%E4%B9%A0%E9%80%82%E5%BA%94%E4%B8%8E%E7%A4%BE%E4%BC%9A%E8%A1%8C%E4%B8%BA/07-NPC%E4%BA%BA%E6%A0%BC%E5%AF%B9%E8%AF%9D%E4%B8%8E%E7%A4%BE%E4%BA%A4AI.md)。

| 决策需要 | 候选与应比较的问题 |
| --- | --- |
| 门、机关或 Boss 宏观阶段 | FSM/HSM：状态及转移数、并行状态、复用和历史恢复怎样管理？ |
| 分层任务与可视调试 | BT：优先级、观察者/轮询、打断、任务取消和黑板所有权能否解释清楚？ |
| 多需求竞争 | Utility：评分归一化、曲线、滞回与动作承诺怎样减少抖动，调参和预测成本怎样？ |
| 多步目标或分层计划 | GOAP/HTN：动作前后置、搜索空间、重规划预算与策划控制怎样取舍？ |
| 博弈前瞻 | Minimax/MCTS：状态/动作模型、信息条件、评估函数与时间预算是什么？不按品类断言实时场景不可用 |
| 连续威胁/控制 | Fuzzy：隶属度、规则冲突、去模糊化和误差边界怎样测试？ |
| 个性与社会互动 | OCEAN、情绪衰减、关系网络和对话中断恢复怎样连接，哪些仍受权威规则约束？ |

混合练习：用 HSM 管宏观战斗阶段、BT 管阶段内任务；用 Utility 选择 BT 的候选行动，再让 FSM/动画执行。先写意图、任务、动作之间的状态与取消合同，不能由模型名称推定低成本、无震荡或自动确定性。LLM 可以提出受限对话/行动申请，业务状态、战斗与资产仍由权威逻辑裁决。

## 运动、战斗导演与预算

顺序：[移动与群组](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AF%BC%E8%88%AA%E7%A7%BB%E5%8A%A8%E4%B8%8E%E7%BE%A4%E4%BD%93%E5%8D%8F%E5%90%8C/01-%E7%A7%BB%E5%8A%A8%E4%B8%8E%E7%BE%A4%E7%BB%84%E8%A1%8C%E4%B8%BA.md) → [战斗与 Boss](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/02-%E6%88%98%E6%96%97%E4%B8%8EBoss%E8%AE%BE%E8%AE%A1.md) → [战斗导演与战术协同](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/07-%E6%88%98%E6%96%97AI%E7%BC%96%E6%8E%92%E4%B8%8E%E6%88%98%E6%9C%AF%E5%8D%8F%E5%90%8C.md) → [服务端 AI 与性能](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E8%AF%84%E6%B5%8B%E5%AE%89%E5%85%A8%E4%B8%8E%E8%BF%90%E8%A1%8C%E9%A2%84%E7%AE%97/04-%E6%9C%8D%E5%8A%A1%E7%AB%AFAI%E4%B8%8E%E6%80%A7%E8%83%BD.md)。移动之后也可先研究服务端预算；Boss 之后可分支进入 [玩家建模与 DDA](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AD%A6%E4%B9%A0%E9%80%82%E5%BA%94%E4%B8%8E%E7%A4%BE%E4%BC%9A%E8%A1%8C%E4%B8%BA/05-%E7%8E%A9%E5%AE%B6%E5%BB%BA%E6%A8%A1%E4%B8%8E%E8%87%AA%E9%80%82%E5%BA%94%E9%9A%BE%E5%BA%A6.md)，服务端约束之后再读 [学习型 AI](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AD%A6%E4%B9%A0%E9%80%82%E5%BA%94%E4%B8%8E%E7%A4%BE%E4%BC%9A%E8%A1%8C%E4%B8%BA/03-%E5%AD%A6%E4%B9%A0%E5%9E%8BAI.md)，最后将学习与 DDA 汇入 [MARL/CTDE](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AD%A6%E4%B9%A0%E9%80%82%E5%BA%94%E4%B8%8E%E7%A4%BE%E4%BC%9A%E8%A1%8C%E4%B8%BA/06-%E5%A4%9A%E6%99%BA%E8%83%BD%E4%BD%93%E5%8D%8F%E4%BD%9C%E4%B8%8E%E5%BC%BA%E5%8C%96%E5%AD%A6%E4%B9%A0.md)。

全局通道、漏斗/Steering 与局部 RVO/ORCA 分层：先判断可达，再生成目标速度，最后处理邻居和几何限制。Seek/Flee/Arrive/Wander、Boids 的分离/对齐/凝聚和严格编队有不同目标；不要把局部避碰当成全局无卡死保证。算法机制回到 [路径平滑与转向](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E8%B7%AF%E5%BE%84%E6%90%9C%E7%B4%A2%E4%B8%8E%E5%AF%BC%E8%88%AA/04-%E8%B7%AF%E5%BE%84%E5%B9%B3%E6%BB%91%E4%B8%8E%E8%BD%AC%E5%90%91%E8%A1%8C%E4%B8%BA.md)、[共享流场](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E8%B7%AF%E5%BE%84%E6%90%9C%E7%B4%A2%E4%B8%8E%E5%AF%BC%E8%88%AA/03-%E6%B5%81%E5%9C%BA%E4%B8%8E%E7%BE%A4%E4%BD%93%E5%AF%BB%E8%B7%AF.md)及 [RVO 与数值鲁棒](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E8%B7%AF%E5%BE%84%E6%90%9C%E7%B4%A2%E4%B8%8E%E5%AF%BC%E8%88%AA/04-RVO%E4%B8%8E%E6%95%B0%E5%80%BC%E9%B2%81%E6%A3%92.md)。

练习为仇恨表列伤害/治疗/距离、衰减与视线缓存；为 Boss 列阶段转换、技能预警和恢复路径。加入攻击令牌、环形槽位、视锥盲区减压与破招失衡，观察它们是否改善围攻节奏；接[Gameplay 路线](Gameplay与交互系统.md)检查输入缓冲、霸体、取消窗口与命中反馈，避免表现替代权威结算。

服务端练习按优先级分帧，比较距离/可见性 LOD、时间切片与同向单位流场。旧例的 4–5ms、5000 单位和距离分档只是待校准场景：须分别定义墙钟配额、工作单元、deadline、队列/内存上限、过期结果丢弃与恢复滞回。用 [AI 查询预算](../../%E7%9F%A5%E8%AF%86/07-%E7%BD%91%E7%BB%9C%E4%B8%8E%E6%B8%B8%E6%88%8F%E6%9C%8D%E5%8A%A1%E7%AB%AF/%E8%BF%90%E8%A1%8C%E8%B0%83%E5%BA%A6%E4%B8%8E%E8%BF%87%E8%BD%BD%E4%BF%9D%E6%8A%A4/11-AI%E4%B8%8E%E5%AF%BB%E8%B7%AF%E6%97%B6%E9%97%B4%E9%A2%84%E7%AE%97.md)核对有效提交吞吐、等待时间、失效原因与业务正确性；不要把已有 A*/Tick 实验证据外推为新调度协议或 Detour 集成已验证。

学习型分支先写状态/动作/奖励与失败基线，再比较 PPO/DQN、模仿学习和自对弈的训练、部署与可控成本；DDA 检查玩家特征、心流目标、隐式帮扶和防作弊，MARL 检查集中训练/分散执行、通信与团队协作。验收需包含未见场景、失败长尾和固定预算下的表现，不以“胜过手写规则”作为无证据前提。

## 评测、回放与 LLM 权限边界

先有决策对象与服务端预算，再读 [AI 评测与回放](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E8%AF%84%E6%B5%8B%E5%AE%89%E5%85%A8%E4%B8%8E%E8%BF%90%E8%A1%8C%E9%A2%84%E7%AE%97/01-AI%E8%AF%84%E6%B5%8B%E5%9B%9E%E6%94%BE.md) → [自动测试 Bot](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E8%AF%84%E6%B5%8B%E5%AE%89%E5%85%A8%E4%B8%8E%E8%BF%90%E8%A1%8C%E9%A2%84%E7%AE%97/02-%E8%87%AA%E5%8A%A8%E6%B5%8B%E8%AF%95%E7%8E%A9%E5%AE%B6%E4%B8%8EAI%E5%9B%9E%E5%BD%92%E5%9F%BA%E5%87%86.md)，另从评测分支进入 [LLM NPC 安全](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E8%AF%84%E6%B5%8B%E5%AE%89%E5%85%A8%E4%B8%8E%E8%BF%90%E8%A1%8C%E9%A2%84%E7%AE%97/03-LLM-NPC%E5%AE%89%E5%85%A8.md)。发布闭环是离线基准 → 小流量灰度 → 运行监控与降级 → 差分回放复盘，测试 Bot 是证据工具，不能默认替代所有人工体验检查。

保留评测维度：任务完成/胜率与回报、路径平滑/绕路/卡死、误伤/命中、响应延迟、CPU/内存峰值、状态哈希分歧、长稳与体验。每项写输入、场景、样本数、采样窗口、分母和置信区间；报告 P50/P95/P99 与失败样本。旧页的 99%、4ms、零卡死或 100% 安全拦截不是普适门槛，要按项目风险校准。

回放练习记录版本/资产、输入、实体顺序、时钟、随机流和快照，定位最早分歧帧；种子相同不自动保证跨平台复现。接 [联机确定性](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E7%A1%AE%E5%AE%9A%E6%80%A7%E4%B8%8E%E5%9F%BA%E5%87%86/05-%E8%81%94%E6%9C%BA%E7%A1%AE%E5%AE%9A%E6%80%A7%E4%B8%8E%E5%9F%BA%E5%87%86%E5%B7%A5%E7%A8%8B.md)、[统计采样](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E9%9A%8F%E6%9C%BA%E9%87%87%E6%A0%B7%E4%B8%8E%E7%A8%8B%E5%BA%8F%E5%8C%96%E7%94%9F%E6%88%90/07-%E6%A6%82%E7%8E%87%E5%88%86%E5%B8%83%E4%B8%8E%E9%87%87%E6%A0%B7%E5%B7%A5%E7%A8%8B.md)及[工程质量路线](工程实践与质量.md)的服务端压测，区分决策质量、并发容量与故障恢复。

LLM 练习从人格/对话出发，限定可检索知识与剧透边界；输入做必要的数据最小化和长度约束，输出由独立权限网关校验工具、参数、对象所有权与副作用。模型提出 grant_item 等高危写申请时，权威逻辑必须拒绝未获权限的调用并进入确定性回退。测试提示注入、越权、敏感泄漏、拒绝误伤和人工接管，保存脱敏证据；敏感词或提示词不能证明绝对安全。

## 按工程角色选读

- 客户端 AI：感知/黑板 → FSM/BT → 移动/群组 → Boss/战斗 → UE 感知、导航与 StateTree/GAS 接线
- 服务端/MMO AI：权威与预算 → 移动/流场 → 战斗校验 → 服务端查询预算 → [假人 AI 案例](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/07-%E5%81%87%E4%BA%BAAI%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md)
- 智能体/强化学习：博弈搜索 → 学习型 AI → 玩家建模/DDA → MARL，同时比较训练和部署成本
- AI 质量：评测/回放 → 测试 Bot → 服务端机器人压测与联机确定性，保留失败样本和复现包
- LLM NPC：人格/对话/社交 → 低权限工具与知识边界 → 对抗样本、回退、回放与灰度门禁

## UE AI 的前置与单体行为主线

先具备 [状态机](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/02-%E7%8A%B6%E6%80%81%E6%9C%BA%E4%B8%8E%E5%B1%82%E6%AC%A1%E7%8A%B6%E6%80%81%E6%9C%BA.md)、[通用行为树](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/03-%E8%A1%8C%E4%B8%BA%E6%A0%91%E9%80%9A%E7%94%A8%E5%8E%9F%E7%90%86.md)、[图搜索](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E8%B7%AF%E5%BE%84%E6%90%9C%E7%B4%A2%E4%B8%8E%E5%AF%BC%E8%88%AA/01-%E5%9B%BE%E8%AE%BA%E5%9F%BA%E7%A1%80%E4%B8%8E%E6%90%9C%E7%B4%A2%E7%AE%97%E6%B3%95.md) 和 [Recast/Detour 工程](../../%E7%9F%A5%E8%AF%86/02-%E6%95%B0%E5%AD%A6%E4%B8%8E%E6%B8%B8%E6%88%8F%E7%AE%97%E6%B3%95/%E8%B7%AF%E5%BE%84%E6%90%9C%E7%B4%A2%E4%B8%8E%E5%AF%BC%E8%88%AA/03-NavMesh%E5%B7%A5%E7%A8%8BRecast%E4%B8%8EDetour.md) 的基本概念，能区分决策状态、路径状态与移动执行状态；在引擎侧完成 UObject、Actor 生命周期和 GameplayTasks 取消责任的阅读。API 使用不代替通用搜索正确性，通用算法模型也不证明 UE 请求生命周期。

阅读顺序为 [UE 行为树](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/01-%E8%A1%8C%E4%B8%BA%E6%A0%91%E8%AF%A6%E8%A7%A3.md) → [感知与 EQS](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/02-%E6%84%9F%E7%9F%A5%E7%B3%BB%E7%BB%9F%E4%B8%8EEQS.md) → [NavMesh](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AF%BC%E8%88%AA%E7%A7%BB%E5%8A%A8%E4%B8%8E%E7%BE%A4%E4%BD%93%E5%8D%8F%E5%90%8C/03-NavMesh%E5%AF%BB%E8%B7%AF.md)。先建立“刺激输入→黑板状态→决策→请求移动→反馈”的闭环，再讨论行为优先级、条件打断、EQS 评分和异步寻路。行为树分支应能解释条件变化为何触发或不触发重新选择；路径不可达、目标失效和移动被打断不能统一当作成功。

## StateTree、能力协作与群体分支

需要明确状态阶段及转移条件时读 [StateTree](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/05-StateTree%E7%8A%B6%E6%80%81%E6%A0%91.md)；需要技能与移动共同取消/恢复时读 [Tasks、StateTree 与 GAS 协同](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/07-GameplayTasks-StateTree-GAS-AI%E5%8D%8F%E5%90%8C.md)。选择 BT 或 StateTree 前，先列出观察数据、并行任务、打断优先级与可解释性要求，不以新旧替代适配判断。

角色规模成为实际瓶颈且数据可批处理时，进入 [Mass](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AF%BC%E8%88%AA%E7%A7%BB%E5%8A%A8%E4%B8%8E%E7%BE%A4%E4%BD%93%E5%8D%8F%E5%90%8C/04-Mass%E5%AE%9E%E4%BD%93%E6%A1%86%E6%9E%B6%E4%B8%8E%E7%BE%A4%E9%9B%86%E6%A8%A1%E6%8B%9F.md)；需要道路空间约束和环境交互槽位时，再读 [ZoneGraph 与 SmartObjects](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AF%BC%E8%88%AA%E7%A7%BB%E5%8A%A8%E4%B8%8E%E7%BE%A4%E4%BD%93%E5%8D%8F%E5%90%8C/06-ZoneGraph%E4%B8%8ESmartObjects.md)。把 Chunk/Archetype 的数据布局、Processor 工作、LOD 与角色表现成本分别测量，不把连续存储直接推导成某个实体数量或帧率。SmartObject 的 Claim、使用、取消和释放要作为完整资源生命周期检查。

## UE AI 的练习与验收

选择一个“发现敌人→找掩体→移动→施法→结束”的场景，同时安排目标销毁、路径失败、技能打断、World 退出和椅子/掩体槽位竞争。用 [AI 调试与性能分析](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E8%AF%84%E6%B5%8B%E5%AE%89%E5%85%A8%E4%B8%8E%E8%BF%90%E8%A1%8C%E9%A2%84%E7%AE%97/08-AI%E8%B0%83%E8%AF%95%E4%B8%8E%E6%80%A7%E8%83%BD%E5%88%86%E6%9E%90.md) 的 Visual Logger、GameplayDebugger 思路记录状态、请求 ID、代次、原因与完成结果。验收要能还原错误选择的输入与评分，解释哪个任务取消了哪个请求，并确认迟到结果不会重新占槽或触发已结束技能。

群体练习固定内容、随机种子、相机和实体工作，分档增加规模，比较决策耗时、寻路等待、表现预算与行为质量。原“万人同屏流畅”的承诺改为问题：当前目标平台和行为组合在哪个规模开始超出预算，降低频率或切换表示会损失什么可见质量？保留原始记录，避免只报告平均帧率。

## AI 跨域与源码出口

决策主文对照 [行为树源码](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%84%9F%E7%9F%A5%E5%86%B3%E7%AD%96%E4%B8%8E%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%92/12-%E8%A1%8C%E4%B8%BA%E6%A0%91%E4%B8%8EAI%E6%BA%90%E7%A0%81.md)，群体/状态树对照 [Mass/StateTree 源码](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E5%AF%BC%E8%88%AA%E7%A7%BB%E5%8A%A8%E4%B8%8E%E7%BE%A4%E4%BD%93%E5%8D%8F%E5%90%8C/21-Mass%E4%B8%8EStateTree%E6%BA%90%E7%A0%81.md)，项目战斗组织对照 [Lyra 机器人与队伍](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/46-Lyra-AI%E6%9C%BA%E5%99%A8%E4%BA%BA%E4%B8%8E%E9%98%9F%E4%BC%8D%E6%BA%90%E7%A0%81.md)；实际系统案例接 [假人 AI 完整链路](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/07-%E5%81%87%E4%BA%BAAI%E5%AE%8C%E6%95%B4%E9%93%BE%E8%B7%AF.md) 与 [战斗与 Boss 设计](../../%E7%9F%A5%E8%AF%86/06-%E6%B8%B8%E6%88%8FAI/%E6%88%98%E6%96%97%E6%88%98%E6%9C%AF%E4%B8%8E%E6%9C%BA%E5%99%A8%E4%BA%BA/02-%E6%88%98%E6%96%97%E4%B8%8EBoss%E8%AE%BE%E8%AE%A1.md)。

保留 MOC 的两条映射：图搜索→NavMesh→服务端假人寻路；状态机→BT/StateTree→Boss 阶段与队伍协作。[A* 实验](../../evidence/algorithms/astar/README.md) 与 [AOI 实验](../../evidence/algorithms/aoi/README.md) 仅为对应模型证据入口，不证明当前 UE 场景达到同样结论；日志仍在原位，仅作为来源上下文。
