# UE 源码阅读路线

> 本页是阅读方法与问题索引，知识成熟度：L0；提出的 UE 构建、运行与性能练习均待执行。源码历史导航保留原路径、叙述、日期与代码，只允许经过审查、可逆的标准 Markdown URL 变换。

> 版本基准：本页组织跨主题阅读次序，具体 UE / Lyra 版本、CL、平台与插件条件以链接主文及实际 checkout 为准；复现前应固定版本，不能将旧来源声明当成本次运行结果。最后更新：2026-10-04（路线整理）。[UE 官方文档与版本入口](https://dev.epicgames.com/documentation/en-us/unreal-engine)用于核对当前版本差异。

## 基线与证据约束

源码学习首先记录实际 checkout 的引擎版本、分支/提交或 CL、目标平台、构建配置、插件开关与 Lyra 版本。旧来源写有 UE 5.8.0、CL55116800 与 Release 分支，但这里仅把它们视为来源自述的检索线索，不能据此断言读者工作区相同、全部覆盖或实际验证通过。定位规则以主文及实际代码为准。

从 [源码覆盖路线图](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E6%BA%90%E7%A0%81%E9%98%85%E8%AF%BB%E4%B8%8E%E8%A6%86%E7%9B%96%E5%9F%BA%E7%BA%BF/19-%E9%AB%98%E4%BC%98%E5%85%88%E7%BA%A7%E6%BA%90%E7%A0%81%E8%A6%86%E7%9B%96%E8%B7%AF%E7%BA%BF%E5%9B%BE.md) 选择一个待回答的问题；它的主责在“引擎架构与资源系统 / 源码阅读与覆盖基线”。先读机制主文，再查实现，再做最小观察。源码分析是一种内容类型，不能重新成为第九个主题域，也不把同一份实现说明复制到多个学习页。

一份阅读记录至少包含：问题与可证伪假设、入口符号/文件、调用或数据依赖方向、对象/线程/时间域、失败分支、版本条件、观察结果与未知项。只找到同名函数或注释不足以证明执行路径；只读到可能路径也不等于它在本次配置中发生。

## 从概念到源码的阅读方法

先在 [引擎路线](引擎架构与资源系统.md) 或 [Gameplay 路线](Gameplay与交互系统.md) 选一个能复述的机制；画出预期状态变化，再带着“谁创建、何时就绪、谁调用、何时失败、谁释放”的问题查主文链接。沿一个请求或数据对象前进，不以阅读文件数量为目标。

将六层学习模型转化成往返路线：C++/操作系统基础 → 引擎对象运行时 → 具体玩法或表现系统 → 工具链与配置 → 对应源码 → [业务运行闭环](../../%E7%9F%A5%E8%AF%86/03-%E5%BC%95%E6%93%8E%E6%9E%B6%E6%9E%84%E4%B8%8E%E8%B5%84%E6%BA%90%E7%B3%BB%E7%BB%9F/%E8%BF%90%E8%A1%8C%E6%9E%B6%E6%9E%84%E4%B8%8E%E4%BB%BB%E5%8A%A1%E8%B0%83%E5%BA%A6/00-%E5%85%A8%E6%A0%88%E8%BF%90%E8%A1%8C%E9%97%AD%E7%8E%AF.md)。它是学习顺序，不是新的分类目录；一次问题只需走相关分支。

练习：选“Actor 何时可接收业务输入”或“异步资源完成后为何对象已失效”，整理三层以内调用/数据图，列出至少一个与直觉不同的条件。验收为入口能定位、条件可以在真实配置中核对、正常和失败路径齐全、结论与版本范围一致。缺乏本地引擎时标注“阅读推导，待运行核对”。

## 角色选择与跨域出口

原角色 B（底层架构）采用核心机制 → Iris/Mass/Nanite 选修 → 工具链 → 全栈闭环；角色 C（技术美术）采用 RHI → Lumen/Nanite → PCG/世界表现；角色 D（多人 DS）采用复制/预测 → DS 构建与裁剪 → DS 启动/NetDriver/ReplicationGraph → 平台化和世界 MainLoop/AOI → 会话重连与故障降级；角色 E（工具链与 CI/CD）采用启动/LoadingPhase → UBT/UAT → GameFeatures/资产验证 → Shader/PSO、质量门禁、Python 自动化与 Trace。每条路线以一个明确项目问题为选课条件。
