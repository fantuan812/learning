# 知识边界与生命周期

> 知识成熟度：L2（路由规则与现行知识图、Canonical 和资料保全边界配合使用）。

本规则区分材料的生命周期与项目边界，分类和稳定身份由[知识图](../../.kb/knowledge-map.json)维护。置信度低于 0.75 的结构动作进入 [review queue](../../.kb/review-queue.md)，材料留在原位，不自动移动或创建接收骨架。

## 四类范围

| 类别 | 判定 | 落点与处理原则 |
| --- | --- | --- |
| universal | 与具体项目、仓库、账号、部署环境无关，可迁移复用 | 按知识图确定八域中的唯一主责正文，存放于 `知识/`；先查已有主题和术语别名 |
| project | 依赖明确项目名、代码路径、配置、线上环境或业务约束 | 保留现有获准的项目、来源或实验证据上下文；新增存储位置须有明确项目和结构计划，不因范围标签创建新根目录 |
| mixed | 同时含通用原理和项目实现或证据 | 可以保留完整链路并互链；只有独立复用边界明确且信息完整时才拆分。可复用案例按主责域归入 `知识/`，由[端到端案例路线](../学习路线/端到端案例.md)提供学习视图 |
| temporary | 日期日志、随手材料、原始对话、未分类输入或删除候选 | 保留当前来源位置与时间上下文；未确定分类时记录 review queue。不得自动成为 Canonical，也不自动创建 Inbox、Archive 或短笔记骨架 |

[八域知识体系](../../知识/README.md)展示当前主题入口；[学习路线](../学习路线/README.md)表达阅读顺序，不建立第二套分类。旧分类可能跨多个当前域，历史目录名不能代替逐文档身份与职责判断。

## 保留的责任层

- [evidence](../../evidence/README.md)：实验源代码、测试、原始结果和复现步骤；它支撑正文，但不替代正文
- [工作日志](../../工作日志/README.md)：按日期保存过程证据和决策上下文；提炼结论时保留原日志及链接
- [读书笔记](../../读书笔记/README.md)：来源集合，书目、章节、PDF、图片、笔记和处理工具保留；来源层按著作组织不等于按著作建立主题分类
- [方案](../../方案/README.md)：仓库建设计划与历史执行记录，不属于知识正文
- 既有书籍引用必需的兼容入口与源码混合历史原位保留；不再接收新主题正文

## 提升流程

当前来源材料 → 区分事实、推断与建议 → 查重与术语别名 → 判定四类范围 → 在知识图中选择或登记唯一 Canonical → 补标准 Markdown 与 OKF 元数据 → 链接 Evidence → 更新图、相关导航与 manifest → 运行根 AGENTS 规定的适用检查。

- temporary 提升时必须保留原材料链接。
- mixed 提升时先检查通用部分是否独立、拆分是否损伤链路叙事，再决定拆分或保留加链接。
- Evidence 只有实际执行并保存原始输出后，才可支持对应的高成熟度声明。

## 禁止事项

- 不按来源名、日期或工具名建立主题主分类；来源集合可以保留书目、日期与工具上下文。
- 不因关键词“项目”“业务”“真实项目”自动判为 project。
- 不复制第二份 Canonical 正文。
- 不在链接影响尚未审计时批量改路径。
