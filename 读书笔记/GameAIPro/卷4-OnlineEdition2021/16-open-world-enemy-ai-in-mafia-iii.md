## 1. 概述与核心架构理念（Introduction & Core Architecture）

在第三人称开放世界动作冒险游戏《黑手党 III》（*Mafia III*）中，技术团队的核心目标是构建一个生动、严谨且符合历史氛围的 1968 年新波尔多（New Bordeaux）。在这样的现实主义世界观设定下，NPC（非玩家角色）必须展现出与真实人类一致的生理属性、行为逻辑与脆弱性：当人类敌人被击中头部时，玩家期望其立即毙命，而非呈现数值化的“海绵体血条”。逼真的拟人表现对感知系统、战术决策以及掩体交互提出了极高的工业化要求。

### 1.1 数据驱动与热重载迭代（Data-Driven Iteration）

为支撑开放世界中数以百计不同类型敌人的快速调整与数值迭代，AI 系统从底层完全践行**数据驱动设计（Data-Driven Design）**：
- **工程解耦**：将 AI 逻辑的配置与底层代码解耦，避免因微调感知距离或行为倾向而触发繁重的 C++ 编译管线。
- **运行时配置重载（In-Game Configuration Reload）**：策划可在游戏运行时直接热重载数据文件，在保持沉浸感的同时，以极高频率验证 AI 在遭遇战、潜行潜行诱导（Luring）以及警察追逐等系统化玩法中的表现。

### 1.2 复合分层架构拓扑（Hybrid Architectural Topology）

在顶层决策机制上，系统采用**行为树（Behavior Trees, BT）**作为核心的调度骨干，但在状态空间推理与微观战术执行层，并非将所有逻辑直接硬编码或扁平堆砌在行为树中，而是将其拆解为多个专业化的支撑子系统：

```
                    +------------------------------------+
                    |      原型定义 (Archetype Def)       |
                    +-----------------+------------------+
                                      |
                                      v
+------------------+        +-------------------+        +--------------------+
| 感知系统         |------->| 行为树            |<-------| 决策树             |
| (Perception)     |        | (Behavior Tree)   |        | (Decision Tree)    |
+------------------+        +---------+---------+        +--------------------+
                                      |
                                      v
+------------------+        +-------------------+        +--------------------+
| 掩体系统         |------->| 选位系统          |        | 射击系统           |
| (Cover System)   |        | (Position Select) |        | (Shooting)         |
+------------------+        +-------------------+        +--------------------+
```

行为树作为黏合中枢（Glue Logic），负责高层生命周期管理与上下文驱动的行为调度；其决策依据则完全依赖输入子系统（如感知引擎、掩体与选位系统）计算输出的高阶空间与态势数据，最终驱动具体的执行器（如射击与移动）。

## 2. 敌方实体抽象与数据模型（Enemy Design & Data Modeling）

技术团队将 NPC 的定义进行高内聚、低耦合的模块化切分，确立了以**原型（Archetype）**为骨架、以**战术（Tactics）**为策略单元的继承与复用体系。

### 2.1 原型抽象（Archetype Abstraction）

**原型（Archetype）**是 NPC 类别的顶层静态描述载体，涵盖以下核心配置：
- 可用战术列表（Usable Tactics）
- 感官感知配置（Perception Configuration）
- 语音与对白音效（Voice & Dialogue Events）
- 携带武器库与弹药定义（Weapons）
- 对玩家动作的反应表（Reactions to Player）
- 动画集合与动作库（Animation Sets）

#### 原型继承架构（Inheritance Hierarchy）
原型体系支持面向对象的树状属性继承结构。根节点定义全项目共享的基类通用配置（Base Configuration），下游各类变体（Variants）仅需覆写局部配置项：
- *范例*：基础“枪手”（Triggerman Base）默认挂载投掷莫洛托夫鸡尾酒（Molotov Cocktail）的战术与道具逻辑；其变体“精锐枪手”（Triggerman Variant）仅需覆写武器插槽与投掷配置，将其切换为破片手榴弹（Frag Grenades），其余感知、动画集与基础掩体逻辑完全继承自父类。

### 2.2 战术执行单元分解（Tactics Decomposition）

战术（Tactic）负责精细化约束 NPC 在战斗状态下的战术执行链路。每个战术均切分为独立的六大基本功能块（Basic Blocks），各模块以独立文件存储并支持跨战术复用：

| 战术功能块 (Tactic Block) | 职责描述 (Responsibility) | 底层驱动架构 (Underlying System) |
| :--- | :--- | :--- |
| **选位系统（Position Selection）** | 评估战斗站位与有效掩体槽位 | 效用系统打分函数（Utility Scoring Functions） |
| **目标选择（Target Selection）** | 筛选敌对实体、仇恨优先级分配 | 效用系统打分函数（Utility Scoring Functions） |
| **移动风格（Movement Style）** | 规划进入目标掩体或站位的位移形态（如潜伏、冲刺、战术规避） | 决策树（Decision Trees） |
| **掩体动作（Cover Action）** | 滞留于掩体内部时的战术行为分支（如盲射、探头、压制、呼叫支援） | 决策树（Decision Trees） |
| **开阔地动作（Open Space Action）**| 处于开阔无掩体地带时的交战逻辑（如跪射、后撤、前压） | 决策树（Decision Trees） |
| **换弹行为（Reload Behavior）** | 触发主动换弹或战术规避换弹的边界条件 | 决策树（Decision Trees） |

通过将选位和目标选择交由效用系统（Utility System）进行多目标连续值评分，同时将掩体内外的具体动作交由确定性极强的决策树（Decision Trees）进行快速遍历，兼顾了战术推演的最优解与动作切换的敏捷度。

## 3. 感知系统与认知状态机（Perception & Awareness Engine）

感知系统充当 AI 观察开放世界的“视听器官”。所有感官参数均完全暴露给策划进行数据驱动配置，凡连续非线性函数关系均以**分段线性图（Piecewise Linear Graph）**的形式进行可视化曲线拟合与编辑。

### 3.1 视觉系统（Sight Pipeline）

视觉系统负责在 NPC 与目标事件之间存在清晰视线（Line of Sight, LoS）时触发检测机制。

#### 3.1.1 传感器与检测点拓扑（Sensor & Detection Points）
每个 NPC 头顶均挂载一个**视锥检测器（Sight Detector）**。在被观察实体（例如玩家）上，引擎并没有粗暴地采用单个包围盒原点，而是部署了 **5 个关键检测点（Detection Points）**：
- **默认骨骼挂载**：分布在头部（Head）、双肘（Elbows）、双膝（Knees）。
- **动画状态重载**：在大部分特定的姿态或动画状态下（尤其在掩体中），美术与策划为动画预定义覆盖坐标，使得检测点在进入掩体时**主动向胸腔中心收敛并贴近碰撞体边缘**。

```
       [ 站立检测点分布 ]                       [ 掩体姿态收敛分布 ]

             ( 头部 )                                ( 头部 )
                o                                       o
          o-----------o                           o-----------o
       (左肘)   |   (右肘)                     (左肘)  o (胸腔) (右肘)
                |                                       |
             o     o                                 o     o
           (左膝) (右膝)                           (左膝) (右膝)
    [骨骼挂载/易暴露在掩体外]               [检测点向胸部/障碍收拢，获得掩体保护]
```

这种机制显著优化了潜行暗杀与掩体枪战中的感知表现，避免了玩家在掩体内部由于骨骼摆动（Idle 呼吸动画）导致肘部穿模被瞬间侦破的恶劣体验。

#### 3.1.2 认知延迟模型与数学公式推导
当玩家出现在视锥内且视线未被阻挡时，NPC 不会发生阶跃式的“超感瞬发警觉”，而是引入认知累加过程（Recognition）。决定 NPC 最终完成认知所需耗时 $t$ 的核心要素包括：
1. 到事件源的距离（Distance）
2. 视角偏差（NPC 视线朝向向量与目标事件方向向量的夹角）
3. 环境光照度（目标对象与 NPC 所处环境的明暗程度）
4. 目标对象的移动速度（Object Speed）
5. 暴露可见的检测点数量（Number of Visible Points，即通过 LoS 射线投射的挂载点总数）

各项属性均映射为区间 $[0, 1]$ 内的分段线性函数 $function_i$。完成完全识别的耗时 $t$ 采用乘积反比公式建模：

$$t = \frac{1}{\prod_{i=0}^{n} function_i}$$

其中：
- $n$ 为参与评估的环境与几何变量总数。
- $function_i \in (0, 1]$ 为各个特征输入经分段线性映射后的加权感知效率因子。
- 当某一关键因子极小（例如距离极远或处于全黑环境）时，$\prod function_i \to 0$，耗时 $t \to \infty$，即永远无法达到完全识别阈值。

### 3.2 听觉系统（Hearing Architecture）

《黑手党 III》的 AI 听觉管线**完全独立于游戏音频渲染引擎（Audio Engine）**构建：
- **事件分发拓扑**：当空间中产生具有 AI 意义的声响（如开火、脚步、爆炸、抛掷物碰撞）时，听觉系统直接接管该声音事件并向周围具有听觉接收器（Hearing Detector）的 NPC 进行广播。
- **声音衰减与传播半径**：每种声音事件拥有独立配置的数据驱动传播半径（Propagation Distance）。
- **差异化触发策略**：
  - *致命威胁事件（如枪声、爆炸）*：瞬间激化警报，直接打断非战斗行为，NPC 瞬间切换至战斗态。
  - *微弱可疑事件（如普通脚步声）*：采用高频累加机制，只有在给定的时间窗口 $\Delta t$ 内接收到的事件累加次数达到阈值 $C_{threshold}$ 时，才会触发调查反应。

### 3.3 认知状态机（Awareness Finite State Machine）

NPC 的认知层通过分层有限状态机（FSM）驱动，整体拓扑结构如下：

```
                    +--------------------+
                    |    闲置 (Idle)     |<----------------+
                    +---------+----------+                 |
                              |                            |
                              v                            |
                    +--------------------+                 |
         +--------->| 认知 (Recognition) |                 |
         |          +---------+----------+                 |
         |                    |                            |
         |                    v                            |
         |          +--------------------+                 |
         |          | 调查 (Investigation)                 |
         |          +---------+----------+                 |
         |                    |                            |
         |                    v                            |
         |          +--------------------+        +--------+-------+
         +----------+   战斗 (Combat)    |------->|  搜索 (Search) |
                    +--------------------+        +----------------+
```

各状态间具备视听参数隔离性：
- **Idle（闲置）**：感官灵敏度最低，视锥收敛，脚步累加阈值最高。
- **Recognition（认知中）**：处于视锥判定边缘，正在基于公式推导累积认知值。
- **Investigation（调查）**：脱离原定巡逻路线，向最后已知可疑位置（Last Known Position, LKP）移动排查。
- **Combat（战斗）**：全局警惕性最高，视锥视距拉至最大，反应延迟缩减至极小。
- **Search（搜索）**：丢失玩家视线后触发，在区域内进行战术清扫，若超时未发现目标则沿状态转移回退至 Idle。

## 4. 潜行交互工具链与多智能体协同（Stealth Mechanics & Multi-Agent Coordination）

### 4.1 潜行交互设计与认知平衡

为了实现开放世界中高宽容度且具备战术深度的潜行玩法，设计团队针对潜行机制进行了关键的推演与权衡：
- **姿态与噪声控制**：玩家蹲伏（Crouch）并低速移动时，脚步声事件的发放半径归零，同时身体检测点位置显著下沉，更容易隐藏在低矮掩体后。
- **视线认知时间缩放**：玩家进入掩体后，公式中的暴露因子被施加额外的掩体衰减系数，极大延长了 NPC 的认知耗时。
- **设计回退经验（Design Trade-off）**：在开发早期，团队曾实装“只要玩家处于潜行状态，即使暴露在空地上识别速度也会变慢”的逻辑。但实际验证发现严重违背常识：一个身形魁梧的成年男子在光天化日的大街中央下蹲，辨识度并没有丝毫下降。因此团队移除了该人工修正，转而依赖**纯粹依靠碰撞遮蔽与收缩的检测点空间几何分布**来赋予玩家潜行优势。

### 4.2 潜行引诱工具技术实现

1. **口哨技能（Whistle）与屏幕空间目标定位**：
   - 玩家吹口哨时，并非简单的范围径向广播，而是采用**玩家驱动的屏幕空间定向选择（Screen Space Targeting）**。
   - 效用打分函数同时将“世界坐标中到玩家的物理距离”与“投影至屏幕空间后距离准心中心的偏移距离”作为复合评分输入，准确选出玩家视野所向的目标敌人。
   - 引入编组反馈机制（Group Awareness Reaction）：被选中的 NPC 前往查探，而同一同盟组内的其余 NPC 则表现出疑惑、保持警戒或眼神跟随等差分行为，避免全组盲目一拥而上。
2. **巫毒娃娃（Voodoo Doll）**：
   - 作为可消耗型投掷道具，落地后持续产生听觉事件脉冲，诱使周围敌人向其位移聚拢，进入预设杀伤半径后引爆。

### 4.3 友军突击小队协同（Hit Squad Coordination）

玩家可呼叫由 4 名 AI 盟友构成的“突击小队”（Hit Squad）。该子系统涉及复杂的多智能体知识共享与空间避让机制：
- **非破隐并发交火机制**：盟友小队与敌方守卫接火交战，敌方会对盟友产生认知并进入战斗态，但只要玩家未暴露自身的检测点，玩家的潜行状态**不会被打破**。
- **跨代理感知黑板共享（Perception Sharing）**：盟友 AI 之间实现瞬时敌情共享。同时，玩家作为特殊的代理实体，其后台运行一个具有 $360^\circ$ 全向视锥的简化版认知检测器，一旦玩家感知到敌人，该情报立即无缝同步给小队黑板。
- **基于选位系统的群体间距协调（Spatial Coordination via Position Selection）**：
  盟友小队并未采用强耦合的刚性群组阵型（Formation System），而是完全依托**选位系统（Position Selection System）**解算。当小队成员 $A$ 搜寻战术掩体或开阔地站位时，打分函数将获取所有其余活跃成员的当前世界坐标与目标路线终端：

$$\text{Score}(P) = S_{combat}(P) - w_{density} \cdot \sum_{j \in Squad \setminus \{i\}} \mathcal{K}(\|P - P_j\|)$$

  其中 $\mathcal{K}$ 为随距离缩减的核惩罚函数，$w_{density}$ 为密度权重。通过惩罚与其他盟友位置过近的候选点，使小队在战术推移过程中自然维持适度松散、互相掩护的高级交火阵型。

## 5. 掩体系统与动态世界适配（Dynamic Cover System）

掩体系统是作为战术掩体射击游戏（Cover Shooter）的核心基石，不仅支持静态烘焙，更具备在复杂动态开放世界中进行实时自适应更新的能力。

### 5.1 掩体槽位数据模型与几何定义

地图中所有基础掩体在编辑器阶段基于静态碰撞体（Static World Collision Geometry）半自动生成，策划可手动干预修改。单个掩体槽位标准宽度为 $1.0\text{ m}$，其数据结构包含如下核心字段：

```
+-----------------------------------------------------------------------+
|                       CoverPosition 数据结构                          |
+-----------------------------------------------------------------------+
| 1. 变换数据 (Transform)                                               |
|    - 空间坐标 (Position: Vector3)                                     |
|    - 空间朝向 (Rotation: Quaternion)                                  |
|    - 槽位宽度 (Width: float = 1.0m)                                   |
|                                                                       |
| 2. 探身射击点位 (Leaning Positions: uint8 Flag)                       |
|    - 左侧探身 (Left Lean)                                             |
|    - 右侧探身 (Right Lean)                                             |
|    - 站立/翻滚探身 (Up Lean)                                          |
|                                                                       |
| 3. 高度轮廓函数 (Height Function: uint64 压缩表达)                     |
|    - 存储 4 个关键控制点 (4 Control Points)                           |
|    - 横轴：沿掩体边缘横向距离 $d$                                      |
|    - 纵轴：掩体障碍物垂直高度 $h$                                      |
|                                                                       |
| 4. 防护朝向位图 (Protection Directions: uint32 Bitfield)              |
|    - 将 $360^\circ$ 全周划分为 32 个等分散形方向区间（每个方向占 11.25°）    |
|    - 利用 $0.5\text{ m}$ 短距离射线探测，有障碍阻挡则置 1，开阔则置 0      |
|                                                                       |
| 5. 拓扑邻接索引 (Topology Adjacency IDs)                              |
|    - 左邻居掩体句柄 (Left Neighbor ID: uint32)                        |
|    - 右邻居掩体句柄 (Right Neighbor ID: uint32)                       |
+-----------------------------------------------------------------------+
```

#### 64-bit 高度轮廓函数设计意图
针对车引擎盖、倾斜瓦砾等表面非平整的掩体，单一的高度标量无法准确反映遮蔽性。系统采用 64 位无符号整数高度压缩 4 个控制点，用分段线性插值表达截面高度变化，确保 AI 蹲伏在其后方时，骨骼探头决策与动画混合完全匹配真实的障碍物外形。

### 5.2 动态障碍物实时适配与掩体图拓扑缝合（Dynamic Adaptation & Merging）

在开放世界中，汽车、垃圾箱、木箱等动态刚体（Dynamic Objects）随时随地会发生位移或被破坏。这要求静态与动态掩体必须具备实时的几何调整、剔除与重连机制。

```
 [ 动态汽车停泊阶段 ]
        
       +-----------------------+
       |   静态障碍物 (Wall)    |
       +-----------+-----------+
       | 静态掩体A | 静态掩体B |
       +-----+-----+-----+-----+
             |           | (被阻挡并失效)
             |           x
             v     +-----+--------------------+
        [延展修补]  | 车辆动态掩体             |
                   |       [ 停靠汽车 (Car) ] |
                   +--------------------------+
```

#### 5.2.1 动态掩体创建与地面贴合（Ground Snapping）
- 当可动实体（如车辆）处于运动状态或被损毁时，其绑定的掩体槽位从 AI 寻路世界中剥离销毁。
- 当车辆完全静止后，其预置的动态掩体被激活。由于车辆静止点可能处于倾斜马路，而掩体槽位可能延伸至人行道台阶，单纯依赖车辆局部坐标系的变换会导致绝对高度异常（若车辆在下、台阶在上，NPC 蹲伏在台阶掩体后头部会从车顶露出来）。因此，**所有动态掩体槽位必须向下发射垂直射线，强制捕捉并对齐到真实的物理地面（Snap to Ground）**，并重新校准局部相对高度。

#### 5.2.2 形状扫掠测试与掩体缝合算法（Shape Casts & Cover Adjustment）
当动态车辆贴近已有静态掩体停靠时，新旧掩体之间可能重叠、交错或形成极小的狭窄死角。系统执行动态掩体缝合流程：

1. **碰撞裁决（Shape Cast Sweep）**：
   - 沿掩体横截面方向，向左（Sweep Left）和向右（Sweep Right）发射一系列几何形状扫掠（Shape Casts）。
   - 检测静态掩体是否已被动态刚体侵占，计算出连续的无阻挡安全区间（Unobstructed Region）。
2. **槽位收缩与禁用（Shrink & Disable）**：
   - 若某一掩体槽位完全被阻挡，该槽位直接禁用。
   - 若被阻挡后剩余的无障碍部分宽度小于独立掩体阈值（$< 1.0\text{ m}$），则该碎片空间不得独立保留；它必须被合并（Stretched / Merged）并入其未被阻挡的邻近掩体槽位中。
3. **多槽位拓扑重组与缝合（Topological Stitching）**：
   - 系统利用最多 2 个相邻掩体的连续无阻挡区域，重新构筑出一个全新的掩体槽位以填补物理缝隙。
   - 重新计算并双向写入新的邻接指针（Left / Right Neighbor IDs），将动态掩体与静态障碍物无缝拼接。NPC 与玩家均可在无需离开掩体态的前提下，平滑自如地在静态墙体与车辆掩体之间完成横向滑动转移（Cover Transit）。

## 6. 工业级实践总结与架构评注（Architectural Takeaways）

在《黑手党 III》的实际工业管线构建中，系统设计体现了高度的务实性与前瞻性，其关键架构模式极具行业参考价值：

1. **分治决策模型（Divide-and-Conquer Control Loop）**：
   - 绝不构建单一庞大（Monolithic）的决策器。行为树（BT）仅作为生命周期的调度器，战术选择交由效用系统（Utility）以浮点数连续打分给出最优倾向，而掩体内外的瞬时动作切换则利用轻量级的决策树（DT）高效定死。
2. **连续拟合替代经验离散（Continuous Piecewise Linear Evaluation）**：
   - 无论是视觉认知的五元函数判定模型，还是三维掩体高度轮廓与感官距离衰减，全线抛弃粗暴的 Hard-coded 魔法数字，统一抽象为分段线性数据驱动模型，最大化赋予内容创作者平衡调整权。
3. **空间几何为首要约束（Spatial Reasoning Primacy）**：
   - 避免将所有认知决策寄托在抽象的黑板数据上。无论是利用 5 个检测点在掩体动画中的自适应向内收敛，还是基于 32 位方向投射（Protection Bitmask）与 64 位高度压缩表达的掩体几何模型，底层的空间几何精度直接决定了高层战术决策的信度。动态掩体的多阶段 Sweeping 缝合算法，更从底层消解了复杂开放世界由于载具位移破坏战术导航拓扑的顽疾。

## 1. 战术位置选择（Position Selection）

在现代 3D 动作游戏与射击游戏中，寻找最具战术优势的掩体或站桩射击点属于典型的高维度空间推理（Spatial Reasoning）与非确定性多项式时间（NP-hard）优化问题。在战斗交火爆发的瞬间，NPC 最稳健的本能反应是就地坚守（Stand its ground）或迅速闪避至最近的障碍物后方。然而，为了维持高对抗性与动态包抄，AI 必须在更广阔的环境空间内展开持续的战术位置搜索。

《黑手党 III》构建了一套通用的**位置评分系统**（Position Evaluation Functions / Generic Scoring System），用于在一组扁平候选点集合（Flat List of Candidates）中完成战术权衡与最优解仲裁。该机制源自经典动作射击游戏的工业实践（Straatman 05），并被通用化扩展为涵盖**战术选点（Position Selection）**、**目标选择（Target Selection）**以及**搜索位点（Searching Positions）**的核心底层管道。

```
                       [ 空间候选点采样空间 ]
          (NavMesh 开阔地网格点 + 构建期生成的静态/动态掩体点)
                                 │
                                 ▼
                     阶段一：空间范围裁剪与过滤
      (基于战术模式 Tactic: 突击 Assault / 支援 Support / 距离阈值剪枝)

                                 │

```

### 1.1 评分系统数学模型与聚合算子

位置评分系统的输入为一个候选位置集合 $\{P_k\}$ 以及一组评分函数族 $\{f_0, f_1, \dots, f_n\}$。每个评分函数从游戏引擎上下文中抽取特定环境状态事实（如与当前位置的几何距离、对玩家的射击线敞开度、玩家火力威胁下的掩体遮蔽角等），并将其映射为一个归一化标量值。

候选位置的最终综合评分公式定义如下：

$$\text{score} = \text{baseValue} \cdot \prod_{i=0}^{n} f_i$$

- $\text{baseValue}$：候选位置的初始基准分值（由战术角色或初始权重指定）。
- $f_i \in [0, 1]$：第 $i$ 项评分函数的归一化输出因子。

#### 乘法聚合模型（Multiplicative Model）的架构决策与权衡
工业界在设计效用评分系统（Utility Systems）时，常用的聚合算子包括加权平均（Weighted Average）、算术均值（Arithmetic Mean）、累加求和（Summation）以及连乘积（Product）。在射击游戏 AI 中选择**连乘积**的核心工程逻辑如下：

1. **绝对否定权（Veto Power / Deal-Breaker）**：
   若某项评分为 $0$（例如某位置正处于玩家持续倾泻火力的直接弹道上，或对敌射击线完全被掩体锁死），连乘积能够瞬间将总评分清零：
   $$\exists i, \, f_i = 0 \implies \text{score} = 0$$
   加权平均或累加模型通常难以彻底消除单项致命缺陷，除非引入复杂的额外条件分支（Branching Guards）或惩罚常数，这会导致调优逻辑迅速失控（Lewis 15）。
2. **多指标协同衰减（Synergistic Degradation）**：
   即使各项指标仅有轻微次优表现（如各项因子均为 $0.7$），在经过多层函数累乘后整体分值将显著受抑，从而优先凸显各方面均表现均衡的“完美点位”。

## 2. 搜索空间受限与分层管道剪枝优化

在包含复杂城市环境与密集掩体资产的大型开放世界中，若在全局导航网格（NavMesh）上对所有可能点位进行无差别空间遍历，其 CPU 时间复杂度与主线程帧预算开销将完全不可接受，即便实施了时间切片（Time Slicing）机制。

### 2.1 战术驱动的搜索空间裁剪（Limiting the Search）

系统依据 NPC 当前正在执行的高阶战术（Current Active Tactic）来动态收敛搜索空间的原点与半径：

- **突击战术（Assault Tactic）/ 侧翼包抄（Flanking）**：搜索圆心锚定在目标（如玩家）周围的一定半径内，迫使 AI 在玩家侧翼及外围寻找施压站位。
- **支援战术（Support Tactic）**：搜索圆心锚定在 NPC 自身坐标周围，使其偏向就近寻找提供远程火力覆盖或防护掩护的防御据点。

### 2.2 候选点生成拓扑机制

《黑手党 III》结合了 Havok 导航网格与离线预计算资产：
1. **开阔地候选点（Open Space Candidates）**：在战斗运行时于以搜索锚点为中心的网格（Grid）中动态采样，并利用启发式拓扑连通性进行距离过滤。
2. **掩体候选点（Cover Positions）**：在离线烘焙/构建期（Build Time）围绕场景中的静态几何体与动态物理障碍物边缘自动生成，记录掩体朝向、高低掩体分类（Low/High Cover）及有效防护角扇区。

### 2.3 分层级联过滤流水线（Hierarchical Cascaded Pipeline）

在密集的城区战术交火场景中，即使搜索半径限制在 6 到 15 米内，候选点数量依然庞大：
- 近战特化模板（Melee Archetype）：在玩家周围 $6\text{ m}$ 半径内采样约 120 个候选点。
- 基础枪手模板（Triggerman Archetype）：在执行突击战术时，需搜集自身 $15\text{ m}$ 半径内所有预烘焙掩体点，外加 120 个开阔地网格点，在复杂关卡中单次查询候选点总量常达 **300 个**。

为杜绝在高频位置选择中执行数百次物理光线投射（Raycasts）与寻路图搜索（A* Path Queries），系统采用了分阶段逐步递进的过滤流程：

```
+-------------------------------------------------------------------------+
| [初始阶段] 遍历所有原始候选点 (例如 300 个候选点)                           |
|  - 执行低开销数学评估：计算欧氏距离、类型分类（掩体/开阔）、基础朝向           |
|  - 输出阶段性局部评分 Partial Score                                      |
+-------------------------------------------------------------------------+
                                    │
                                    ▼ 截断至战术配置阈值 (Top 50)
+-------------------------------------------------------------------------+
| [中间阶段] 物理射线检测 (Raycast Phase)                                   |
|  - 仅针对排名前 50 的候选点进行场景几何碰撞查询                             |
|  - 验证对玩家视线掩蔽度 (LoS) 与射击线 (Line of Fire)                     |
+-------------------------------------------------------------------------+
                                    │
                                    ▼ 再次截断至顶层集合 (Top 20)
+-------------------------------------------------------------------------+
| [最终阶段] 完整路径精算 (Full Path Search Phase)                          |
|  - 仅对得分最高的 20 个候选点发起 Havok NavMesh 完整路径搜索              |
|  - 测定精确折线距离（Pathing Distance）及跨越障碍的通行可行性             |
+-------------------------------------------------------------------------+
```

### 2.4 级联裁剪风险与调试诊断机制（"Would be removed" 架构）

*局部贪心淘汰陷阱（Local Optimum Pruning Failure）*：基于阶段性评分提前过滤存在潜在风险——某个候选点可能在几何距离上略逊一筹，但在后续的射击线与防护角度上具有绝对战术价值。若在前期被武断抛弃，全局最优解将被丢弃。

工程应对方案：
1. **参数化配置（Tactic Configuration）**：各阶段保留点位配额（如 50、20）由数据驱动的战术配置表显式定义，设计人员可根据兵种特征平衡计算精度与帧率。
2. **离线与开发期断言检测机制**：
   在开发调试版本（Development Builds）中，底层流水线开启一种非破坏性旁路检测模式：
   - 当某候选点在早期阶段达到过滤淘汰线时，系统**不将其移出队列**，而是赋予其 `Would be removed` 标记，并允许其跟随全量流水线继续执行后续所有高开销函数。
   - 在流程终点，系统计算所有候选点的最终真实得分。若最终入选的最佳候选点集合（Top Subset）中包含了任何带有 `Would be removed` 标记的点，底层即触发断言（Assert），输出调用栈与环境拓扑数据，供 AI 工程师与关卡设计师精准定位排序函数或阈值设定的缺陷。

## 3. 评分函数的工业工程调优准则

### 3.1 归一化响应曲线：分段线性函数（Piecewise Linear Functions）

游戏内所有评分函数通常需将输入维度映射至 $[0.0, 1.0]$ 区间。《黑手党 III》选择分段线性函数（Piecewise Linear Functions）作为主要的响应曲线构造手段，而非高阶多项式或样条函数。

```
Score (y)
 1.0 ┼───────────────╭───────╮
     │              /         \
     │             /           \
 0.5 │            /             \
     │           /               \
 0.0 ┼──────────╯                 ╰─────────────
     └──────────┬────┬───────────┬─────────────► Distance (x)
               x0   x1          x2
```

其工程裁量依据包括：
- **直观易读且免工具依赖**：设计师只需在配置表（如 JSON/XML）中填入拐点数组 $[(x_0, y_0), (x_1, y_1), \dots, (x_n, y_n)]$，无需强依赖专用的曲线编辑器工具（如 Curvature 等，Lewis 18）。
- **极低的运行时开销**：求值仅需一维线性插值（LERP），无复杂代数或浮点三角运算，利于 SIMD 并行矢量化处理。

### 3.2 极简原则（"Less is more"）与剪枝调优

在工业级战术评分系统的迭代过程中，工程师常倾向于通过持续追加评分函数来修复偶发的边缘案例子（Edge Cases）。实践表明，过多的评分因子会导致多维特征空间相互耦合、彼此抵消，产生无法预测的异常决策。《黑手党 III》确立的设计法则是：
1. **最小充分集**：优先从极少数关键评分函数起步。
2. **剔除冗余**：当 AI 选点出现战术误判时，首要手段是审查现有评分列表并剔除非核心条件，而非引入新函数。

### 3.3 游戏内可视化调试（In-Game Debug Draw）

空间推理黑盒必须通过高密度的可视化运行时信息进行暴露（Gregory 14）：
- **球体颜色编码（Color Coding）**：
  - 红色球体（Red）：不可达点位（Unaccessible / 拓扑连通失败）。
  - 灰色球体（Gray）：未通过阶段阈值淘汰的非候选点。
  - 绿色球体（Green）：进入最终优选集的有效点。
- **亮度标定（Brightness Scaling）**：绿色球体的发射亮度与最终综合评分成正比，全局最亮点即为系统仲裁的最优解。
- **近距 HUD 文本转储**：针对距离游戏摄像机 $5\text{ m}$ 范围内的所有候选点，在 3D 屏幕空间实时打印其输入特征源数据、各分段函数得分因子及公式乘积演算过程。

## 4. 应对动态世界：状态维持与重选机制

在高速对抗的动作环境中，世界状态时刻处于震荡之中（例如玩家在 NPC 规划就位前已大范围位移）。为使 AI 的空间抉择具备连贯性与鲁棒性，系统在架构上分离了**全局初始搜索（Full Search）**与**选中点运行时维护（Selected Position Update）**两套逻辑。

### 4.1 全量重搜与局部更新的开销隔离

NPC 绝不可在跑位过程中每帧发起全量位置评估，否则将耗尽运算资源。系统引入了双频更新架构：
- **低频全量搜索（Full Search）**：周期极长（典型情况下 NPC 每 $12\text{ s}$ 仅触发一次新位置重选）。
- **高频选中点校验（Selected Position Update）**：帧率相对较高（如以 $5\text{ Hz}$，即每秒 5 次的频率追踪并刷新当前目标位置的分值）。

两套体系所执行的评分函数拓扑各异：

| 评估指标（Scoring Function） | 全量初始搜索（Full Search） | 运行时状态更新（Update） | 工业工程决策依据 |
| :--- | :---: | :---: | :--- |
| **与敌欧氏距离（Distance to enemies）** | **✓** | **✓** | 确保目标未逼近至自身安全距离以内 |
| **对敌射击线（Line of fire to enemies）** | **✓** | **✓** | 确保所朝向的掩体仍能维持对敌视线窗口 |
| **对敌掩护遮蔽（Cover from enemies）** | **✓** | **✓** | 确保所选掩体未因玩家位移而产生侧向暴露 |
| **距自身路径距离（Path distance from self）** | **✓** | — | **移出更新列表**：NPC 既已起跑，原始路径代价已成沉没成本 |
| **在当前点停留时长（Time spent in position）** | — | **✓** | **动态疲劳惩罚**：随驻留时间拉长逐步扣减分值，迫使其适时机动 |

### 4.2 剧烈分值跌落与状态机回退决策

当 NPC 沿 NavMesh 奔向选定点位的过程中，由于玩家位移或掩体破坏，导致当前追踪点位的综合得分发生突降（通常阈值设定为**相对分值跌落超过 50%**）：
1. **立即中止路径追踪**：系统判定该目标点已丧失战术价值，丢弃该位置目标。
2. **行为树切入开阔地默认行为（Default Open Space Behavior）**：
   - NPC 立即制动刹车，停留在原地开阔空间并展开站立/蹲伏还击。
   - **架构实验反思**：团队曾实验过“边跑向失效掩体边在后台异步重搜新掩体，并动态重定向路径”的方案。实机表现表明，该逻辑会导致 NPC 在战场中由于目标频繁突变而表现出怪异的急转与游移（Erratic Movement）。相比之下，“原地急停并向玩家对射”的决断动作在感官认知上更具果敢性（Decisive），也避免了 NPC 盲目冲入已被玩家火力架死的无防护掩体中。

## 5. 通用化扩展：目标选择与射击验证系统

### 5.1 目标选择系统（Target Selection）

目标选择完全复用了位置选择的**通用评分流水线（Generic Scoring System）**，仅改变了候选实体类型与专有评分函数簇：
- **候选实体池**：除真实玩家实体与敌对 NPC 外，系统显式支持**虚拟目标（Virtual Targets）**（例如 NPC 基于感知推理预测玩家即将现身的走廊拐角、窗口或门洞）。
- **执行效率优势**：由于同屏潜在目标实体数量通常极少（通常 $< 10$ 个），目标选择的评估压力远小于位置选择，能在几乎无延迟惩罚下高频运算。

### 5.2 射击决策解耦与逐帧验证架构（Shooting and Aiming）

在射击系统设计中，AI 的痛点并非“如何击中目标”，而是“如何合乎逻辑且受控地描边脱靶”。在帧率与架构控制上，《黑手党 III》将射击系统严格切分为两个异步层级：

```
+-------------------------------------------------------------+
| 决策层：行为树 (Behavior Tree) [低频更新 5~10 Hz]              |
|  - 仅负责战略意图判定：何时开火、何时停火、锁定谁为主要目标   |
|  - 将目标引用 (Target) 与一组射击验证函数管线传递给底层         |
+-------------------------------------------------------------+
                              │
                              ▼ 提交目标与验证函数族
+-------------------------------------------------------------+
| 执行层：射击核心引擎 (Shooting Game Code) [逐帧更新 Tick 60 Hz] |
|  - 负责物理瞄准转向 (Aiming)、骨骼动画匹配 (IK/Animation)     |
|  - 在触发实际扣动扳机 (Pull the trigger) 前遍历执行校验函数族  |
|  - 任意函数返回 false，立即阻断当帧射击行为                    |
+-------------------------------------------------------------+
```

#### 核心逐帧射击验证函数（Validation Functions）：
1. **射击风格限制（Shooting Style）**：
   - 控制武器开火节奏、单发瞄准前摇时延及连发间歇。
   - *案例（狙击手特化）*：狙击手在骨骼朝向对齐玩家后仅需 $0.5\text{ s}$ 即可击发，但射击风格强行注入一个 $\ge 2.0\text{ s}$ 的瞄准等待窗口，在此期间输出红外激光瞄准线，为玩家创造闪避与反制空档。
2. **友军保护逻辑（Ally Protection）**：
   - 自枪口向目标发射圆柱体或球形射线扫掠（Sweep Check）。若任何友方 NPC 的碰撞体处于该射击弹道（Line of Fire）内部，当帧强制禁断开火，杜绝误伤。
3. **玩家剧情保护逻辑（Player Protection）**：
   - 响应全局剧情与脚本交互状态。例如当玩家处于“据点首领处决质问（Hideout Boss Interrogation）”等不可控的特定 QTE/交互动画状态时，无条件屏蔽一切外围杂兵对玩家的弹道伤害。

## 6. 全局系统整合与架构拓扑

驱动动态战术 AI 的关键，在于将上述分散的子系统整合为一个结构清晰的运行实体。《黑手党 III》构建了一套**“行为树驱动意图管线，决策树特化微观战术”**的分层混合架构。

```
                       [ 战术黑板 Blackboard ]
               (战术模式: Assault / Reserve / Support)
                                 │
                                 ▼
                     ┌───────────────────────┐
                     │ 行为树 Behavior Tree  │
                     │ (驱动宏观战术状态转移)  │
                     └───────────┬───────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 │ 派遣执行战术序列 (Sequence)    │
                 ▼                               ▼
       [ 走出载具 / 翻越 ]               [ 路径导航定位到位 ]
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                                 ▼
         ┌────────────────────────────────────────────────┐
         │       掩体动作微观决策：嵌入式决策树            │
         │           (Decision Tree / DT)                 │
         └───────────────────────┬────────────────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        ▼                        ▼                        ▼
[ 持续掩蔽循环动画 ]       [ 探头侦察探查玩家 ]     [ 探身开火/盲射抑制 ]
(Loop Hide Anim)        (Peek & Check Player)      (Lean & Suppress)
```

### 6.1 行为树（BT）与决策树（DT）的正交解耦

在掩体内具体执行何种战术微操作时，团队并未直接使用行为树展开庞杂的子树分支，而是嵌入了**轻量级决策树（Decision Tree）**（见文内图 7 所示的工作室自研可视化编辑决策树系统）：

- **行为树（Behavior Tree）职责**：定义“如何去执行”（*How to do it*）。负责需要持续数秒的长程时序动作控制流，例如“跳出轿车 $\to$ 运行战术选点 $\to$ 沿路径奔向掩体 $\to$ 执行进入掩体姿态动画”。
- **决策树（Decision Tree）职责**：定义“当下选择做什么”（*What to do*）。负责瞬间状态求值，输出短平快的离散意图提示（Hint）。

#### 战术解耦运作实例：
假设一名处于“预备/保留（Reserve）”战术的 NPC 已抵达掩体内部：
1. **意图检索**：行为树在掩体挂起状态下向“预备战术决策树”索取操作建议。
2. **规则裁决**：决策树依据感知计时器，发觉 NPC 刚躲入掩体，输入返回：`Keep Hiding`。
3. **动作执行**：行为树获取该意向，驱动底层播放一段抱头隐蔽循环动画。
4. **状态轮询**：动画周期结束，行为树再次查询决策树。此时决策树判定距离上次目视玩家已过去数秒，返回：`Look for Player`。
5. **执行分发**：行为树立即切换至探头观察动画。

该解耦方式使策划在添加全新战术（Tactics）或微调某兵种在掩体内的攻防逻辑时，**无需修改任何行为树的拓扑结构**，彻底消除了巨型行为树状态爆炸与并发维护风险。

## 7. 工业生产实践结论与工程启示

《黑手党 III》的战术战斗系统在工业化高规格生产落地中，凝练了以下核心工程范式：

1. **信息决定决策质量（Data Quality Over Model Complexity）**：
   无论上层决策机制采用行为树、效用系统还是状态机，决策的合理性从根本上取决于空间支撑系统（选点、视野、威胁拓扑）所喂入的数据质量。保持选点与目标选择模块的高内聚与低耦合，建立严格的职责边界，在项目临近交付（Shipping Phase）阶段具有极高的排错与替换容错度。
2. **全量数据驱动（Data-Driven Architecture）**：
   将所有的评分阈值、搜索配额（50/20 淘汰截断）、分段线性响应曲线均抽离至数据配置文件中，赋予战斗设计团队无需重新编译代码即可自由迭代敌兵战斗表现的完整自由度。
3. **数据继承机制应对组合爆炸（Inheritance Model for Archetypes）**：
   《黑手党 III》最终交付了 **18 种基础兵种原型（Base Archetypes）**，并在此基础上派生出 **120 种变体（Variations）**。若每个变体均从零配置全部评分参数，系统维护成本将不可控。系统引入了强类型的数据继承系统（Data Inheritance），使绝大多数兵种变体只需针对父模板覆盖（Override）少数几条差异化的阈值曲线，在兼顾多样性的同时保持了资产管线的整洁稳定。
