## 18.1 引言与底层物理映射本质（Introduction）

在现代商业游戏 AI 架构设计中，寻路规划架构（Path Planning Architecture）的技术选型直接决定了游戏运行时的核心能力边界与工程成本。正如工业界与学术界的广泛研讨所指出的，不同空间表征方案在支持动态阻挡、高精度平滑、内存开销以及多智能体协同等特性时，其实现复杂度与运行性能存在显著鸿沟。

```
   物理世界 / 碰撞几何体 (Physics / Collision Geometry)
                    │
                    ▼ [空间离散化与抽象 (Spatial Abstraction)]
     ┌──────────────┼──────────────┐
     ▼              ▼              ▼
栅格系统 (Grids)  路径点图 (Waypoints)  导航网格 (NavMesh)
```

从系统架构层面来看，所有可行的路径规划架构本质上都是**对游戏角色可行走物理空间的降维与结构化抽象（Spatial Abstraction）**。游戏引擎中的物理模拟系统（Physics Simulation System）通常依赖于高度精细的刚体碰撞体（Rigid Bodies）、凸包网格（Convex Hulls）或物理网格碰撞体（Mesh Colliders）。这些碰撞数据在计算复杂度和几何结构上无法直接作为寻路图搜索的状态空间（Search State Space）。因此，空间表征选型的核心技术本质在于：**哪一种抽象表征能够以最低的内存与计算代价，最精确地匹配游戏世界的底层物理规则与几何约束**。

工业界最核心的三种主流空间表征技术方案包括：
1. **栅格系统（Grids）**
2. **路径点图（Waypoint Graphs）**
3. **导航网格（Navigation Meshes, 简称 NavMesh）**

## 18.2 评估任务与全生命周期考量（Tasks & Evaluation Metrics）

评估与选型路径规划表征架构时，必须建立覆盖算法生命周期的全维度评估模型：

```
[空间坐标拾取] ──> [图元定位(Localization)] ──> [启发式寻路规划(Planning)]
                                                        │
[动态修改/热更新] <── [物理平滑/执行(Smoothing/Following)] <──┘
```

1. **内存占用（Memory Usage）**：表征数据在构建期及运行期的内存占用空间，包含节点元数据、拓扑连接邻接表与加速查询索引。
2. **空间定位（Localization）**：从游戏世界物理连续坐标（World Coordinates, 向量形式 $\vec{p} = (x, y, z)$）映射到寻路底层原生图元（单元格、凸多边形或路径点节点）的计算开销与算法确定性。
3. **寻路规划（Path Planning）**：在状态拓扑图 $G = (V, E)$ 上求解两个图元间最低代价通行路径的算法复杂度与搜索状态空间大小。
4. **路径平滑与路径跟随（Path Smoothing and Path Following）**：消除规划离散路径中的折角、对称伪影或几何断点，使其适配智能体动力学控制、局部避障（Steering Behaviors）以及高品质运动匹配骨骼动画（Motion Matching / Locomotion Animation）的后期处理成本。
5. **动态修改（Dynamic Modification）**：在游戏运行时应对环境变化（如建筑物坍塌、门锁启闭、动态障碍放置、陷阱感知）时，热更新空间表征拓扑的开销与同步延迟。
6. **工程落地周期（Implementation & Debugging Time）**：从算法开发、边界测试到专用管线工具链开发的人力成本。
7. **通用 AI 空间推理辅助（Spatial Reasoning Queries）**：空间表征对高阶战术查询的支撑能力，例如战斗阵型分布（Battle Positioning）、掩体评定（Cover Evaluation）、建筑建造选址（Base Building）等环境推理能力。

## 18.3 栅格系统（Grids）

### 18.3.1 架构原理与实现机制

栅格系统将连续空间离散化为规则的均质单元矩阵。最基础的二维实现采用由可通行标识构成的紧凑数组，进阶实现则向单元格注入法线斜率（Slope）、地形材质代价（Terrain Traversal Cost）及战术影响图权重（Influence Map Weight）。

```
+---+---+---+---+---+
| 0 | 0 | 1 | 0 | 0 |   0: 可通行 (Traversable)
+---+---+---+---+---+   1: 阻挡 (Blocked)
| 0 | 1 | 1 | 0 | 0 |   T: 动态陷阱 (Dynamic Trap, Cost > 1)
+---+---+---+---+---+
| 0 | 0 | T | 0 | 0 |
+---+---+---+---+---+
```

三维空间栅格可利用多层高度图或稀疏三维体素栅格（Sparse 3D Grids）实现，将离散层按需挂载到稀疏哈希表或八叉树结构中，以控制三维体素膨胀导致的内存开销。

### 18.3.2 优势分析（Pros）

* **极低的开发与调试门槛**：数据结构直观，常规二维带权 $A^*$ 寻路系统在数小时内即可完成工业级原型开发。
* **极佳的外置化与免工具链特性**：天然兼容纯文本或位图编辑，关卡策划可直接使用轻量级外部图像或文本编辑器完成关卡原型设计，省去定制网格生成工具链的繁重工期。
* **高效的局部动态通行代价更新**：地表代价可在 $O(1)$ 时间复杂度内完成动态覆写。
* **低开销的可行状态切换**：动态障碍物生成或消除仅需翻转目标单元格的状态位。
* **近乎零成本的坐标定位（Localization）**：给定世界坐标 $(x, z)$、地图偏移原点 $(x_0, z_0)$ 与单元格分辨率 $r$，仅需常规代数除法与向下取整操作即可完成瞬时定位：
  $$Cell_x = \left\lfloor \frac{x - x_0}{r} \right\rfloor, \quad Cell_z = \left\lfloor \frac{z - z_0}{r} \right\rfloor$$

### 18.3.3 缺陷分析（Cons）

* **大体量世界下的高内存负荷**：对于庞大的开放世界（如 MMORPG），密集阵列会带来严重的内存占用。即便采用稀疏栅格压缩技术，空旷不可行空间的索引开销依然可观。
* **运动伪影与平滑代价**：网格搜索路径天然受到 $45^\circ$ 与 $90^\circ$ 离散邻域的拓扑限制，必须在后处理阶段引入基于视线追踪（Line-of-Sight）的拉直裁剪，或在规划期间执行任意角度寻路算法（Any-Angle Path Planning，如 $\text{Theta}^*$）。
* **细粒度状态爆炸引发搜索性能损耗**：细颗粒度栅格使得状态节点集 $|V|$ 显著膨胀。在未应用抽象层次架构（Hierarchical Abstraction / HPA*）时，远距离搜索极易引发性能瓶颈。
* **拓扑对称路径（Symmetric Paths）导致的冗余扩展**：在开阔地形中，等长且代价值相同的折线排列会导致开集（Open Set）反复扩展等效节点。必须集成跳点搜索（Jump Point Search, JPS）等剪枝算法以消除对称性。

## 18.4 路径点图（Waypoint Graphs）

### 18.4.1 架构原理与实现机制

路径点图将可行走空间抽象为由人工显式布设或稀疏采样提取的图结构 $G = (V, E)$。其关键特征在于：**图中的拓扑节点与物理可行走连续空间之间不存在显式的双射几何映射（Explicit Mapping）**，节点仅表示局部空间中具备战略或通行意义的离散参考坐标点。

```
 (WP1)●───────────────────●(WP2)
       \                 /
        \    [障碍物]    /
         \   ┌─────┐   /
          \  └─────┘  /
           ●─────────●
         (WP3)     (WP4)
```

### 18.4.2 优势分析（Pros）

* **拓扑实现清晰轻量**：以标准邻接表或边列表存储图元，逻辑架构极为纯粹。
* **对离散已知触发事件更新友好**：对于预设的动态交互对象（如受脚本控制的闭合门禁），只需在编辑器中预先关联对应的边 $e \in E$，运行时执行开关标记即可。
* **内存占用极小与图搜索极快**：点集与边集数量仅占连续空间几何体很小的比例，极度紧凑的搜索空间带来极短的 $A^*$ 耗时。

### 18.4.3 缺陷分析（Cons）

* **路径品质严重依赖密度，兼顾代价高昂**：边数量不足会导致角色绕远或行动轨迹僵硬，过度增加边又会导致存储与规划开销剧增。
* **严重依赖高成本人工布点调试**：为避免角色穿模撞墙，常需关卡设计师逐点手工摆放并测试连通性，人工维护负担巨大。
* **定位困难与“脱轨（Off-graph）”死锁**：当角色因受击击飞、物理布娃娃系统（Ragdoll）或刚体挤压脱离预定图元范围时，系统很难在无几何拓扑支撑的物理空间中准确推导出其归属节点。
* **脱离拓扑平滑极易引发物理穿模**：在后处理阶段若强行拉直跨节点的路径点，极易因缺乏边界碰撞包络检测而导致角色卡入物理碰撞体内。
* **对非预置动态环境变化的响应极度匮乏**：若场景发生非预置的物理形变（如场景爆破在墙体上轰出缺口），动态重建节点及对周围所有邻近连接执行穿透射线检测（Raycast Validation）的计算成本极高。

## 18.5 导航网格（Navigation Meshes）

### 18.5.1 架构原理与实现机制

导航网格采用二维或二维半凸多边形集合（Convex Polygons）覆盖整个场景的可行走物理表面。由于任意凸多边形内部任意两点间连线均落在多边形内部，智能体在多边形内部移动具有天然的直线通行保真度。导航网格的特例之一是**约束德劳内三角网（Constrained Delaunay Triangulation, CDT）**，其将通行区域严格离散为三角形基元。从广义几何拓扑来看，二维均匀栅格亦可视为由规则矩形组成的特殊凸多边形网格，但在工业界实践中，非结构化非均匀分布的凸多边形网格代表了完全不同的工程方向。

```
 ┌─────────────────┬──────────────────────┐
 │                 │                      │
 │    Polygon A    │      Polygon B       │
 │                 │                      │
 └────────┬────────┴─────────┬────────────┘
           \    共享传送门   /
            \  (Shared Portal)
             \             /
              ┌───────────┴──────────────┐
              │                          │
              │        Polygon C         │
              └──────────────────────────┘
```

### 18.5.2 优势分析（Pros）

* **非栅格对齐的高保真几何匹配**：完全脱离轴对齐栅格边界的束缚，能精确贴合复杂、倾斜与多边形场景物理几何表面。
* **高效安全的连续平滑与轨迹生成**：依托多边形凸性，角色在跨越相邻多边形共享边（Portals）时，可直接采用漏斗算法（String Pulling / Funnel Algorithm）快速求解最短折线路径，平滑过程不会引发碰撞穿模。
* **兼顾大尺度粗粒度图搜索与全方向（Any-angle）机动**：凸多边形能够吞吐大面积开阔区域，图节点数量大幅缩减，从而大幅提升远距离宏观路径规划的性能。
* **极佳的内存占用**：即使对于面积庞大的复杂地表，仅需少量大尺寸凸多边形即可完成全覆盖。

### 18.5.3 缺陷分析（Cons）

* **系统架构与算法工程实现极其复杂**：涵盖三维模型体素化、轮廓过滤、轮廓分割及凸多边形划分等完整生成管线（如工业界成熟的 Recast 开源方案）。自行研发该管线通常需要数月乃至更长的高精度开发投入。
* **计算几何特异性断裂与浮点精度陷阱**：在多边形切割与三角化计算中，极易因浮点数误差出现共线退化、近平行线相交失效等几何计算边界问题。
* **运行时动态修改计算开销较高**：在场景中插入动态阻挡体（NavMesh Obstacle）涉及局部的几何布尔运算（Boolean Subtraction）与重新多边形化，其计算开销远超简单的位操作更新。
* **多边形定位需要辅助加速结构**：在非均匀多边形中定位点坐标需要耗费计算资源。生产环境通常需要引入二阶段空间查询系统，挂载低精度分桶栅格（Bucket Grids）或 BVH 树构建加速索引。

## 18.6 选型决策全景对比与工业级落地指南（Conclusion & Engineering Trade-offs）

### 18.6.1 空间表征技术维度多方权衡

| 技术考量维度 | 栅格系统 (Grids) | 路径点图 (Waypoint Graphs) | 导航网格 (Navigation Meshes) |
| :--- | :--- | :--- | :--- |
| **内存占用 (Memory Usage)** | 高（密集矩阵随地图尺寸几何膨胀） | 低（仅保留稀疏点集与邻接表） | 低至中（大空间凸多边形合并压缩率高） |
| **空间定位复杂度 (Localization)** | $O(1)$，通过坐标除法与向下取整瞬时映射 | 较慢，需遍历邻域节点或构建空间加速结构 | 依赖空间索引结构（如 BVH 或定位栅格加速） |
| **路径规划性能 (Path Planning)** | 中至低（节点细密易导致状态空间爆炸） | 极快（节点集极度精简） | 快（基于宏观凸多边形双重图 Dual Graph 搜索） |
| **路径平滑品质 (Path Smoothing)** | 差（需依赖后处理拉直或 $\text{Theta}^*$ 消除离散折角） | 极差（脱网平滑极易导致物理穿模） | 极佳（基于共享边漏斗算法，保真贴合） |
| **动态阻挡更新 (Dynamic Updates)** | 极快（单点标记重算，开销极低） | 仅支持已知预设边；意外开洞/修改开销极高 | 较高（需局部多边形布尔剔除或重嵌切片） |
| **空间推理友好度 (Spatial Reasoning)**| 极佳（天然支持战场影响图与距离变换场计算）| 极低（缺乏空间边界几何物理上下文） | 高（利于覆盖区域查询，但连续张量场较难离散）|
| **研发与调试周期 (Dev & Debug Time)** | 极低（数小时内可出可运行原型，直观透明）| 低至中（数据易写，但人工布点维护繁复） | 极高（需依赖成熟中间件或投入数月开发） |

### 18.6.2 工业级实战选型决策流

根据项目类型、工程约束与运行物理特性的选型决策步骤如下：

```
[开始项目技术选型]
       │
       ▼
物理核心是否为平坦二维空间且环境高度动态？
(如：塔防、RTS、大型战棋游戏)
       │───[是]───> 【栅格系统 (Grids)】
       │            ├─ 配合 JPS / HPA* 解决性能与对称性瓶颈
       │            └─ 配合影响图 (Influence Map) 实现战术选址
       ▼ [否]
工程研发周期是否极度受限且仅需低保真宏观移动？
(如：小团队敏捷开发、预设廊道漫游、低成本室内 AI)
       │───[是]───> 【路径点图 (Waypoint Graphs)】
       │            ├─ 确保路径点全部手工校验，避免非预置动态穿模
       │            └─ 对门禁、电梯等预置交互直接硬编码关联边
       ▼ [否]
需要支持高度复杂的 3D 物理交互、高质量动画与自由角度寻路？
(如：3A 级动作角色扮演、大型拟真射击、复杂开阔大世界)
       │───[是]───> 【导航网格 (Navigation Meshes)】
       │            ├─ 引入成熟开源方案 (如 Recast/Detour) 避免重复造轮子
       │            └─ 搭建基于加速网格的分层定位 (Localization) 索引
       ▼
```

### 18.6.3 选型经验总结与架构落地法则

1. **栅格系统（Grids）的黄金区间**：游戏底层运行机制本质是二维空间，世界状态呈现高频动态读写特性（例如玩家可自由放置炮塔、施放地形范围法术破坏地貌），且设备内存允许分配连续矩阵。在这些场景中，栅格能够大幅压低工程维护成本。
2. **路径点图（Waypoint Graphs）的生存空间**：适合在极度受限的开发周期中，为空间结构相对固化、对物理边界容错率高、且无须精确动画贴合的轻量级项目提供极度低成本的原型闭环。
3. **导航网格（NavMesh）的工业标准统治地位**：在当今主流商业三维游戏开发中，若项目对角色的运动表现有严格要求（包括平滑转弯、贴合障碍物边缘潜行、动态姿态解算），导航网格是不可替代的基石架构。尽管其算法构建门槛极高，但借助成熟的中间件工具链（如 Recast & Detour）可以规避大部分底层几何断裂与浮点退化陷阱。

在大型游戏系统研发中，架构师的核心使命是在**开发人员工期成本投入**与**游戏体验技术上限**之间寻求动态平衡。深刻理解三种表征背后的几何数学与物理抽象机制，是保障寻路子系统长期可维护性、高并发吞吐与平滑物理表现的关键前提。
