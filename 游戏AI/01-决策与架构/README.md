## 1. 核心定位与设计思想

「01-决策与架构」负责游戏 AI 的**核心认知与决策推理层（Decision & Reasoning Core）**。

其核心命题是回答：“面对动态演变的世界局势与玩家行为，智能体应该**感知什么、记住什么、并在有限帧时隙内决定做什么**”：

- **感知与黑板契约（Perception & Blackboard）**：将分散的视锥几何、听觉距离衰减与物理碰撞转化为结构化的刺激事件（Stimulus），通过黑板（Blackboard）提供类型安全、带遗忘衰减的共享数据总线；
- **全谱系经典决策技术**：系统覆盖从离散确定的有限/层次状态机（FSM/HSM）、工业级分层任务执行的行为树（Behavior Tree），到连续多需求权衡的效用 AI（Utility AI）、目标逆向推演的 GOAP/HTN、完全/不完全信息博弈搜索（Minimax/Alpha-Beta/MCTS）、模糊逻辑连续控制（Fuzzy Logic），以及社会化拟人人格与对话系统（OCEAN/Dialogue Tree）；
- **引擎无关的通用抽象**：以严谨伪代码与标准设计模式阐明算法机理，与引擎客户端具体组件解耦，作为全栈开发者（客户端、服务端、AI 策划）共同的心智模型。

## 3. 逻辑学习顺序与推导闭环

```mermaid
flowchart TD
    A[01 AI总体架构与感知<br/>感知锥/黑板契约/分频] --> B[02 状态机与层次状态机<br/>离散状态/HSM继承]
    A --> C[03 行为树通用原理<br/>组合/装饰打断/任务]
    B --> D[04 Utility与GOAP<br/>连续评分/逆向目标规划]
    C --> D
    A --> E[06 模糊逻辑与连续决策<br/>模糊规则/动态威胁评估]
    D --> F[05 博弈搜索与对战AI<br/>Minimax/Alpha-Beta/MCTS]
    C --> G[07 NPC人格对话与社交AI<br/>大五人格/对话树/关系网]
    D --> G
```

1. **第一阶段（体系地基）**：必读 `01-AI总体架构与感知`，建立“感知 → 记忆 → 决策 → 动作”的通用时序模型，搞清 AI 更新频率（Tick Interval）与渲染帧率的解耦机制；
2. **第二阶段（工业核心主流）**：精读 `02-状态机与层次状态机` 与 `03-行为树通用原理`，理解离散状态转换与分层树状任务遍历的区别，掌握商业项目中最核心的行为树被打断（Abort）机制；
3. **第三阶段（复杂意图与规划）**：攻克 `04-Utility与GOAP`，理解模拟人生式的意图涌现（Utility）与极度恐慌式的逆向动作推导（GOAP/HTN），解决行为树条件分支爆炸的痛点；
4. **第四阶段（专业与专项领域）**：
   - 战局态势感知：研读 `06-模糊逻辑与连续决策`；
   - 回合对战与棋牌策略：研读 `05-博弈搜索与对战AI`；
   - 叙事交互与社会化 NPC：研读 `07-NPC人格对话与社交AI`。

## 4. 决策技术横向选型与工程落地

| 维度 | FSM / HSM | 行为树 (BT) | 效用 AI (Utility) | GOAP / HTN |
| :--- | :--- | :--- | :--- | :--- |
| **思维模型** | “我在什么状态，发生事件去哪” | “我从左到右尝试，谁能执行跑谁” | “当前局面下，所有可选动作谁分最高” | “我的最终目标是什么，逆向搜索行动链” |
| **状态爆炸风险** | 极高（$O(N^2)$ 转移连线） | 极低（树状模块化隔离） | 无（各动作独立评分） | 低（定义动作的前置与后置即可） |
| **策划友好度** | 中（状态多时连线成乱麻） | 极高（可视化强，逻辑直观） | 中（曲线微调需要数学感觉） | 较低（方案由算法动态生成，不易硬控） |
| **打断与反应敏捷度** | 依赖事件触发，极快 | 依赖 Decorator 轮询或观察者 | 每次决策重新评估，极平滑 | 重新规划成本较高，易出现停顿 |
| **典型适用场景** | 门/机关/UI、Boss 宏观阶段机 | 绝大多数 3D 动作怪兽、开放世界 NPC | 市民生活模拟、载具驾驶选择、多武器切换 | 战术小队进攻、解谜 NPC、复杂长线生存行为 |
