## 1. 核心定位与设计思想

「02-移动学习与服务端」负责游戏 AI 的**行动执行层、大规模服务端并发工程与智能体进化层（Locomotion, Server Scaling & Learning）**。

在游戏研发中，“决定做什么”只是第一步，“怎么把动作做漂亮、怎么在大规模下不卡顿、怎么让 AI 具备学习进化能力”才是决定产品品质的胜负手：

- **平滑运动与仿生群聚（Locomotion & Flocking）**：将寻路输出的折线航点，通过 Reynolds Steering Behaviors（Seek/Arrive/Wander/避障）转化为平滑自然的向心力、离心力与转向力；借助 Boids 三法则（分离、对齐、凝聚）与动态包围圈槽位，实现令人惊叹的鱼群、鸟群与战术包围表现；
- **战斗编排与战术协同（Combat Director & Ring Slots）**：打破单体 AI 围殴风暴，建立中央战斗导演、攻击欲望令牌桶（Attack Token Bucket）、三层动态环形包围圈（Multi-Ring Slots）以及视锥盲区降权减压机制；
- **战斗与 Boss 体验工程**：超越生硬的“数值堆砌”，构建包含仇恨衰减表、目标动态加权、招式发号施令、阶段狂暴转换与攻击预警的工业级 Boss 战斗体系；
- **服务端大规模 AI 调度与时间预算**：针对 MMO 与万人大世界，确立权威服务器架构（Server Authority）、单帧时间切片（Time Slicing）、距离与可见性 Tick LOD 降频、以及基于流场寻路（Flow Field）的军团级性能优化方案；
- **学习型智能体与多智能体协作**：跨越手写规则的局限，探索强化学习（RL）、模仿学习（IL）、玩家建模动态难度自适应（DDA）以及多智能体强化学习（MARL/CTDE）在真实商业项目中的应用边界与落地约束。

## 4. 移动、战斗与服务端调度工程落地

### 4.1 运动控制技术分层
- **全局规划层（Macro Path）**：在 NavMesh 或网格图上运行 A* / JPS，获得关键拐角点序列（Waypoints）；
- **局部平滑层（Funnel / Steering）**：利用漏斗算法拉平折线，使用 Arrive 与 Seek 行为产生平滑速度矢量；
- **局部避障层（Micro Avoidance）**：利用 RVO / ORCA 计算避让圆锥，在不改变宏观目标的前提下互相错车，避免集群拥堵。

### 4.2 服务端时间预算与降级契约
在服务端主循环中，AI 运算必须被严格限制在时间预算内（如每 Tick 预留 4ms）：

```mermaid
flowchart LR
    Start[Tick 开始] --> Check{已耗时 > 4ms?}
    Check -- 否 --> RunHigh[执行 High LOD 实体<br/>完整视野检测与决策]
    Check -- 是 --> Yield[剩余任务推入下一帧队列]
    RunHigh --> Check2{已耗时 > 4ms?}
    Check2 -- 否 --> RunLow[执行 Low LOD 实体<br/>降频仅做位移插值]
    Check2 -- 是 --> Yield
    RunLow --> End[Tick 结束]
```

- **距离分级（Distance LOD）**：离玩家 0~20m（Tick 0.1s），20~50m（Tick 0.5s），50m 以上仅更新状态机不跑物理；
- **流场寻路（Flow Field）**：当几百个单位涌向同一目标时，从目标点反向生成一次 Dijkstra 势能场，所有单位直接读取网格矢量，寻路复杂度从 $O(K \cdot N \log N)$ 骤降到 $O(N)$。
