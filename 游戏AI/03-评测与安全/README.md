# 游戏AI「评测与安全」知识库

> 本目录聚焦游戏 AI 的质量证明与风险控制：如何定义可比较的指标，如何保存可复现的回放，如何让多智能体服务端在预算内稳定运行，以及如何把 LLM NPC 放在可审计、可回滚、低权限的产品边界内。

## 分类简介

本目录是游戏 AI 从“能运行”走向“可上线”的工程闭环，覆盖四个相互连接的主题：

1. **评测指标体系**：把任务成功率、胜率/回报、路径质量、碰撞/误伤、延迟、CPU、内存、稳定性、确定性、玩家体验和安全风险转成可执行的指标与门禁。
2. **回放与确定性**：记录输入、随机种子、版本、资产清单、状态哈希和事件时间线，让离线回归、仿真重跑、客服查证与线上事故复盘有共同证据。
3. **多智能体与服务端**：在 AI 预算、调度、公平性、AOI、寻路、回放和故障降级之间建立明确的优先级。
4. **LLM NPC 安全**：限制提示注入、越权工具调用、RAG 越界、敏感内容、剧透、隐私、成本与延迟风险，不让语言模型直接持有交易、战斗等高权限。

## 学习路径

1. 先读 [01-决策与架构](../01-决策与架构/README.md)，建立感知、决策、行动和黑板数据流的通用模型。
2. 再读 [02-移动学习与服务端](../02-移动学习与服务端/README.md)，理解移动、战斗、学习型 AI 与服务端 AI 的工程背景。
3. 阅读本文的第 1～3 节，先建立指标、回放、数据版本和确定性证据链。
4. 阅读本文的第 4～5 节，把固定回归集、随机/对抗场景、多智能体预算、AOI 和降级策略落成方案。
5. 阅读本文的第 6 节，再将 LLM NPC 接入低权限工具网关、RAG 边界、审核队列和兜底流程。
6. 最后阅读本文的第 7～10 节，把门禁、灰度、观测、回滚和事故复盘串成上线闭环。
7. 需要服务端容量背景时，联读 [游戏服务端](../../游戏服务端/README.md)。
8. 需要寻路、碰撞和路径质量背景时，联读 [游戏算法](../../游戏算法/README.md)。
9. 需要 UI 指标呈现时，联读 [UI 状态与可观测性闭环](../../游戏知识/07-UI与性能优化/06-UI状态与可观测性闭环.md)。
10. 需要发布门禁和灰度流程时，联读 [全栈质量门禁与灰度回滚](../../游戏知识/08-工具链与打包发布/08-全栈质量门禁与灰度回滚.md)。

## 目录边界

- 本目录讲通用 AI 原理、评测与安全工程，不替代具体引擎的 API 手册。
- UE 具体实现只做方案级指路，官方实现细节以 [Unreal Engine 官方文档](https://dev.epicgames.com/documentation/en-us/unreal-engine)为准。
- 学习框架只作为评测对象和工具链案例，能力、版本和许可证应以 [Unity ML-Agents 官方仓库](https://github.com/Unity-Technologies/ml-agents)及其 [Releases](https://github.com/Unity-Technologies/ml-agents/releases)为准。
- 可观测性字段可映射到 OpenTelemetry，但采集 SDK、导出器和部署形态需要按项目确认，参考 [OpenTelemetry 文档](https://opentelemetry.io/docs/)。
