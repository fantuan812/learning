## 概述：先分清姿态、路径与速度

角色转身、镜头环绕、枪口指向、骨骼摆动、刚体翻滚，都需要表示物体朝向。但“现在朝哪边”“经过哪条路径转过去”“每秒转多快”是不同问题。一个单位四元数可以表示三维旋转姿态；它不会同时记录转了一圈还是三圈，也不会自动保证关节不超限、镜头不穿墙或刚体运动符合力学。

欧拉角直观，适合编辑和某些受限输入状态；它依赖轴序，并在特定姿态存在参数化奇异。单位四元数用四个实分量表示三个旋转自由度，带一个单位长度约束，适合组合和插值。它避免了欧拉角作为姿态参数时的万向锁，但仍需处理符号等价、归一化、角差、时间和控制约束。矩阵则便于把旋转与平移、尺度接入变换链。选择表示要看操作，不应把“全部运行状态只能存四元数”当规则。

### 本文统一约定

- 右手正交坐标系、列向量和主动旋转 `v' = R v`；正角遵循右手规则，从正轴端看向原点是逆时针。所有角公式使用弧度，时间使用秒
- 写作 `q=(w,x,y,z)=(w,u)`；`⊗` 专指 Hamilton 积，`dot4(a,b)` 专指四个实分量的点积。不要让同一个点号同时表示二者
- `q_WL` 把局部 L 的向量映到世界 W：`v_W=R(q_WL)v_L`。反向被动坐标变换用逆/转置：`v_L=R(q_WL)^T v_W`
- `R[row,col]` 是数学行列下标；列向量与列主序存储是两回事。C++ 的4×4输出示意采用 `m[4*col+row]`，Python 的嵌套元组按 `[row][col]` 读
- 相机例采用 y 向上、默认朝 −z 的本文模型。已读 Unity 6000.0 页面描述左手系、X右/Y上/Z前，不与本文混用。换坐标先定义基变换 C，再用 `R_new=C R_old C⁻¹`；不能仅凭“左右手”机械取反或倒乘
- UE的轴向与API乘法分别核对：[官方坐标说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/coordinate-system-and-spaces-in-unreal-engine)说明左手、X前/Y右/Z上；[TQuat文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/TQuat)另行规定 `A*B` 先B后A、局部增量右乘/世界增量左乘，并提示这与FTransform乘法顺序不同。左手坐标本身不推出“所有乘积都倒序”。本次只读页面标注UE 5.8、读取日2026-10-10；未读对应CL源码，本文数学矩阵仍按列向量约定，未将其数组直接当UE矩阵布局
- 数学推导按实数；教学接口限定有限输入域并明确失败。单位归一化只处理允许的数值偏差，不会把 NaN、零姿态、奇异矩阵或协议错误变成合法旋转

| --- | --- | --- |

## 1. 欧拉角与万向锁

明确说“绕固定 X，再固定 Y，再固定 Z”时，本文矩阵为 `R=Rz(γ)Ry(β)Rx(α)`。若把轴改成随物体转动的轴，顺序解释会改变。Unity 6000.0 的已读文档说明其欧拉旋转按固定轴 Z→X→Y，角度接口以度表示；这不是本文的 X→Y→Z 推导顺序。

三轴互异的 Tait–Bryan 参数在中间角 ±π/2 处奇异。例如：

```text
Rz(t) Ry(π/2) Rx(t) = Ry(π/2)       对任意t成立
```

不同的第一、第三角能给同一姿态，局部微小姿态变化也可能要求角值大幅变化。这里退化的是参数表示和控制映射，不是说所有目标姿态从此不可到达。首尾轴相同的 proper Euler 序列有不同的奇异角，不能把“中间角一律±90°”套在所有序列上。[SciPy 1.14.1 的欧拉表示说明](https://docs.scipy.org/doc/scipy-1.14.1/reference/generated/scipy.spatial.transform.Rotation.as_euler.html)明确区分内禀/外禀序列，并指出万向锁时第一、第三角不能唯一确定，输出仍可表示正确姿态。

飞行器仰头接近竖直时，某种 yaw/pitch/roll 参数控制可能让两项响应重合；改用四元数增量可避免不断反解欧拉角。FPS 则常有意只保留水平 yaw 和有限 pitch，限制抬头是防越顶、控制奇异和玩法选择。89°不是通用常数，存储为q也不会自动解决“前向与up共线”或玩家不想翻滚的问题。

## 2. 四元数、半角与双覆盖

Hamilton 四元数写作：

```text
q = w + x i + y j + z k
i² = j² = k² = ijk = -1
ij=k，ji=-k；jk=i，kj=-i；ki=j，ik=-j
```

四个系数都是实数。记虚部向量为u，则 q=(w,u)，单位轴n和旋转角θ对应：

```text
q = (cos(θ/2), n sin(θ/2))
|q|² = w² + u·u = 1
```

θ=0给I=(1,0,0,0)，不需要唯一旋转轴；θ=π给(0,n)。q和−q表示同一姿态，因为在夹乘中两侧的符号抵消。取负号不是反转旋转方向；单位q的反旋转是共轭 `(w,−u)`。

这也解释了为什么姿态不保存圈数：转2π后得到−I，与I对应同一SO(3)旋转。若转盘必须正向转三圈再停，只有起止q不够；要额外保存phase/winding、角速度或包含路径信息的关键帧。

## 3. 向量作用、组合与误差

### 3.1 从Hamilton积推导旋转

设a=(wa,ua)、b=(wb,ub)：

```text
a⊗b = (wa wb − ua·ub, wa ub + wb ua + ua×ub)
(0,a)⊗(0,b) = (−a·b, a×b)
```

把三维向量v写作纯四元数(0,v)，用 `q⊗(0,v)⊗q⁻¹` 作用。单位q下展开为：

```text
R(q)v = (w²−u·u)v + 2u(u·v) + 2w(u×v)
      = v + 2w(u×v) + 2u×(u×v)
```

代入 u=n sin(θ/2)，使用倍角恒等式，得到 Rodrigues 公式：

```text
R(q)v = v cosθ + n(n·v)(1−cosθ) + (n×v) sinθ
```

v沿轴的平行分量保持，垂直分量在平面内旋转θ，因此保长保角、不引入剪切。半角的准确原因是展开后出现上述倍角项，而不是把“q单独作用一次”等同为三维半角旋转。

单侧 `q⊗(0,v)=(-u·v,wv+u×v)` 一般含非零标量，不能直接截取虚部称为三维旋转。例如绕z转90°的q乘纯ez，得到(-√2/2,0,0,√2/2)；正确夹乘后的ez仍是ez。轴向分量没有被抵消。

### 3.2 共轭不总是代数逆

```text
q* = (w,−u)
q⊗q* = (|q|²,0)
q⁻¹ = q*/|q|²，q≠0
```

只有单位q才可直接用共轭当逆。若q=s a、a单位、s非零，真逆夹乘中的s会消掉，结果仍是R(a)v；误用共轭则得到s² R(a)v。P04的q=2I分别产生v与4v。因此“非单位q一定缩放”漏了使用哪种逆的前提。工程旋转接口通常采用单位专用公式，仍应维护单位不变量；零q没有逆，不能归一化成有效姿态。

### 3.3 先后顺序与所在空间

先q1、后q2，按夹乘结合律：

```text
q2⊗[q1⊗(0,v)⊗q1⁻¹]⊗q2⁻¹
 = (q2⊗q1)⊗(0,v)⊗(q2⊗q1)⁻¹
```

所以右侧先作用。P02中先绕x90°再绕z90°把ex送到ey；反过来把ex送到ez，不能交换。[SciPy 1.14.1 组合合同](https://docs.scipy.org/doc/scipy-1.14.1/reference/generated/scipy.spatial.transform.Rotation.__mul__.html)也采用这种主动旋转顺序，但不能据此猜所有引擎同名运算符。

对局部到世界的q_WL：

```text
世界坐标增量：q_new = δq_W ⊗ q_WL
本地坐标增量：q_new = q_WL ⊗ δq_L

从q_from到q_to：
δq_W = q_to ⊗ q_from*       左乘回q_from
δq_L = q_from* ⊗ q_to       右乘回q_from
```

“先乘偏航再乘俯仰”没有交代空间，容易误读。明确world/local和乘侧才能决定相机、枪口或关节转向。

### 3.4 用角差比较姿态

对单位a、b，最短姿态差大小为：

```text
d = clamp(abs(dot4(a,b)),0,1)
θ = 2 acos(d)，θ∈[0,π]
```

负dot只表示所选S³代表在相反半球；只有b=±a才是同一姿态。I与(-√2/2,0,0,√2/2)的dot虽负，仍差90°。clamp只处理有效单位输入的舍入，不修复坏数据。

小角时d非常接近1，直接acos对舍入敏感。可改用单位相对q：

```text
δ = normalize(b⊗a*)
θ = 2 atan2(hypot(δx,δy,δz), abs(δw))
```

它给无符号大小，不包含轴的方向选择。若要驱动有方向的角速度，仍需决定相对q代表、零角的无轴情况与π处的分支。误差阈值使用弧度，不能拿四分量直接相等或欧拉角分量差替代姿态误差。

## 4. 插值与时间不是同一件事

### 4.1 Slerp的球面角与物理角

对单位a、b先做短弧对齐：若dot4(a,b)<0，令b=−b。记d=clamp(dot4(a,b),0,1)，则：

```text
Ω = acos(d)，0≤Ω≤π/2
q(u) = [sin((1−u)Ω)a + sin(uΩ)b] / sinΩ
0≤u≤1；物理最短角差θ=2Ω
```

在a、b张成的二维平面上选正交基e0=a、e1=(b−cosΩ a)/sinΩ。圆弧点为cos(uΩ)e0+sin(uΩ)e1，代回便得到公式，所以单位长度和弧长线性来自圆上的参数化。

Ω接近0时直接除sinΩ不合适，本文实现以d>0.9995转Nlerp，并归一化结果。0.9995是教学近似政策，不是库默认，也不保证这个实现对全部输入严格恒角速。u必须有限且在[0,1]；域外明确失败，外推需另立合同。

三个容易混淆的边界：

- a和−a是S³对跖代表，物理姿态相同；符号对齐后应保持姿态，而不是转180°
- 两姿态物理差180°时Ω=π/2、sinΩ=1，分母并不退化；此时有两条同长最短路。本文exact dot=0保持输入代表，换成−b可走另一条，临界扰动下不承诺路径连续
- u=1可能返回原b的负号，姿态正确。长期时序要维护符号连续策略；单纯强制w≥0会在跨180°时跳符号

固定起终姿态且u对真实时间线性时，理想Slerp段内才恒角速度。ease(u)、每帧把起点改成current、目标移动都会改变速度；多个关键帧逐段Slerp也不自动让段间角速度连续。[SciPy 1.14.1 Slerp](https://docs.scipy.org/doc/scipy-1.14.1/reference/generated/scipy.spatial.transform.Slerp.html)的固定时间关键帧说明不能用来认证所有追随代码。

### 4.2 Nlerp和多姿态混合

Nlerp是 `normalize((1−u)a+u b)`，仍先同半球。理想单位输入、u∈[0,1]下，和的模长至少1/√2，所以不会遇到未对齐a/−a的中点消失。它与Slerp走相同大圆短弧，但u到弧长的映射不同，通常中间更快；小角时接近不等于任何30°以下都可忽略误差。

多个同关节、同局部空间姿态的有限近似混合可采用：

```text
输入1≤N≤64；每个qi有效，wi有限且0≤wi≤1，sum(wi)>0
r = 按输入顺序第一项正权姿态
将dot4(r,qi)<0的qi取反；exact dot=0不变
αi = wi/sum(wi)
s = sum(αi qi)
若|s|<1e−8或非有限：失败；否则返回s/|s|
```

原权重和可以不是1，先归一化；全零权重失败，不能默认identity。归一化之前的和通常不是单位q。逐对Nlerp会受次序与每次归一化影响，通常不等同这一个加权和；它也不是唯一的SO(3)均值。不同“平均”需先定义损失函数，例如[SciPy的chordal L2均值](https://docs.scipy.org/doc/scipy-1.14.1/reference/generated/scipy.spatial.transform.Rotation.mean.html)。本文不把这段近似归因成未经核对的“Shoemake通用平均算法”。关节限位仍需另外处理。

### 4.3 三种时间策略

时间使用同一相对时钟；|τ|、|τ0|≤1e9秒。dt、ω_max、k均须有限，0≤dt≤10秒、0≤ω_max≤1000 rad/s、0≤k≤100 s⁻¹。这些是防数值范围失控的教学工作域，不是玩法推荐值。长暂停由调用者重置、分步或拒绝。

**固定时长播放**：锁定q_start、q_end、τ0及1e−6≤T≤1e6秒，`u=clamp((τ−τ0)/T,0,1)`，每次从固定q_start插值。τ<τ0时Paused返回q_start，角残差相对q_end；τ0≤τ<τ0+T时Advancing返回该时刻的固定起点采样，τ≥τ0+T时Reached返回q_end。该模式只按τ决定输出和状态，不读取外部current或dt，也不要求current=q_start。理想段内速率θ/T；T=0失败，若要瞬移由上层显式选择。固定时长不能每帧把q_start重设成current，否则变成另一种响应。

**最大角速度转向**：计算对齐后的世界相对δ=q_to⊗q_current*及θ。如果θ=0或θ≤ω_max dt，直接目标；若ω_max dt=0，保持当前。其余从δ虚部的非零hypot提取内部单位轴n，构造角步s=ω_max dt的δ_step，返回normalize(δ_step⊗q_current)。理想算术下不超过允许角步。内部极小非零轴不套外部轴1e−8阈值，仍检查hypot非零、结果有限；浮点误差另记预算。此模式不用Nlerp近角回退冒充严格理想角步。

**指数追随**：`u=−expm1(−k dt)` 后从current向target作短弧插值。expm1在小kdt时避免1−exp的消减。固定target且同一最短分支的理想Slerp满足：

```text
θ_new=(1−u)θ_old=exp(−k dt)θ_old
多步剩余误差=初始误差·exp(−k sum(dt))
```

它是越接近越慢，通常没有有限的精确到达时刻。k=0/dt=0保持原姿态。目标移动、离散采样、浮点和Nlerp回退均不保证分割dt后完全同轨迹，不能笼统叫“完全帧率无关”。

### 4.4 单步返回与停止责任

一步控制示意返回 `{status, pose?, angular_error?}`；有效角残差相对本步target计算。Invalid、Cancelled、TimedOut不给可消费pose和残差，上层自行保存上一有效状态，不把缺失值当identity或误差0。

| 状态 | 本步含义与终止责任 |
| --- | --- |
| Invalid | 输入、模式、时间域或数值失败；无pose，调用方报告错误 |
| Cancelled | 调用方显式取消后不推进；无pose，取消不等于到达 |
| Paused | 角步/指数模式未到达且未耗尽期限，dt=0或ω/k=0时返回current及角残差；固定播放τ<τ0时返回锁定q_start及其相对q_end的角残差。暂停不算完成 |
| Advancing | 固定播放尚未到期或最大角步尚未到达；返回本步pose，由上层时钟再调度 |
| Following | 指数追随步结束尚早于期限且结果残差仍大于ε；返回pose，仍是未完成 |
| Reached | 固定时长到期、角步足够到达，或指数模式达到显式角容差；返回目标与误差0，结束这次请求 |
| TimedOut | 指数请求在步开始或步结束已到达允许持续时长，仍未达容差；无可消费pose，停止并报告未到达 |

固定播放只按上述τ分支判定，已到期返回Reached，不因其他模式的dt=0规则改说Paused。最大角步先判θ=0/可到达，再判暂停。指数模式额外接收0<ε≤0.01 rad、0<T_follow≤1e6秒和0≤elapsed≤1e9秒。elapsed明确是本步开始已用时，current对应该时刻；合法步的结果时刻为elapsed_end=elapsed+dt。ε与T_follow由上层在请求创建时固定，elapsed随有效步更新，不能每次清零以延长等待；k=0的正dt暂停步仍消费这段时间。末步先按结果角残差判Reached，未达容差则在elapsed_end≥T_follow时当步TimedOut，不能再返回Following等待下一次调用。

```text
OneStepExponential(current,target,k,dt,elapsed,T_follow,ε,cancelled):
    验证全部输入和相对时基；失败 -> Invalid（无pose）
    若cancelled -> Cancelled（无pose）
    θ = 当前到目标的角差
    若θ≤ε -> Reached（明确snap到target）
    若elapsed≥T_follow -> TimedOut（无pose）
    若dt>T_follow−elapsed -> Invalid（调用者缩为剩余时间或结束）
    elapsed_end = elapsed + dt
    若dt=0或k=0：
        若elapsed_end≥T_follow -> TimedOut（无pose；暂停也不延长期限）
        否则 -> Paused（当前pose与θ）
    u = −expm1(−k dt)
    next = SlerpShortestChecked(current,target,u)；失败 -> Invalid
    residual = AngleDistance(next,target)
    若residual≤ε -> Reached（snap到target，末步到期也优先判到达）
    若elapsed_end≥T_follow -> TimedOut（无可消费pose）
    否则 -> Following（next与residual）
```

固定时长播放用固定起点计算；最大角步用上一节轴角步骤，二者都只处理一个请求步，不含循环。指数结束依赖显式ε/snap、期限或取消，不能靠浮点碰巧相等；固定播放和最大角步不暗中继承ε提前snap政策。移动目标的新请求另立，不能把“追随一直在运行”报告成完成。

## 5. 旋转矩阵与四元数互转

### 5.1 q到矩阵

单位q=(w,x,y,z)在本文约定下对应：

```text
R = [ 1−2(y²+z²)   2(xy−wz)      2(xz+wy)   ]
    [ 2(xy+wz)     1−2(x²+z²)    2(yz−wx)   ]
    [ 2(xz−wy)     2(yz+wx)      1−2(x²+y²) ]
```

把ex、ey、ez依次代入旋转公式，结果分别是三列。R满足RᵀR=I、detR=+1，所以属于SO(3)。q和−q产生相同R。矩阵可接入TRS或批量顶点变换，但渲染并非必须先转矩阵；shader也可直接用q，需看管线数据路径。

### 5.2 先验证R再反解

本教学转换接收3×3有限实矩阵、每元素绝对值≤2，计算：

```text
e_orth = max_abs(RᵀR−I) ≤ 1e−6
abs(detR−1) ≤ 1e−6
```

不满足则InvalidRotationMatrix。反射矩阵可以正交却det=−1；尺度/剪切也不能无损装进q。通过的是容差内近SO(3)输入，不是严格精确SO(3)证明。反解、单位化后重建R_hat，`max_abs(R_hat−R)>1e−5`仍拒绝；成功返回q和重建残差。这些无量纲阈值是教学政策，不是通用精度保证。

有些库另有近似策略，例如[SciPy 1.14.1 from_matrix](https://docs.scipy.org/doc/scipy-1.14.1/reference/generated/scipy.spatial.transform.Rotation.from_matrix.html)会针对非proper-orthogonal输入建立近似。这不证明近似等于原矩阵，也不把本文算法变成SVD最近旋转或通用TRS分解。

### 5.3 完整四分支反解

所有下标是R[row,col]，先算：

```text
Dw=1+r00+r11+r22     Dx=1+r00−r11−r22
Dy=1−r00+r11−r22     Dz=1−r00−r11+r22
```

选最大D，平局按w、x、y、z顺序。D须有限且>0，令s=0.5sqrt(D)、den=4s：

| 选中 | w | x | y | z |
| --- | --- | --- | --- | --- |
| w | s | (r21−r12)/den | (r02−r20)/den | (r10−r01)/den |
| x | (r21−r12)/den | s | (r01+r10)/den | (r02+r20)/den |
| y | (r02−r20)/den | (r01+r10)/den | s | (r12+r21)/den |
| z | (r10−r01)/den | (r02+r20)/den | (r12+r21)/den | s |

精确旋转矩阵下D_i=4q_i²，四项和4，最大|qi|≥1/2，因此选大分母避开180°附近很小的w。这个算法没有acos，不能把分支理由说成acos反解不稳定。[GLM 1.0.1 的quat_cast](https://raw.githubusercontent.com/g-truc/glm/1.0.1/glm/gtc/quaternion.inl)可对照最大分量策略，但其m[col][row]下标不能原样当本文行列下标。

分量线性插值矩阵是有定义的运算，只是通常离开SO(3)、引入缩放/剪切；若要把它用作旋转插值，须另定投影/分解策略。不能说“矩阵插值没有数学意义”。

## 6. 相机、骨骼与有限网络姿态链

### 6.1 有界yaw和pitch控制

本文FPS例只保存姿态yaw，不保存圈数。维护yaw_pose∈[−π,π)，每步Δyaw有限且|Δyaw|≤π：

```text
r = yaw_pose + Δyaw             r∈[−2π,2π)
if r≥π: r=r−2π
if r<−π: r=r+2π
yaw_pose = r
pitch = clamp(pitch + Δpitch, −p_max, p_max)
q_WL = q_y(yaw_pose) ⊗ q_x(pitch)
```

pitch、Δpitch须先验证有限且处于声明范围，0<p_max<π/2；本例每步|Δpitch|≤π。这两步加法有界。世界yaw、本地pitch通过左右乘明确表达，输入角度不会因持续正常水平转身而跑出后文轴角接口的|θ|≤2π域。Δyaw越界由调用者拆分或拒绝，不扩大整个接口域。

三次+3π/4输入的概念累计为9π/4，存储yaw最终π/4；该周期政策只针对明示的姿态控制。若业务需要累计转角，应另外存phase/winding。wrap点q可跳负号，可再与上一有效q对齐以利连续插值；这不改变姿态，也不等于保存运动圈数。

枪口“指向目标”还要确定roll/up。目标重合或forward与up共线时不存在唯一完整朝向，调用者应明确替代up或保留上一有效姿态并报告。q归一化不解决这些约束，更不实现碰撞、相机避障或关节限位。

### 6.2 从局部动画到蒙皮顶点

设P_bind在绑定网格空间S，B_j把关节绑定局部映到S，故B_j⁻¹把绑定顶点送入该关节绑定局部。当前局部变换 `L_j=T(t_j)R(q_j)S(s_j)`，按父先子后顺序构造 `G_j=G_parent L_j` 映到世界；根的父变换是明确的root-world。同关节动画混合只混合相同局部空间q，平移/尺度分别处理。

本链消费由资产导入或调用方验证过的有限、可逆B_j和对应有限预计算B_j⁻¹，不在这里实现通用求逆。缺少合格inverse-bind、绑定零尺度或其他验证失败，入口返回InvalidBindTransform且不输出顶点；不能用identity或normalize(q)掩盖。单位q不保证包含尺度的仿射矩阵可逆。

有限J个关节、每顶点最多K个影响（示例K=4）、非负有效权重和为1：

```text
P_world = sum_j [ weight_j · G_j · B_j⁻¹ · P_bind ]
```

求逆的是绑定变换，不是顶点。parent已经在G_j中，不能再重复乘一次。若管线要先输出当前网格局部空间，再左乘该网格global的逆；该分支也要求调用方预验证当前网格global及其逆有限可逆，否则InvalidMeshTransform。当前G_j若仅作正向变换，不因含尺度就额外求逆；接近奇异/逆残差的接受政策归资产验证合同，不冒称这里解决全部数值问题。

P20的一个关节：B=T(1,0,0)，G=T(1,0,0)Rz(π/2)，P_bind=(2,0,0,1)，权重1。依次逆绑定、旋转、平移，得到(1,1,0,1)。多个关节矩阵的加权和通常不是单一刚体旋转，线性蒙皮仍可能缩体积；局部q不会自动消除这种变形。

```mermaid

    A["每关节局部旋转关键帧"] --> B["有效输入/同半球/明确权重"]
    B --> C["局部姿态 q + t + s\n独立关节约束"]
    C --> D["FK: G_joint = G_parent L_joint"]
    E["已验证可逆绑定 B\n预计算 inverse-bind"] --> F["G_joint B_inverse\n同空间权重和"]
    D --> F

```

### 从两个90°输入走到最终向量

先用一个手算例把“输入轴、角度、乘法、空间、插值”接起来，再看代码。输入是向量 `v=(1,2,3)`，先绕**固定X轴**转 `π/2`，再绕**固定Z轴**转 `π/2`。这里是本文的右手主动旋转；90°只用于阅读，传给函数的角是弧度。轴故意给成 `(2,0,0)`、`(0,0,2)`，让入口的轴单位化也有明确用途。

令 `c=√2/2`。轴单位化后，半角式给出 `qx=(c,c,0,0)`、`qz=(c,0,0,c)`。绕X的90°映射是 `(x,y,z)→(x,−z,y)`；绕Z的90°映射是 `(x,y,z)→(−y,x,z)`，所以逐次作用为：

```text
v=(1,2,3) --qx--> (1,−3,2) --qz--> (3,1,2)
```

合并时后一项放左边。代入Hamilton积，标量为 `c²=1/2`，向量为 `(c²,c²,c²)`，故 `q_total=qz⊗qx=(1/2,1/2,1/2,1/2)`。从§5得到：

```text
R(q_total) = [ 0 0 1 ]
             [ 1 0 0 ]
             [ 0 1 0 ]
R(q_total)(1,2,3) = (3,1,2)
```

逐次作用、一次合成、矩阵作用都到同一结果，前后长度均为 `√14`。如果误写成 `qx⊗qz`，实际变成 `(1,2,3)→(−2,1,3)→(−2,−3,1)`；这不是数值误差，是先后顺序换了。选择非对称向量使三个分量都能暴露错误。

再换一个提问：当前局部到世界姿态是 `q_WL=qz`，给它增加 `qx`。本地增量右乘，`qz⊗qx` 将该局部向量送到 `(3,1,2)`；世界增量左乘，`qx⊗qz` 将它送到 `(−2,−3,1)`。这里的两种提问共用相同数字，却不能共用“先转哪个轴”的口头描述。

最后从单位姿态I走到这个 `q_total` 的短弧中点。它的物理角是 `2acos(1/2)=2π/3=120°`，轴是 `(1,1,1)/√3`；`u=1/2` 时角为60°，不是“把X、Z各转45°”。中点四元数是 `(√3/2,√3/6,√3/6,√3/6)`。用Rodrigues式逐项算：

```text
v cos60°                = (1/2, 1, 3/2)
n(n·v)(1−cos60°)         = (1,   1, 1)
(n×v)sin60°              = (1/2,−1, 1/2)
相加                    = (2,   1, 3)
```

这条120°合成姿态的最短路径，与先完整转X、再完整转Z的两段路径不同；端点相同不能反推出过程。将目标换成 `−q_total`，短弧对齐后仍应到同一中点；将起终点设成 `q_total/−q_total` 则整段保持姿态，不转180°。

### 加权和与未来验证

a=I、b=(0,0,0,1)，各权1/2，未归一化和=(1/2,0,0,1/2)，模长1/√2；只有检查非零并normalize后才单位。“加权平均天然保持单位性”省略了关键运算和前提。单个特例也不能证明所有姿态/权重都稳定。

未来项目验证应单独记录语言/库/编译器/精度、源码版本、输入合同、原始结果和失败；用角误差、单位长度及矩阵残差判正确性。至少覆盖0/近0、物理π、q/−q、组合顺序、尺度/剪切/镜像、近零/非有限及错形状输入。固定目标和移动目标的dt序列分别测，不能用前者纸面恒等式证明后者观感。

若比较Nlerp/Slerp或q/矩阵性能，应固定输入分布、角差、共享姿态数量、归一化次数、内存布局与编译选项，记录批量规模和耗时分布（如P50/P95），同时报告最大角误差；不能拿旧倍速数字作预算。可在项目自有测试框架接入这些用例；本次只在正文内提供固定入口，没有向仓库新增测试文件或runner，有限运行原流独立保留。

## 常见问题 FAQ

**Q1：为什么是半角？直接q乘向量不行吗？**

单侧q⊗(0,v)一般含标量，不是三维旋转结果。夹乘展开为Rodrigues式，cos²(θ/2)−sin²(θ/2)与2sin(θ/2)cos(θ/2)产生cosθ/sinθ；平行于轴的分量保持。不是把轴向向量抵消，也不是单侧必然“沿轴拉伸”。

**Q2：万向锁的具体数字是什么？**

本文固定轴X→Y→Z时，β=π/2使Rz(t)Ry(π/2)Rx(t)对所有t都相同，第一、第三角无法独立确定。姿态仍有效，退化的是角参数；不能说物体永久少一个物理自由度。Unity的外禀Z→X→Y须单独按其约定分析。

**Q3：四元数能表示所有旋转吗，为什么双覆盖？**

单位q能表示所有三维proper rotation，即SO(3)，不包括镜像/尺度。q与−q夹乘相同，形成双覆盖；它们不是两个不同姿态。仅给端点q不能确定转过的圈数、选择哪条长路径或π处哪条同长路径。

**Q4：Slerp与Nlerp何时用？**

二者先同半球。Nlerp沿同一大圆短弧但参数非匀速，Slerp在固定端点和线性时间下理想恒角速。小角误差与实际成本应由项目测量；没有统一30°阈值或5–10倍成本。本例Slerp的小角Nlerp回退也只有近似恒速。

**Q5：矩阵转q为什么要分支？**

以w反解时180°附近w很小，随后除4w会放大误差。选择四分量中最大的一个作分母，在精确SO(3)下该分量绝对值至少1/2；§5给完整四分支。输入验证同样必要，不能从任意尺度/剪切矩阵直接抽q并称保持原变换。

**Q6：FPS用欧拉角是不是一定出问题？**

不是。yaw/pitch可以是明示受限控制状态，本文yaw周期维护、pitch按玩法限幅后再构造q。应避免每帧把任意q转欧拉再累加引入跳变，但不能要求所有FPS同用±89°。up共线、roll政策、避障与转速限制也不是换存储形式就能解决的。

**Q7：骨骼为何常用q，还需要矩阵吗？**

q紧凑并便于局部旋转插值；完整骨骼仍需平移/尺度、层级和inverse-bind。纯旋转payload的4/9个标量比较不代表整个动画资产都固定少2.25倍。线性蒙皮的加权矩阵有明确定义，但一般不是单一刚体旋转，仍可能变形；四元数局部姿态不保证动力学正确或满足关节限位。

**Q8：怎么判断两个q几乎相同？**

先验证单位姿态，再用2acos(clamp(abs(dot4),0,1))，或相对q的atan2角差，与明确的弧度阈值比较。abs处理±q等价；分量差和裸2acos(δ.w)可能把同姿态认作大转角。网络量化误差与动画过渡判定可用该角差，但阈值须服务实际用途。

## 概述

旋转是游戏中最常见的操作之一：角色转身、镜头环绕、枪口指向、骨骼摆动、刚体翻滚……
而「用什么数据结构表示旋转」直接决定代码的稳定性与质量。早期游戏与许多教学代码
使用**欧拉角（Euler Angles）**（绕 X/Y/Z 三轴的角度），它直观易读，却有两个致命
缺陷：**万向锁（Gimbal Lock）**导致自由度丢失、姿态出现诡异抖动；三角度插值不平滑，
且不同顺序（YXZ、ZXY…）含义完全不同。

**四元数**是复数在四维空间的推广，用 4 个分量 `(w, x, y, z)` 紧凑地表示旋转：
它没有万向锁、插值平滑（Slerp）、组合旋转只需一次乘法、与矩阵互转有闭合公式，
因此成为 Unity、Unreal、Godot 等引擎旋转数据的**默认存储格式**。

本文先剖析欧拉角与万向锁问题（用飞行模拟器与 FPS 镜头的真实例子说明），再给出
四元数的代数定义与几何意义（旋转轴 + 半角），推导核心公式：旋转公式 `v' = q·v·q⁻¹`、
四元数乘法、共轭与逆、Slerp 插值、与旋转矩阵的互转；最后讲解骨骼动画中的关节
旋转、第三人称相机的平滑旋转等应用，并附 C++/Python 实现与完整 FAQ。

## 原理详解

### 1. 欧拉角与万向锁

欧拉角把任意旋转分解为绕三个固定（或随动）轴的依次旋转，例如 Unity 的 `(x, y, z)`
表示「先绕 Z 轴，再绕 X 轴，最后绕 Y 轴」（顺序因引擎而异）。问题在于：

1. **顺序依赖**：`(90, 0, 0)` 再绕 Y 转 30° 与先绕 Y 转 30° 再 `(90, 0, 0)` 结果不同；
2. **万向锁**：当**中间那次旋转**（如 YXZ 顺序中的 X）达到 ±90° 时，第一次与第三次
   旋转的轴在空间中重合，三个角度退化成「两个自由度」，表现为：无论怎么转，某个方向
   都无法到达；且角度微小变化会导致姿态突变、插值抖动。

**飞行模拟器实例**：飞机先抬头 90°（俯仰），此时再「偏航」实际是在绕机头轴滚动；
玩家继续操作偏航，飞机却像被卡住一样打转——这就是万向锁。**FPS 镜头实例**：第一人称
相机把俯仰限制在 ±89°，正是为了避免俯仰到达 ±90° 触发万向锁。

### 2. 四元数的定义

四元数由哈密顿（Hamilton, 1843）提出，形如：

```text
q = w + x·i + y·j + z·k
```

其中虚部满足：

```text
i² = j² = k² = i·j·k = -1
i·j = k,  j·i = -k     （乘法不交换）
```

把纯虚部记为三维向量 `v = (x, y, z)`，四元数可写作标量-向量对 `q = (w, v)`。

**几何意义**：单位四元数（`w² + x² + y² + z² = 1`）对应**绕单位轴 `n̂` 旋转 `θ` 角**：

```text
q = (cos(θ/2), sin(θ/2)·n̂)
```

**为什么是半角？** 因为四元数旋转通过**双面乘法**实现（见下一节）：`q` 作用两次
等价于旋转 θ。类比复数：单位复数 `e^{iθ}` 通过单面乘法旋转 θ；四元数在 3D 中
必须以「左乘 q、右乘 q⁻¹」的方式夹逼，每次只贡献 θ/2。□

### 3. 旋转公式：v' = q·v·q⁻¹

把三维向量 `v` 写成纯四元数 `(0, v)`，则绕单位轴 `n̂` 旋转 θ 的公式为：

```text
v' = q · v · q⁻¹，   q = (cos(θ/2), sin(θ/2)·n̂)
```

**推导**：把 `v` 分解为平行于轴与垂直于轴的两部分：

```text
v = v_∥ + v_⊥
v_∥ = (v·n̂)·n̂          # 平行分量，旋转不变
v_⊥ = v - v_∥          # 垂直分量，在垂直于轴的平面内旋转
```

垂直分量在平面内旋转 θ 等价于复数平面乘法：`v_⊥' = cosθ·v_⊥ + sinθ·(n̂ × v_⊥)`。
将 `cosθ = cos²(θ/2) - sin²(θ/2)`、`sinθ = 2sin(θ/2)cos(θ/2)` 代入，并利用四元数乘法
的几何性质（纯四元数相乘：`(0,a)(0,b) = (-a·b, a×b)`），整理后恰好得到
`q·v·q⁻¹` 的展开式。□

由此可知四元数旋转**保长保角**（是刚体变换），且**不引入剪切**。

### 4. 四元数乘法（哈密顿积）

设 `q1 = (w1, v1)`、`q2 = (w2, v2)`：

```text
q1·q2 = (w1·w2 - v1·v2,  w1·v2 + w2·v1 + v1 × v2)
```

**推导**：展开 `(w1 + x1i + y1j + z1k)(w2 + x2i + y2j + z2k)`，利用虚部乘法表
（`ij = k` 等）合并同类项，标量部分得到 `w1w2 - (x1x2 + y1y2 + z1z2)`，向量部分
得到 `w1v2 + w2v1 + v1×v2`。□

**复合旋转**：先应用 `q1`、再应用 `q2` 的等价旋转为：

```text
q_total = q2 · q1      （注意顺序：与矩阵相同，右乘先作用）
```

验证：`q2·(q1·v·q1⁻¹)·q2⁻¹ = (q2·q1)·v·(q2·q1)⁻¹`。□

**共轭与逆**：

```text
q* = (w, -v)
q⁻¹ = q* / |q|²
```

单位四元数 `|q| = 1`，故 `q⁻¹ = q*`。几何上共轭即**反向旋转**（绕同轴转 −θ）。

**点积与夹角**：两个单位四元数 `q1·q2`（当作 4D 向量点积）的绝对值越大，表示两个
旋转越接近；`dot < 0` 时两者方向相反（表示同一旋转的双倍覆盖现象，见 FAQ）。

### 5. 旋转插值：Slerp 与 Nlerp

**Slerp（球面线性插值）**：在四维单位球面上沿**测地线（大圆弧）**插值，保证恒定
角速度。公式：

```text
Ω = acos(q1 · q2)                 # 两旋转之间的夹角
q(t) = [ sin((1-t)·Ω)·q1 + sin(t·Ω)·q2 ] / sin(Ω)
```

**推导**：在 2D 平面上类比——单位圆上两点 `p0, p1`，其夹角 Ω，圆上点可写作
`p0` 与 `p1` 的线性组合：`p(t) = [sin((1-t)Ω)·p0 + sin(tΩ)·p1] / sinΩ`（由三角恒等式
`sin((1-t)Ω) = sinΩ·cos(tΩ) - cosΩ·sin(tΩ)` 可验证其位于圆上且与 p0 夹角为 tΩ）。
把这个构造直接推广到四维单位球面即得 Slerp。□

**工程要点**：

- 若 `q1·q2 < 0`，先取 `q2 = -q2`（两个四元数表示同一旋转，但取反后插值路径更短，
  避免绕远路）；
- `Ω` 很小时（如 `sinΩ < 1e-6`），退化为普通 Lerp + 归一化，避免除零；
- 对**多个**四元数插值可用 `nlerp` 近似（如骨骼动画的多个姿态混合），速度更快。

**Nlerp**：普通线性插值后归一化。速度最快但角速度不均匀（中间快两端慢），
小角度旋转（< 30°）时误差可忽略，是 Slerp 的廉价替代。

### 6. 与旋转矩阵互转

设单位四元数 `q = (w, x, y, z)`，对应旋转矩阵（列主序向量乘法 `v' = R·v`）：

```text
R = [ 1-2(y²+z²)   2(xy-wz)    2(xz+wy)  ]
    [ 2(xy+wz)     1-2(x²+z²)  2(yz-wx)  ]
    [ 2(xz-wy)     2(yz+wx)    1-2(x²+y²)]
```

**推导思路**：把基向量 `e1=(1,0,0)` 代入旋转公式 `v' = q·v·q⁻¹`，用纯四元数乘法
展开得到矩阵第一列；同理可得第二、三列。该矩阵是正交矩阵（`RᵀR = I`），且
`det(R) = 1`，符合刚体旋转特征。□

**矩阵 → 四元数**（从迹 `tr = m00+m11+m22` 出发）：

```text
若 tr > 0：  w = 0.5·sqrt(tr + 1)，再由 R 反对称部分解出 x, y, z
若 tr ≤ 0：  取最大对角元所在轴为基准（数值稳定），例如 m00 最大时：
  x = 0.5·sqrt(1 + m00 - m11 - m22)
  w = (m21 - m12) / (4x)
其余分量由 R 元素线性组合求出（实现见代码示例）
```

**为什么要分情况？** 因为 `acos` 类反解在接近 ±1 时数值不稳定；从最大对角元出发
可保证除法分母最大、误差最小。这是工业实现的标准技巧。□

### 7. 骨骼动画与相机应用

**骨骼动画**：每个关节的局部旋转用四元数存储，顶点变换链为：

```text
P_world = M_parent · M_joint · P_bindPose⁻¹ · P_vertex
```

其中 `M_joint` 由局部旋转（四元数转矩阵）与局部平移复合。动画混合时对同一关节的
多个动画姿态做**加权混合**：小角度用 Nlerp 逐对混合（如 `normalize(Σ wi·qi)`），
需要高质量时用「多四元数加权平均」（Shoemake 算法）。四元数避免了三角度混合时
的万向锁抖动。

骨骼动画中四元数的完整流转：

```mermaid
flowchart LR
    A["动画剪辑<br/>每关节一组四元数关键帧"] --> B["动画混合<br/>Nlerp/Slerp 加权平均"]
    B --> C["局部姿态<br/>关节的 q（旋转）+ t（平移）"]
    C --> D["正向动力学 FK<br/>M = M_parent · T(t) · R(q)"]
    D --> E["蒙皮矩阵<br/>M_joint · BindPose⁻¹"]
    E --> F["顶点着色器<br/>批量变换网格顶点"]
```

**第三人称相机**：相机跟随角色时，期望朝向 `targetRot` 与当前朝向 `currentRot`
之间的平滑过渡用：

```text
currentRot = Slerp(currentRot, targetRot, 1 - exp(-k·dt))    # 帧率无关平滑
```

比直接赋值更自然，且**不会**出现欧拉角插值中途「转大圈」的问题（因为 Slerp 走
最短弧）。FPS 相机则把「俯仰」与「偏航」分开累计，再合成四元数，规避万向锁。

### 伪代码：Slerp 与四元数旋转

```text
function Slerp(q1, q2, t):
    dot = q1·q2                        # 4D 点积
    if dot < 0:                        # 最短路径修正
        q2 = -q2; dot = -dot
    if dot > 0.9995:                   # 夹角过小，退化为 Nlerp
        return normalize(q1 + t·(q2 - q1))
    Ω = acos(dot)
    return (sin((1-t)·Ω)·q1 + sin(t·Ω)·q2) / sin(Ω)

function RotateVector(q, v):           # v' = q·v·q⁻¹
    qv = (0, v)
    return (q · qv · q⁻¹).vector
```

### C++ 示例

```cpp
#include <cmath>

struct Quat {
    float w, x, y, z;
    Quat operator*(const Quat& o) const {          // 哈密顿积
        return {
            w*o.w - x*o.x - y*o.y - z*o.z,
            w*o.x + x*o.w + y*o.z - z*o.y,
            w*o.y - x*o.z + y*o.w + z*o.x,
            w*o.z + x*o.y - y*o.x + z*o.w
        };
    }
    Quat conj() const { return {w, -x, -y, -z}; }
    Quat normalized() const {
        float l = std::sqrt(w*w + x*x + y*y + z*z);
        return {w/l, x/l, y/l, z/l};
    }
};

// 轴角 → 四元数（注意半角）
Quat FromAxisAngle(float ax, float ay, float az, float angle) {
    float h = angle * 0.5f;
    float s = std::sin(h);
    return {std::cos(h), ax*s, ay*s, az*s};
}

// Slerp（假设两个都是单位四元数）
Quat Slerp(Quat a, Quat b, float t) {
    float d = a.w*b.w + a.x*b.x + a.y*b.y + a.z*b.z;
    if (d < 0.0f) { b = {-b.w, -b.x, -b.y, -b.z}; d = -d; }
    const float kEps = 1e-6f;
    if (d > 1.0f - kEps) {                       // 几乎相同，用 Nlerp
        Quat r = {a.w + t*(b.w-a.w), a.x + t*(b.x-a.x),
                  a.y + t*(b.y-a.y), a.z + t*(b.z-a.z)};
        return r.normalized();
    }
    float omega = std::acos(d);
    float s0 = std::sin((1-t)*omega) / std::sin(omega);
    float s1 = std::sin(t*omega)   / std::sin(omega);
    return {a.w*s0 + b.w*s1, a.x*s0 + b.x*s1,
            a.y*s0 + b.y*s1, a.z*s0 + b.z*s1};
}

// 四元数 → 旋转矩阵（列主序）
void ToMatrix(const Quat& q, float m[16]) {
    float xx=q.x*q.x, yy=q.y*q.y, zz=q.z*q.z;
    float xy=q.x*q.y, xz=q.x*q.z, yz=q.y*q.z;
    float wx=q.w*q.x, wy=q.w*q.y, wz=q.w*q.z;
    m[0]=1-2*(yy+zz); m[4]=2*(xy-wz);   m[8]=2*(xz+wy);  m[12]=0;
    m[1]=2*(xy+wz);   m[5]=1-2*(xx+zz); m[9]=2*(yz-wx);  m[13]=0;
    m[2]=2*(xz-wy);   m[6]=2*(yz+wx);   m[10]=1-2*(xx+yy); m[14]=0;
    m[3]=0; m[7]=0; m[11]=0; m[15]=1;
}
```

### Python 示例（NumPy）

```python
import numpy as np

def quat_mul(a, b):
    wa, va = a[0], a[1:]
    wb, vb = b[0], b[1:]
    return np.concatenate(([wa*wb - va @ vb],
                           wa*vb + wb*va + np.cross(va, vb)))

def quat_conj(q):
    return np.array([q[0], -q[1], -q[2], -q[3]])

def slerp(q1, q2, t):
    d = float(q1 @ q2)
    if d < 0:
        q2 = -q2; d = -d
    if d > 1 - 1e-6:
        r = q1 + t*(q2 - q1)
        return r / np.linalg.norm(r)
    omega = np.arccos(np.clip(d, -1, 1))
    s0 = np.sin((1-t)*omega) / np.sin(omega)
    s1 = np.sin(t*omega) / np.sin(omega)
    return s0*q1 + s1*q2

def rotate_vector(q, v):
    qv = np.concatenate(([0.0], v))
    qinv = quat_conj(q) / (q @ q)          # 通用逆
    return quat_mul(quat_mul(q, qv), qinv)[1:]

# 验证：绕 Z 轴转 90°，(1,0,0) 应变为 (0,1,0)
q = np.array([np.cos(np.pi/4), 0, 0, np.sin(np.pi/4)])
print(rotate_vector(q, np.array([1., 0, 0])))   # ≈ [0, 1, 0]
```

## 复杂度分析

| 运算 | 浮点开销（约） | 对比矩阵 |
| --- | --- | --- |
| 四元数乘法 | 16 次乘 + 12 次加 | 矩阵乘 48 次乘 + 36 次加（快 3 倍） |
| 旋转向量 `q·v·q⁻¹` | 约 30 次乘加 | 矩阵旋转 9 次乘加（矩阵更快，适合批量） |
| Slerp | 1 次 acos + 2 次 sin + 若干乘加 | 无矩阵等价物（矩阵插值无意义） |
| 四元数→矩阵 | 常数（约 20 次乘加） | 每帧对渲染批处理一次即可 |
| 存储 | 4 个 float（16 字节） | 3×3 矩阵 9 个 float（36 字节） |

结论：**单次旋转向量时矩阵更快，但四元数在存储、组合、插值、稳定性上全面占优**。
工业实践：逻辑层（动画、相机、物理姿态）用四元数，渲染前统一转矩阵并批量变换顶点。

## 最佳实践

1. **存储与交换一律用单位四元数**：任何外部输入（文件、网络、物理引擎）进入系统时
   先归一化；非单位四元数会导致旋转「附带缩放」，渲染出拉伸的物体。
2. **Slerp 前检查点积符号**：`dot < 0` 时对其中一个取反，否则插值会绕远路（看似
   突然翻转 360°）。这是四元数「双倍覆盖」特性带来的最隐蔽 bug。
3. **避免存储欧拉角**：仅在编辑器/调试 UI 中用欧拉角展示；运行期姿态一律四元数。
   需要欧拉角时（如 FPS 俯仰偏航）独立累计角度再合成四元数，且**俯仰限幅 ±89°**。
4. **组合旋转注意顺序**：`q_total = q2·q1` 表示先 q1 后 q2（右乘先作用）。相机
   偏航、俯仰组合时先乘偏航再乘俯仰，可避免世界轴/本地轴混淆。
5. **小角度插值用 Nlerp**：骨骼动画批量混合、误差容忍度高时，Nlerp 快且足够好；
   需要恒定角速度（相机旋转、观感敏感的 UI 旋转）才用 Slerp。
6. **矩阵互转注意数值分支**：矩阵→四元数务必按迹/对角元分情况取最大分母，否则
   接近 180° 旋转时数值误差被放大。
7. **测角差用 `q1·q2⁻¹` 的旋转角**：想得到「从 q1 到 q2 的旋转」用
   `Δq = q2·q1⁻¹`，其旋转角 `θ = 2·acos(Δq.w)` 可用来驱动转向动画。

## 常见问题 FAQ

**Q1：为什么旋转公式用半角？直接四元数乘向量不行吗？**
不行。三维旋转必须保持向量模长与「垂直轴分量」的旋转结构。若只用单侧乘法 `q·v`，
结果不仅旋转还会沿轴拉伸（除非 v 恰在旋转平面内）。双面乘法 `q·v·q⁻¹` 恰好抵消
轴向分量、让垂直分量旋转 2·(θ/2) = θ。这也是四元数能表示**三维**旋转而复数只能
表示二维旋转的原因。

**Q2：万向锁到底是怎么发生的？能举个具体数字吗？**
以 YXZ 顺序（先绕 X 再绕 Y 再绕 Z，Unity 常见）为例：绕 X 转 90° 后，原来的 Z 轴
被转到了 Y 方向，此时「绕 Z 转」与「绕 Y 转」作用于同一根物理轴。设初始姿态为
`(90°, 0, 0)`，后续无论怎么调 Y、Z 角度，只能改变两个自由度方向，第三方向不可达；
而为了让姿态「看起来动了」，Y、Z 会以相反方向快速变化——表现为旋转轴疯狂摆动。

**Q3：四元数能表示所有旋转吗？为什么说它双倍覆盖？**
能。任何三维旋转都能写成单位四元数。但 `q` 与 `-q` 表示**同一个旋转**（因为
`(-q)·v·(-q)⁻¹ = q·v·q⁻¹`），这就是双倍覆盖：四维单位球面上的每个点与其对跖点
对应同一姿态。Slerp 若不处理符号，可能在两个「等价」表示之间绕远路。

**Q4：Slerp 和 Lerp+归一化（Nlerp）差在哪？什么时候用哪个？**
Slerp 沿四维球面测地线走，角速度恒定，但包含 acos/sin，开销约为 Nlerp 的 5~10 倍。
Nlerp 是直线插值后投影回球面，角速度不均匀（中段偏快），但实现简单、可批量。
准则：相机、武器、观感敏感处用 Slerp；骨骼动画逐关节混合、角度差 < 30° 时用 Nlerp。

**Q5：为什么矩阵→四元数要分 `tr > 0` 和 `tr ≤ 0` 两种情况？**
因为 `w = 0.5·sqrt(tr+1)` 在 `tr ≈ -1`（即 180° 旋转附近）时分子趋近 0，后续
用 `w` 做除法的公式会爆炸。标准解法：tr > 0 用 w 作分母；否则取最大对角元（x、y、
z 中最大者）作分母，保证除法稳定。

**Q6：FPS 相机用欧拉角真的会出问题吗？很多教程就这么写的。**
现代引擎内部都是四元数；教程里的「欧拉角」通常是**输入层**的俯仰/偏航累计，
最终合成四元数。若直接把三个角度存下来并互相叠加，俯仰 ±90° 时（例如玩家抬头看
正上方）偏航与滚动混淆，镜头会瞬间翻转——这正是万向锁。所以工程上：输入用角度，
状态用四元数。

**Q7：骨骼动画为什么要用四元数而不是矩阵？**
每个骨骼关节存一个矩阵的话，动画数据量是四元数的 2.25 倍（36 vs 16 字节），且
矩阵插值没有数学意义（线性插值矩阵会引入剪切/缩放）；四元数可以 Slerp/Nlerp 出
物理上正确的旋转路径。此外四元数混合（加权平均后归一化）天然保持单位性。

**Q8：怎么判断两个四元数「几乎相同」？**
计算 `|q1·q2|`（4D 点积绝对值）：接近 1 表示旋转几乎一致（注意取绝对值是因为
`q` 与 `-q` 等价）。在动画过渡检测、网络同步的旋转差值计算中常用此判据。
