# RVO/ORCA 与数值鲁棒性

> 知识成熟度：L2。学习主线是“相对运动 → 速度障碍 → 互惠半平面 → 速度圆盘内求解 → 实际运动复核”。
> 最后更新：2026-10-10。
> 知识基线：版本基线为 RVO 2008、ORCA 2011；实现对照为 RVO2 v2.0.2，提交 `c96a6ec8328492bae0721e59774026a119a60b4a`。第3节只用 Python 标准库对一个共线正常例及后处理反例做精确算术，不是完整 RVO2 实现。

## 1. 本篇解决哪一层问题

全局路径回答“应从墙的哪边绕过去”，Steering 根据下一个路径目标、到达减速、队形等生成期望速度 `preferredVelocity`；局部避障再根据邻居和障碍选择这一小段时间内的运动。合法局部速度可能是停止，也可能把角色带离当前路径方向，所以它不证明目标可达、全局最优或不会死锁。

本篇以二维圆盘代理为入口：位置和半径使用米，速度使用米/秒，时间窗和积分步长使用秒。基本模型允许立即选定速度，并假定参与避让的代理准确观察到一致状态、遵循同一互惠协议。服务端权威移动、客户端预测、群体AI可借用这层模型，但真实引擎的碰撞响应、加速度、转弯、Root Motion、网络时延与静态障碍接入还要另外满足执行合同。

读完应能手算一对代理的允许速度，解释多邻居时怎样求半平面交集，识别“求解成功但实际执行破坏约束”的错误，再把数值退化与预算降级变成明确状态。NavMesh烘焙、全局搜索和完整物理求解器由关联主篇负责。

## 2. 从相对运动到 ORCA 约束

### 2.1 先固定符号与碰撞定义

对代理 A 与 B，定义：

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| pA、pB | 圆心位置 | m |
| vA、vB | 当前速度 | m/s |
| p = pB − pA | B 相对 A 的位置 | m |
| vrel = vA − vB | A 相对 B 的速度 | m/s |
| R = rA + rB | 半径和 | m |
| τ | 预测时间窗 timeHorizon | s |
| dt | 本次实际积分步长 timeStep | s |

若两者保持所选速度，t 秒后的中心相对位置为 `p − t·vrel`。中心距小于 R 表示圆盘内部重叠；恰等于 R 是接触边界。用开圆盘 D(p,R) 表示重叠区域，速度障碍就是：

`VOτ = {v | 存在 t∈[0,τ]，使 t·v∈D(p,R)}`

它是**相对速度**的集合，而不是世界坐标中的障碍物。对于初始分离的圆盘，速度空间中的形状可看成截断的锥：截断圆的中心为 p/τ、半径为 R/τ，再接向远处延伸的两条切线腿。完整边界由相关圆弧和两条腿组成，不是整个圆周都能独立作为最近边界。

因此时间窗会改变约束：相同距离和速度下，较长 τ 提前考虑未来相遇，也可能缩小可选速度区域。τ 与 dt 不是同一个参数；τ=2s 不意味着每2s才更新一次。

### 2.2 VO、RVO、ORCA 不能当作同一个名字

VO 先预测对方保持其速度；若两者同时主动避让，却都按“对方完全不变”决策，可能反复互相补偿。RVO 把对方也会调整运动的互惠假设纳入选择，原论文讨论了这种局部反应的振荡问题。ORCA 进一步为每一对代理构造各自允许的**凸半平面**，便于把多对约束求交。[RVO 2008 §III–IV](https://gamma-web.iacs.umd.edu/RVO/icra2008.pdf)

对一个邻居，先在相对速度空间找到从当前 vrel 到 VOτ 边界的最近位移 u，再取该边界向安全侧的单位法线 n。A 承担一半修正，得到线点 `qA = vA + u/2`；其允许区域为：

`H_A|B = {v | (v − qA)·n ≥ 0}`

B 用对称位置、相反相对速度构造另一半责任。两者都遵循约定、选到各自允许集合时，才有这对代理的条件保证。**n 应从几何边界确定，不能总用 normalize(u)**：当前相对速度已经在安全侧时，u 可以指向边界，方向与外法线相反；u=0 时也不能归一化零向量。这里采用可观察的当前速度建立约束，preferredVelocity 用于后面的最优选择，两者职责不同。

为 A 收集全部相关邻居和静态边界的约束，再与最大速度圆盘相交：

`F_A = {v | |v| ≤ maxSpeed_A} ∩ H_A|B1 ∩ H_A|B2 ∩ …`

在 F_A 非空时，选择离 `preferredVelocity_A` 最近的速度。此处“最优”只指当次速度空间中的距离目标，不是最短路、最短到达时间或优先级公平。模型、半平面及圆盘约束见 [ORCA §3–5，式(2)、(5)–(9)](https://gamma.cs.unc.edu/ORCA/publications/ORCA.pdf)。

### 2.3 同一快照求解，再一起更新

先保存所有代理这一帧的位置、当前速度、半径和参数；由此查询邻居、生成各自约束，计算全部新速度，最后统一更新 `position += newVelocity * dt`。不能刚算完 A 就写回位置，让 B 读到 A 的新位置和其他代理的旧位置。

固定版本 [RVOSimulator.cpp 的 doStep](https://github.com/snape/RVO2/blob/c96a6ec8328492bae0721e59774026a119a60b4a/src/RVOSimulator.cpp) 正是先计算各代理的邻居与新速度，随后另一轮统一 update。并行计算可以使用这一分阶段组织，但“使用了并行”不自动保证所有外围输入、浮点运算和回放结果一致。

## 3. 完整正常例：两名代理对向接近

### 3.1 输入、分支、速度与位置

只有两名全向圆盘代理，y 坐标和 y 速度均为0；互相完整观察且同步更新，没有静态障碍，也没有实际加速度限制。每个半径0.5m、最大速度1m/s，τ=2s，dt=0.25s。

| 输入 | A | B |
| --- | --- | --- |
| 稳定 ID | 1 | 2 |
| 位置 m | (0,0) | (4,0) |
| 当前速度 m/s | (0.9,0) | (−0.9,0) |
| preferredVelocity m/s | (1,0) | (−1,0) |

对 A，p=(4,0)、R=1、vrel=(1.8,0)，两者还未接触。截断圆中心为(2,0)m/s、半径0.5m/s；从圆心指向当前相对速度的向量 `w = vrel − p/τ = (−0.2,0)`。

按固定实现的非重叠分支，`w·p=−0.8<0`，且 `(w·p)²=0.64 > R²|w|²=0.04`，因此最近点落在截断圆弧，不走切线腿分支。单位外法线 n=(−1,0)，修正 `u = (R/τ − |w|)n = (−0.3,0)m/s`，所以 qA=(0.75,0)m/s，允许区域为 **vAx≤0.75**。B 对称得到 qB=(−0.75,0)m/s、**vBx≥−0.75**。

两者期望速度都在允许侧以外。与各自单位速度圆盘求交后，最近点分别是 **vA'=(0.75,0)、vB'=(−0.75,0)m/s**。同步积分一步得到 A=(0.1875,0)m、B=(3.8125,0)m，**中心距29/8=3.625m**；减去半径和后，表面间隙为21/8=2.625m。

如果把这对新速度保持整整2s，中心距从4m单调下降到1m，恰好接触。它满足本例“不发生内部重叠”的边界定义，却没有正的物理安全裕量。若项目要求额外间隔，应事先在几何尺寸或约束合同中建模，不能把数值容差当作实际安全余量。

### 3.2 可直接运行的精确算术短例

以下程序只核算上述**共线、单邻居、cut-off圆弧分支**及一个事后限加速度反例。使用 `Fraction` 避免这个教学例的十进制舍入混淆；它没有实现通用二维ORCA、切线腿、多邻居、静态障碍、浮点退化或真实动力学。保存为Python文件后用 `python3 -I -B 文件名.py` 运行，不加 `-O`；`-I` 忽略包括 `PYTHONOPTIMIZE` 在内的Python环境配置，断言保持开启。

```python
from fractions import Fraction as F

p_a, p_b = F(0), F(4)
v_a, v_b = F(9, 10), F(-9, 10)
pref_a, pref_b = F(1), F(-1)
r_a = r_b = F(1, 2)
max_speed, horizon, dt = F(1), F(2), F(1, 4)
p, radius, relative_v = p_b - p_a, r_a + r_b, v_a - v_b
w = relative_v - p / horizon
assert p * p > radius * radius
assert w * p < 0 and (w * p) ** 2 > radius ** 2 * w ** 2
normal_a = F(-1)  # w < 0, all y = 0
u_a = (radius / horizon - abs(w)) * normal_a
q_a, q_b = v_a + u_a / 2, v_b - u_a / 2
assert -max_speed <= q_a and q_b <= max_speed
new_a = min(max(pref_a, -max_speed), q_a, max_speed)
new_b = max(min(pref_b, max_speed), q_b, -max_speed)
assert new_a == F(3, 4) and new_b == F(-3, 4)
assert new_a <= q_a and new_b >= q_b
assert abs(new_a) <= max_speed and abs(new_b) <= max_speed
next_a, next_b = p_a + new_a * dt, p_b + new_b * dt
assert (next_a, next_b) == (F(3, 16), F(61, 16))
assert next_b - next_a == F(29, 8)
closing = new_a - new_b
assert closing > 0 and p - closing * horizon == radius
assert p - closing * dt > radius

# Both agents limit their velocity change after ORCA: violates its half-planes.
max_acceleration = F(2, 5)
limit = max_acceleration * dt
clamped_a, clamped_b = max(new_a, v_a - limit), min(new_b, v_b + limit)
assert (clamped_a, clamped_b) == (F(4, 5), F(-4, 5))
assert clamped_a > q_a and clamped_b < q_b
touch_time = (p - radius) / (clamped_a - clamped_b)
assert touch_time == F(15, 8) and dt < touch_time < horizon
print("exact teaching case: velocities=(3/4,-3/4), center_distance_after_step=29/8")
print("post-clamp counterexample: velocities=(4/5,-4/5), touch_time=15/8")
```

本次实际观察：2026-10-10 UTC，Python 3.12.14；从本节逐字抽取上述程序，用该解释器的 `-I -B` 参数执行一次，设置5秒上限。断言开启（优化级别0），退出码0、未超时、stderr为空；stdout如下。程序UTF-8字节（含末尾换行）的SHA-256为 `f941dfbff6f8b0bac0af033e09d8072fed7eb3ca8047358fa4884d97f03b00c1`。

```text

post-clamp counterexample: velocities=(4/5,-4/5), touch_time=15/8
```

这一观察仅说明该精确算术程序的断言通过；未运行RVO2浮点实现、完整二维求解器、UE、产品轨迹或性能测试。

### 3.3 为什么求解后限加速度会破坏原结论

假设两者又被要求加速度最多0.4m/s²。本步最多改变0.1m/s，若在上述求解之后裁剪速度，实际得到±0.8m/s，双方分别违反原半平面0.05m/s。保持这些裁剪速度时，首次接触时间为 `(4−1)/(0.8−(−0.8))=15/8=1.875s`，早于2s预测窗。

这不表示0.25s这一帧已经碰撞：此时中心距仍为3.6m；也不表示随后每帧重算的实际轨迹必撞。它准确说明：**后处理后的速度已经不能沿用刚才的允许集合和2s外推结论**。

把加速度可达圆盘加入速度求解，只限制了可选终点速度，仍不能自动证明一帧内连续加速、车辆转弯或动画驱动的真实轨迹安全。需要相应运动模型与轨迹检查，或选择专门考虑动力学约束的方法。

## 4. 推广到二维、多邻居与静态障碍

### 4.1 一般代理约束怎样生成

固定版本 [Agent.cpp](https://github.com/snape/RVO2/blob/c96a6ec8328492bae0721e59774026a119a60b4a/src/Agent.cpp) 的 `computeNewVelocity` 先生成障碍线，再生成代理线。代理初始分离时，计算 `w=vrel−p/τ`：满足第3节的两个条件就投影到截断圆弧；否则选择相关切线腿，将相对速度投影到这条腿的方向上。两种分支都得到 u，再取代理线点 `vA+u/2`。第3节只执行了其中第一种正常分支。

若中心距已小于或等于 R，实现改用 **dt** 构造接触/重叠恢复线；这不是把普通预测时间窗机械改小就能获得的新安全证明。初始已经重叠时，“未来采用哪个分离方向”与“从未发生碰撞”是不同命题；相同中心、相同速度还会产生零长度 w，见第6节。

静态障碍不会承担另一半责任，不能简单伪装为普通互惠代理。多边形边、顶点、凸性与可见切线使其生成过程比圆盘对复杂；RVO2有单独障碍线处理和 `timeHorizonObst`。本篇解释它与代理约束共用后续求解器，但不以两圆短例声称验证了多边形处理。

### 4.2 用一条有方向的线表示半平面

令线点为 q，单位切向为 d，允许侧在这条有向线的左侧。定义二维行列式 `det(a,b)=ax·by−ay·bx`，约束就是：

`det(d, v−q) ≥ 0`，等价于 `det(d, q−v) ≤ 0`

对应单位法线为 n=(−dy,dx)。在第3节，A可用 q=(0.75,0)、d=(0,1)，左侧正是vx≤0.75。这样先检查一个容易画图的小例，可以防止相对速度符号和允许侧一起写反后“自洽地通过”错误测试。RVO2 API也把允许侧定义为左侧：[RVOSimulator.h，getAgentORCALine](https://github.com/snape/RVO2/blob/c96a6ec8328492bae0721e59774026a119a60b4a/src/RVOSimulator.h)。

### 4.3 增量求交为什么变成一维区间

下面是一般二维求解的几何解释，**不是第3节程序已实现的功能**。初始只考虑最大速度圆盘：若期望速度在圆盘内，当前最优值就是它；否则取圆盘上沿期望方向的点。之后依次加入半平面。

新半平面包含当前最优速度时，旧最优仍是新集合中的最近点，可以继续。若违反新半平面，而加入后仍有可行解，最近点会落在这条新边界上：旧可行集合是凸的，旧最优在新约束外，向新可行区域收缩时需跨过这条边界。因此把新线 i 上的速度写成：

`v(t)=q_i+t·d_i`，其中 `|d_i|=1`

首先用速度圆盘截出允许 t 区间。把 v(t) 代入 `|v|²≤s²`，得到判别式 `Δ=(q_i·d_i)²+s²−|q_i|²`。若Δ<0，直线不与圆盘相交，本次边界求解失败；否则初始区间是：

`[−q_i·d_i−sqrt(Δ), −q_i·d_i+sqrt(Δ)]`

接着依次用每条先前半平面 j 截断该区间。令 `α=det(d_j,d_i)`、`β=det(d_j,q_i−q_j)`，它在新线上的条件为 `β+α·t≥0`：

- α>0：加入下界 t≥−β/α
- α<0：加入上界 t≤−β/α
- α=0：两条边界平行；β<0时整条新边界都违反旧约束，否则旧约束不再限制t

若下界超过上界，表示不存在同时位于新线、速度圆盘和全部旧半平面内的点，不能随意挑一个端点当成功。否则期望速度在该线上的投影参数为 `t0=d_i·(preferredVelocity−q_i)`；把t0夹到最终区间，得到本次最优速度，再继续处理后续约束。实现中的近零α和微小负Δ还需数值政策，不能直接把所有失败都钳成0掩盖。

这解释了 `linearProgram2` 的逐线检查与 `linearProgram1` 的边界区间求解为何配合工作；函数名中的“线性规划”不能代替圆盘、方向和区间的实际几何意义。静态循环分析可看出，一次新线修复需扫描先前约束，固定次序的基本增量过程最坏可出现二次扫描量；它不是“一次循环所以总是O(m)”。

### 4.4 无可行解与复杂度该怎样报告

例如速度上限1m/s，又同时要求vx≥0.8和vx≤−0.8，允许集合为空。拥挤、初始交叠、互相冲突的约束或额外运动限制都可能导致这种情况。固定实现基本求解失败后调用 `linearProgram3` 做后备处理；返回了向量并不说明它满足所有原始代理约束。应报告候选、违反量和退化状态，并由实际运动系统处置，不继续标注“无碰撞”。

性能来自多个阶段：空间结构构建/更新、候选查询、邻居维护、障碍与代理约束生成、逐线求解、失败后备。若A有m条线，m既受代理邻居数影响，也受静态障碍影响；加大 `maxNeighbors` 不只多几个距离比较。论文中随机增量算法的期望线性结论带有约束顺序等前提，不能移植成固定顺序RVO2的最坏界，更不是整个N代理场景的帧耗时。

任何P50/P95/P99、吞吐或内存预算，都需固定场景、工具链和真实阶段计时。本篇没有执行RVO2计时或容量基准。

## 5. 工程接入：把求解速度变成可执行运动

### 5.1 邻居覆盖、排序与责任

朴素两两候选检查是O(N²)；网格、动态树、KD树或空间哈希可以缩小搜索范围，但聚集分布仍可能很贵。AOI可以给出粗候选，却不是精确碰撞邻居集合：先依据碰撞层、体型、时间窗、速度上界与实体状态确定需要覆盖的对象，再做精确距离等过滤。

若采用最近邻截断策略，可以按 `(distanceSquared, stableEntityId)` 排序，用稳定ID打破同距平局，不按指针地址或哈希遍历顺序。固定v2.0.2源码按距离插入，没有承诺这个ID平局规则；后者是项目自己的确定性政策。确定地漏掉一个危险近邻仍然是漏选。

邻居距离过小或数量上限过低会损失安全性，官方[参数说明](https://gamma-web.iacs.umd.edu/RVO2/documentation/2.0/params.html)也明确提醒这一点。应记录候选数、采用数、截断数及状态年龄，并核对被忽略对象是否可能在执行区间内进入碰撞范围；不能因为AOI事件一致，就断言ORCA威胁覆盖完整。

默认互惠代理各承担1/2修正。若用优先级改变责任比例，双方必须对同一对代理使用一致、互补的规则，不能各自都认为对方会多让。`priorityClass`、`teamMask`、`collisionLayer`、`preferredSpeed`、`maxAcceleration`、`maxNeighbors`、`timeHorizon`、`yieldDeadline`等项目字段需进入回放或可由输入重建；这些不是RVO2原生字段清单。静态墙、玩家或不合作对象不能被默认赋予另一半责任。

### 5.2 Steering、动画与结果合同

推荐流程是：全局走廊给下一目标 → 根据角色状态形成preferredVelocity → 在当前避障与所选运动模型下求候选 → 检查实际要执行的运动 → 统一提交。侧向偏好、滞回和队形意图可以影响preferredVelocity；求解后再加力、归一化为满速、限加速度或改转向，会改变已验证对象。

服务端权威位置的修改应有统一入口。动画可以表现已认可的运动，若Root Motion本身驱动权威位移，就必须纳入输入和轨迹校验，不能无记录地覆盖结果。局部避障也不应偷偷改变全局NavMesh。相关分层见[路径平滑与转向行为](04-路径平滑与转向行为.md)和[流场与群体寻路](03-流场与群体寻路.md)。

输出至少分清以下信息，而不只返回一个速度和含糊的bool：

- 候选及其状态：输入非法、数值退化、约束未满足或当前模型内可行；不要把有限向量等同安全速度
- 使用的快照/地图/算法版本、dt、τ和邻居年龄，便于判断结果是否过期
- `numConstraints`是生成线数；`activeConstraints`需另定义靠近边界的残差阈值并逐条计数，不能直接填总线数
- 对单位方向，逐条半平面违反量为 `r_i=max(0,det(d_i,q_i−v))`，全部半平面的最大违反量为 `r_max=max_i r_i`，单位m/s；零约束时定义 `r_max=0`。这只度量半平面违反量，速度上限、输入与结果的有限性及静态几何仍须分别检查

若实际运动是恒速圆盘，对一对代理可在执行区间 `[0,dt]` 上检查中心距最小值：相对速度非零时取 `t*=clamp((p·vrel)/|vrel|²,0,dt)`，检查 `|p−t*·vrel|`；相对速度为零时检查初始距离。此式只覆盖这种线性运动和这一对对象，真实扫掠体或加速轨迹不能直接套用。

### 5.3 振荡、死锁与预算降级

振荡可由相同优先级的对称选择、邻居平局不稳定、太短时间窗或求解与积分不同步引起。可记录方向翻转次数，对preferredVelocity使用小滞回、短时绕行侧偏好，并固定参数和随机流版本；不能求解后突然添加一个未检查的侧向速度。

死锁则是局部速度合法但长期无目标进展。窄门双向对冲、环形队列和优先级环都可能发生。检测窗口可用固定帧数表示，同时看目标距离下降、累计位移、速度和约束状态；只看速度会漏掉原地转向，只看位置可能把合理低速移动误报。`epsilonProgress`与`epsilonDisplacement`须带长度单位，并结合目标和地形设定。

恢复可先改变路径目标/让行计划或短时偏好，再请求局部绕行点、全局重规划，最后进入服务端裁决的停靠或脱困。公平策略可限制最大让行时间，防止低优先级无限等待；不得为了脱困直接删除安全约束或假定高优先级可以穿过其他单位。

服务端可按帧、分区和实体类别分配预算；关键战斗单位与远处NPC可以有不同处理频率，但低频、群体代理、少邻居和旧速度复用都会改变模型或输入时效。**旧速度只在当前快照、当前执行区间复核后才可复用**；零速度也可能被别的物体撞上。预算不足应报告降级和未满足的保证，而不是在“安全优先”之后默认删邻居即可安全。

至少记录 `localAvoidanceBudgetUs`、`agentsProcessed`、`neighborTruncated`、`fallbackCount`，并补阶段耗时、输入年龄、约束违反量和真实位移。回放还需保存稳定排序、速度/半径、责任协议、时间参数与结果哈希；哈希能定位差异，不会自动修复差异。

## 6. 数值鲁棒性：单位、退化与确定性

### 6.1 有限输入不是有限结果的充分条件

误差来自数值表示、运算顺序、编译器优化、FMA/SIMD、指令集和遍历顺序。相同十进制输入或都用float32不保证中间位模式相同。接近切线时，行列式的最后几位差异可能改变分支；应分别声明哪些结果要求位一致、哪些允许误差。

先检查位置/速度有限，dt、τ、障碍时间窗为正，半径/最大速度/邻居距离非负，再对中间差值、平方、归一化、求解结果和积分位置检查有限性。两个很大的有限数相减或平方仍可能溢出；NaN也不能进入排序或最优值比较。拒绝时记录对象、阶段、算法和地图版本，不把“比较未报错”当作合法。

### 6.2 容差必须跟着表达式的量纲走

可以用“绝对容差 + 相对容差×尺度”表达允许误差，但尺度和单位要明确，且这种近似相等不适合直接当排序关系。

| 表达式或参数 | 量纲 | 典型用途 |
| --- | --- | --- |
| 位置差、半径、通道宽、位移 | m | 几何尺寸与退化长度 |
| 距离平方、位置向量的det | m² | 圆盘重叠、面积/方向判断 |
| 速度、单位方向与速度差的det | m/s | ORCA半平面残差、近零速度 |
| 两个单位方向的det | 无量纲 | 近平行方向，不是面积 |
| dt、τ、累计模拟时间 | s | 步长与时间合同 |
| 加速度 | m/s² | 可执行运动模型 |

不能把1e−5复制到以上所有判断；更不能把长度阈值直接用于平方量。将米改成厘米时，长度和速度变100倍、平方量变10000倍、时间不变。相应阈值和日志也要转换。小残差容忍、几何安全膨胀与玩法允许的接触距离是三种不同政策。

### 6.3 必须定义的退化分支

| 输入或数值情形 | 风险 | 处理边界 |
| --- | --- | --- |
| 两代理中心与速度完全相同 | 重叠分支w=0，固定源码中的w/|w|无定义 | 报告初始重叠/退化；若选稳定分离方向须记录策略，不能追认从未碰撞 |
| 零长度边、连续重复顶点 | 障碍方向归一化或线段投影分母为0 | 输入清理须保拓扑；不能随意删点后仍称同一障碍 |
| 共线/近共线、零面积三角形 | 方向符号和裁剪拓扑翻转 | 明确共线分支，必要时采用可靠谓词 |
| 近切线、速度圆盘判别式微负 | 数学可行与浮点判失败难分 | 用声明的误差政策判定/报告；不能无条件sqrt(max(0,Δ))掩盖真正不相交 |
| 近平行半平面 | 很小分母放大误差 | 使用方向量纲的阈值并区分同向/反向约束，检查区间是否为空 |
| 半平面与限速/运动约束无交集 | 后备向量违反原约束 | 输出失败/降级及残差，不标安全 |

在路径后处理里，线段退化可返回端点或明确的指定最近点；漏斗门户左右重合则按通道合同处理为中心门户或不可用。这些选择必须来自各自几何模型，不能用一个“鲁棒模式”统一猜测。

[Shewchuk的自适应几何谓词](https://www.cs.cmu.edu/~quake/robust.html)解释了近零行列式符号为何可能出错，并提供特定orientation/incircle判断方法。可靠谓词能改善这些判定，不保证半径误差、积分、邻居漏选和动力学模型也随之正确。

### 6.4 坐标尺度与排序合同

项目应记录 `worldUnitPerMeter`、角色半径、最大速度/加速度、最小通道宽、地图跨度，以及导航、碰撞、渲染是否共享原点。局部原点或分区坐标有助于控制量级；若输入低位早已丢失，事后减原点不能恢复。回放/哈希需包含分区、原点重定位版本和量化政策。

比较器要求严格弱序，不能把“误差范围内相等”塞进小于判断。例：令eps=1，`less(a,b)=(a < b−eps)`，a=0、b=0.75、c=1.5。a与b不可比，b与c不可比，但a<c，不可比较等价关系不传递，违反有序算法的合同。[C++ strict weak order要求](https://eel.is/c%2B%2Bdraft/concept.strictweakorder)

拒绝NaN/无穷后，可用固定的有限成本/距离key，再用稳定节点或实体ID打平；若选择量化，需要明确网格、舍入、范围与溢出行为。量化会改变比较和几何，不能当成无代价的通用修复；也不能用随机扰动或内存地址掩盖平局。稳定排序仍不证明跨工具链的中间浮点运算逐位相同。模拟时间与本地墙钟也应分开。

### 6.5 GJK、EPA、CCD与本层的接口

GJK常用于凸体相交/距离，EPA在相交后估计穿透深度和方向，CCD检查连续运动中的接触，三者不是一个“精确碰撞开关”。支持点的坐标系与形状边界、退化单纯形、最大迭代次数、扫掠形状/区间及接触响应都会影响结果。

导航或避障输出可先做包围盒、圆/胶囊等粗查询，再对实际路径段使用匹配运动模型的swept test；离散端点都不重叠仍可能中途穿透。超时或退化应进入未认证/需重规划状态，不能默认为安全。通用碰撞和积分细节见[碰撞检测](../空间查询与碰撞/04-碰撞检测.md)与[数值积分与运动学模拟](../数学与数值计算/05-数值积分与运动学模拟.md)。物理库的尺度建议只能在其单位和版本背景下使用，不能推广成全部引擎的硬阈值。

## 7. 如何验证，已有证据能回答什么

验收应观察实际执行对象，而不是仅检查函数返回了一个向量：

| 检查 | 应记录的结果 | 不能据此推出 |
| --- | --- | --- |
| 本文固定正常例 | 分支、两条允许侧、限速、速度、一步中心距 | 完整二维求解器或RVO2浮点实现通过 |
| 本文后处理反例 | ±0.8违反半平面、恒速首次接触15/8s | 本帧已撞或逐帧重算后必撞 |
| 原点/大坐标/尺度变化 | 单位换算、有限性、几何残差与声明容差 | 任意大地图都等价 |
| 共线、重复点、中心重合 | 明确失败/恢复分支、无未处理NaN | 初始重叠也具有无碰撞保证 |
| 极窄通道、接触边界 | 扫掠距离、接触定义与物理裕量 | 全局可达或必然脱困 |
| 多邻居、邻居截断、低频更新 | 覆盖、年龄、约束违反与真实轨迹 | 少量样例代表所有分布 |
| 长时间回放与排序平局 | 固定输入的首差、哈希及模拟时间 | 一个平台通过等于跨平台位确定性 |

上表除第3节那一个有限程序外，均为需要真实实现/场景另行覆盖的检查方向，本次没有执行这些测试矩阵、旧实验、RVO2、UE或性能采样。
