# 04-线程池、任务调度与协程调度

> 知识成熟度：L2。主承诺是解释准入、工作分配、数据依赖和协程寿命之间的合同；依据固定 N4861 C++20 工作草案条文、2005/2013 原论文相关段落及 Epic 公开文档作静态核对。第 7 节另列本文原样代码的有限本机验证，不能推广成无锁算法证明、跨平台认证或生产性能结论。
> 适用范围：标准 C++20，最多两个工作线程、每队列四个预分配槽；固定纯值 DAG 与 main→io→logic→final 协程路线。任务最终返回，捕获析构不抛异常；外部拥有者保证池和借用对象存活。
> 最后更新：2026-10-06。本文不实现 epoll、真正异步数据库、通用取消运行时或 UE 调度后端；logic 池也不代表游戏主线程。

## 1. 先分清四种责任，再决定线程数

线程池把多项任务交给一组复用的 OS 线程，避免每项任务都创建、销毁线程。是否更快仍取决于任务粒度、排队、同步和执行成本。Linux NPTL 的默认线程栈与进程启动时的资源限制、架构及线程属性有关，不能给所有进程套用“2–8 MB”或固定创建周期；本页没有测过这些数值。[pthread_create 的 NOTES](https://man7.org/linux/man-pages/man3/pthread_create.3.html)

```text
Producer：拥有输入，处理准入结果
    |
    v
Scheduler：队列决定谁可执行；DAG 决定何时可执行
           协程 awaiter 负责移交某一挂起点的恢复责任
    |
    v
Worker 0 / Worker 1：OS 工作线程，领取后执行
    |
    v
结果拥有者：取值或异常；收束执行方；最后释放资源
```

集中队列、工作窃取、DAG 与协程是可组合的机制，不是每个池都必备的四层模块。任务分配给 Worker 0 不表示线程绑定 CPU 0；顺序依赖也不自动替共享数据建立同步。小规模、较粗任务可先用集中队列，再以实测决定是否值得增加调度复杂度。

CPU 数只提供测量起点。`hardware_concurrency()` 是允许返回 0 的提示，不是容器 CPU 配额或物理核心保证。需要同时考虑主线程自身计算、可用配额、任务粒度和尾延迟。[N4861 thread.thread.static /1](https://timsong-cpp.github.io/cppwp/n4861/thread.thread.static)

估算 `CPU数量 × (1 + 等待时间/计算时间)` 需要负载稳定、等待可被其他任务覆盖等前提，不是容量合同。磁盘等待与解压计算也应分开计量，解压可能占用大量 CPU。长阻塞工作常应与有期限的计算隔离，或分别限制并发；非阻塞 I/O、有界短阻塞和充足资源可以采用其他组织。无论多少线程，都还需要队列预算、拒绝和上游限流，否则积压没有边界。

## 2. 从执行权开始：一个有限而完整的线程池

下面不是生产调度器或 Chase–Lev 的实现。它用一把 mutex 保护所有队列、`queued_` 和 `closed_`，保留真实的本地尾取、远端头取；代价是准入和领取仍然串行。固定最多两线程、每队列四槽，避免把索引溢出、扩容和通用配置混入主证明。

全文四个标为 `BEGIN PART 1` 到 `BEGIN PART 4` 的 C++ 块，按顺序原样连接就是一个完整翻译单元。其余示意和编译反例不是该程序的一部分。`Gate`/`PoolProbe` 只用于第 7 节的有限门控和真实领取记录，默认不启用；它们在队列锁外使用，且必须活得比借用它们的池长。

### 2.1 准入不是“返回了 future”

`Job::Make` 接受已绑定为零参数的 callable。返回类型按实际存储对象的左值调用 `std::decay_t<F>&` 推导，与 `packaged_task` 调用其存储对象的类别一致。调用者得到一个 fresh `unique_ptr<Job>` 和一个 future，但没有执行 Job 的接口。`valid()` 只能检查共享状态存在，不能证明 packaged_task 从未执行；这里通过封装隐藏执行权，而不是假称能检测所有重复执行。[N4861 futures.task.members /3、/13、/18–20](https://timsong-cpp.github.io/cppwp/n4861/futures.task.members)

`Accepted` 才把唯一执行权交给池。`Full` 是指定队列已满，即使另一队列有空位也会拒绝；`Closed` 是准入已关闭；`Invalid` 是空指针或非法队列编号。三个拒绝结果均不移动输入。调用者可以以后重试，或放弃仍持有的 Job；放弃未完成状态时 future 报 `broken_promise`，不是业务成功或已经合作取消。

Job、callable、future 共享状态和类型擦除对象全在进入池锁之前构造。内部 shared_ptr 只服务于可复制的 `std::function` 包装，不给调用者第二份执行权；这是简明实现的分配成本，不是无分配承诺。例子只返回拥有的值，不支持 `future<T&>`；按引用捕获仍须由调用者证明被引用对象活到任务结束。

```cpp
// BEGIN PART 1: jobs, fixed storage, and work stealing
#include <array>
#include <atomic>
#include <cassert>
#include <condition_variable>
#include <coroutine>
#include <cstdint>
#include <exception>
#include <functional>
#include <future>
#include <initializer_list>
#include <iostream>
#include <memory>
#include <mutex>
#include <optional>
#include <stdexcept>
#include <string>
#include <thread>
#include <type_traits>
#include <utility>
#include <vector>

// Only the finite tests use Gate/PoolProbe. They outlive every borrowing pool.
class Gate {
    std::mutex mutex_;
    std::condition_variable cv_;
    bool open_ = false;
public:
    void Open() noexcept {
        { std::lock_guard lock(mutex_); open_ = true; }
        cv_.notify_all();
    }
    void Wait() noexcept {
        std::unique_lock lock(mutex_);
        cv_.wait(lock, [this] { return open_; });
    }
    bool IsOpen() noexcept {
        std::lock_guard lock(mutex_);
        return open_;
    }
};
struct Pick { int id; unsigned worker, victim; bool remote; };
struct PoolProbe {
    std::array<Gate, 2> start;
    std::mutex mutex;
    std::vector<Pick> picks;
    void Record(Pick p) {
        std::lock_guard lock(mutex);
        picks.push_back(p);
    }
    std::vector<Pick> Read() {
        std::lock_guard lock(mutex);
        return picks;
    }
};

class Pool;
class Job final {
    friend class Pool;
    int id_;
    std::function<void()> run_;
    Job(int id, std::function<void()>&& run)
        : id_(id), run_(std::move(run)) {}
public:
    Job(const Job&) = delete;
    Job& operator=(const Job&) = delete;
    template<class F>
        requires std::is_invocable_v<std::decay_t<F>&>
    static auto Make(int id, F&& f) {
        using R = std::invoke_result_t<std::decay_t<F>&>;
        static_assert(!std::is_reference_v<R>, "this example returns owned values");
        auto task = std::make_shared<std::packaged_task<R()>>(std::forward<F>(f));
        auto future = task->get_future();
        std::function<void()> run = [task = std::move(task)] { (*task)(); };
        return std::pair{std::unique_ptr<Job>(new Job(id, std::move(run))),
                         std::move(future)};
    }
};

enum class Admission { Accepted, Full, Closed, Invalid };
class Pool {
    static constexpr unsigned MaxWorkers = 2, Capacity = 4;
    static_assert(MaxWorkers > 0 && Capacity > 0);
    struct Queue {
        std::array<std::unique_ptr<Job>, Capacity> slots;
        unsigned head = 0, count = 0;
    };
    std::array<Queue, MaxWorkers> queues_;
    std::mutex mutex_;
    std::condition_variable cv_;
    unsigned queued_ = 0;
    bool closed_ = false;
    unsigned n_;
    PoolProbe* probe_;
    std::array<std::thread, MaxWorkers> workers_;

    void Worker(unsigned me) noexcept {
        // Synchronization failures and unexpected infrastructure errors are fatal.
        try {
            if (probe_) probe_->start[me].Wait();
            for (;;) {
                std::unique_ptr<Job> local; // Empty destination, anew every turn.
                unsigned victim = me;
                {
                    std::unique_lock lock(mutex_);
                    cv_.wait(lock, [this] { return closed_ || queued_ != 0; });
                    if (queued_ == 0) return; // Predicate implies closed_.
                    if (queues_[me].count == 0) {
                        victim = (me + 1) % n_; // n_ is only 1 or 2.
                    }
                    auto& q = queues_[victim];
                    assert(q.count != 0);
                    bool remote = victim != me;
                    unsigned slot = remote ? q.head
                                          : (q.head + q.count - 1) % Capacity;
                    assert(!local && q.slots[slot]);
                    local = std::move(q.slots[slot]);
                    if (remote) q.head = (q.head + 1) % Capacity;
                    --q.count;
                    --queued_;
                }
                if (probe_) probe_->Record({local->id_, me, victim, me != victim});
                local->run_(); // User errors go to future; infrastructure errors reach catch.
                // local and the Job are destroyed here, outside mutex_.
            }
        } catch (...) {
            std::terminate();
        }
    }
public:
    explicit Pool(unsigned workers = 2, PoolProbe* probe = nullptr)
        : n_(workers), probe_(probe) {
        if (n_ == 0 || n_ > MaxWorkers)
            throw std::invalid_argument("workers must be 1 or 2");
        try {
            for (unsigned i = 0; i != n_; ++i)
                workers_[i] = std::thread([this, i] { Worker(i); });
        } catch (...) {
            // Test gates must also release workers if construction is partial.
            if (probe_) for (auto& gate : probe_->start) gate.Open();
            DrainJoin();
            throw;
        }
    }
    Pool(const Pool&) = delete;
    Pool& operator=(const Pool&) = delete;
    ~Pool() { DrainJoin(); }

    Admission TrySubmit(std::unique_ptr<Job>& fresh, unsigned preferred = 0) noexcept {
        // Caller exclusively owns fresh and keeps this Pool alive for the call.
        if (!fresh || preferred >= n_) return Admission::Invalid;
        {
            std::lock_guard lock(mutex_);
            if (closed_) return Admission::Closed;
            auto& q = queues_[preferred];
            if (q.count == Capacity) return Admission::Full;
            unsigned slot = (q.head + q.count) % Capacity;
            assert(!q.slots[slot]); // move assignment must not delete an old Job.
            q.slots[slot] = std::move(fresh);
            ++q.count;
            ++queued_;
        }
        cv_.notify_one();
        return Admission::Accepted; // No throwing step after publication.
    }
    void CloseAdmission() noexcept {
        { std::lock_guard lock(mutex_); closed_ = true; }
        cv_.notify_all();
    }
    void DrainJoin() noexcept {
        // Only the single external owner calls this, after external callers exit.
        CloseAdmission();
        for (auto& t : workers_) {
            if (!t.joinable()) continue;
            if (t.get_id() == std::this_thread::get_id()) std::terminate();
            try { t.join(); } catch (...) { std::terminate(); }
        }
    }
};
// END PART 1
```

### 2.2 为什么通知不会丢掉工作

每个队列的有效元素是从 `head` 起的 `count` 个环形槽。外部准入向尾部空槽写，owner 从尾部取，thief 从头部取；同一锁内始终满足 `queued_ == 所有 count 之和`。上限是八个排队 Job，另可有两个正在执行的 Job；这不限制捕获大小、调用者尚未提交的 Job 或整个进程内存。

锁内移动只转移默认 deleter 的 unique_ptr。入队目的槽必须为空；每轮 worker 的 `local` 也重新为空。因为移动赋值会先处理旧目标，如果把上一轮非空 `local` 留到下一轮锁内覆盖，就可能在持锁时析构用户捕获。现在 Job 执行、销毁均在锁外；future 共享状态的最后释放仍可能发生在结果拥有者线程，不能承诺所有释放都在 worker。[N4861 unique_ptr 移动赋值 /3–5](https://timsong-cpp.github.io/cppwp/n4861/unique.ptr.single.asgn)、[析构](https://timsong-cpp.github.io/cppwp/n4861/unique.ptr.single.dtor)

等待条件是 `closed_ || queued_ != 0`。Submit 在同一锁下写任务并增加计数，wait 也在这把锁下重查事实；notify 只是提示重查，既不保存“通知次数”，也不把 false 谓词改为 true。旧例的谓词只有 stop，正常提交时 stop 仍为 false，notify 后可以继续等待；50 微秒超时也不是唤醒延迟上界。[N4861 condition_variable /13、/30、/36](https://timsong-cpp.github.io/cppwp/n4861/thread.condition.condvar)

### 2.3 Close 的线性化与真正的完成

一次提交与关闭争用同一锁，只有两种归属：先入队得到 Accepted，随后由池 drain；或关闭先发生，提交得到 Closed 且保留输入。关闭后 `queued_ > 0` 的 worker 仍领取，只有 `closed_ && queued_ == 0` 才退出。旧代码的外层 `while (!stop)` 可能在关闭后直接遗留排队项，本例没有这条路径。

空队列不是所有任务结束：另一个 worker 可能仍在执行。因此生命周期是 Open→AdmissionClosed→所有线程 join 完成。`DrainJoin` 只由唯一池外拥有者串行调用；重复关闭和拥有者后续重复 join 是幂等的，不允许多个调用者同时 join。worker 可以关准入，但不能 join 自己，更不能成为池的最后拥有者并触发析构。

若存在外部 producer，拥有者须先关准入，再停止并 join producer 或以其他协议确认它们的调用已退出，最后 join worker 并释放池。closed 位不能救回对已析构池的调用；本文测试没有留存外部 producer。[N4861 join /3–7](https://timsong-cpp.github.io/cppwp/n4861/thread.thread.member)

所有槽和同步成员在线程启动前已建立，线程容器是固定数组。第 k 次启动抛错时，构造 catch 关闭、唤醒并 join 已启动者，再重抛；完整对象构造失败不会自动调用 `~Pool()` 来代劳。测试启动门也在该 catch 中释放，避免测试装置挡住清理。[线程构造 /6–10](https://timsong-cpp.github.io/cppwp/n4861/thread.thread.constr)、[joinable thread 析构](https://timsong-cpp.github.io/cppwp/n4861/thread.thread.destr)

用户闭包抛出的异常进入其 future；它不是任务丢失。mutex、condition_variable、非法内部 packaged_task 状态或 join 的不可恢复错误，本例明确采用 terminate，不能吞错后声称 Joined 再释放 worker 所借内存。任意用户析构不得抛异常。构造线程失败和极端 join 错误没有故障注入实测，仍是静态责任审查。

## 3. 工作窃取的两端与 Chase–Lev 的额外合同

```text
                     owner push / pop (LIFO)
                                  |
                                  v
Top / head   [较早1] [2] [3] [较新4]   Bottom / tail
                 ^
                 |
       other worker steal (FIFO)
```

递归分治中，本地 LIFO 常有复用刚产生数据的机会；偷早期项可能带走更大的子树。但任意任务的年龄不等于任务大小，FIFO 也不保证“最大粒度”，局部性与收益都依赖负载。第 2 节按固定次序选另一个 worker，不是随机 victim，也没有自旋或自适应退避。

Chase–Lev 的合同是每个 deque 只有一个 owner 执行 push/pop，多名 thief 执行 steal。外部 producer 不能直接冒充 owner 往 bottom 写，可采用独立注入队列或另行证明的加锁入口。本例所有操作共锁，允许外部指定队列提交；不能把这一点推广到论文 deque，也不据此断言 UE、oneTBB、Go 使用同一种具体实现。

2005 论文的一般 owner 路径与最后项竞争不同：owner pop 最后一项也要 CAS Top，与 thief 争夺唯一领取权。Top 不是只由 thief 修改。原文已提到最后项 CAS，但同时把 Top 归给 thief、给出“99%以上”比例会误导；本页没有这种操作比例数据。

2005 的基本方案、buffer 扩容/回收方案，与 2013 弱内存研究的发布、屏障和假设要分开阅读。将论文伪代码移植成 C++，还必须核查原子对象能力、slot 发布、旧 buffer 存活、索引回绕及载荷操作。本文不另写未证明的 Chase–Lev 实现，也不以锁保护短例验证它的线性化、弱内存正确性或性能。[Chase & Lev 2005 §2、Fig.1–4、§3–4](https://www.dre.vanderbilt.edu/~schmidt/PDF/work-stealing-dequeue.pdf)、[Lê 等 2013 §1–2、Fig.1](https://fzn.fr/readings/ppopp13.pdf)

## 4. DAG 必须传产物，也必须传终态

图上的边首先是业务必要的数据依赖，不能只把若干游戏阶段排成一张漂亮图。具体引擎如何安排物理、动画、AI 和渲染取决于读写关系，本例用固定值排除这些外部前提：

```text
A: 生成 [1,2,3,4]
      /        \
     v          v
B: 求和10     C: 平方和30
      \        /
       v      v
       D: {10,30}
```

A 的值由拥有者取出后，分别复制给 B/C；B/C 不并发写同一普通变量。D 只有在两者都 Succeeded 时才构造。池外协调者等待 future，不占用本池 worker 等待后继；它是固定图的完整执行路线，不是通用无锁 DAG 引擎。

节点还需要 Failed、Rejected、Skipped：A 失败或拒绝，B/C/D 为 Skipped；B 失败，已接受的 C 仍必须收取自己的终态，D 为 Skipped；准入失败的节点是 Rejected，协调者放弃其仍拥有的 Job。本例不忙等重试 Full。构造错误发生于接受之前，记 Failed 且 `accepted=false`；已接受任务的用户异常则是 Failed 且 `accepted=true`。`Pending` 只表示已接受但还未收取。

主成功输入使用两 worker、无其他 producer，队列容量足够。`RunDag` 中无论先收 B 还是先收 C，都单独 catch、记录，避免 B.get 抛出后漏掉 C。节点结果中的 `error` 可继续交给业务报告；不把异常改写成默认值。

```cpp
// BEGIN PART 2: a fixed value DAG, coordinated outside the pool
using Values = std::array<std::int64_t, 4>;
using Pair = std::pair<std::int64_t, std::int64_t>;
enum class State { Pending, Succeeded, Failed, Skipped, Rejected };
template<class T> struct Node {
    State state = State::Skipped;
    bool accepted = false;
    Admission admission = Admission::Invalid;
    std::future<T> future;
    std::optional<T> value;
    std::exception_ptr error;
};
template<class F>
auto Launch(Pool& pool, int id, F&& f, unsigned q = 0) {
    using R = std::invoke_result_t<std::decay_t<F>&>;
    Node<R> node;
    try {
        auto [job, future] = Job::Make(id, std::forward<F>(f));
        node.admission = pool.TrySubmit(job, q);
        node.accepted = node.admission == Admission::Accepted;
        node.state = node.accepted ? State::Pending : State::Rejected;
        if (node.accepted) node.future = std::move(future);
        // Rejected: this finite coordinator abandons its still-owned job.
    } catch (...) {
        node.state = State::Failed; // Construction failed before acceptance.
        node.error = std::current_exception();
    }
    return node;
}
template<class T> void Collect(Node<T>& node) {
    if (node.state != State::Pending) return;
    try {
        node.value = node.future.get();
        node.state = State::Succeeded;
    } catch (...) {
        node.error = std::current_exception();
        node.state = State::Failed;
    }
}
struct DagResult {
    Node<Values> a;
    Node<std::int64_t> b, c;
    Node<Pair> d;
};
DagResult RunDag(Pool& pool, bool fail_b = false, bool collect_c_first = false) {
    DagResult r;
    r.a = Launch(pool, 101, [] { return Values{1, 2, 3, 4}; });
    Collect(r.a);
    if (r.a.state != State::Succeeded) return r;
    Values input = *r.a.value; // Each task owns its own small input copy.
    r.b = Launch(pool, 102, [input, fail_b] {
        if (fail_b) throw std::runtime_error("B failed");
        std::int64_t sum = 0;
        for (auto x : input) sum += x;
        return sum;
    });
    r.c = Launch(pool, 103, [input] {
        std::int64_t sum = 0;
        for (auto x : input) sum += x * x;
        return sum;
    }, 1);
    if (collect_c_first) { Collect(r.c); Collect(r.b); }
    else { Collect(r.b); Collect(r.c); }
    if (r.b.state == State::Succeeded && r.c.state == State::Succeeded) {
        r.d = Launch(pool, 104, [b = *r.b.value, c = *r.c.value] {
            return Pair{b, c};
        });
        Collect(r.d);
    }
    return r; // All accepted nodes were individually collected, including C.
}
// END PART 2
```

### 4.1 计数器只选出最后一个前驱

通用图常以原子入度计数决定 ready，这是常见选择，不是已证明“最轻量级”。下面仅是触发器节选，不参加完整程序编译，也没有空的 Enqueue 接口冒充引擎：

```cpp
// 前提：remaining 初值为真实前驱数，每条边恰好结算一次。
// 每个前驱先写自己拥有的产物，再执行这一条 RMW。
bool responsible_for_ready =
    remaining.fetch_sub(1, std::memory_order_acq_rel) == 1;
```

最后一次 acq_rel RMW 可经前序 RMW 链获得前驱发布；随后仍须由实际队列发布/领取把读取权交给后继。`==1` 只选出唯一 ready 责任人，不证明入队成功、节点存活或整个调度系统无锁。[N4861 atomics.order /2](https://timsong-cpp.github.io/cppwp/n4861/atomics.order)、[intro.races](https://timsong-cpp.github.io/cppwp/n4861/intro.races)

纸面反例：漏掉 C→D 边时，D 可在 C 产物不存在时就 ready；把 B 完成结算两次，可过早减到零或下溢；A→B→A 的环可能根本没有前沿节点。若前驱失败，后继应 Skipped 或显式接受错误输入，不能读未初始化产物。ready 入队遇 Full 必须保留待派发责任，遇 Closed 必须将图结算为拒绝/跳过；计数这一行不实现这些政策。还需冻结图结构、限制每边完成一次，并持有节点和后继表直至所有访问退出。

## 5. 协程移交的是恢复权，不是 frame 所有权

`co_await` 可能挂起协程的求值，OS 线程继续返回调用者或调度器，不会因此成为“被挂起的专属线程”。`await_ready=false` 后，协程在调用 `await_suspend` 前就已被视为挂起；若 `await_suspend` 返回 false，则继续当前协程；若抛异常，语言规则恢复并在协程中重抛。[N4861 expr.await /3、/5](https://timsong-cpp.github.io/cppwp/n4861/expr.await)

所以发布 handle 是关键边界：一旦成功入队，worker 可以在 `await_suspend` 尚未返回时恢复，甚至结束该 await-expression 并销毁 awaiter。原 awaiter 恰好没有显式的发布后成员访问，不能据此指控一个已证实的 UAF；问题是没有完整公布拒绝、frame owner 和退场合同。下面把这些责任写全。

### 5.1 固定路线与唯一拥有者

只允许 main→io→logic→final，不回跳、不嵌套新池。`OwnedTask` 唯一拥有 frame，initial_suspend 先让拥有者建立，Start 只调用一次；final_suspend 保留 frame，队列只借某个挂起点的一次 resume 权。不要把非空 handle 当作所有权，也不要在 final_suspend 再 resume。[N4861 coroutine.handle.resumption](https://timsong-cpp.github.io/cppwp/n4861/coroutine.handle.resumption)

`Start` 在首个 resume 前设置 owner 的状态、把 handle 拷到普通局部，调用后不再读 frame。awaiter 也在发布前把所需信息复制到普通调用栈局部；所有可能抛的 Job 构造发生在发布前。Full/Closed 拒绝不公布句柄，随后抛明示异常；成功后不再抛，也不读 `this`、promise 或 frame。这样不会让语言异常恢复与 worker 恢复各执行一次。

`RouteProbe` 仅为有限验证保存事件，位于协程外并活到 frame 销毁后；正常使用可传 nullptr。它的门控方法 noexcept，成功发布后使用的是局部指针指向的外部状态。`ResumeCall` 的故障输入只让实际 callable 移动构造在发布前抛错，不执行非法恢复或故意悬垂访问。

```cpp
// BEGIN PART 3: fixed main -> io -> logic -> final, with a unique frame owner
struct Profile { int id; std::int64_t score; };
struct RouteProbe {
    bool force_overlap = false;
    Gate io_body, at_final, logic_returned, io_returned;
    Gate old_stack_held, release_old_stack;
    std::atomic<bool> early_resume{false};
    std::atomic<int> destroyed{0};
};
class OwnedTask {
public:
    struct promise_type;
    using Handle = std::coroutine_handle<promise_type>;
private:
    Handle handle_{};
    bool started_ = false;
    explicit OwnedTask(Handle h) noexcept : handle_(h) {}
public:
    struct promise_type {
        std::optional<Profile> value;
        std::exception_ptr error;
        RouteProbe* probe;
        promise_type(Pool&, Pool&, int, RouteProbe* p, int) noexcept : probe(p) {}
        ~promise_type() { if (probe) ++probe->destroyed; }
        OwnedTask get_return_object() noexcept {
            return OwnedTask{Handle::from_promise(*this)};
        }
        std::suspend_always initial_suspend() const noexcept { return {}; }
        struct FinalNotice {
            RouteProbe* probe;
            bool await_ready() const noexcept { return false; }
            void await_suspend(Handle) const noexcept {
                auto* p = probe;
                if (p) p->at_final.Open();
            }
            void await_resume() const noexcept {}
        };
        FinalNotice final_suspend() const noexcept { return {probe}; }
        void return_value(Profile p) noexcept { value = p; }
        void unhandled_exception() noexcept { error = std::current_exception(); }
    };
    OwnedTask() noexcept = default;
    OwnedTask(const OwnedTask&) = delete;
    OwnedTask& operator=(const OwnedTask&) = delete;
    OwnedTask(OwnedTask&& other) noexcept
        : handle_(std::exchange(other.handle_, {})), started_(other.started_) {}
    void Adopt(OwnedTask&& other) noexcept {
        if (handle_) std::terminate(); // Never overwrite a borrowed live frame.
        handle_ = std::exchange(other.handle_, {});
        started_ = other.started_;
    }
    ~OwnedTask() { if (handle_) handle_.destroy(); } // Caller must first join both pools.
    void Start() {
        if (!handle_ || started_) throw std::logic_error("Start exactly once");
        started_ = true;
        auto h = handle_;
        h.resume();
        // Do not inspect h.done(), promise, awaiter, or other frame storage here.
    }
    Profile TakeAfterJoin() {
        // Precondition: Start returned; io and then logic completed DrainJoin.
        if (!handle_ || !started_ || !handle_.done())
            throw std::logic_error("not at final suspension");
        auto& p = handle_.promise();
        if (p.error) std::rethrow_exception(p.error);
        return p.value.value();
    }
};
struct BuildFailure : std::runtime_error {
    BuildFailure() : std::runtime_error("resume job construction failed") {}
};
struct QueueRejected : std::runtime_error {
    Admission reason;
    explicit QueueRejected(Admission r) : std::runtime_error("resume rejected"), reason(r) {}
};
struct ResumeCall {
    std::coroutine_handle<> handle;
    RouteProbe* probe;
    int hop;
    bool fail_move;
    ResumeCall(std::coroutine_handle<> h, RouteProbe* p, int s, bool fail) noexcept
        : handle(h), probe(p), hop(s), fail_move(fail) {}
    ResumeCall(ResumeCall&& other)
        : handle(other.handle), probe(other.probe), hop(other.hop), fail_move(other.fail_move) {
        if (fail_move) throw BuildFailure{}; // Finite test input; no handle published yet.
    }
    void operator()() & {
        auto h = handle;
        auto* p = probe;
        int stage = hop;
        h.resume();
        // Only ordinary callback locals and external test state are used after resume.
        if (p) {
            if (stage == 1) p->io_returned.Open();
            else p->logic_returned.Open();
        }
    }
};
struct SwitchToPool {
    Pool& pool;
    RouteProbe* probe;
    int hop;
    bool fail_make;
    bool await_ready() const noexcept { return false; }
    void await_suspend(std::coroutine_handle<> h) const {
        auto* target = &pool;
        auto* p = probe;
        const int stage = hop;
        const bool force = p && p->force_overlap;
        const bool fail = fail_make;
        auto [job, ignored] = Job::Make(200 + stage, ResumeCall{h, p, stage, fail});
        const auto admission = target->TrySubmit(job);
        if (admission != Admission::Accepted) throw QueueRejected{admission};
        // Published: this/awaiter/frame may already have been destroyed.
        // Gate methods are noexcept; the rest uses ordinary call-stack locals only.
        if (force && stage == 1) {
            p->io_body.Wait();
            p->early_resume.store(true);
        }
        if (force && stage == 2) {
            p->at_final.Wait();
            p->logic_returned.Wait();
            p->old_stack_held.Open();
            p->release_old_stack.Wait();
        }
    }
    void await_resume() const noexcept {}
};
OwnedTask BuildProfile(Pool& io, Pool& logic, int id, RouteProbe* probe, int fail_hop) {
    co_await SwitchToPool{io, probe, 1, fail_hop == 1};
    if (probe) probe->io_body.Open();
    std::int64_t parsed = static_cast<std::int64_t>(id); // Pure value, no fake DB call.
    co_await SwitchToPool{logic, probe, 2, fail_hop == 2};
    co_return Profile{id, parsed * parsed};
}
```

### 5.2 什么时刻才允许 destroy

新挂起点可以合法恢复，即使上一次 resume 的调用栈还没退回。合法性取决于协程是否已经挂起、每个挂起点是否只有一次恢复，以及旧调用栈是否还访问 frame；不能笼统把这种调用栈时间重叠都叫非法并发 resume。相反，对同一执行中的协程重复 resume，或未收束就 destroy，才违反本例协议。

本例刻意采取保守收束：

1. Start 返回，证明 main 发起的初始 resume/await_suspend 调用栈已退场；这时不读 done 或结果
2. 关 io 准入并 drain/join，证明所有 io callback 以及它们可能向 logic 发布的调用已经结束
3. 此后关 logic 准入并 drain/join，证明最后的 resume callback 已经返回
4. 再检查最终挂起、读值或重抛异常，最后由唯一 owner destroy 一次

顺序不能交换：先关 logic 会拒绝尚在 io 阶段、合法将要转交的工作。固定单向路线使 io join 后“不会再向 logic 发布”可证明；若加入 logic→io 回跳、main continuation 或外部发布者，就必须重新设计停止协议。

`done()` 自身要求 handle 指向挂起协程；无同步地轮询它不是协议。即使已到 final，旧 await_suspend、resume 调用栈或包装回调也可能还在退场；future ready 同样不提供 destroy 许可。本例只在两个池完成 join 后调用 `TakeAfterJoin`。[N4861 done 的前提](https://timsong-cpp.github.io/cppwp/n4861/coroutine.handle.observers)、[协程对象寿命](https://timsong-cpp.github.io/cppwp/n4861/dcl.fct.def.coroutine)

第 7 节的具体声明顺序是先空 owner、再 logic、再 io，最后创建 frame 和 Start。正常路径显式按 io→logic join；异常展开时逆序析构也先 io、再 logic、最后 owner。即使 io/logic 拒绝、callable 构造失败、结果提取抛出或外部代码抛错，仍按同一顺序收束。owner 只接收一次空位 Adopt，不覆盖工作中的 frame；不允许在执行方还借 handle 时移动或析构它。

### 5.3 切线程不等于非阻塞或主线程资格

例子在 io 阶段只把输入转成纯值，在 logic 阶段平方，返回 `Profile{-3,9}`。没有空 Database/World 函数冒充实际服务集成。若换成同步数据库查询，查询仍会阻塞 io worker，只是移出了调用线程；端到端非阻塞需真正异步 I/O 的完成、取消与资源归还协议。

logic worker 不是游戏主线程。业务应用应由拥有者在合法主线程、对象仍存活且请求仍有资格时进行。纯值完成、业务应用成功、执行资源全部退场，是三个不同事件。

## 6. 进展、取消与引擎边界

drain 能保证已接受项继续领取，不保证固定时间结束。前提是任务最终返回、OS 最终调度它们，且没有等待关闭者持有的资源。两个 worker 都在等同池排队子任务的 future，子任务就无处执行；持任务所需锁 join、worker join 自己、等待只能由当前主线程执行的 continuation，也各自构成等待环。这些是纸面反例，不通过故意挂死程序来验证。

优先将关系表达为依赖/continuation，或像第 4 节在池外等待。帮跑等待需要运行时自己的可重入、锁和任务选择合同，任意拿别的任务执行可能制造新的嵌套环。优先级通常改变 ready 任务的领取顺序，不会自动抢占正在运行的任意 C++ 闭包，也不自动消除持锁反转或低优先级饥饿。

本例选择 drain，没有通用取消 API。`stop_token` 是合作请求，任务可在有限步骤边界读它并返回明确 Cancelled 结果；请求不是杀线程，也不能中断任意阻塞数据库调用。取消后仍须让已接受任务和借出的 resume 权收束，不能立即销毁 frame。`jthread` 析构的 request_stop→join 不会替任意队列补上 closed 谓词或自动 drain。[N4861 stop_token](https://timsong-cpp.github.io/cppwp/n4861/thread.stoptoken)、[jthread 析构](https://timsong-cpp.github.io/cppwp/n4861/thread.jthread.cons)

Epic 核对时的 UE5.8 公开页说明 Tasks System 与 TaskGraph 共用调度和 worker 后端，可从 Launch、结果、prerequisites、nested tasks 和 pipes 理解各自用途。本页撤去“全面替代”和没有本轮依据的通用 `.Then(...)` 写法，不据此断言所有版本或扩展都不存在该名字。该页还记载 UE5.5 起以 oversubscription 替换旧 busy-wait；这是公开文档合同，不是本轮私有源码核查。[Epic Tasks System](https://dev.epicgames.com/documentation/en-us/unreal-engine/tasks-systems-in-unreal-engine)

## 7. 复现：验证本文程序，而不是平行模型

第四部分直接调用上面三个部分。门控不依赖 sleep：先挡住 worker，再观察确切任务 ID、领取 worker、victim 和 local/remote 路径。协程门控强制一次提前恢复，并在 final 已到达、logic 回调已返回而 io 旧栈仍挂在普通局部门上时，检查 owner 尚未销毁；打开门后才 join 并读 frame。`Check` 不因 NDEBUG 关闭，测试门的异常释放也先于池析构。

```cpp
    Check(rejected.a.state == State::Rejected && !rejected.a.accepted);
    Check(rejected.b.state == State::Skipped && rejected.c.state == State::Skipped);
    Check(rejected.d.state == State::Skipped);
    pool.DrainJoin();
    std::cout << "values: 9; user exception; DAG {10,30}; B Failed/C Succeeded/D Skipped; A Rejected\n";
}
void TestRoute(int closed_hop, int fail_hop, bool force_overlap) {
    RouteProbe probe;
    probe.force_overlap = force_overlap;
    {
        OwnedTask owner; // Destruction order is io, logic, then frame, on every exit.
        Pool logic;
        Pool io;
        ReleaseOnExit release{{&probe.release_old_stack}};
        if (closed_hop == 1) io.CloseAdmission();
        if (closed_hop == 2) logic.CloseAdmission();
        owner.Adopt(BuildProfile(io, logic, -3, &probe, fail_hop));
        owner.Start();
        bool twice = false;
        try { owner.Start(); } catch (const std::logic_error&) { twice = true; }
        Check(twice);
        if (force_overlap) {
            probe.old_stack_held.Wait();
            Check(probe.early_resume.load() && probe.at_final.IsOpen());
            Check(probe.logic_returned.IsOpen() && !probe.io_returned.IsOpen());
            Check(probe.destroyed.load() == 0);
            probe.release_old_stack.Open();
        }
        io.DrainJoin();
        logic.DrainJoin();
        bool rejected = false, build_failed = false;
        try {
            auto value = owner.TakeAfterJoin();
            Check(closed_hop == 0 && fail_hop == 0);
            Check(value.id == -3 && value.score == 9);
        } catch (const QueueRejected& e) {
            rejected = e.reason == Admission::Closed;
        } catch (const BuildFailure&) { build_failed = true; }
        Check(rejected == (closed_hop != 0));
        Check(build_failed == (fail_hop != 0));
        Check(probe.destroyed.load() == 0);
    }
    Check(probe.destroyed.load() == 1);
    std::cout << "route closed_hop=" << closed_hop << " fail_hop=" << fail_hop
              << " overlap=" << force_overlap << " destroyed=1\n";
}
void TestUnwind() {
    RouteProbe probe;
    bool caught = false;
    try {
        OwnedTask owner;
        Pool logic;
        Pool io;

        owner.Start();

    Check(probe.io_returned.IsOpen() && probe.logic_returned.IsOpen());

}
```

### 7.2 为什么旧泛型 adapter 会在值类别上失败

旧模板用 `invoke_result_t<F, Args...>` 推导返回类型，却在捕获后把 `func` 当左值、把参数强制 move。接收 `int&` 的函数配普通左值，前一表达式成立，后一个不能绑定；只有 `operator()() &&` 的临时 functor 则相反，推导看右值，实际调用却是左值。下面是完整的编译诊断用翻译单元；同步 `PostRawTask` 仅补齐旧接口依赖，不用来证明任何异步行为，不运行该程序。

```cpp
#include <functional>
#include <future>
#include <memory>
#include <type_traits>
#include <utility>
#ifndef CASE
#define CASE 0
#endif
void PostRawTask(std::function<void()> task) { task(); }
template<class F, class... Args>
auto OldAdapter(F&& f, Args&&... args)
    -> std::future<std::invoke_result_t<F, Args...>> {
    using R = std::invoke_result_t<F, Args...>;
    auto task = std::make_shared<std::packaged_task<R()>>(
        [func = std::forward<F>(f), ...args = std::forward<Args>(args)]() mutable {
            return std::invoke(func, std::move(args)...);
        });
    auto future = task->get_future();
    PostRawTask([task] { (*task)(); });
    return future;
}
struct RvalueOnly { int operator()() && { return 9; } };
int main() {
    [[maybe_unused]] int input = 3;
#if CASE == 1
    auto result = OldAdapter([](int& value) { return value; }, input);
#elif CASE == 2
    auto result = OldAdapter(RvalueOnly{});
#else
    auto result = OldAdapter([](int value) { return value; }, input);
#endif
    return result.get();
}
```

同一工具链先用 `-DCASE=0 -c` 编译正控制，再分别用 `-DCASE=1 -c`、`-DCASE=2 -c`；只有诊断确实指向 `std::invoke(func, std::move(args)...)` 的类别不匹配才算预期负例，缺头文件或缺接口不算。新 Job 让调用者显式绑定参数：需拥有就值捕获，需引用就显式引用并证明寿命；不会自动把每个绑定值都转成右值。
