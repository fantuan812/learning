# 02-STL 容器与 Allocator

> 知识成熟度：L2
> 验证入口：运行文中容器复杂度、分配次数与缓存局部性基准，记录 P50/P95/P99。
> 知识基线：ISO C++20/23 容器需求与 AllocatorAwareContainer。
> 最后更新：2026-08-20。
> 来源：[cppreference containers](https://en.cppreference.com/w/cpp/container)、[C++ draft allocator.requirements](https://eel.is/c++draft/allocator.requirements)。
> 验证入口：使用 GCC/Clang `-std=c++20 -O2 -Wall -Wextra` 编译示例，并以 Sanitizer 检查生命周期。
> 验证与基准：对不同容器和分配器运行基准测试，比较吞吐、分配次数与 P95 延迟。

## 1. 总览

STL 容器把所有权、元素生命周期、迭代器和复杂度组合成可复用契约。选择容器时先描述访问模式，再核对失效规则、异常保证和内存布局。

## 2. 顺序容器

1. `vector` 提供连续存储和摊销常数尾插。
2. `vector` 扩容通常按增长因子重新分配。
3. 重新分配会使所有迭代器、引用和指针失效。
4. `reserve` 只改变容量，不改变元素数量。
5. `resize` 改变元素数量并可能值初始化元素。
6. `shrink_to_fit` 是非强制请求。
7. `deque` 由多个缓冲区组成，支持两端常数插入。
8. `deque` 的元素不保证连续。
9. `list` 节点稳定，任意位置插入为常数但缓存局部性差。
10. `forward_list` 只有单向链接，适合极简节点场景。
11. `array` 在对象内嵌连续存储，大小是类型的一部分。
12. `basic_string` 具有连续字符存储和可能的小字符串优化。
13. 字符串的尾部空字符由标准保证可访问。
14. `span` 是非拥有视图，生命周期由外部对象负责。
15. `mdspan` 表达多维布局，不拥有数据。

## 3. 关联与无序容器

1. `map` 通常以平衡树实现并按键有序。
2. `set` 只存储键并保证唯一性。
3. `multimap` 允许等价键重复。
4. `unordered_map` 使用哈希桶，平均查找常数。
5. 最坏哈希退化为线性，应选择稳健哈希。
6. `reserve` 和 `rehash` 可提前控制桶数量。
7. 无序容器 rehash 会使迭代器失效。
8. 节点句柄可在容器间移动而不复制元素。
9. `try_emplace` 避免无谓构造映射值。
10. `insert_or_assign` 适合覆盖已有值。
11. 异质查找要求透明比较器或哈希器。
12. 比较器必须满足严格弱序。
13. 哈希器对等价键必须返回相同哈希值。
14. 关键字段不可在容器中原地修改导致顺序破坏。
15. `flat_map` 适合读多写少的小型数据集。

## 4. 迭代器与范围

1. 输入迭代器只能单遍读取。
2. 前向迭代器可多遍读取同一范围。
3. 双向迭代器支持递减。
4. 随机访问迭代器支持算术运算。
5. 连续迭代器额外承诺无间隙地址。
6. `begin/end` 定义半开区间。
7. `end` 迭代器不可解引用。
8. 擦除后使用失效迭代器是未定义行为。
9. 范围算法减少 begin/end 不匹配风险。
10. 借用范围避免返回悬空视图。
11. `filter_view` 的谓词不得依赖已失效状态。
12. `transform_view` 不保证缓存转换结果。
13. 视图通常是轻量对象，不延长底层生命周期。
14. 调试迭代器模式可捕获跨容器比较。
15. 算法复杂度取决于迭代器类别。

## 5. Allocator 模型

1. allocator 负责原始存储，不负责业务所有权。
2. `allocate(n)` 返回可容纳 n 个 `T` 的存储。
3. `deallocate` 必须使用相同 allocator 和对应数量。
4. `construct` 在存储上创建对象。
5. `destroy` 结束对象生命周期。
6. `allocator_traits` 提供统一适配层。
7. `rebind_alloc<U>` 支持节点类型重新绑定。
8. propagate_on_container_copy_assignment 决定复制赋值传播。
9. propagate_on_container_move_assignment 决定移动赋值传播。
10. propagate_on_container_swap 决定 swap 合法性。
11. `is_always_equal` 影响释放跨实例存储的安全性。
12. 单调资源适合批量释放而非单元素回收。
13. 同步池应明确线程安全级别。
14. 对齐分配必须满足 over-aligned 类型需求。
15. 资源耗尽应抛出 `bad_alloc` 或明确错误。

## 6. 失效与异常

1. 插入、擦除、扩容前后必须查阅容器特定规则。
2. `vector::push_back` 无扩容时通常不使既有引用失效。
3. `list` 插入不使既有迭代器失效。
4. `deque` 中间插入可能使全部迭代器失效。
5. 强异常保证要求失败后状态不变。
6. 元素移动不可抛出有助于维持强保证。
7. allocator 分配失败不应泄漏已构造元素。
8. 析构函数应默认 noexcept。
9. 比较器抛异常会中止部分操作，需审查状态保证。
10. 哈希器异常同样影响无序操作。

## 7. 性能设计

1. 连续容器通常具有更好缓存局部性。
2. 节点容器减少移动但增加指针追踪。
3. 预留容量避免热路径分配。
4. 批量插入可降低重复扩容。
5. 小对象优化需通过基准而非猜测判断。
6. 内存池应记录峰值、碎片和回收延迟。
7. 迭代器调试开关会改变性能与 ABI。
8. PMR 资源可把分配策略从容器类型中解耦。
9. `unsynchronized_pool_resource` 仅适合单线程访问。
10. `synchronized_pool_resource` 通过锁提供共享安全。

## 8. 工程检查清单

1. 记录元素数量、访问比例和生命周期。
2. 记录是否需要稳定引用。
3. 记录排序、哈希和比较成本。
4. 记录线程并发访问边界。
5. 记录异常与错误处理契约。
6. 记录分配次数和内存上限。
7. 使用静态分析检查悬空迭代器。
8. 使用 ASan 检查越界与释放后访问。
9. 使用 benchmark 比较候选容器。
10. 在目标平台验证 allocator 对齐。

## 9. 最小验证示例

```cpp
#include <vector>
#include <memory_resource>
#include <cassert>
int main() {
  std::byte buf[4096];
  std::pmr::monotonic_buffer_resource r(buf, sizeof buf);
  std::pmr::vector<int> v{&r};
  v.reserve(128);
  for (int i=0;i<100;++i) v.push_back(i);
  assert(v[42]==42);
}
```

## 11. 结论

容器选择是契约设计问题，不是 API 偏好。先锁定生命周期、失效、复杂度和线程边界，再决定具体容器与 allocator。任何性能结论都必须由目标平台基准支持。

## 12. 常见陷阱

1. 以为 `reserve` 会初始化元素。
2. 以为 `capacity` 等于可安全索引范围。
3. 保存扩容前的 `data()` 指针。
4. 在 range-for 中擦除当前元素。
5. 用临时字符串构造悬空 `string_view`。
6. 将 `span` 返回给局部数组。
7. 在比较器中读取会变化的全局状态。
8. 哈希键修改后未重新插入。
9. 误把节点稳定性推广到容器 swap。
10. 让 allocator 生命周期短于容器。
11. 跨资源释放 PMR 内存。
12. 忽略 over-aligned 分配。
13. 用未同步 pool resource 跨线程。
14. 在异常路径重复 destroy。
15. 依赖未规定的容量增长因子。

## 13. 设计模板

1. 高频尾插、随机访问：优先 vector。
2. 双端队列：评估 deque。
3. 稳定节点地址：评估 list，但先证明局部性代价。
4. 有序范围查询：选择 map 或 flat_map。
5. 精确查找：选择 unordered_map 并设定负载因子。
6. 临时批处理：选择 PMR 单调资源。
7. 帧内分配：使用帧 arena，帧末整体回收。
8. 长生命周期对象：使用池并提供显式回收。
9. 共享资源：封装同步策略而非隐藏锁。
10. ABI 边界：避免暴露具体 allocator 类型。
11. 插件边界：使用稳定 C 接口传递数组。
12. 序列化：先固定字节序和对齐策略。
13. 热点循环：用连续存储和批量算法。
14. 大对象：存储句柄而非复制对象。
15. 读多写少：考虑不可变快照。

## 14. 评审问题

1. 元素所有权由谁负责？
2. 迭代器能否跨操作继续使用？
3. 分配失败如何传播？
4. 移动操作是否 noexcept？
5. 比较器是否满足严格弱序？
6. 哈希是否抗攻击？
7. 容器是否在多个线程访问？
8. 资源是否需要统计？
9. 峰值内存是否可界定？
10. 测试是否覆盖空容器？
11. 测试是否覆盖重复键？
12. 测试是否覆盖异常？
13. 测试是否覆盖迭代器失效？
14. 测试是否覆盖对齐？
15. 基准是否固定编译器和 CPU？

## 16. 案例：订单簿容器选择

假设订单按价格排序、同价位按时间入队。

`std::map<Price, std::deque<Order>>` 提供稳定的有序价格访问。

撮合循环只访问最优买卖价，复杂度为 `O(log P)` 插入和 `O(1)` 队首撮合。

若价格离散且范围有限，可改用 `std::vector<std::deque<Order>>`。

向量方案避免树节点指针跳转，通常拥有更好的缓存局部性。

但价格范围扩大时，内存占用变为 `O(R)`，需要压缩坐标或分段索引。

`std::unordered_map` 不保证价格顺序，不能直接替代 map。

错误做法是每次撮合都遍历整个 unordered_map 寻找最优价。

基准应分别测量插入、删除、最优价读取和批量撮合。

记录 P50、P95、P99 延迟，而不是只记录平均值。

## 17. 实验：迭代器失效

实验一：向 vector 反复 `push_back`，保存首元素迭代器。

当容量增长时，旧迭代器全部失效，解引用属于未定义行为。

调用 `reserve(N)` 可把扩容次数降为零，但不能阻止 erase 引起的移动。

实验二：deque 两端插入通常不使中间引用失效，但标准保证需查阅具体操作。

实验三：list 插入不会使已有迭代器失效，erase 仅使被删节点失效。

用 AddressSanitizer 编译实验，观察失效迭代器可能被检测或静默通过。

建议同时开启 `_GLIBCXX_DEBUG`（GCC）检查 libstdc++ 调试迭代器。

测试代码应在每次修改容器后重新获取迭代器。

## 18. 实验：Allocator 与 PMR

使用 `std::pmr::monotonic_buffer_resource` 为短生命周期消息分配内存。

准备固定栈缓冲区，统计超出缓冲区后的上游分配次数。

比较默认 allocator、unsynchronized_pool_resource 与 monotonic resource。

在相同对象数量和线程数下测量分配吞吐、峰值 RSS、释放耗时。

monotonic resource 不支持单对象释放，适合 arena 生命周期统一回收。

pool resource 适合大量相同大小对象，可降低 malloc 元数据开销。

跨线程共享 unsynchronized resource 会产生数据竞争，必须使用 synchronized 版本或线程本地资源。

资源对象必须长于所有依赖它的容器，否则容器析构时访问悬空资源。

## 19. Benchmark 设计模板

固定编译器版本、标准库实现、优化选项和 CPU 频率策略。

预热缓存和分支预测，区分冷启动与稳态结果。

使用随机种子记录输入，避免优化器删除无效计算。

通过 `benchmark::DoNotOptimize` 或等价方法保留结果依赖。

分别报告吞吐（ops/s）和延迟（ns/op）。

改变数据规模，观察从 L1、L2 到 LLC、内存的拐点。

改变负载分布，比较均匀、热点和顺序访问。

用 perf、VTune 或 ETW 采样 cache-miss、分支失误和 cycles。

当差异小于置信区间时，不应宣称某容器更快。

## 20. 常见故障排查

出现 vector 性能抖动时，首先检查是否频繁扩容。

出现 map 延迟长尾时，检查分配器锁竞争和 NUMA 远端访问。

unordered_map 性能退化时，检查哈希碰撞和 rehash 峰值。

遍历 list 很慢通常是节点分散导致的缓存未命中，而非算法复杂度问题。

自定义 allocator 崩溃时，检查 `construct`、`destroy` 和对齐保证。

移动容器后继续使用源迭代器，除非标准明确保证，否则应视为无效。

## 21. 复习与验收

能解释 vector、deque、list 的布局和失效规则。

能依据访问模式选择 map、unordered_map 或 flat 容器。

能实现一个记录分配次数的 allocator。

能用 PMR 构建按帧释放的临时对象池。

能写出包含预热、重复运行和置信区间的 benchmark。

能用 sanitizer 复现并定位越界、UAF 与双重释放。
