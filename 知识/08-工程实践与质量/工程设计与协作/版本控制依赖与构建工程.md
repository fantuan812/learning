# 版本控制、依赖与构建工程

> 知识成熟度：L2；命令和策略需在目标仓库验证。
> 知识基线：Git、CMake 3.x、Unreal Build Tool 与 SBOM 规范。
> 最后更新：2026-08-20。
> 官方参考：https://git-scm.com/docs、https://cmake.org/cmake/help/latest/。
> 验证入口：在干净环境执行 configure、build、install 与制品哈希比对。

## Git

- 提交应表达单一意图。
- 提交消息说明动词、范围和结果。
- 分支命名包含任务或发布上下文。
- rebase 适合整理未共享历史。
- merge 保留分支拓扑和审计信息。
- 公共历史禁止无协调强推。
- tag 指向可复现发布提交。
- bisect 用于定位引入回归的提交。
- blame 只提供线索，不代表责任归属。
- cherry-pick 需记录来源提交。
- submodule 版本必须锁定。
- git-lfs 管理大型二进制资产。
- hooks 不能替代服务端门禁。
- CODEOWNERS 明确评审边界。
- 保护分支要求 CI 通过。
- 变更前检查工作树和未跟踪文件。

## CMake 与 Build.cs

- 构建目标比全局变量更可组合。
- target_link_libraries 表达依赖方向。
- PUBLIC、PRIVATE、INTERFACE 决定传播范围。
- 头文件目录应按可见性声明。
- 编译特性使用 target_compile_features。
- 配置与生成阶段要区分。
- toolchain file 固定编译器和 sysroot。
- Preset 统一开发者和 CI 参数。
- Export/Install 支持包消费。
- CMake 包配置需提供版本和组件。
- Build.cs 应明确模块依赖。
- RuntimeDependencies 需声明运行时文件。
- 第三方库不能通过隐式全局路径引入。
- Debug、RelWithDebInfo、Release 需有明确用途。
- 生成代码必须声明输入输出。
- 增量构建验证隐式依赖。

## 依赖治理

- 锁文件保证解析结果一致。
- 记录来源、版本、许可证和哈希。
- 依赖升级先看变更日志和 ABI。
- 直接依赖与传递依赖分开审计。
- SBOM 描述最终制品组成。
- 供应链扫描识别已知漏洞。
- 私有镜像需权限和可用性设计。
- 缓存命中不能绕过完整性校验。
- 补丁版本也可能改变行为。
- 依赖冻结窗口降低发布风险。

## 可复现构建

- 固定源码、工具链和环境变量。
- 禁止把时间戳写入产物内容。
- 归一化路径和文件顺序。
- 记录编译器版本和 linker 参数。
- 制品应包含构建 provenance。
- 在干净环境运行 smoke test。
- 对二进制做哈希比对。
- 失败时保留日志和依赖缓存摘要。
- 交叉编译需验证目标运行库。
- 发布包必须可从 tag 重建。
## 案例、实验与 Benchmark

采用 trunk-based、Conventional Commits、签名 tag 和 lockfile；构建容器固定编译器、SDK、时区与 locale。

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build --target server -j
ctest --test-dir build --output-on-failure
```

增量构建实验：分别修改 cpp、私有头、公共头，记录重编译范围、wall time、峰值内存和对象数；比较 Ninja、Make、Unity Build。

依赖实验：生成 SBOM，扫描许可证/CVE，篡改 lockfile 哈希验证失败，检查离线构建仍可完成。

Benchmark 固定 commit、工具链、并行度和机器规格，冷/热/远程缓存各运行 10 次，报告中位数与 MAD。

Git 练习：用 `git bisect run` 定位回归，`git worktree` 并行发布分支；冲突演练不得丢弃迁移脚本和测试。

门禁：格式化、编译、单测、静态分析、ABI 检查、SBOM；发布前执行回滚演练。

## 最小可运行 CMake 项目

以下目录可直接复制到临时目录验证构建闭环：

```text
mini/
  CMakeLists.txt
  include/mini/add.h
  src/add.cpp
  tests/add_test.cpp
```

```cmake
cmake_minimum_required(VERSION 3.24)
project(mini VERSION 1.0 LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_library(mini src/add.cpp)
target_include_directories(mini PUBLIC include)
add_executable(add_test tests/add_test.cpp)
target_link_libraries(add_test PRIVATE mini)
enable_testing()
add_test(NAME add COMMAND add_test)
include(GNUInstallDirs)
install(TARGETS mini EXPORT miniTargets)
```

```cpp
// include/mini/add.h
#pragma once
int add(int a, int b);
```

```cpp
// src/add.cpp
#include "mini/add.h"
int add(int a, int b) { return a + b; }
```

```cpp
// tests/add_test.cpp
#include "mini/add.h"
#include <cassert>
int main() { assert(add(2, 3) == 5); }
```

```bash
cmake -S mini -B mini/build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build mini/build --parallel 2
ctest --test-dir mini/build --output-on-failure
```

预期输出包含 `100% tests passed`；若缺少公开头目录，编译器应故意报找不到 `mini/add.h`，用于验证 target 依赖边界。

## CI 与可复现性

```yaml
name: verify
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-22.04
    steps:
      - uses: actions/checkout@v4
      - run: cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
      - run: cmake --build build --parallel 2
      - run: ctest --test-dir build --output-on-failure
      - run: sha256sum build/mini_test > artifact.sha256
```

固定 runner 镜像、CMake/Ninja 版本、编译器版本、依赖锁文件和环境变量；将 `SOURCE_DATE_EPOCH` 设置为提交时间，避免归档时间戳导致哈希漂移。

同一 commit 在两台相同镜像机器上重建，二进制哈希应一致；若不一致，使用 `diffoscope` 检查路径、调试信息、构建时间和链接器随机种子。

## 依赖与 SBOM

依赖清单至少包含名称、版本、来源 URL、许可证、校验和、直接/传递关系、升级负责人。Conan/vcpkg 使用 manifest + lockfile，禁止隐式下载未锁版本。

```bash
syft dir:. -o cyclonedx-json=sbom.json
grype sbom:sbom.json --fail-on high
sha256sum third_party/*
```

示例门禁：严重漏洞 `critical=0`，高危漏洞有修复计划且不得进入生产镜像；许可证冲突必须在合并前阻断。SBOM 作为发布制品与二进制哈希一同归档。

篡改实验：修改 lockfile 中一个 SHA256，离线执行 `cmake --build`，预期依赖管理器拒绝下载或校验失败；若仍成功，说明缓存未按校验和隔离。

## Benchmark 与验收表

|实验|变量|指标|示例阈值|
|---|---|---|---|
|增量构建|改 cpp/私有头/公共头|wall time、重编译目标数|公共头变更目标数≤依赖图预期|
|冷构建|删除 build 目录|p50/p95 时间|p95≤基线 1.2 倍|
|依赖扫描|lockfile 与 SBOM|漏洞、许可证|critical=0，SBOM 覆盖率 100%|
|可复现|双机同 commit|SHA256 差异|差异为 0|

每项至少运行 10 次，报告中位数、p95、标准差和机器规格；不要用单次最快值作为结论。构建回归超过 20% 自动创建 issue，并附 `ninja -d stats` 输出。

## 发布前检查清单

- 工作树无未跟踪源码、生成物已被忽略。
- 提交签名可由 CI 公钥验证。
- tag 指向已通过门禁的提交。
- 版本号与 ABI 兼容策略一致。
- 公共头文件安装路径经过干净环境测试。
- Debug、RelWithDebInfo、Release 配置均能生成。
- 编译器警告级别在所有目标一致。
- 第三方依赖均来自锁定源。
- 许可证清单与 SBOM 一致。
- 依赖下载失败时错误信息可定位。
- 构建脚本不读取开发者本机绝对路径。
- 构建不依赖未声明的环境变量。
- 生成目录与源码目录分离。
- 并行构建与串行构建结果一致。
- 安装后仅依赖声明的运行库。
- 制品包含版本、commit、构建器信息。
- 符号文件与发布制品建立映射。
- 崩溃回溯可用符号化服务还原。
- 回滚包在预生产验证过。
- 发布说明包含迁移和兼容性风险。

## 失败模式与诊断

若增量构建没有重新编译修改后的公共头依赖，优先检查 `target_sources`、生成头依赖和 `compile_commands.json`。若链接顺序在不同平台不一致，检查 PUBLIC/PRIVATE 传播和循环依赖。

若 CI 与本地结果不同，导出 `cmake --system-information`、编译器版本、环境变量和容器 digest；禁止通过关闭警告掩盖差异。

若 SBOM 漏报传递依赖，确认扫描的是最终镜像和安装树，而不是源码目录；对静态链接库执行二进制组件识别并人工复核。

若哈希不可复现，依次排查时间戳、绝对路径、用户名、随机 UUID、链接器 build-id 和压缩归档顺序。

## 复盘模板

事件编号、影响版本、触发提交、检测信号、首次错误时间、回滚时间、根因、逃逸原因、修复、预防、负责人、截止日期。每一项要能链接到 commit、CI run 或 artifact，避免只写口号。

## 工程约束速查

- 每个目标声明自身编译特性。
- 每个公共头有最小 include 测试。
- 每个安装包可在空目录运行。
- 每个脚本失败都返回非零码。
- 每个生成文件标注来源。
- 每个版本变更记录兼容性。
- 每个依赖有升级窗口。
- 每个漏洞有处置状态。
- 每个发布包有校验和。
- 每个构建环境可被重建。
- 每个缓存有失效策略。
- 每个构建步骤记录耗时。
- 每个跨平台差异有测试。
- 每个工具版本写入日志。
- 每个密钥不进入制品。
- 每个失败提供复现命令。
- 每个回滚经过演练。
- 每个临时 workaround 有到期日。
- 每个供应链变更需评审。
- 每个构建基线定期更新。
- 依赖下载使用 TLS 和校验和。
- 远程缓存按项目权限隔离。
- 产物仓库启用不可变 tag。
- 发布权限采用双人复核。
- 生产构建禁止调试开关。
- 预发布保留符号用于回溯。
- ABI 变更生成差异报告。
- API 删除先经过弃用周期。
- 数据库迁移与代码版本绑定。
- 配置默认值经过安全评审。
- 构建失败自动关联责任团队。
- 失败重试次数有上限。
- 长任务输出心跳防止假死。
- CI 并发配额纳入容量计划。
- 构建节点定期打补丁。
- Runner 镜像来源可审计。
- Action 版本固定到 SHA。
- 外部脚本下载需签名验证。
- 供应商组件记录维护状态。
- 归档制品设置保留策略。
- 清理任务不得删除审计证据。
- 版本号遵循统一规范。
- 分支保护禁止绕过门禁。
- 强推操作需要临时授权。
- 重要 tag 启用签名验证。
- 代码所有权文件定期复核。
- 变更请求包含风险分级。
- 大型重构拆分可回滚批次。
- 依赖升级先跑兼容矩阵。
- 构建脚本变更需要安全评审。
- 产物发布前生成 SBOM。
- CVE 修复验证实际加载版本。
- 许可证扫描覆盖静态链接。
- 发布日志包含已知限制。
- 迁移脚本支持前向和回滚。
- 运行时配置不写入镜像。
- 构建时网络访问可关闭。
- 离线模式作为定期演练。
- 编译器升级有性能基线。
- 链接器升级有崩溃回归。
- 包管理器升级锁定测试。
- 符号剥离规则经过验证。
- 核心转储与版本映射。
- 产物签名密钥分离保存。
- 签名失败阻断上传。
- 镜像层避免嵌入凭据。
- 基础镜像定期重建。
- 构建日志避免泄漏环境变量。
- 质量趋势按周发布。
- 门禁阈值变更需记录原因。
- 质量债务有偿还计划。
- 复盘行动项验证关闭。
- 负责人离职前完成交接。
- 文档示例定期实际运行。
- 过期链接由 CI 检测。
- 关键命令提供 Windows/Linux 变体。
- 时间和时区测试固定。
- 生成器版本写入元数据。
- 安装路径支持前缀重定位。
- 共享库搜索路径不依赖本机。
- 发布包最小权限运行。
- 容器用户不使用 root。
- 编译缓存不跨信任边界。
- 并行构建结果不依赖顺序。
- 随机种子在日志中脱敏记录。
- 最终验收由非实施者复核。
- 构建矩阵覆盖最低支持平台。
- 交叉编译产物执行目标机 smoke test。
- 发布前冻结依赖解析结果。
- 构建失败保留完整命令行。
- 版本回滚验证数据库兼容性。
- 制品上传采用断点续传校验。
- 产物下载后再次验证签名。
- 构建节点时钟保持同步。
- CI 任务设置最大运行时长。
- 超时任务自动收集诊断包。
- 失败重试不超过两次。
- 关键门禁禁止手工跳过。
- 发布审批记录审批人和理由。
- 变更窗口避开高峰期。
- 紧急发布仍执行最小测试集。
- 依赖来源故障有镜像兜底。
- 离线缓存定期清理并重建。
- 编译警告趋势按版本比较。
- 生成代码经过格式化和静态分析。
- CMake 配置选项有默认安全值。
