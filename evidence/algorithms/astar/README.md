# Evidence · astar：A* 优化前后对比基准

> 状态：已执行（2026-08-12，Windows x64 / MSVC）
> 定位：为《2026-08-03-假人AI-A星优化与耗时测试》《2026-08-05-假人寻路路径缓存方案》工作日志补齐本地可复现数据（真实项目 before/after 数据待回填）。

## 问题

1. 二叉堆 Open List（优化后）相对线性扫描（优化前）在 100×100 网格的耗时优势？
2. 两种实现是否同样最优（代价一致）与正确（路径有效）？
3. 扩展节点数差异？（理论：一致启发下应几乎相同）
4. LRU 路径缓存的命中收益？

## 假设

- 一致启发（Octile）下，堆与线性扫描扩展节点数应几乎相同；差距只在 Open List 操作复杂度（O(log n) vs O(n)）。
- 堆的优势主要体现于 P95/P99（线性扫描的最坏情况退化）。
- 缓存命中 ≈ O(1) 路径拷贝，远快于重跑 A*。

## 环境

- 系统：Windows x64；编译器：MSVC 14.44.35207，`cl /O2 /std:c++17 /EHsc /utf-8 /W4`
- 地图：100×100，8 方向，Octile 启发；普通密度 25% 障碍 / 高障碍 40%

## 运行方式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_run.ps1
```

## 输入与指标

- 1000 次随机可达查询 ×2 场景；指标：有效路径数、不可达一致数、代价一致数（最优性）、平均路径长、平均扩展节点、P50/P95/P99、缓存命中率与命中/未命中耗时。

## 原始结果

`results/astar_benchmark_win_x64_msvc.txt`（2026-08-12）摘要：

```text
== 普通密度（25% 障碍）==
正确性：有效路径 998/1000，不可达（两实现一致）2；最优性（代价一致）998/1000；平均路径长 49.4 / 49.4
扩展节点（平均）：堆 257 / 线性 258（1.0x）
堆耗时：P50=0.027 ms  P95=0.087 ms  P99=0.117 ms
线性耗时：P50=0.060 ms  P95=0.365 ms  P99=0.630 ms   ← P99 差 5.4 倍
路径缓存（LRU 128）：可缓存 249，命中 249（100.0%），命中平均 0.0010 ms vs 未命中平均 0.0330 ms

== 高障碍（40%）==
正确性：有效路径 996/1000，不可达 4；最优性（代价一致）996/1000
扩展节点（平均）：堆 388 / 线性 389
堆耗时：P50=0.034 ms  P95=0.126 ms  P99=0.185 ms
线性耗时：P50=0.074 ms  P95=0.500 ms  P99=0.845 ms   ← P99 差 4.6 倍
```

## 结论

1. **正确性与最优性**：两种实现 100% 一致（有效路径与代价一致数 = 可达查询数）；不可达判定一致。
2. **扩展节点几乎相同**（257 vs 258、388 vs 389）：验证"一致启发下扩展数由启发质量决定，与 Open List 实现无关"。
3. **堆的优势在长尾**：P50 差 ~2 倍，P99 差 4.6~5.4 倍——线性扫描在 Open List 较大时退化，堆保证 O(log n) 弹出。
4. **路径缓存**：命中 0.001ms vs 未命中 0.033ms（约 33 倍），是"按 (起点,终点) LRU 缓存"工作日志方案的可复现支撑。
5. 工程启示：性能验收看 P95/P99；服务器寻路预算按 P99 签（对应 W2-05 AI/寻路时间预算）。

## 局限

- 本机为 100×100 小地图；大地图（500+）下线性扫描退化更严重，堆优势更明显（可改 `kSize` 复测）。
- 缓存命中率依赖负载模式（本实验受控为 25% 重复）；真实假人群体共享路径时命中率取决于移动模式。
- 未建模多线程寻路与 Tick 预算调度（见系统实战 07 与 W2-05）。
