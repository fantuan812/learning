## 复现

在仓库根运行，需要Python3及支持C++23 expected的GCC风格工具链。本次实际用g++14：

~~~sh
python3 -B evidence/cpp/foundation-contracts/run.py --cxx g++-14
~~~

不改系统权限、不联网；默认新建临时目录。`--out`只能指向尚不存在的目录，拒绝覆盖旧报告。编译120秒、正常运行30秒、负例10秒超时均算失败；缺编译器也失败。报告含编译器、平台、源码SHA、逐命令退出码。没有把缺工具/超时当跳过通过。

## 为什么选择这些测试

| 教学缺陷 | 正确例/观察 | 判据与限制 |
|---|---|---|
| 原子标志被误认为自动保护普通载荷 | 一次性release/acquire+join | 读值正确，并在正文解释同步关系；一次运行不证明全部调度 |
| load加store被误认为整体RMW | 合法顺序模型读0两次、写1两次 | 最终1，展示逻辑丢更新；没有故意运行数据竞争 |
| 多线程墙钟比忽略总工作差异 | 1/4线程三种order共6组，各总计40000 | 仅计数，不测时间、不推导性能倍率 |
| CAS失败后复用旧expected | 失败写回、再次成功 | 比较状态和新值 |
| 字节池步距1、异常耗槽、漏析构 | 类型化Slot+独立live元数据 | 容量1/3、64对齐、不覆盖、构造失败复用、析构计数 |
| variant模板实参直接定义struct | 外部类型定义+visit | 合法两分支、错误get抛出 |
| 宿主struct被误当网络格式 | 固定3字节大端显式解码 | 长度/tag/range/冗余尾部拒绝、1000边界 |
| span被误认为拥有及自动检查 | 借用修改与合法subspan | 展示别名；不故意做越界或悬空访问 |

安全程序三种构建各45项：原子12、池15、类型/协议15、布局3。实际源码见[contracts.cpp](contracts.cpp)。正文中的主要程序片段从同一源抽取；头文件和测试main保留在完整源中。

## 隔离负例

runner另外创建三个很小的源文件，实际编译或运行并检查失败类别：

1. 在variant模板实参定义struct：必须编译失败且诊断涉及模板
2. `FixedPool<int,0>`：必须静态断言失败，不能因缺链接库冒充预期失败
3. 旧`byte[index]`步距构造Node：只在UBSan子进程执行，须非零退出且有misaligned诊断；这是有意非法示例，不应拿到应用中使用

负例不是“任何非零都成功”。正常程序必须45项全过；错误源码编译超时、工具缺失或运行未触发指定诊断都会使runner失败。本轮未运行ASan或TSan。
