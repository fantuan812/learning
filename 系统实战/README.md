# 系统实战 · 纵向链路（建设中）

> 定位：把横向知识点串成"一个功能从客户端输入到线上服务器、数据库、测试与性能"的完整链路。不再解释"什么是 GAS/RPC/Buff"，而是回答"一个技能/移动在完整线上游戏里究竟是怎么跑的"。
> 状态：七条链路已落地（02-角色移动 L3、03-技能释放 L3、04-Buff L3、05-背包道具 L4、07-假人AI L5 待回填线上数据、10-性能问题定位 L4、11-伤害与属性结算 L4），其余规划链路见下方状态表。其中 05/10/11 附带本机可运行的测试与基准证据（[evidence/tests/gameplay-core](../evidence/tests/gameplay-core/README.md)、[evidence/tests/damage-core](../evidence/tests/damage-core/README.md)、[evidence/labs/profiling](../evidence/labs/profiling/README.md)）。
> 成熟度目标：每条链路完成后标注知识成熟度 L4/L5（有测试与数据），并在本 README 状态表登记。

## 写作模板（每条链路统一 15 步）

```text
1. 客户端输入 → 2. 本地预测 → 3. RPC 到服务器 → 4. 服务器校验（CD/Mana/State）→ 5. 目标筛选
→ 6. 技能执行 → 7. Buff Conflict → 8. Damage Pipeline → 9. 网络同步 → 10. 客户端表现
→ 11. 回放一致性 → 12. 异常场景 → 13. 单测 → 14. 压测 → 15. 性能预算
```

每步必须给出：涉及模块/文件、协议或调用链、边界与失败路径、可验证入口（源码路径 / 测试用例 / 数据）。涉及流程与数据流使用 Mermaid，图下必须有文字解释。
