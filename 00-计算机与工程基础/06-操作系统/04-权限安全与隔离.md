# 权限、安全与隔离

> 知识成熟度：L2
> 知识基线：当前标准与工具链版本，平台差异需验证。
> 最后更新：2026-08-20。
> 官方参考：https://docs.kernel.org/userspace-api/
> 验证与基准：按文中步骤执行实验并记录指标。
来源：https://docs.kernel.org/admin-guide/cgroup-v2.html｜验证与基准：namespace/cgroup/seccomp 实验。

## 身份与授权
- UID/GID 决定传统 DAC 检查。
- mode bits 分 owner、group、other 三段。
- umask 从创建权限中扣除默认位。
- ACL 提供超越三段权限的主体规则。
- Capability 将 root 权限拆成细粒度能力。
- setuid 程序必须最小化环境、路径和继承 fd。

## Namespace
- mount namespace 隔离挂载树。
- pid namespace 隔离进程编号，首进程负责回收孤儿。
- network namespace 隔离网卡、路由、端口空间。
- user namespace 映射容器 UID 到宿主无特权 UID。
- uts namespace 隔离 hostname 与 domainname。
- ipc namespace 隔离 SysV IPC 与 POSIX 队列。

## cgroups
- cgroup v2 统一 cpu、memory、io、pids 控制器。
- memory.max 触发回收或 OOM，memory.high 用于节流。
- cpu.max 配额决定周期内可运行时间。
- io.max 限制设备读写带宽与 IOPS。
- pids.max 防止 fork 炸弹。
- pressure stall information 暴露资源争用压力。

## 安全边界
- 隔离不是授权：容器内 root 仍需内核漏洞防护。
- seccomp 限制系统调用集合。
- LSM（SELinux/AppArmor）按标签或路径施加策略。
- no_new_privs 阻止 execve 获得额外特权。
- 只读根文件系统减少持久化攻击面。
- 丢弃 capability 后再启动业务进程。

## 威胁与防护
- 路径穿越：规范化路径并使用 openat2 约束解析。
- TOCTOU：避免先 stat 后 open 的检查竞态。
- fd 泄漏：设置 O_CLOEXEC，审计 exec 边界。
- symlink 攻击：临时目录设安全权限并使用 O_NOFOLLOW。
- 资源耗尽：cgroup、超时、连接上限和 backpressure。

## 设计流程
1. 列出资产、主体和信任边界。
2. 为每个 syscall/文件/设备定义最小权限。
3. 创建 namespace 与 cgroup，验证逃逸面。
4. 加入 seccomp/LSM 策略并记录拒绝日志。
5. 通过故障注入验证 OOM、网络隔离、权限拒绝。
6. 定期升级内核和容器运行时。

## 观测
- `/proc/$pid/status` 查看 CapEff、NSpid。
- `/proc/$pid/cgroup` 确认归属层级。
- `nsenter` 在授权场景进入目标 namespace 诊断。
- auditd 记录策略拒绝与特权操作。
- `systemd-analyze security` 检查服务沙箱项。

## 实验与 Benchmark

建立基线、控制变量、预热并重复至少 30 次，记录中位数、p95/p99、错误率和资源占用。保存源码、编译器、内核、硬件与原始日志。

### 实验流程

1. 定义问题与假设。
2. 构造最小样例并验证正确性。
3. 使用 perf、strace、bpftrace 或对应分析器采集证据。
4. 每次只改变一个变量，测试对照组。
5. 检查异常路径、资源上限和恢复行为。
6. 输出表格、分布和结论边界。

### 指标解释

吞吐是单位时间完成量；IOPS 是请求数；CPU/请求体现软件开销；p99 体现长尾；错误率和重试率决定真实可用性。

| 项目 | 基线 | 优化 | 证据 |
|---|---:|---:|---|
| 端到端延迟 |  |  | p50/p99 |
| 吞吐 |  |  | ops/s |
| CPU |  |  | cycles/op |
| 内存 |  |  | RSS/显存 |
| 错误 |  |  | errno/重试 |

### 常见陷阱

- 首次运行包含加载、分配和 JIT 成本。
- 异步程序未等待同步点，计时提前结束。
- 编译器删除无可观察副作用的基准代码。
- CPU 频率、SMT、NUMA 和后台任务造成噪声。
- 只测峰值吞吐，不测尾延迟、功耗和错误恢复。
- 优化改变数值精度、ABI 或安全边界，却未回归。

### CI 验收

将 Benchmark 纳入性能回归套件，设定相对基线阈值（例如 p99 退化不超过 10%）。超阈值时保留 perf 数据和环境信息并执行 bisect；不同硬件只比较相对变化。
## 可运行实验

### 环境与安全边界

- Linux 6.1+、rootless 容器运行时、`capsh`、`unshare`、`nsenter`、`strace`。
- 实验目录使用普通用户；涉及 user namespace 的命令先验证内核开关。

```bash
id
capsh --print
unshare --user --map-root-user id
```

预期最后一条显示 namespace 内 uid 0，但宿主权限不提升。若失败，记录 `kernel.unprivileged_userns_clone` 配置，不绕过安全策略。

### capabilities 最小权限

```bash
getcap /usr/bin/ping
capsh --drop=cap_net_raw -- -c 'ping -c1 127.0.0.1'
```

丢弃 capability 后应返回权限错误；恢复方式是结束 shell，不修改系统二进制。

### Namespace 与 cgroups

```bash
unshare --mount --pid --fork --mount-proc sh -c 'ps -ef; mount | head'
mkdir -p /sys/fs/cgroup/lab-$PPID
echo $((50*1024*1024)) > /sys/fs/cgroup/lab-$PPID/memory.max
```

cgroup 写入需要管理员权限；失败信号为 EACCES 或只读文件系统，回滚是删除本实验 cgroup 目录。

### seccomp 观察

使用 `strace -f -e trace=%process,%file` 建立 syscall 基线，再用容器 profile 拒绝 `ptrace`、`mount`、`bpf`。验收标准是被拒绝调用返回 EPERM，允许的业务调用不变。

### Benchmark 矩阵

|维度|水平|
|---|---|
|隔离|宿主、namespace、容器|
|权限|root、rootless、cap-drop|
|策略|无 seccomp、默认 profile、自定义 deny|
|负载|进程创建、文件访问、网络连接|
|指标|启动延迟、syscall p99、失败率|

每组运行 30 次；报告平均、p95、p99 和拒绝 syscall 数。安全策略变更前保存 profile，变更失败立即恢复旧 profile。

## 威胁建模与响应

资产包括凭据、配置、用户数据和内核接口。攻击面包括 setuid、设备节点、容器 socket、环境变量和日志。每项控制记录预防、检测、响应三类措施。

|事件|检测|响应|回滚|
|---|---|---|---|
|异常提权|auditd capability 事件|隔离进程、吊销令牌|恢复白名单|
|容器逃逸尝试|seccomp deny|冻结容器、保留镜像|回滚镜像|
|敏感文件读取|fanotify/audit|阻断主体|恢复权限 ACL|

## 排障清单

1. 权限错误：查看 uid/gid、ACL、capability 和 mount flags。
2. 容器网络异常：分别检查 netns 路由、veth、宿主防火墙。
3. cgroup 限流：确认 effective 配置和父级 cgroup 继承。
4. seccomp 误杀：从审计日志提取最小 syscall 集合。
5. SELinux/AppArmor 拒绝：查看拒绝日志并新增最小规则。

## 深入实验清单

|实验|输入|观测|验收|
|---|---|---|---|
|uid 映射|userns|/proc/self/uid_map|宿主 uid 不变|
|挂载隔离|mount ns|/proc/self/mountinfo|宿主不可见|
|pid 隔离|pid ns|ps 输出|仅见子树|
|资源限额|memory.max|memory.events|触发 oom 计数|
|syscall 过滤|seccomp|audit 日志|拒绝率可解释|

记录每次实验的 namespace inode、cgroup 路径和策略 hash。策略文件采用版本控制，变更前后运行同一回归集。

常见误区：root in user namespace 不等于宿主 root；capability 只在对应 namespace 生效；cgroup 限额会继承父级；seccomp 过滤器不能替代认证授权。

## 回滚剧本

1. 终止实验容器与 namespace init。
2. 移除实验 cgroup，确认 tasks 为空。
3. 恢复旧 seccomp/AppArmor profile。
4. 清理 audit 规则，避免日志洪泛。
5. 对比宿主 capability 与挂载表，确保无残留。

质量门禁：无 root 绕过命令；所有拒绝事件有审计证据；所有性能数字含基线和置信区间。

## 最小可运行安全回归

下面的回归套件验证身份、隔离、资源和系统调用边界。测试前保存策略文件哈希。

```bash
set -eu
mkdir -p /tmp/sec-lab
id > /tmp/sec-lab/id.txt
capsh --print > /tmp/sec-lab/capsh.txt
unshare --user --map-root-user --mount-proc sh -c 'id; cat /proc/self/uid_map; ps -ef' > /tmp/sec-lab/userns.txt
```

验收：namespace 内显示 uid 0 但宿主 uid 不变；uid_map 只映射当前无特权 UID；退出后宿主进程表和挂载表无变化。

### 文件权限与 ACL 对照

```bash
mkdir -m 700 /tmp/sec-lab/private
printf secret > /tmp/sec-lab/private/data
chmod 600 /tmp/sec-lab/private/data
getfacl /tmp/sec-lab/private/data
setfacl -m u:nobody:r-- /tmp/sec-lab/private/data
sudo -u nobody cat /tmp/sec-lab/private/data
setfacl -x u:nobody /tmp/sec-lab/private/data
```

预期：授予 ACL 后 nobody 只能读取不能写入；删除 ACL 后恢复 EACCES。测试结束检查 getfacl 与基线一致。

### cgroup 限额与恢复

```bash
cg=/sys/fs/cgroup/sec-lab-$PPID
sudo mkdir "$cg"
echo $$ | sudo tee "$cg/cgroup.procs" >/dev/null
echo 100M | sudo tee "$cg/memory.max" >/dev/null
echo 1000 | sudo tee "$cg/pids.max" >/dev/null
cat "$cg/memory.events" "$cg/pids.current"
```

超过 100 MiB 时 memory.events 的 max/oom 计数应增加；fork 超限返回 EAGAIN。停止子进程后确认 memory.current、pids.current 回到基线，再删除 cgroup。

### seccomp 拒绝与允许集

先用 strace 建立 syscall 基线，再用 profile 拒绝 ptrace、mount、bpf，允许 read/write/openat/epoll_wait。

```bash
strace -f -o /tmp/sec-lab/trace.before ./service --self-test
grep -oE '^[^ ]+ +[a-zA-Z0-9_]+' /tmp/sec-lab/trace.before | sort -u > /tmp/sec-lab/syscalls.before
```

验收：被拒调用返回 EPERM 且日志带 PID/profile 版本；允许调用与基线一致。误杀时切回上一版 profile，禁止放开全部 syscall。

### 故障注入矩阵

|故障|注入方式|预期观测|恢复验收|
|---|---|---|---|
|权限拒绝|chmod 000|EACCES、审计事件|恢复 mode，重试成功|
|能力缺失|drop cap_net_raw|EPERM|宿主 capability 不变|
|PID 隔离|新建 pid namespace|仅见子树|init 退出无孤儿|
|网络隔离|新建空 netns|连接失败|宿主路由不变|
|内存超限|超过 memory.max|oom 计数增加|cgroup 归零|
|进程数超限|循环 fork|EAGAIN|pids.current=0|
|系统调用拒绝|seccomp deny mount|EPERM/审计|旧 profile hash 一致|
|路径竞态|并发替换 symlink|openat2 拒绝|无越界文件|

### 性能 Benchmark

宿主、user namespace、rootless 容器和 seccomp 四种配置各运行 30 次：

```bash
hyperfine --warmup 5 --runs 30 './service --self-test'
perf stat -r 10 -e cycles,instructions,context-switches,cpu-migrations ./service --self-test
```

记录启动 p50/p95/p99、syscall 数、上下文切换、错误率和 RSS。相对基线 p99 退化超过 10% 必须定位具体策略或 syscall。

### 事件响应演练

1. 触发 capability 拒绝和 cgroup OOM，保存 audit、memory.events、服务日志及 UTC 时间戳。
2. 冻结实验进程，复制 status、mountinfo 和 namespace inode。
3. 吊销凭据，停止容器，恢复上一版 seccomp/LSM 配置。
4. 重启服务并执行健康检查、权限回归和数据完整性校验。

验收：恢复后无高权限进程、挂载点、cgroup 或临时 socket 残留，所有证据可按时间线关联。

### 最终清理清单

```bash
sudo rmdir /sys/fs/cgroup/sec-lab-$PPID 2>/dev/null || true
rm -rf /tmp/sec-lab
```

复核 ps、findmnt、ip netns list 与实验前快照；无法删除的 cgroup 必须先找到持有 PID 再清理。
