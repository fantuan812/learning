# 进程、线程、虚拟内存与系统调用
> 验证与基准：按文中命令执行最小实验，记录结果与边界。

> 知识成熟度：L2（以 Linux 6.x/POSIX 为主要语境；命令与实验计划已给出但尚未形成运行证据；Windows/主机实现存在差异）
> 知识基线：POSIX.1-2017 与 Linux 6.x 进程、线程、虚拟内存和系统调用语义。
> 最后更新：2026-08-20。
> 官方参考：[Linux man-pages](https://man7.org/linux/man-pages/)、[The Linux Kernel documentation](https://docs.kernel.org/)。
> 验证入口：使用 strace、/proc 与 perf 按文中步骤复现实验。
> 证据状态：尚未保存最小实验脚本、原始 strace/proc/perf 输出或跨内核复测记录。

## 1. 总览

操作系统把硬件资源抽象成进程、线程、地址空间、文件和设备。
进程是资源隔离与权限边界。
线程是可被调度的执行流。
虚拟内存把进程看到的地址映射到物理页。
系统调用是用户态进入内核态的受控入口。
调度器决定哪个可运行线程占用 CPU。
文件系统提供持久化命名空间。
本文聚焦游戏客户端、专用服务器和工具链常见问题。

## 2. 进程模型

进程拥有独立虚拟地址空间。
地址空间通常包含代码、只读数据、数据段、堆和栈。
进程控制块记录 PID、状态、凭据和资源引用。
fork 创建近似副本并采用写时复制。
exec 用新程序映像替换当前地址空间。
父进程通过 wait 回收子进程状态。
孤儿进程会被重新托管。
僵尸进程只保留退出状态和少量元数据。
进程退出应释放文件、映射和 IPC 资源。
进程边界降低故障传播，但 IPC 成本更高。

## 3. 线程模型

同一进程线程共享代码、堆和打开文件。
每个线程有独立栈、寄存器上下文和线程本地存储。
线程切换通常比进程切换轻，但仍涉及调度和缓存扰动。
共享数据必须建立同步协议。
数据竞争在 C/C++ 中可能导致未定义行为。
线程池限制并发度并摊薄创建成本。
工作窃取适合任务粒度不均的并行计算。
I/O 线程与逻辑线程分离可降低阻塞影响。
线程过多会增加上下文切换和内存占用。
线程命名有助于火焰图和崩溃诊断。

## 4. 上下文切换

上下文包括通用寄存器、程序计数器和栈指针。
切换时调度器保存旧线程并恢复新线程。
地址空间切换可能影响 TLB。
现代 CPU 使用 ASID/PCID 减少冲刷。
切换还会带来指令和数据 cache 污染。
锁竞争导致自旋或睡眠切换。
短临界区可自旋，长临界区应阻塞。
实时路径要观察调度延迟而非平均吞吐。

## 5. 调度

可运行队列保存等待 CPU 的线程。
时间片轮转保障公平性。
优先级影响响应和吞吐。
实时策略要求更严格的延迟保证。
优先级反转可通过优先级继承缓解。
CPU 亲和性减少迁移但降低负载平衡空间。
NUMA 机器应关注线程与内存节点绑定。
抢占点和不可抢占区影响最长延迟。
服务器 tick 线程应避免被后台任务抢占。
调度统计可从 /proc、tracepoint 或 perf 获取。

## 6. 虚拟内存

虚拟地址由页号和页内偏移组成。
页表把虚拟页映射到物理页框。
页大小影响内部碎片与 TLB 覆盖范围。
多级页表节省稀疏地址空间的页表内存。
页表项包含存在、可写、用户和执行权限位。
NX/W^X 限制数据页执行。
地址随机化提高利用漏洞难度。
用户态不能直接访问内核地址。
内核通过 copy_from_user 等接口检查用户指针。

## 7. 缺页与 TLB

TLB 缓存近期地址转换。
TLB miss 会触发页表遍历或软件处理。
访问未映射页会触发 page fault。
需求分页在首次访问时建立映射。
写时复制页在写入时产生保护异常。
缺页可能只需分配零页，也可能需要磁盘 I/O。
minor fault 不需要磁盘读取。
major fault 可能等待存储设备。
随机大内存访问易造成 TLB 和 cache miss。
大页可提高 TLB 覆盖，但增加碎片和管理成本。
缺页延迟必须纳入帧时间和 tick 预算。

## 8. 堆、栈与映射

堆由分配器向进程提供动态内存。
malloc 可能通过 brk 或 mmap 获取页。
释放内存未必立即归还操作系统。
碎片分为内部碎片和外部碎片。
线程缓存分配器可减少锁竞争。
栈通常按线程预留地址空间。
栈溢出可能表现为保护页异常。
mmap 可映射文件或匿名共享内存。
munmap 后继续访问是悬空指针。
映射权限应遵循最小权限原则。

## 9. 系统调用

系统调用编号和参数由 ABI 约定。
用户态通过特定指令进入内核入口。
内核切换涉及权限级别和寄存器保存。
系统调用可能复制参数和数据。
read/write 的成本包含检查、锁和调度。
批量 I/O 可摊薄每次进入内核的固定成本。
vDSO 为部分时间查询提供用户态快速路径。
io_uring 通过共享环减少提交与完成开销。
系统调用失败必须检查 errno。
EINTR 表示被信号中断，是否重试要看语义。
短读短写是流式 I/O 的正常现象。

## 10. 文件与 I/O

文件描述符是进程表中的整数句柄。
打开文件表保存偏移、状态和引用计数。
dup 共享打开文件状态但拥有不同描述符。
非阻塞 I/O 在无数据时返回 EAGAIN。
page cache 缓存文件页。
fsync 请求将数据推进持久介质，但设备语义仍需确认。
顺序读通常比随机读更易预取。
direct I/O 绕过部分 page cache，需严格对齐。
文件锁和应用锁的边界必须明确。
日志写入应考虑批量、刷盘和崩溃恢复。

## 11. IPC

管道适合父子进程的字节流通信。
Unix domain socket 支持本机双向通信和凭据传递。
共享内存吞吐高，但同步由应用负责。
消息队列保留消息边界。
信号适合通知，不适合承载复杂数据。
eventfd 和 signalfd 可把通知纳入事件循环。
IPC 协议需要版本、超时和关闭语义。
共享内存要处理进程异常退出后的恢复。

## 12. 同步原语

互斥锁保护临界区不变量。
读写锁适合读多写少但可能发生写者饥饿。
条件变量等待谓词而不是等待一次通知。
信号量表达资源计数。
屏障等待一组线程到达阶段点。
原子操作只保护单变量，不自动保护复合不变量。
锁顺序应全局统一以避免死锁。
超时锁能把不可恢复等待变成可观测错误。
自旋锁不应跨越可能睡眠的操作。

## 13. 内存回收与缓存

页回收受工作集、脏页和压力影响。
匿名页回收可能写入 swap。
游戏服务器通常避免关键路径 swap。
mlock 需谨慎使用并考虑额度。
内存压力会引起回收抖动。
工作集是近期活跃页集合。
冷热分离有助于降低工作集。
大块预分配可稳定延迟但提高常驻内存。
监控 RSS、虚拟大小、PSS 和 page fault。

## 14. 信号与异常

SIGTERM 通常表示请求优雅退出。
SIGKILL 无法被捕获或清理。
SIGSEGV 常见于非法访问或栈溢出。
信号处理函数只能调用异步信号安全函数。
崩溃处理应记录寄存器、线程和映射信息。
不要在信号处理函数中分配内存或获取普通锁。
core dump 需配合符号文件分析。
Windows 异常模型与 POSIX 信号不同。

## 15. 服务器实践

主循环应明确 tick、I/O 和后台任务的优先级。
网络线程只做轻量解析并投递消息。
逻辑线程批量消费消息可降低锁次数。
定时器堆的惰性删除要设置上限。
连接关闭必须幂等。
优雅停机包含停止接入、排空队列和持久化状态。
资源配额要限制连接数、线程数和内存。
背压通过队列水位、丢弃策略和超时实现。

## 16. 诊断方法

先确认症状是 CPU、内存、I/O 还是调度。
用 time 区分用户态和内核态时间。
用 vmstat 观察运行队列、缺页和 swap。
用 pidstat 观察线程级 CPU 与上下文切换。
用 /proc/PID/maps 检查地址空间布局。
用 strace 观察系统调用序列与耗时。
用 perf record/report 定位热点和缺页事件。
用 ftrace 或 eBPF 分析调度延迟。
记录采样时的负载、内核和容器限制。
先建立基线，再比较单变量改动。

## 17. 常见误区

线程共享地址空间不等于共享安全。
fork 后写入才触发写时复制，并非立即复制全部内存。
虚拟地址连续不保证物理连续。
系统调用不一定比库函数慢，库函数可能直接走 vDSO。
page cache 命中不代表数据已持久化。
高 CPU 不一定是业务计算，也可能是自旋或软中断。
平均延迟正常不代表 p99 正常。
锁数量少不代表竞争少。

## 18. 实验建议

编写 fork/exec 程序观察 RSS 与 COW。
使用 mmap 修改页并统计 minor fault。
比较顺序与随机访问的 TLB miss。
用线程池测任务粒度和上下文切换。
用 pipe 与共享内存比较 IPC 吞吐。
用 strace 统计小写入和批量写入的调用次数。
模拟内存压力观察回收与尾延迟。
为服务端停机编写可重复的排空测试。

## 19. 复盘清单

进程还是线程，隔离边界是否正确？
是否明确所有权、关闭和回收责任？
关键路径是否可能缺页或阻塞？
是否记录系统调用错误和重试策略？
调度优先级是否造成反转或饥饿？
内存预算是否包含映射、栈和分配器缓存？
诊断数据是否带版本、硬件和负载？
结论是否经过目标平台复测？

## 20. 参考边界

Linux 行为以目标内核版本文档和 man pages 为准。
POSIX 只规定可移植语义，不覆盖所有性能细节。
Windows、主机平台和容器运行时可能改变调度与内存表现。
任何性能数字都应标记为实验结果，而非普遍定律。
