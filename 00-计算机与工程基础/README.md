# 00-计算机与工程基础 · 领域知识体系

> 定位：游戏客户端、引擎底层、高性能游戏服务端与核心算法的统一底层工程底座。
> 核心任务：回答系统机制“为什么这样设计”与“性能与正确性边界在哪里”——从 CPU 缓存一致性、内存序、虚函数与对象对齐，到系统调用开销、缺页中断、网络背压、存储引擎事务与分布式共识。
> 状态：16 个分类全部落地，覆盖 40 篇核心工程专题（均 ≥300 行深度分析与可复现验证基准）。
> 知识成熟度：各专题正文顶部按 [写作规范](../references/写作规范.md) 严格标明 L0~L5 成熟度。

## 1. 为什么需要统一的基础工程底座

在大型游戏工程中，知识往往从 UE 引擎（UObject、Actor、GAS、Iris 复制、Nanite 渲染）或游戏业务服务端（Server Loop、Tick、AOI、协议序列化）直接切入，容易陷入“只能死记框架 API，无法诊断深层性能与并发 Bug”的困境：

```text
┌───────────────────────────────────────────────────────────────────────────────┐
│ UE 客户端链路：C++ → 对象模型 → 体系结构/SIMD → 引擎源码 (UObject/TaskGraph/渲染)│
│ 服务端核心链路：C++ → Linux 内核/网络 → 并发/事务 → 游戏服务端 (Tick/AOI/分布式)  │
└───────────────────────────────────────▲───────────────────────────────────────┘
                                        │ 统一技术汇合
┌───────────────────────────────────────┴───────────────────────────────────────┐
│                         00-计算机与工程基础知识体系                           │
│  语言核心 │ 内存模型 │ 体系结构 │ 操作系统内核 │ 网络分层 │ 存储与分布式 │ 工程效能 │
└───────────────────────────────────────────────────────────────────────────────┘
```

当遇到以下典型生产问题时，必须依托本层的机理推导解决：
1. **帧率与掉帧诊断**：`TArray` 扩容卡顿（01 值语义与移动）、对象跨缓存行访问引发的 L1 Cache Miss（02 对象布局与对齐 ↔ 08 体系结构）。
2. **多线程并发竞态**：高频原子计数引发的 CPU 总线风暴与 False Sharing（04 并发内存序 ↔ 08 MESI 缓存一致性协议）。
3. **服务端吞吐与延迟**：网络网关在海量连接下的 Epoll 事件处理与背压调节（07 Linux系统编程 ↔ 09 计算机网络）。
4. **内存与卡顿治理**：大地图流送时因缺页中断（Page Fault）与脏页回写引发的主线程停顿（06 操作系统虚拟内存与存储栈）。
5. **数据一致性与持久化**：玩家资产交易、跨服迁移与断线重连中的原子性保证（12 数据库与分布式系统 ↔ 14 安全认证）。

## 4. 与其他领域的专业分工边界

本层聚焦底层机理，与上层各领域的职责切分如下：

- **与 [游戏知识（UE5 引擎）](../游戏知识/README.md) 的分工**：
  本层讲 C++ 语言与系统模型（对象生命周期、虚函数表、对齐填充、内存分配器）；引擎源码分析层讲 UE 的特定工程实现（`UObject` 反射与 GC、`FMallocBinned`、`TaskGraph` 调度、`TArray` 源码）。
- **与 [游戏服务端](../游戏服务端/README.md) 的分工**：
  本层讲标准 OS 内核与系统编程（Epoll、Reactor、非阻塞 I/O、TCP/QUIC 机制、分布式事务）；游戏服务端层讲业务场景的具体落地（自研网关协议拆包、Tick 循环调度、AOI 广播、跨 Zone 状态迁移）。
- **与 [游戏算法](../游戏算法/README.md) 的分工**：
  本层讲通用数据结构复杂度与数学前置（渐进分析、离散图论、线性代数、数值计算）；游戏算法层讲专用领域算法（A* 优化、分层寻路、NavMesh 动态构建、RVO 避障）。
- **与 [evidence 实验](../evidence/README.md) 的对接**：
  基础理论章节提供直接对应的本机实测工程与测试数据（如原子内存序基准、False Sharing 性能对比）。

- **深度门禁**：正文必须 ≥300 行、UTF-8 无 BOM、无损坏的字面换行符。
