# 虚拟化与硬件辅助隔离

## 学习目标

- 区分 Type-1（裸机）与 Type-2（宿主操作系统上的监控器）。
- 理解 VT-x/AMD-V、Arm EL2 对特权指令和地址转换的扩展。
- 能解释 EPT/NPT、VM exit、IOMMU、SR-IOV 的性能与安全边界。
- 设计 vCPU、NUMA、时钟和设备模型的容量实验。
- 识别虚拟机、容器、沙箱之间不同的隔离假设。

## 术语速查

|术语|含义|主要风险|
|---|---|---|
|VMM/Hypervisor|管理客户机 CPU、内存和设备的监控器|控制面漏洞影响多租户|
|Type-1|直接运行在硬件之上|驱动和升级复杂|
|Type-2|依赖宿主 OS|额外调度层和攻击面|
|VMX root/non-root|Intel 主机与客户机执行环境|切换产生 exit 开销|
|EL2|Arm 虚拟化特权级|异常路由配置错误会越权|
|EPT/NPT|二级页表，把 GPA 映射到 HPA|页表缺失导致 VM exit|
|IOMMU|设备 DMA 地址转换和隔离|映射错误可 DMA 越界|
|SR-IOV|一个物理设备切分 PF/VF|VF 固件和租户隔离依赖设备|

## Type-1 与 Type-2

Type-1 直接控制物理 CPU、内存和设备，典型实现包括 ESXi、Hyper-V、Xen 和 KVM 配合 Linux 作为宿主。KVM 内核模块本身提供硬件辅助的虚拟 CPU，QEMU 通常承担设备模型，因此部署形态常被称为“Type-1-ish”。

Type-2 运行在普通宿主 OS 进程中，VirtualBox、VMware Workstation 和 QEMU TCG 属于这一类。Type-2 便于开发和调试，但宿主调度、文件系统和驱动路径更长。

不要仅依据产品名称判断类型；应记录谁拥有物理中断、页表和 DMA 映射，以及客户机退出后由哪一层处理。

## Intel VT-x

- VMXON 进入 VMX root 模式，VMCS 保存客户机状态、主机状态和执行控制。
- VMLAUNCH/VMRESUME 启动或恢复 non-root 客户机。
- pin-based、primary/secondary processor-based controls 选择哪些事件触发 VM exit。
- MSR bitmap、I/O bitmap 可减少不必要的退出。
- APIC virtualization、posted interrupt 降低虚拟中断路径成本。
- VMFUNC 可在受控条件下切换 EPTP。

VM exit 不是异常本身，而是硬件将控制权交回 VMM 的事件。VMM 读取 exit reason、qualification 和 guest RIP，再模拟指令、注入中断或终止客户机。

## AMD-V

- SVM 使用 VMCB 描述客户机状态和拦截控制。
- VMRUN 进入客户机执行，#VMEXIT 返回监控器。
- ASID 减少 TLB 刷新；AVIC 优化虚拟 APIC 访问。
- NPT 提供二级地址转换，与 Intel EPT 目标相同但实现细节不同。

AMD 文档中的 intercept 位图必须和操作系统 KVM 代码结合阅读；不同 CPU 世代的特性开关不可假定一致。

## Arm EL2

Armv8-A 将 hypervisor 运行在 EL2，客户机通常位于 EL1/EL0。HCR_EL2 控制异常路由、Stage-2 翻译和系统寄存器陷阱；VTTBR_EL2 指向客户机的 Stage-2 页表。

Stage-1 由客户机管理 VA→IPA，Stage-2 由 hypervisor 管理 IPA→PA。两级转换叠加 TLB、权限位和内存属性，设备映射必须与 GIC、SMMU 配置一致。

## EPT、NPT 与地址转换

客户机虚拟地址（GVA）先经客户机页表得到 GPA，再经 EPT/NPT 得到主机物理地址（HPA）。缺少二级页表项、权限冲突或内存类型不匹配时会产生 EPT violation/NPF。

大页（2 MiB/1 GiB）可减少页表层级和 TLB miss，但会增加内存碎片与写时复制成本。透明大页、KSM、ballooning 需结合工作负载验证。

## VM exit 成本模型

典型退出来源：CPUID、MSR、HLT、I/O、EPT violation、外部中断、定时器和调试寄存器。成本包括状态保存、VMM 调度、设备模拟、重新填充 TLB 和重新进入客户机。

降低成本的方法：启用 paravirtualized clock、virtio、posted interrupt、MSR bitmap、批量 I/O、vhost、vCPU pinning，并避免高频 MMIO 模拟。

## 内存与 NUMA

- vCPU 应尽量与 vNUMA 拓扑匹配物理 NUMA 节点。
- 内存绑定可用 `numactl --cpunodebind` 和 `--membind`。
- KVM balloon 让客户机归还页，但可能造成回收抖动。
- virtio-balloon 的 free-page reporting 需要客户机驱动配合。
- 预分配内存可降低运行时缺页，但启动时间和占用增加。
- 机密虚拟机的内存加密会改变迁移、调试和设备直通策略。

## 虚拟 CPU、调度与超卖

vCPU 是可运行实体，不等于独占物理核。vCPU overcommit 会引入 ready time、steal time 和调度延迟；实时游戏或低延迟服务应监控 P99/P999。

固定 vCPU 亲和性、隔离 housekeeping CPU、配置 emulatorpin/iothreadpin，并比较 SMT 开启与关闭的尾延迟。不要只看平均 CPU 利用率。

## 时钟与计时器

客户机可见 TSC 可能被虚拟化。KVM 使用 paravirtualized clock、kvmclock、TSC offset/scaling 提供稳定时间；迁移和宿主频率变化仍需校验。

定时器注入、虚拟 HPET、PIT 和 APIC timer 的精度与成本不同。应用应使用单调时钟测量间隔，避免把 wall clock 调整误认为暂停。

## IOMMU 与 DMA 隔离

Intel VT-d、AMD IOMMU 和 Arm SMMU 将设备 DMA 地址映射到受控 IOVA。设备直通前应建立 domain、映射 BAR 和中断，并验证 ACS/ARI 拓扑。

IOMMU 不能自动修复恶意固件；必须限制可分配设备、启用中断重映射并审计 reset 能力。VFIO 将用户态设备访问与 IOMMU 绑定。

## SR-IOV

物理功能（PF）创建多个虚拟功能（VF），每个 VF 暴露队列和配置空间。SR-IOV 接近裸机性能，但迁移、快照、热插拔和跨租户计量比 virtio 复杂。

实验时记录 PF/VF 驱动、队列数、RSS、中断亲和性、带宽上限和 reset 行为。不同 NIC 的 VF 隔离能力不能互相推断。

## 容器、VM 与沙箱边界

容器共享宿主内核，通过 namespaces、cgroups、capabilities、seccomp 和 LSM 限制进程；容器逃逸意味着内核或运行时边界被突破。VM 提供独立客户机内核，攻击面转移到 hypervisor、设备模型和固件。

gVisor、Kata Containers、Firecracker 等在性能和隔离之间取折中。威胁模型应明确是否需要防御恶意租户、恶意内核模块、侧信道或设备固件。

## 安全控制清单

- 固件、BIOS、microcode、hypervisor 和 QEMU 版本可追溯。
- 禁用不需要的模拟设备和管理 socket。
- 使用最小权限、SELinux/AppArmor、seccomp 和 cgroup 限制。
- 管理面与数据面网络隔离，API 使用双向认证。
- IOMMU 开启 DMA 隔离和中断重映射。
- 迁移流量加密并验证目标主机信任状态。
- 机密数据避免写入快照、core dump 和调试日志。
- 对 VM exit、设备 reset、迁移和异常关机留审计记录。

## 实验一：VM exit 归因

目标：比较 CPUID、I/O、EPT fault 和 virtio 批处理的退出率。启动两个相同 Linux 客户机，一个使用 virtio-blk，另一个使用模拟 IDE。

步骤：固定 vCPU 和内存；运行 `perf kvm stat record -a`；客户机执行 CPUID 循环、4 KiB 随机 I/O 和顺序 I/O；导出 `perf kvm stat report`。

指标：每秒 exit 次数、每次 exit 纳秒、客户机吞吐、P50/P99 I/O 延迟、宿主 CPU。验收：解释至少前三种 exit reason，并说明批量 I/O 是否降低退出率。

## 实验二：EPT/NPT 与大页

准备 4 KiB、2 MiB、1 GiB hugepage 三组内存；运行内存带宽和随机访问程序，分别开启/关闭 THP。记录 `perf stat -e kvm:kvm_page_faults,dTLB-load-misses`（事件名按平台调整）。

矩阵：

|变量|水平|
|---|---|
|页大小|4 KiB/2 MiB/1 GiB|
|工作集|L3 内/跨 NUMA|
|vCPU|1/2/8|
|重复|至少 10 次|

报告均值、标准差、P95/P99 和页故障数，不以单次最快结果下结论。

## 实验三：IOMMU 与 SR-IOV

在支持的 NIC 上创建 1、2、4、8 个 VF，分别使用 virtio-net、VF 直通和无 IOMMU 基线（仅测试机）。运行 `iperf3`、`pktgen` 或 DPDK，并记录吞吐、P99 延迟、宿主 CPU、中断分布和 VF reset 成功率。

安全验收：尝试访问未映射 DMA 区域应失败并产生 IOMMU fault；验证 VF 不能读取其他 VF 的队列或配置。禁止在生产租户环境进行越界测试。

## 实验四：vCPU 亲和性与 NUMA

比较未绑定、仅 vCPU 绑定、vCPU+内存绑定三组。工作负载使用 `stress-ng --cpu` 与真实服务混合，逐步将 overcommit 从 1:1 提升至 4:1。

记录 steal time、run queue、调度等待、服务吞吐和 P99/P999 延迟。容量结论必须注明 SMT、频率 governor、宿主噪声和 NUMA 拓扑。

## 故障排查

1. `/dev/kvm` 不存在：检查 BIOS 虚拟化开关、内核模块、嵌套虚拟化和权限组。
2. EPT/NPT 未启用：检查 CPU 特性、KVM 日志和 hypervisor 参数；部分旧 CPU 只能软件二级页表。
3. VM exit 过高：查看 `perf kvm stat`，关闭高频调试、改用 virtio、启用 APICv/posted interrupt。
4. P99 抖动：检查 vCPU 争用、宿主 housekeeping、NUMA 远端内存、SMT 和频率调节。
5. IOMMU fault：核对 IOMMU group、VFIO 绑定、DMA 映射长度和设备 reset。
6. SR-IOV VF 不出现：确认 PF 驱动、`sriov_numvfs`、固件许可和 PCIe ACS。
7. 时钟跳变：检查 kvmclock、TSC 稳定性、迁移日志和客户机 NTP。
8. 迁移失败：确认 CPU model、设备版本、dirty rate、共享存储和目标信任策略。
9. 容器性能异常：区分 cgroup 限流、宿主 oversubscription 与内核共享锁竞争。
10. 安全告警：先隔离 VM/设备，再保留 hypervisor、QEMU、IOMMU 和审计日志。

## 设计取舍

- 追求通用迁移时优先 virtio；追求极低延迟且可接受硬件绑定时考虑 VFIO/SR-IOV。
- 追求隔离时减少设备模型和管理接口；追求兼容性时保留成熟模拟设备并加强补丁管理。
- 追求吞吐时使用大页和绑核；追求弹性时接受 balloon、过量分配和迁移开销。
- 机密计算提升内存保护，但会限制调试、快照、直通和实时迁移。

## 性能解释注意事项

- 不要把宿主机总体 CPU 利用率当作客户机可用算力；steal、iowait 和 emulator 线程需分开统计。
- 不同 CPU 型号的 VM exit 成本不能直接横向比较，应固定 microcode、频率和 SMT 设置。
- `perf kvm stat` 的事件支持依赖内核配置；缺失事件时记录替代指标和限制。
- fio 的 ioengine、iodepth、direct 标志会改变页缓存路径，必须写入报告。
- 网络 benchmark 要分别报告吞吐、pps、重传和软中断，避免只报 Gbps。
- 迁移测试应记录 dirty-page rate；仅比较停机时间会掩盖迁移前预复制阶段成本。

## 常见误区

把“启用了 VT-x”误认为“所有设备都已隔离”；CPU 虚拟化与 DMA 隔离是两条独立链路。

把“容器更轻”误认为“容器天然更安全”；容器的安全边界仍依赖宿主内核、运行时和配置。

把“直通性能最好”误认为“生产总成本最低”；直通会增加调度、迁移、监控和故障恢复成本。

把“NUMA 绑定”误认为“永远更快”；跨节点流量、线程迁移和内存回收可能抵消收益。

把“机密 VM”误认为“所有数据都受保护”；启动链、输入输出设备、管理面和侧信道仍需单独建模。

## 学习路径

先阅读 CPU 特权级和页表，再阅读 VT-x/AMD-V 控制结构；随后用 KVM API 创建最小 vCPU，最后分析 virtio、VFIO 和迁移。

每个实验先建立裸机或宿主基线，再只改变一个变量。所有结果保留原始 CSV、命令行和环境摘要，避免只保存结论图。

出现不稳定结果时，优先增加预热、重复次数和隔离 CPU；不要用删除异常样本的方式“修复”P99。

- 能画出 GVA→GPA→HPA 和用户态→KVM→硬件的路径图。
