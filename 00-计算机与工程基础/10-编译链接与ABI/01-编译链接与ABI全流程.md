# 编译、链接与 ABI 全流程
> 验证与基准：按文中命令执行最小实验，记录结果与边界。

> 知识成熟度：L2（原理稳定，平台细节以 MSVC、Clang/GCC x86-64 为例；命令与实验计划已给出但尚未形成运行证据）
> 版本边界：C++20；Windows 11、Linux 6.x；结论需以目标工具链验证。
> 知识基线：C++20、PE/COFF、ELF 与 Itanium/MSVC ABI；平台差异不可互换。
> 最后更新：2026-08-20。
> 官方参考：[cppreference translation](https://en.cppreference.com/w/cpp/language/translation_phases)、[Itanium C++ ABI](https://itanium-cxx-abi.github.io/cxx-abi/abi.html)。
> 验证入口：按文中 cl/clang/g++、dumpbin/readelf/nm 命令核对产物。
> 证据状态：当前未保存编译产物、符号工具原始输出或不同 ABI 工具链的复测记录。

## 1. 总览

1. 源文件经过预处理形成翻译单元。
2. 编译器把翻译单元降为目标文件。
3. 链接器合并目标文件与库。
4. 加载器映射段、解析动态符号并执行初始化。
5. 运行时通过 ABI 约定调用函数和访问对象。

## 2. 预处理

6. `#include` 是文本展开，不是模块导入。
7. 宏在词法阶段替换，缺少类型安全。
8. include guard 防止同一翻译单元重复展开。
9. `#pragma once` 依赖编译器实现但已被广泛支持。
10. 条件编译可改变结构体布局和函数签名。
11. `-E` 或 `/P` 可导出预处理结果。
12. 预处理输出用于定位宏污染和头文件顺序问题。
13. 宏参数必须加括号避免运算符优先级错误。
14. 多行宏应使用 `do { ... } while (0)`。
15. 头文件不应定义非 `inline` 的全局实体。

## 3. 翻译单元与编译

16. 每个 `.cpp` 独立解析并生成目标文件。
17. 编译器先做语法分析，再做语义分析。
18. 模板通常在实例化点生成代码。
19. `-O0` 便于调试，不能代表线上性能。
20. `-O2/-O3` 允许内联、常量传播和循环变换。
21. `-g` 或 `/Zi` 保留调试信息。
22. 调试信息通常放在独立 PDB/DWARF 文件。
23. 警告级别应在 CI 中固定。
24. 将警告视为错误可阻断隐式转换缺陷。
25. 编译缓存以命令行、头文件内容和环境为键。
26. PCH 降低重复解析成本但增加依赖耦合。
27. Unity build 合并多个源文件，可能掩盖 ODR 问题。
28. LTO/ThinLTO 在链接阶段进行跨翻译单元优化。
29. 编译器版本变化可能改变内联和布局。
30. 不要混用不兼容的运行时库选项。

## 4. 目标文件

31. ELF、PE/COFF、Mach-O 是常见目标格式。
32. 目标文件包含代码、只读数据、可写数据和重定位表。
33. `.text` 通常具备可执行权限。
34. `.rodata` 保存字符串常量和只读表。
35. `.data` 保存有初值的可写全局对象。
36. `.bss` 保存零初始化对象，文件中只记录大小。
37. 符号表记录名称、绑定、可见性和所在节。
38. 未定义符号等待链接器从其他对象解析。
39. 局部符号只对当前目标文件可见。
40. 全局符号可参与跨文件解析。
41. 弱符号允许被强符号覆盖。
42. `nm`、`objdump -t` 可检查 ELF 符号。
43. `dumpbin /symbols` 可检查 COFF 符号。
44. 重定位项描述加载地址变化后的修补位置。
45. PC-relative 调用减少绝对地址修补。

## 5. 名字改编

46. C++ 重载要求符号编码参数类型。
47. 名字改编使链接器区分同名重载。
48. `extern "C"` 关闭 C++ 名字改编。
49. C 接口适合跨编译器边界。
50. C++ ABI 不同于语言标准本身。
51. MSVC 与 Itanium ABI 的符号编码不同。
52. `__declspec(dllexport)` 导出 PE 符号。
53. ELF 可用 visibility 属性限制导出集合。
54. 导出过多会增加加载和冲突风险。
55. API 头文件应明确调用约定。

## 6. 链接解析

56. 链接器先收集输入文件与库。
57. 对每个未定义符号执行候选查找。
58. 静态库通常是目标文件归档。
59. 静态库成员按需抽取，顺序可能影响结果。
60. 循环依赖可用重复库参数或对象合并解决。
61. `--start-group/--end-group` 处理复杂循环依赖。
62. MSVC 使用 `.lib` 表示静态库或导入库。
63. 导入库把 DLL 符号转为链接时占位。
64. 重复强符号通常导致 multiple definition。
65. 未解析外部符号通常意味着缺库、签名不一致或导出遗漏。
66. ODR 要求实体在程序中满足单一定义规则。
67. `inline` 允许多个等价定义，但必须逐字一致。
68. 模板定义通常放在头文件以便实例化。
69. 匿名命名空间产生内部链接。
70. `static` 文件作用域变量也可限制可见性。

## 7. 重定位与地址

71. 链接器为符号分配虚拟地址。
72. PIE/ASLR 使模块每次装载地址可变化。
73. 重定位在静态链接或装载时完成。
74. GOT 保存可变的外部函数地址。
75. PLT 提供延迟绑定跳板。
76. `-fno-plt` 可减少部分间接跳转。
77. Windows IAT 承担类似导入地址表职责。
78. RELRO 让解析后的表变为只读。
79. `-z now` 可禁用延迟绑定以提前暴露错误。
80. 绝对地址常量会增加重定位数量。

## 8. 调用约定

81. ABI 规定参数放寄存器还是栈。
82. System V AMD64 使用 RDI、RSI、RDX、RCX、R8、R9 传整数参数。
83. Windows x64 使用 RCX、RDX、R8、R9 传前四个参数。
84. Windows 调用者需预留 shadow space。
85. 返回值通常在 RAX 或 XMM0。
86. 被调用者保存寄存器必须恢复。
87. 栈按 ABI 要求对齐，常见为 16 字节。
88. 可变参数函数依赖额外寄存器保存区。
89. 结构体返回可能隐式增加 sret 指针。
90. 大对象参数可能按地址传递。
91. `__vectorcall` 改变 SIMD 参数传递方式。
92. 尾调用必须满足栈和寄存器约束。
93. 内联汇编不得假设跨平台寄存器名称。
94. FFI 边界优先使用固定宽度整数。
95. 句柄接口比暴露 C++ 对象更稳定。

## 9. 对象布局

96. 非多态类通常按成员声明顺序布局并插入填充。
97. `alignof` 描述类型对齐要求。
98. `sizeof` 包含尾部填充。
99. 空类仍至少占一个字节以区分对象地址。
100. 基类子对象可能位于派生对象起始位置。
101. 多继承可能产生多个基类地址。
102. 虚函数类通常含 vptr，但标准不强制该实现。
103. vtable 存储虚函数入口和 RTTI 信息。
104. 调整 this 指针的 thunk 处理多继承调用。
105. 虚基类会引入额外布局元数据。
106. 不要跨 DLL 直接传递含 STL 成员的类。
107. 编译器选项可能改变枚举和 bit-field 布局。
108. `#pragma pack` 会破坏自然对齐并降低性能。
109. 共享内存结构必须明确字节序与版本。
110. 用静态断言锁定关键布局。

## 10. 动态库加载

111. 加载器映射代码段与数据段。
112. 依赖库按搜索路径逐级查找。
113. Windows 使用 DLL 搜索顺序和 SxS 规则。
114. Linux 使用 RPATH、RUNPATH、LD_LIBRARY_PATH。
115. 不应依赖工作目录提供库文件。
116. 延迟加载把失败推迟到首次调用。
117. 库初始化函数可能在主函数前执行。
118. 静态对象初始化顺序跨翻译单元未定义。
119. 用函数内局部静态对象延迟初始化。
120. `dlopen`/`LoadLibrary` 返回模块句柄。
121. 卸载库前必须销毁仍指向其代码的对象。
122. 线程回调可能在卸载竞态中跳入已释放代码。
123. 热更新需要版本化接口与生命周期协议。
124. ABI 兼容不等于语义兼容。
125. 依赖图应在构建产物中可追踪。

## 11. 版本与兼容性

126. ABI 破坏包括布局、符号、调用约定变化。
127. 添加虚函数会改变 vtable 索引。
128. 重排成员会改变偏移和 sizeof。
129. 改变异常规范可能影响跨边界展开。
130. 改变编译器运行时库会影响 new/delete 配对。
131. DLL 分配内存应由同一模块释放或提供释放函数。
132. 字符串所有权必须写入接口契约。
133. 句柄加代数可避免悬空引用。
134. PImpl 隐藏私有布局变化。
135. C ABI 结构体需带 size/version 字段。
136. 兼容检查应在启动时失败并给出诊断。
137. 符号版本化可支持多代 API 共存。
138. 语义版本不能替代二进制兼容测试。
139. 保留旧入口并转发到新实现。
140. 记录编译器、标准库和编译选项指纹。

## 12. UE 模块实践

141. `MODULE_API` 控制跨模块导出。
142. API 宏在编译 DLL 时展开为 export。
143. 使用模块类型宏而不是手写平台属性。
144. Build.cs 的 Public/PrivateDependencyModuleNames 影响可见头文件。
145. 公共头文件引用的类型必须来自公共依赖。
146. 私有依赖泄漏会导致其他模块无法编译。
147. UHT 生成代码也参与最终链接。
148. Generated.cpp 缺失会产生反射符号错误。
149. 模块加载阶段由 `.uplugin` 与 `.uproject` 决定。
150. `IMPLEMENT_MODULE` 提供模块入口。
151. 编辑器模块不应被运行时模块反向依赖。
152. 第三方库通过 `PublicAdditionalLibraries` 注入。
153. 延迟加载 DLL 需声明 RuntimeDependencies。
154. Shipping 构建应验证导出和依赖完整性。
155. 不同配置可能使用不同宏和布局。

## 13. 诊断命令

156. `clang -###` 显示编译器实际子命令。
157. `clang -ftime-trace` 输出模板耗时。
158. `ldd` 查看 ELF 依赖。
159. `readelf -Ws` 查看动态符号。
160. `objdump -dr` 同时查看反汇编和重定位。
161. `dumpbin /DEPENDENTS` 查看 PE 依赖。
162. `dumpbin /EXPORTS` 查看 DLL 导出。
163. `link /VERBOSE` 输出库搜索过程。
164. `c++filt` 还原 Itanium 名字。
165. `undname` 还原 MSVC 名字。
166. `nm -C` 直接 demangle C++ 符号。
167. `addr2line` 将地址映射到源码行。
168. `llvm-readobj --sections` 检查节属性。
169. `dumpbin /headers` 检查段权限。
170. 对比 map 文件确认符号归属。

## 14. 常见故障

171. LNK2019：声明与实现签名不同。
172. LNK2005：重复定义或运行时库冲突。
173. undefined reference：库顺序或导出缺失。
174. vtable 错误：虚函数实现缺失或 cpp 未加入构建。
175. 找不到 DLL：部署目录或搜索路径错误。
176. 加载失败 193：架构不匹配。
177. 加载失败 126：依赖 DLL 缺失。
178. 崩溃地址无符号：未加载匹配的 PDB/DWARF。
179. ABI 崩溃常表现为堆损坏而非入口错误。
180. 首先核对架构、配置、编译器和运行库。
