# 调试与性能分析方法论

> 知识成熟度：L2；工具行为以 Windows 11、Linux 6.x 和 Clang/GCC/MSVC 为例，命令与实验计划已给出但尚未形成运行证据。
> 知识基线：可复现调试闭环；符号、sanitizer、profiler 行为以工具版本为准。
> 最后更新：2026-08-20。
> 官方参考：[GDB documentation](https://sourceware.org/gdb/documentation/)、[AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html)。
> 验证入口：使用最小复现、sanitizer、采样 profiler 和回归测试记录证据。
> 证据状态：尚未归档最小复现工程、profiler 原始采样、sanitizer 日志和修复前后对比数据。

## 1. 闭环

1. 先定义症状、影响范围和成功标准。
2. 固定版本、配置、平台和输入。
3. 建立最小可复现案例。
4. 收集日志、转储、指标和时间线。
5. 提出可证伪假设。
6. 使用最小侵入实验验证假设。
7. 实施修复并添加回归测试。
8. 在相同负载下比较修复前后。
9. 记录结论、证据和未决风险。

## 2. 调试器基础

10. 断点暂停线程并保存寄存器上下文。
11. 软件断点通常改写指令首字节。
12. 硬件断点监控地址访问，数量有限。
13. 条件断点避免高频路径污染时序。
14. 日志点比断点更适合线上复现。
15. 单步会改变线程调度和缓存状态。
16. 查看调用栈先确认栈指针是否可信。
17. 变量显示依赖调试信息和优化级别。
18. 优化后变量可能被寄存器合并或消除。
19. `-Og` 是兼顾调试和优化的常用选项。
20. MSVC `/Od /Zi` 便于本地单步。
21. Watch 窗口不应调用有副作用函数。
22. 线程窗口用于识别死锁和饥饿。
23. 反汇编可验证编译器是否内联。
24. 内存窗口可识别越界写入痕迹。
25. 数据断点适合追踪谁修改了字段。

## 3. 崩溃现场

26. 记录异常码、故障地址、线程 ID 和模块版本。
27. Windows minidump 应包含线程、模块和内存流。
28. Linux core 需配套可执行文件与符号文件。
29. 先加载完全匹配的 PDB/DWARF。
30. 栈回溯从故障线程开始，再看其他线程。
31. `SIGSEGV` 常见原因是野指针或权限错误。
32. `SIGABRT` 通常由断言或运行库检测触发。
33. 访问地址接近零提示空指针偏移。
34. 访问地址随机且变化提示悬空指针。
35. 栈指针异常提示栈破坏或 ABI 不匹配。
36. 检查最后一个可信帧而非盲信顶部帧。
37. 多线程崩溃需检查持锁状态。
38. 记录最近事件环形缓冲可补足前置因果。
39. 线上转储应脱敏并限制大小。
40. 崩溃聚合按签名、版本、设备分组。

## 4. 内存错误

41. AddressSanitizer 检测越界、UAF 和 double free。
42. ASan 通过 shadow memory 标记不可访问区域。
43. UBSan 检测有符号溢出、错位和非法转换。
44. ThreadSanitizer 检测数据竞争，但开销较大。
45. MSVC `/fsanitize=address` 支持常见堆错误。
46. Sanitizer 构建不能代表发布性能。
47. 保留符号和栈展开信息提高报告可读性。
48. 报告中的第一处非法访问最有价值。
49. 红区 poisoning 让越界更早失败。
50. 关闭 sanitizer 只能用于隔离，不是修复。
51. Valgrind Memcheck 适合无源码重编译场景。
52. Memcheck 速度慢，应缩小测试输入。
53. 碎片化问题可用堆统计和分配采样分析。
54. 自定义 allocator 要提供 sanitizer 友好钩子。
55. 释放后置空只能降低重复使用，不能修复竞态。

## 5. 线程与同步

56. 死锁需要至少两个线程和环路等待。
57. 统一锁顺序可消除环路。
58. 超时获取锁能把永久阻塞转为可观测错误。
59. 优先级反转需要优先级继承或分层设计。
60. 活锁表现为持续运行但无有效进展。
61. 饥饿表现为某线程长期得不到资源。
62. 采集锁等待时间而非只看持锁时间。
63. 线程命名帮助转储和 profiler 识别。
64. 原子变量不能自动保护复合不变量。
65. TSan 报告需确认是否为真实共享状态。
66. 无锁结构必须明确内存回收方案。
67. hazard pointer 和 epoch reclamation 解决 UAF。
68. 条件变量等待必须使用谓词循环。
69. 虚假唤醒是允许行为。
70. 关闭流程要定义线程退出和资源释放顺序。

## 6. 日志与可观测性

71. 日志事件包含时间、级别、模块和关联 ID。
72. 使用单调时钟计算持续时间。
73. 墙上时钟用于展示和跨机器对齐。
74. 结构化日志便于查询和聚合。
75. 高频路径采用采样或聚合计数。
76. 日志级别可动态调整但需权限保护。
77. 严重错误必须包含输入摘要而非完整敏感数据。
78. 关键路径使用 trace span 记录开始和结束。
79. span 应传播请求、玩家或任务 ID。
80. 指标分为计数器、仪表盘和直方图。
81. 直方图用于 p50、p95、p99 延迟。
82. 平均值会掩盖长尾。
83. 指标标签数量必须受控避免基数爆炸。
84. 采样率写入元数据便于解释数据。
85. 观测系统自身开销也要基准测试。

## 7. 性能假设

86. 先确认瓶颈属于 CPU、内存、IO 或锁。
87. Amdahl 定律限制局部优化收益。
88. 先测量再优化，避免凭直觉改代码。
89. 每次实验只改变一个主要变量。
90. 预热 JIT、缓存和连接池后再测。
91. 固定 CPU 频率和绑核减少噪声。
92. 记录样本数、均值、中位数和分位数。
93. 报告置信区间而非单次最好成绩。
94. 基准输入应覆盖小、中、大三档。
95. 负载模型要说明并发度和请求分布。
96. 避免把日志输出计入核心函数耗时。
97. 使用黑洞防止编译器消除工作。
98. 检查编译器是否把测试循环优化掉。
99. 端到端指标与微基准必须相互印证。
100. 优化结果需在目标硬件复测。

## 8. 采样分析

101. 采样 profiler 周期性记录调用栈。
102. 火焰图宽度代表样本占比而非绝对时间。
103. 平顶函数是自身消耗高的候选热点。
104. 宽而浅的栈表示大量调用分散开销。
105. 先看业务符号，再看运行库和系统调用。
106. perf `record` 采集样本，`report` 汇总。
107. `perf stat` 可观察 cycles、instructions 和 cache-misses。
108. Windows 可用 WPA、ETW 和 Visual Studio Profiler。
109. Unreal Insights 适合 UE 线程和任务时间线。
110. 采样频率过高会扰动程序。
111. 采样丢失时检查权限和 buffer 大小。
112. 反汇编确认热点是否由分支或访存主导。
113. 分支预测失败会造成流水线清空。
114. LLC miss 常意味着工作集或访问模式问题。
115. 采样结果需标注构建配置。

## 9. 插桩分析

116. 插桩在入口和出口记录精确耗时。
117. RAII span 可保证异常路径结束记录。
118. 插桩适合短时间、低频或关键事务。
119. 高频函数插桩可能改变内联和缓存行为。
120. 通过采样开关动态降低开销。
121. 记录计数器比记录每次事件更省空间。
122. 事件缓冲采用无锁单生产者队列。
123. 缓冲满时应丢弃低优先级事件。
124. 绝不能因观测阻塞主线程。
125. 将时间戳统一为 TSC 或单调时钟。
126. TSC 跨核同步性需在目标平台验证。
127. GPU 插桩要区分提交、执行和等待时间。
128. 网络插桩记录排队、发送和确认阶段。
129. 数据库插桩记录连接池等待与服务端执行。
130. 插桩字段要有稳定 schema。

## 10. CPU 与内存

131. IPC 低可能由分支、依赖或缓存等待造成。
132. CPI 可粗略定位流水线瓶颈。
133. 顺序访问通常比随机访问更友好。
134. SoA 适合批处理同一字段。
135. AoS 适合需要同时访问完整对象。
136. cache line 常见为 64 字节但应运行时确认。
137. false sharing 会放大跨核写入成本。
138. 对热点计数器按 cache line 填充。
139. 过度填充增加内存占用和带宽压力。
140. 预取只应在测量确认收益后加入。
141. 大页减少 TLB miss 但增加管理复杂度。
142. NUMA 机器优先本地分配和本地访问。
143. 绑核后必须检查线程与内存亲和性。
144. 内存带宽瓶颈无法靠更多线程解决。
145. 使用 roofline 思路判断算力或带宽受限。

## 11. IO 与网络

146. IO 延迟由排队、系统调用和设备服务组成。
147. 批量读写减少系统调用次数。
148. `O_DIRECT` 绕过页缓存但要求对齐。
149. 异步 IO 需要明确完成通知语义。
150. epoll 等待时间应与处理时间分开统计。
151. TCP 小包可能受 Nagle 和 delayed ACK 影响。
152. UDP 丢包需在应用层定义重传或容错。
153. 网络吞吐受带宽、拥塞窗口和 CPU 共同限制。
154. 使用 pcap 或 ETW 关联线上异常。
155. DNS、TLS、连接建立耗时要独立拆分。

## 12. 基准与回归

156. 基准代码与生产代码共享核心实现。
157. 负载生成器应支持固定随机种子。
158. 先验证结果正确，再比较速度。
159. 结果文件保存硬件、编译器和提交号。
160. 采用 warmup、测量、冷却三个阶段。
161. 统计离群值并说明剔除规则。
162. 性能门禁应设置相对退化阈值。
163. 阈值过紧会造成环境噪声误报。
164. 阈值过松会放过真实回归。
165. CI 运行固定容器或固定裸机。
166. 比较分布而非只比较均值。
167. 对关键路径保存历史趋势图。
168. 版本升级需重新建立基线。
169. 优化提交附带可复现实验命令。
170. 任何“快了”都必须有样本与场景。

## 13. 典型排障

171. CPU 飙高先看热点线程和调用栈。
172. 延迟飙高先看 p99 与排队深度。
173. 内存增长先区分常驻、缓存和泄漏。
174. 卡顿问题要记录主线程帧时间。
175. 偶发崩溃优先启用转储和事件环。
176. 数据错乱先检查竞争与生命周期。
177. 启动变慢检查动态库和静态初始化。
178. 首帧变慢区分 IO、编译着色器和资源上传。
179. 网络抖动比较客户端、服务端和链路时间戳。
180. 优化无效时检查测量点是否覆盖真实路径。

## 14. 实验清单

181. 用 ASan 复现一次 UAF。
182. 用 TSan 复现两个线程的非原子竞争。
183. 生成 core 并用 gdb 回溯。
184. 生成 minidump 并加载匹配 PDB。
185. 用 perf stat 比较顺序和随机访问。
186. 画一张 CPU 火焰图并标注平顶函数。
187. 用 ETW 追踪一次长尾请求。
188. 为接口添加 p50/p95/p99 指标。
189. 写基准并固定随机种子。
190. 注入 1% 失败，验证错误路径日志。
191. 模拟锁竞争并观察等待直方图。
192. 测量日志开启和关闭的开销。
193. 比较 AoS 与 SoA 的缓存 miss。
194. 使用 heap profiler 定位分配热点。
195. 将性能门禁接入 CI。

## 15. 复盘模板

196. 事件时间线：发现、缓解、修复、验证。
197. 影响面：用户、区域、版本和持续时间。
198. 触发条件：输入、并发、资源和环境。
199. 证据链：日志、转储、指标和实验。
200. 根因：违反了哪个不变量。
201. 修复：代码、配置或流程变更。
202. 回归：自动测试和线上监控。
203. 未决项：仍存在的风险与假设。
204. 行动项：负责人、截止日期和验收标准。
205. 将复盘结论沉淀为运行手册。

## 16. 参考边界

206. 参考 sanitizer、perf、ETW、gdb、lldb 官方文档。
207. 工具版本会影响采样事件名称和输出格式。
208. 采样结果不能直接证明因果关系。
209. 微基准不能替代端到端压测。
210. 线上数据需遵循隐私和保留策略。
211. 调试开关必须可审计并可回滚。
212. 生产环境避免永久启用高开销插桩。
213. 结论附带硬件、配置和样本范围。
214. 对未知行为标注待验证，而非猜测。
215. 任何性能优化都应保留正确性测试。
216. 为每个服务定义启动健康检查。
217. 为每个关键线程定义存活指标。
218. 为队列定义长度和等待时间告警。
219. 为缓存定义命中率和淘汰率。
220. 为连接池定义利用率和耗尽次数。

222. 为限流定义拒绝率和恢复时间。
223. 为熔断定义打开、半开和关闭事件。
224. 为后台任务定义积压年龄。
225. 为定时任务定义错过周期计数。

236. 采集指标时记录实例与区域标签。

249. 定期演练符号服务器恢复。
250. 定期演练历史数据查询。
251. 将性能基线纳入版本发布模板。
