## 2. 核心机理：理论复杂度 vs 硬件物理现实

在传统算法教学中，数据结构以“比较次数”衡量代价；但在现代超标量处理器上，**一次 DRAM 随机访问（约 200 个 CPU 周期）足以执行数百次顺序 ALU 运算**：
- **连续内存的降维打击**：`std::vector` / `TArray` 具备优良的空间与时间局部性，触发硬件预取器（Hardware Prefetcher），遍历几乎全命中 L1/L2 缓存；
- **离散节点的性能深渊**：`std::list` / `std::map` 每次节点访问都可能是随机指针跳跃，极易导致 TLB Miss 与 L3 Cache Miss；
- **哈希冲突与平铺哈希**：拉链法哈希存在离散指针惩罚，现代工业级哈希普遍采用开放寻址闭散列（如 Flat Hash Map / `TMap`），以连续内存桶保证寻址高速。

## 3. 游戏研发与工程落地对接

- **Unreal Engine (UE5)**：
  - UE 核心容器设计哲学：优先使用紧凑数组 `TArray`，稀疏数组 `TSparseArray` 与紧凑索引集合 `TSet`；
  - 为什么 UE 没有提供官方的 `TList`（双向链表）：避免离散节点引发的严重缓存污染；
  - 空间划分数据结构：四叉树/八叉树在实际游戏场景中常以扁平线性数组（Linear Array）或 BVH 形式存储。
- **游戏服务端**：
  - 定时器轮（TimerWheel）与最小堆（PriorityQueue）在百万级心跳/倒计时调度中的复杂度与内存权衡；
  - 实体管理：连续内存 Archetype 表与稀疏集合（Sparse Set）的高效遍历。
