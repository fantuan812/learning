# 数据结构、复杂度与工程容器选型

## 1. 目标与边界

数据结构把状态组织成可操作的抽象。
复杂度描述输入规模增长时的资源趋势。
工程选型还必须考虑常数、内存、局部性、并发和生命周期。
本文覆盖顺序表、链表、栈队列、哈希、树、堆、图与并查集。
不替代具体 STL/UE API 文档。

## 2. 复杂度模型

设 n 为元素数，m 为边数，V 为顶点数。
O(1) 表示有界操作次数，不代表零成本。
O(log n) 常见于平衡树和二分查找。
O(n) 通常需要扫描一次。
O(n log n) 是比较排序的典型上界。
O(n²) 在成对比较时出现。
均摊复杂度把一系列操作的总成本平均到每次。
动态数组扩容单次可能 O(n)，但 push_back 均摊 O(1)。
最坏情况用于延迟上界；平均情况必须声明分布假设。
空间复杂度应区分额外空间与输入存储。
递归还需计算调用栈深度。

## 3. 证明与估算

循环次数可用求和式表达。
二重循环 i、j 独立时通常为 O(n²)。
j 从 i 到 n 时为 n(n+1)/2，仍为 O(n²)。
每次减半的循环满足 k=log₂n。
分治递推 T(n)=aT(n/b)+f(n)。
哈希平均 O(1) 依赖装载因子和散列质量。
尾递归不应默认被编译器消除。
常数估算可用“每帧预算”和“每 tick 预算”。
复杂度不能掩盖 I/O、锁竞争和缺页。

## 4. 顺序表与动态数组

连续数组提供最佳空间局部性。
索引访问为 O(1)。
尾部插入通常均摊 O(1)。
中间插入需要移动后缀，成本 O(n)。
删除同样需要搬移元素。
扩容策略常见为 1.5 倍或 2 倍。
增长因子越大，扩容少但峰值内存高。
reserve 预留容量可避免热路径重新分配。
resize 改变逻辑长度，reserve 不改变长度。
迭代器可能因扩容失效。
元素移动可能触发析构、分配和异常处理。
SoA 将字段拆成数组，适合批量遍历。
AoS 保留对象语义，适合按实体访问多个字段。
热字段与冷字段拆分能减少 cache line 载入。

## 5. 链表

单链表节点含值和 next 指针。
已知节点位置时插入删除 O(1)。
按索引访问为 O(n)。
节点离散分配导致 cache miss。
额外指针使每元素占用增加。
侵入式链表把链接字段放进业务对象。
free list 可复用节点并降低分配器压力。
双向链表支持向前和向后删除。
哨兵节点可统一边界条件。
实时系统不应在不可控路径频繁 new 节点。

## 6. 栈与队列

栈遵循后进先出。
调用栈、撤销操作和 DFS 都使用栈模型。
栈顶 push/pop 为 O(1)。
队列遵循先进先出。
环形队列用 head、tail 和容量实现。
容量为 2 的幂可用位掩码取模。
无锁队列需明确单生产者/多生产者约束。
阻塞队列还要定义唤醒、关闭和超时语义。
双端队列支持两端 O(1) 操作。

## 7. 哈希表

哈希表通过 key 映射桶位置。
装载因子 α=n/b 影响冲突概率。
开放寻址把元素存于桶数组内。
线性探测简单且局部性好。
二次探测减少主聚集。
拉链法使用桶内链或小数组。
开放寻址删除需墓碑或后移修复。
rehash 会重新计算全部位置，成本 O(n)。
reserve 应按目标元素数和装载因子换算桶数。
坏散列可能退化到 O(n) 查找。
哈希 key 必须满足相等对象哈希相同。
浮点数不宜直接作为业务 key。
随机种子可降低对抗性碰撞风险。
并发哈希表要规定读写锁或分片策略。

## 8. 树与堆

二叉搜索树要求左小右大。
退化树高为 n，查找退化 O(n)。
AVL 通过旋转保持严格平衡。
红黑树平衡较宽松，更新常数较低。
B 树按页组织节点，适合磁盘和数据库。
堆只保证根是最小或最大元素。
二叉堆插入、删除根为 O(log n)。
建堆可在线性 O(n) 完成。
优先队列适合定时器、任务调度和 A* open set。
需要修改任意优先级时应保存句柄或采用惰性删除。

## 9. 图与并查集

邻接矩阵空间 O(V²)，查询边 O(1)。
邻接表空间 O(V+E)，遍历稀疏图更优。
BFS 按层访问，时间 O(V+E)。
DFS 可用于连通分量和拓扑排序。
Dijkstra 要求非负边权。
Bellman-Ford 可处理负边但更慢。
并查集支持连通性判断。
路径压缩与按秩合并近似 O(α(n))。
拓扑排序要求有向无环图。
图数据应明确顶点编号、边方向和权重类型。

## 10. 字符串与空间索引

前缀树按字符路径组织 key。
前缀树查询复杂度与字符串长度相关。
压缩 trie 合并单分支，降低节点数。
字符串小对象优化可避免短串堆分配。
字符串视图必须保证被引用内存生命周期。
网格索引适合固定地图和近邻查询。
四叉树按空间递归分区。
动态场景需限制重建和迁移成本。
空间哈希用量化坐标映射桶。

## 11. 容器选型决策

先写访问模式：顺序、随机、按 key、按优先级或邻域。
再写更新模式：尾插、中插、删除、批量重建。
明确 n 的范围、峰值和增长速度。
明确实时约束：单帧预算、尾延迟和是否允许分配。
优先连续存储，除非稳定迭代器或局部插入更重要。
小 n 时线性扫描常胜过哈希。
需要排序遍历时选择有序树或排序后的数组。
读多写少可采用不可变快照。
批量查询可先排序 key 再归并。
跨线程共享优先考虑所有权转移和消息传递。

## 12. 缓存与内存

CPU 以 cache line 搬运内存，常见为 64 字节但需实测。
顺序访问通常触发硬件预取。
指针追逐会破坏空间局部性。
分支不可预测会造成流水线清空。
结构体填充影响容量和带宽。
对齐要求由类型和 ABI 决定。
热循环应减少间接调用和随机访问。
批处理可摊薄边界检查与虚函数开销。
压缩索引能提高缓存命中，但增加解码成本。
不要仅凭 sizeof 判断性能，需基准验证。

## 13. C++ 与 UE 注意事项

std::vector 扩容会使引用、指针和迭代器失效。
std::deque 非连续但两端操作稳定。
std::list 仅在确有节点语义时使用。
std::unordered_map 不保证遍历顺序。
UE TArray 适合连续元素和索引访问。
TMap 的哈希与内存行为应结合引擎版本确认。
对象指针容器不等于对象生命周期管理。
GC 对象引用必须遵循 UE 标记规则。
容器元素移动构造应保证异常和不变量。

## 14. 基准测试方法

固定编译器、优化级别和 CPU 频率策略。
预热缓存和分配器后再测稳态。
分别测冷启动、稳态和扩容峰值。
记录吞吐、p50、p95、p99 和最大值。
避免测试循环被优化掉，使用校验和。
隔离线程，记录 NUMA 与 CPU 亲和性。
改变 n、命中率、装载因子和数据分布。
比较随机访问与顺序访问。
用 perf、VTune 或 Unreal Insights 观察 cache miss。
性能结论必须附硬件、编译器和数据集。

## 15. 常见误区

O(1) 不代表比 O(log n) 快。
哈希平均复杂度不是最坏保证。
链表插入 O(1) 需要已知节点位置。
reserve 不是减少逻辑元素。
缓存友好不等于永远使用数组。
无锁不等于无等待或无 ABA 风险。
微基准不能直接推导线上收益。
复杂度分析不能替代正确性证明。

哈希最坏查找：O(n)。
平衡树查找：O(log n)。
堆插入：O(log n)。
堆取根：O(log n)。
堆建堆：O(n)。
BFS：O(V+E)。
DFS：O(V+E)。
并查集合并：近似 O(1)。
排序数组二分：O(log n)。
排序数组插入：O(n)。
前缀树查询：O(L)。
空间哈希近邻：取决于桶和邻域。
