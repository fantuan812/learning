# 软件工程与构建

本分类连接源代码、构建系统、测试和交付，面向可重复、可诊断、可演进的软件工程实践。

## 主题

- 构建图、CMake、依赖与 ABI
- 分支、代码评审与变更管理
- 单元、集成、系统、性能和模糊测试
- 静态分析、格式化、覆盖率与质量门禁
- CI/CD、制品、版本和可回滚发布
- 架构决策、模块边界和技术债

## 专题

- [版本控制、依赖与构建工程](./版本控制依赖与构建工程.md)
- [测试、静态分析、Fuzz 与持续交付](./测试静态分析Fuzz与持续交付.md)

## 阅读顺序

1. 先读 [软件工程与构建基础](./软件工程与构建基础.md)。
2. 再结合语言、操作系统、网络和调试章节做实验。
3. 将构建日志、测试报告和发布记录作为证据保存。

## 实践要求

- 所有构建命令应可在干净环境重放。
- 依赖必须锁定版本并记录来源、许可证和哈希。
- 失败测试先定位最小复现，再修改实现。
- 每次架构变更记录上下文、决策和替代方案。
