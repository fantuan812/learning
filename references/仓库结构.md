## 3. README 同步规则

1. 每个包含知识 Markdown 的分类目录必须有 `README.md`。
2. 分类 README 的正文文件清单必须使用真实 Markdown 链接，不能只写反引号文件名。
3. 上级 README 必须链接到每个下级分类 README；根 README 必须链接到每个顶层内容目录 README。
4. 删除、改名或新增正文时，同一目录 README 的导航和文件简介必须同一提交同步修改。
5. 只允许使用仓库内相对链接指向本地文件；外部资料使用稳定的官方 URL，并注明版本与核对边界。

## 4. UE 版本与源码边界

- 当前 UE 资料基准为本机 `C:\Program Files\Epic Games\UE_5.8`。
- 当前本机证据来自 `Engine\Build\Build.version`：Major 5、Minor 8、Patch 0、Changelist 55116800、BranchName `++UE5+Release-5.8`。
- 文档必须把版本差异写成“当前基准 + 历史兼容性说明”。`UE 4.27` 只能作为迁移/差异背景，不能出现在未加说明的当前适用版本位置。
- 源码分析必须列出实际存在的源码路径、代表文件和验证命令；未完成的主题必须标为“待补/规划”，不得用概念文章数量替代源码覆盖。
- 源码安装目录只读，知识库维护脚本不得修改引擎文件。

## 5. 维护目录约定

- [写作规范](写作规范.md) 是正文、元数据、链接和 Mermaid 的写作约束。
- [lessons.md](../learning/lessons.md) 只保存提炼后的稳定规则。
- [log.md](../learning/log.md) 只增不改，使用 `scripts/append_lesson.ps1` 按实际发生时间追加经验。
- [check_repo.ps1](../scripts/check_repo.ps1) 输出 `PASS`、`WARN`、`FAIL`，失败项必须在交付前归零；正文短于 300 行属于警告，除非该文件是 README、日志或路线图。

## 7. 多智能体知识库控制面（2026-08-13 新增）

仓库根新增 Codex 多智能体知识库控制面，与既有目录共存：既有领域目录（游戏知识、游戏服务端等）继续作为 Canonical Knowledge 实体，新控制面负责“如何整理”的规则、角色与状态。

| 路径 | 职责 |
| --- | --- |
| `AGENTS.md` | Codex 最高层行为：Inspect → Analyze → Plan → Review → Execute → Audit；主线程决策、子代理只读取证 |
| `.codex/config.toml` | 开启子代理，`max_concurrent_threads_per_session=5`，默认子代理模型 `opencode-go/deepseek-v4-flash`、推理 `max` |
| `.codex/agents/kb-*.toml` | 五个只读角色：kb_scanner / kb_analyzer / kb_architect / kb_curator / kb_auditor |
| `.agents/skills/knowledge-base-organizer/SKILL.md` | 知识库整理标准工作流（single_document / inbox_cleanup / incremental_update / topic_cleanup / audit / full_rebuild） |
| `.kb/` | 控制平面状态：manifest / taxonomy / aliases / decisions / review-queue / plans |
| `00_Index/` | 全局 MOC 与导航索引 |
| `Knowledge/`、`Projects/` | 通用知识 / 项目知识的规范位置（既有领域目录为实体） |
| `Inbox/`、`Archive/` | 未处理材料入口 / 历史原材料与删除候选 |

约束：子代理一律只读；所有结构性写入由主线程串行执行；confidence < 0.75 的操作进入 `.kb/review-queue.md`；永久删除须用户明确要求。
