## 3. README 同步规则

1. 每个包含知识 Markdown 的分类目录必须有 `README.md`。
2. 分类 README 的正文文件清单必须使用真实 Markdown 链接，不能只写反引号文件名。
3. 上级 README 必须链接到每个下级分类 README；根 README 必须链接到每个顶层内容目录 README。
4. 删除、改名或新增正文时，同一目录 README 的导航和文件简介必须同一提交同步修改。
5. 只允许使用仓库内相对链接指向本地文件；外部资料使用稳定的官方 URL，并注明版本与核对边界。

## 4. UE 版本与源码边界

- 当前 UE 资料基准为本机 `C:\Program Files\Epic Games\UE_5.8`。
- 当前本机证据来自 `Engine\Build\Build.version`：Major 5、Minor 8、Patch 0、Changelist 55116800、BranchName `++UE5+Release-5.8`。
- 文档必须把版本差异写成“当前基准 + 历史兼容性说明”。`UE 4.27` 只能作为迁移/差异背景，不能出现在未加说明的当前适用版本位置。
- 源码分析必须列出实际存在的源码路径、代表文件和验证命令；未完成的主题必须标为“待补/规划”，不得用概念文章数量替代源码覆盖。
- 源码安装目录只读，知识库维护脚本不得修改引擎文件。

## 5. 维护目录约定

- [写作规范](写作规范.md) 是正文、元数据、链接和 Mermaid 的写作约束。
- [lessons.md](../learning/lessons.md) 只保存提炼后的稳定规则。
- [log.md](../learning/log.md) 只增不改，使用 `scripts/append_lesson.ps1` 按实际发生时间追加经验。
- [check_repo.ps1](../scripts/check_repo.ps1) 输出 `PASS`、`WARN`、`FAIL`，失败项必须在交付前归零；正文短于 300 行属于警告，除非该文件是 README、日志或路线图。
