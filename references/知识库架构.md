# 知识架构与唯一事实源

## 按知识职责分类

[八域知识体系](../知识/README.md)是读者主入口。编程基础、数学算法、引擎、表现仿真、Gameplay、AI、联机服务端、工程质量分别回答不同问题。UE是技术栈，源码分析是内容类型，官方文档是来源；三者独立于主题分类。

每篇只有一个主责领域；每个跨域概念登记一个主文。正文可解释完整链路，不因为跨域而机械拆碎，也不复制第二套正文。具体边界见[知识体系](../知识/README.md#分类边界)。

## 每类事实只维护一次

| 事实 | 唯一来源 | 消费方 |
| --- | --- | --- |
| 文档稳定身份、当前路径、主域、内容类型与技术栈标签 | [.kb/knowledge-map.json](../.kb/knowledge-map.json) documents | 八域导航与图检查 |
| 跨域概念主责与类型化关系 | 同图 concepts / relations | [跨域关系](../00_Index/跨域关系.md)、学习路线 |
| 标题、来源、状态、成熟度、验证事件 | 正文frontmatter | YAML / OKF检查、Obsidian |
| 文件路径、字节、行数快照 | [.kb/manifest.yaml](../.kb/manifest.yaml) | 现行架构门禁；机械重建 |
| 顶层目录责任 | [.kb/architecture.json](../.kb/architecture.json) | 现行架构门禁 |
| 维护授权、单写者与保全合同 | [AGENTS](../AGENTS.md) | 所有维护操作 |

稳定ID首次分配后不随重命名变化。路径变更更新对应path、标准Markdown入链，并在legacy_paths保存不重用的旧路径。legacy_paths是定位与质量规则的迁移历史，不是可访问的重复正文，也不能豁免新域门禁。概念主责必须引用已有文档ID；前置关系不得成环，普通相关关系可以互链。关系方向明确：prerequisite为前置→依赖它的知识；implemented_by为主责→源码实现；applied_in为主责→应用案例；verified_by为主责→实验；related是普通关联。identity graph 不复存正文的成熟度或标题。

## 保留的资料与证据

- [书籍与读书笔记](../读书笔记/README.md)：现有全部书籍、中文版、PDF、图片、笔记及相关处理工具保留；主题图提供阅读关联，不替换原件
- [工作日志](../工作日志/README.md)：原文、日期、项目上下文及附件保留；可以另提炼知识，但不能以提炼结果或Git历史代替原日志
- [实验](../evidence/README.md)：源代码、依赖、输入输出与复现说明成套保留；运行证据必须注明平台及实际执行边界

知识正文和资料视图互链，不按书名、日期、AI工具重新建立主题主分类。已有资料授权不自动外推给未来新引入材料；新增来源按真实许可与版本登记，不编造授权条款。

## 分阶段迁移

第一批已建立八域身份图、主责关系、导航及增强校验。306篇核心知识条目已按职责迁入知识目录，每个稳定身份只有一个当前路径；旧README的独特学习指导正在独立收敛为路线视图，书籍、日志和实验证据保留原位。所有物理迁移使用固定旧→新映射，确保纯移动内容可复核、跨文件链接可解析、受保护资料原文不丢失，再清除无知识的旧骨架和过时维护噪声。

旧taxonomy和旧领域MOC处于兼容期，不再决定新内容主域。它们随物理迁移收敛，不能另设一份互相冲突的分类事实源。
